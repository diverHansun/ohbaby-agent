# 模块目标与职责

状态：待实施设计。产品规则以 [00 讨论记录](../00-discussion.md) 为准。

## Design Goals

子代理结束后，结果先成为可恢复的事实，再交给主代理处理。主代理空闲时能自动继续，忙时在安全的输入边界接收；界面能够区分子任务完成与主代理处理失败。服务故障后，恢复过程能够说明中断原因，不要求用户重新描述原任务。

可靠性的范围是本机现有持久化存储和单会话执行边界。保证稳定身份、幂等接收、成功请求确认和可解释的恢复；不承诺模型请求、外部工具副作用或任务语义的 exactly-once。

## Duties

| 职责 | 内容 |
| --- | --- |
| 接收父子消息 | 复用主到子消息通道，校验来源、父子关系、scope 和重复请求的一致性 |
| 交付终态事实 | 完成、失败、超时、服务故障中断生成稳定结果来源；主动停止子代理保留控制回执语义 |
| 协调消费 | 复用 runtime input，将已接收、已尝试、成功请求确认分开；补齐成功后确认前崩溃的核对 |
| 请求主代理续跑 | 使用现有 gate 和 Goal 准入；合并当时可处理的结果，不等待所有子代理 |
| 恢复与诊断 | 依持久记录判定能否补投、能否再启动；暴露入口失败、处理中断和未消费结果 |

主 Stop 只结束当前主运行。后台子代理之后产生的新结果仍可唤醒主代理。主代理收到故障通知后，可以在原任务、权限和预算范围内自行选择补救方法。

## Non-Duties

不运行 LLM、不复制会话执行器、不重新实现 provider retry、不代替主代理决定补救任务。不增加信箱表、通用消息队列、任意代理通信协议、周期性模型巡查、跨机器调度和新的权限体系。

不把执行状态和投递状态合并；不让 list/monitor 消费结果或触发恢复。不自动重放崩溃前的工具命令，不把已关闭的主到子消息再次隐式发送。不承诺进程死亡期间仍能运行模型；中断通知在服务恢复并取得会话执行所有权后交付。
