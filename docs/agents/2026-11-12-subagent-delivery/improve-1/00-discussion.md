# 讨论记录与已确认要点

2026-11-12。来源为本次用户对话，以及用户指定的 lifecycle 历史设计。当前工作是分析和文档，不实施代码。

## 1. 背景

用户指出本地会话“搜索海淀高校秋招活动时间”的子代理均已结束，主代理仍停留在等待最后一份结果的回答。要求调查原因、对应历史提交，并阅读本地 Codex、DSH、Kimi Code、ZCode 后逐项讨论方案。

## 2. 已确认规则

| 编号 | 结论 |
| --- | --- |
| D01 | 把可靠投递整理为内部服务模块，复用现有存储，不增加一套需要同步的信箱状态。 |
| D02 | 本轮只覆盖父子代理可靠传递与自动续跑，能力边界参考现有优秀项目。 |
| D03 | 结果保存、输入接收、请求发起、请求成功是不同事实。包含该输入的模型请求成功且记录已保存，才确认消费；不保证模型理解正确或整个任务完成。 |
| D04 | 多个结果可合并，不等所有子代理结束。A、B 先完成就先处理，C 完成后再续跑。 |
| D05 | 主代理 Stop 只停止主代理当前执行，后台子代理继续。新的子代理结果仍能唤醒主代理。停止指定子代理沿用独立 stop 操作。 |
| D06 | 同一结果触发的主轮次失败或被停止后，不因重复通知或扫描立即再次启动；新的结果或用户输入可以带上尚未消费的结果。 |
| D07 | 子代理 LLM 请求重试耗尽、超时以及服务故障造成的中断，都应通知主代理。服务崩溃须恢复并核实后通知。主动 stop/close 的控制回执不单独自动唤醒。 |
| D08 | 主代理收到通知后，可在原任务范围内自行补救，不要求用户再说“继续”；使用现有 monitor、send 等工具，也可自行完成剩余工作。 |
| D09 | 主代理可主动用 list、monitor 查看进度。读取立即返回已有记录，不等待、不轮询占用模型，不确认结果已消费。 |
| D10 | 保留已有输出和未处理消息信息；读取输出失败时仍交付基本结果或故障通知。服务退出后的工具结果可能不完整，继续前检查实际状态。 |
| D11 | 子代理执行状态与结果交付状态分开。列表只补必要的等待或异常说明；主代理自动运行即使没有输出也应显示失败。复用现有 Web/TUI 轮次错误展示。 |
| D12 | 只补交已有结果，不由恢复程序自动重放中断命令或重新派遣任务。主代理收到故障通知后如何补救，仍受现有任务、权限和预算约束。 |
| D13 | 文档放在本目录，包含精简关键改动清单；使用 plan-module-design 与 plan-code-improvement，文档完成后调用指定 Pi 模型 high 检查。 |

## 3. 本轮边界

不增加消息中间件、通用代理网络、单独的信箱表、分布式调度器或新的恢复工具。不恢复已删除的定时模型监督，不替换 provider 的重试策略，不重做子代理面板，不承诺跨进程恢复正在执行的 LLM 请求或命令。

文档中的启动故障重试次数、字段命名和接口组织属于工程细化；不得因此改变 D05、D06。Goal 的暂停、终止、预算、Rewind 与会话销毁继续遵守已有规则，不能借普通结果唤醒绕过。

## 4. 与旧设计的关系

- 继承 [lifecycle D08、D54](../../../problem-lists/2026-10-26-subagent-lifecycle/improve-1/00-discussion.md)：跨主轮次运行、Stop 后新结果仍可唤醒、统一后台模式。
- 继承 [lifecycle 结果交付规则](../../../problem-lists/2026-10-26-subagent-lifecycle/improve-1/02-optimization-plan-and-change-scope.md)：稳定来源、请求成功确认、同一失败结果不反复唤醒、monitor 只读。
- 本轮补充故障中断通知，区分故障与主动停止。旧代码将所有 `interrupted` 都排除投递，需要调整。
- 保留 11 月 7 日取消定时模型监督的决定。
- [模型等待与错误反馈](../../../problem-lists/2026-11-11-model-waiting-and-error-feedback/README.md) 定义错误展示方式；本轮补齐无可见消息的自动运行失败，属于其原“轮次可见性不变”边界之外的明确扩充。
