# 2. 优化方案与改动面

> 2026-10-21 根据讨论定稿，尚未实施。已确认决策见 [00](00-discussion.md)，代码依据见 [01](01-problem-analysis-and-current-state.md)，验收见 [04](04-test-and-acceptance.md)。本文约定行为与必要改动，具体内部字段名由实施阶段确定。

## 2.1 方案总览

保留“一个目录对应一个实例”的运行方式，增加固定默认工作区，并把会话的项目归属与实际工作目录分开。全局层负责会话列表、搜索与项目归属操作；实际对话仍由对应目录的实例执行。

| 层 | 职责 |
|---|---|
| daemon 全局层 | 项目列表、默认目录、跨项目会话列表与搜索、会话项目归属变更 |
| 目录实例 | 执行对话，提供该目录下的 MCP、Skills、Agents 和设置快照 |
| Web | 管理发送前的草稿，以会话为中心展示侧栏，按服务端返回的执行目录发送请求 |

新增全局接口沿用 token 鉴权。实例内接口继续要求 `x-ohbaby-directory`，缺头仍返回 400。无项目会话使用真实目录运行，工具与权限沿用现有规则。

## 2.2 会话生命周期与最小数据模型

### 用户操作

| 操作 | 项目归属 | 工作目录与会话行为 |
|---|---|---|
| 点“新会话” | 草稿默认无项目 | 不创建服务端会话；可输入、选项目、换项目，保留输入文字 |
| 首次发送，未选项目 | 无项目 | 在默认目录创建普通会话 |
| 首次发送，选了项目 A | A | 在 A 的目录创建会话 |
| 空闲时移入或换到 B | 立即归入 B | 下一次发送在 B 运行，保留同一会话 ID 和历史 |
| 运行时换到 B | 立即归入 B | 当前轮在原目录完成，下一轮在 B 运行，不中断回复 |
| 移出当前项目 | 立即变为无项目 | 保留实际工作目录；运行中也可操作 |

已有会话通过 Project 菜单调整归属。首次发送时确定的是初始工作目录，不代表此后永远不能换目录。移动不复制历史、不创建第二个会话，也不搬动磁盘上的项目文件。

### 需要持久化的信息

现有 `project_id` 是 Git 项目标识，非 Git 目录共用 `global`，不能拿来表示侧栏归属。最小改动是：

- 为会话保存独立、可为空的项目归属，值直接是项目目录（scope 路径），不做指向 `workspace_registry` 的外键。注册表只管名称、隐藏、排序等显示信息；TUI 在新目录建会话时注册表里可能还没有这条记录，存路径就不会对不上。
- 新建时的归属规则写在共用的 `createSessionRecord`（`services/session/manager.ts`）：执行目录是默认工作区则为空，否则等于该目录的 scope。子代理会话继承父会话。TUI 不用改代码也能写对。
- 保留实际工作目录；现有 `project_root` 可继续承担这个职责，不为改名重建整张表。
- 增加一个可为空的“待生效目录”。换项目时只写它，不直接改执行目录；空闲和运行中走同一条路径，归属接口不需要判断会话是否在运行。Web 显示“下一轮在 B”和重启后恢复都依赖这个字段。移出项目时清空归属，并取消尚未生效的目录变更，保留当前实际工作目录。

当前轮使用启动时确定的目录，下一轮进入目标实例。每一轮开始前，实例先读取会话的目标目录（待生效目录，没有则为执行目录），用于路由校验：

- 目标目录等于本实例目录：先通过现有 run ledger 的领取检查，确认该会话可以开始新一轮；成功后才应用待生效目录、清空该字段，并重新读取会话用于执行和更新目标实例的会话视图。会话忙时等待重试，不提前改执行目录。
- 目标目录不等于本实例目录：不执行，返回 §2.5 约定的错误和目标目录。

下一轮加载目标目录的配置和工具，并让模型知道工作目录已变更，历史消息保持原样。原目录这一轮里创建的子代理会话保留创建时的目录，不跟着父会话迁移。

排队消息同时属于目录和具体实例：调度器的 `listQueued`、`claim` 都校验 `scope_key`、`owner_id`、`owner_pid`（`runtime/prompt-scheduler/database-store.ts`）。换项目时，先取得目标实例，再通过现有队列存储在同一事务里更新会话归属、待生效目录，以及该会话 `queued` 记录的目录和领取归属，保留原提示词 ID、内容和队列次序。只改 `scope_key` 会让目标实例领不到消息。`starting`、`running` 的记录不动，仍在原目录跑完。移出时如取消了待生效目录，尚未开始的队列也交回保留的实际目录。目标（goal）续跑不跨实例交接：原目录发现会话已移走时结束本轮驱动，目标保留；目标实例按现有恢复规则读回为暂停，用户在目标目录继续。

排队消息转到 B 后，B 可能在 A 这一轮结束前尝试领取。现有 `claimPendingRun` 在事务里检查同一会话是否正在运行，有就抛 `SessionRunBusyError`；调度器将消息放回队列后延迟重试。因此复用现有检查即可，不新增跨实例锁，但必须在检查通过后才应用目录变更。队列交接提交后，再唤醒一次目标调度器；不能只依赖实例加载时的那次扫描，目标实例可能早已加载。

空归属是有效状态。不能再用 `project_root == 默认目录` 判断无项目，也不能在每次启动时把空归属重新补成原项目。

### 默认工作区

服务端统一解析 `<OHBABY_HOME>/workspace/default`；默认 home 为 `~/.ohbaby`。`GET /v1/scopes` 返回 `defaultWorkspace.directory`，需要时幂等创建目录，新建权限为 `0o700`，已有内容和权限不改。创建目录不等于立即启动一个实例。

默认目录自身就是 scope，不向上合并到父级 Git 仓库。环境检测也应以此为边界，避免因 `$HOME` 是仓库而误报；如果默认目录自身确实是仓库，仍如实识别。

默认目录不进入普通项目列表，也不作为普通项目登记。过滤要覆盖已加载实例、历史会话目录、注册表三个来源，以及启动和打开项目时的登记入口。

## 2.3 全局列表与搜索

### 列表与查询范围

全局列表和搜索读取共享数据库中的未归档根会话，覆盖所有项目与无项目会话，不包含子代理会话。普通列表按会话更新时间倒序，提供分页；页面大小只限制单页返回数量，不限制可查询的历史范围。

侧栏项目名称默认取根目录名，目录作为身份。沿用现有项目显示、隐藏、排序规则，并保留会话置顶等能力。展开或继续加载可以找回较早的会话；搜索独立覆盖全部符合条件的历史，不受当前已展开分组和已加载页数限制。

隐藏的项目沿用现有规则：侧栏不显示该项目及其会话，搜索仍能找到。会话的执行目录被删除或不可读时，沿用现有目录校验报错，用户可通过 Project 菜单换到其它项目后继续；不另做只读模式或自动迁移。

### 搜索规则

1. 去掉首尾空白，按一个或多个空白拆关键词；空查询显示普通列表。
2. 标题与正文使用同一规则：每个关键词按连续字面子串匹配，英文不区分大小写，关键词顺序不限。
3. 一次命中必须满足：所有关键词都在同一个标题，或都在同一条用户/助手可见消息内。不同消息之间、标题与正文之间不能拼接命中。
4. 只搜索可见正文。工具调用、工具结果、思考过程、系统提示词和内部记录不参与。
5. 一个会话只返回一次。标题命中排在前面，只有正文命中的排后面；每组按会话 `updatedAt` 倒序。更新时间相同用会话 ID 作稳定次序，不引入相关性评分。

| 查询 | 内容 | 是否命中 |
|---|---|---|
| `登录 报错` | 同一消息：“报错发生在登录时” | 是，顺序不限 |
| `登录 报错` | 一条消息只有“登录”，另一条只有“报错” | 否 |
| `登录 报错` | 标题只有“登录”，正文只有“报错” | 否 |
| `API timeout` | 同一消息：“api request TIMEOUT” | 是 |
| `登录报错` | 同一消息：“登录后出现报错” | 否，单个关键词必须连续 |
| `a.b`、`%`、`_` | 正文包含对应字面字符 | 按原字符匹配，不作为正则或通配符 |

搜索结果显示标题、项目归属和命中片段；正文命中可返回对应消息 ID。打开结果按会话执行目录恢复对话，不能拿侧栏项目目录替代它。

第一版复用 SQLite 和现有消息存储，先实现准确、可分页的查询，不引入搜索服务或模糊评分，也不新增可搜索文本列。可见正文直接取 `part` 表里 `type = 'text'` 且非 `synthetic` 的记录，用 `json_extract(data, '$.text')` 读出文字，再关联 `message` 限定用户与助手角色；“同一条消息”指同一个 `message_id` 下的这些文本块。数据量变大、出现慢查询时再考虑派生列或索引。不得先取最近 100/500 条再搜索，也不以固定文本长度截掉可搜索的历史。若采用 SQL `LIKE`，需转义其通配字符；查询参数绑定，匹配规则不随查询实现改变。

## 2.4 设置后端

实例内新增只读 `GET /v1/settings`，聚合现有配置与运行时状态，不新建设置存储。六个后端分区各返回 `{ data }` 或安全的 `{ error }`，一块读取失败不影响其它块。

| 分区 | 第一版内容 | 数据来源与约束 |
|---|---|---|
| `models` | 当前一套模型连接，未配置则为空；附凭据是否配置 | 复用 `UiCurrentModelConfig`；不把 `listModels` 或模型能力元数据包装成多 provider 配置库 |
| `mcp` | 服务器状态、失败原因、已加载工具数与列表 | 状态取 `getStatus()`；工具取过滤后的 `getAllTools()`，按 `mcpServer` 归属计数 |
| `skills` | 当前目录生效的名称、描述、可调用性等信息 | 复用 registry；来源和作用域只展示可确认的元数据 |
| `agents` | 当前目录生效的 `name`、`mode`、`description` | 现有 registry 未保留内置/来源信息，不能按名称猜；无可靠数据时省略标签 |
| `search` | 服务与配置状态、凭据变量名 | `tools/search.json` 通过变量名引用全局 env 中的 key，不返回 key |
| `about` | 版本、ohbaby home、日志和诊断路径、当前与默认工作目录 | 复用已有路径与版本函数 |

MCP 工具列表只需返回 `name`、`description`、`mcpServer`、`mcpToolName`。`getStatus()` 的原始工具数与过滤后数量可能不同，设置页的“已加载”数量以实际列表为准。命令摘要同时补齐已有的工具数、失败原因，保持旧字段兼容。

模型页保存复用 `connectModel()` 等现有入口，搜索 key 保存复用 `/v1/settings/search-api-key`。第一版只编辑当前连接；多套 LLM provider 配置的保存与切换后续再做。模型与搜索配置属于全局，界面要明确保存会影响后续使用这些配置的会话；已开始的模型请求沿用本轮配置。

MCP、Skills、Agents 按实际执行目录展示。运行中换项目时，当前设置仍对应原目录，并提示下一轮使用目标目录；移出项目后继续展示原目录设置。草稿按所选项目或默认目录查看设置，无须先创建会话。没选项目时打开设置，会按需加载默认目录的实例并启动其 MCP，这是可以接受的代价，不为此把部分分区拆到全局层。

只输出允许的字段和“已配置”状态，不透传配置对象、环境变量值或带凭据的原始诊断错误。项目来源能确认才显示标签。

## 2.5 接口与兼容

以下路径是实施契约；内部存储字段可按代码风格命名，但响应必须区分项目归属与执行目录。

| 接口 | 所在层 | 请求与响应要点 |
|---|---|---|
| `GET /v1/scopes` | 全局 | 响应增加 `defaultWorkspace: { directory }`；普通 `scopes` 排除默认目录 |
| `GET /v1/sessions` | 全局 | 活跃根会话分页；`limit` 默认 100、上限 500，支持 `cursor`；返回 `sessions`、`nextCursor` |
| `GET /v1/sessions/search` | 全局 | `q`、`limit`、`cursor`；覆盖全部活跃根会话，分页规则与列表一致，按 §2.3 匹配和排序 |
| `POST /v1/sessions/:sessionId/project` | 全局 | `{ projectDirectory: string \| null }`；字符串选择已有项目，显式 `null` 移出；返回更新后的会话目录信息 |
| `GET /v1/settings` | 实例 | 六个分区的只读快照，按目录头选择实例 |

列表项至少包含 ID、标题、状态、创建/更新时间、消息数、可为空的项目归属、实际工作目录；存在下一轮目录变更时也返回该信息。搜索结果在此基础上增加 `matchType`（标题或正文）、命中片段及可选消息 ID。若保留 `kind` 字段，应由项目归属判断，不能由工作目录推断。

归属接口校验目标项目并复用已有路径校验，按 §2.2 更新归属、待生效目录及排队消息的目录与领取归属，再通知目标调度器。回复运行中允许调用；当前轮不会因归属更新重新加载目录或中断。下一轮发起前，客户端与服务端应使用已经确定的目标目录。

执行目录以数据库为准，实例内存不作为依据。每一轮开始前（用户发送、重发、排队消息出队、自动续跑），实例都按 §2.2 从数据库算出该会话的目标目录（待生效目录优先，没有则为执行目录），与自己的目录比较：

- 相同：通过现有运行领取检查后，再应用待生效目录并重新读取会话用于执行；忙重试不应用变更。
- 不同：不执行，返回明确的错误码（名称实施时定，例如 `session-moved`）和目标目录。Web 收到后换成目标目录的请求头重发，并切换事件订阅。

这样多个标签页、旧客户端或晚到的请求都不会在旧目录里继续跑。Web 发送时优先使用待生效目录，减少一次被拒绝再重发。

权限不随会话迁移。现有的权限级别与模式按实例保存，会话级放行规则和沙箱批准的外部路径也只在原实例内存里（`permission/state.ts`、`sandbox/trusted-roots.ts`）。下一轮进入目标实例后，使用目标目录自己的权限状态，需要授权的操作重新询问。实施时不写任何权限搬迁逻辑；Web 在切换生效后显示目标目录当前的权限级别。

### 存储与旧数据

新增归属需要持久化，并执行一次明确的旧数据兼容处理：旧会话默认按原工作目录补齐归属，默认工作区会话归为无项目。保留原 ID、目录、消息和运行历史。回填放在 `services/database/migrations.ts` 的一条新版本迁移里，只执行一次；之后归属为空就是无项目，不需要额外标记来区分“尚未迁移”和“主动移出”。

按现有存储选择小范围新增字段或扩展数据映射，不借此重做数据库。不能再承诺“完全无迁移、随时无损回退”；回退前须核对旧代码是否能读取新增数据，尤其是无项目但保留原目录的会话。

旧 Web 可继续使用原有打开目录与对话能力，但不能完整表达新的归属语义。TUI 不改交互，共用代码需要回归。旧浏览器导航状态用于恢复原会话；点“新会话”仍默认不选项目，不沿用旧 `selectedDirectory` 作为草稿预选。

## 2.6 按功能分批与改动面

按用户要求分成两批，每批包含必要的后端、SDK 和 Web 接入，完成后可以独立走查。不再把全部 Web 页面留到第三个阶段，也不因此新建 improve-2。

| 批次 | 内容 | 完成标准 |
|---|---|---|
| 第一批：工作区绑定优化 | 默认目录、归属与执行目录分离、旧数据兼容、项目移入/换项目/移出、全局列表与搜索；同步完成草稿首发、侧栏、输入框和 Project 菜单 | [04](04-test-and-acceptance.md) 的 T1–T12、T18–T22、T24；完整走通创建、移动、继续聊天与搜索 |
| 第二批：设置 | 六分区快照、MCP 状态与工具列表、当前连接和搜索 key 保存、凭据过滤；同步完成七页设置及入口 | T13–T17、T23；页面可用，数据随实际目录展示 |

**已确认顺序：先工作区，后设置。** 设置后端的大部分数据可以直接从现有实例读取，但完整设置体验还需要无项目草稿的默认目录，以及换项目后应该读取哪个目录的规则。先完成工作区批次，设置批次就能一次完成这些验收，无须先写一套临时行为再调整。

每批内部先完成所需后端与 SDK，再接 Web 并验收。相应页面开工前补充详细前端设计，已确认的产品规则保持不变。本轮仅审核文档，顺序确认不等于开始实施。

| 模块 | 必要改动 |
|---|---|
| `ohbaby-agent` | 默认目录解析、会话归属持久化与查询、实例间续聊衔接、消息可见正文提取、设置聚合、MCP 摘要 |
| `ohbaby-server` | 默认 scope 边界、项目列表过滤、全局会话接口、实例设置接口 |
| `ohbaby-sdk` | 全局列表/搜索/归属操作、设置快照的类型与客户端方法 |
| `ohbaby-web` | 从当前目录中心改为会话中心，增加本地草稿、项目菜单、搜索与设置，替换旧图标项目栏 |
| `ohbaby-cli` | 保留 TUI 使用方式，验证共用代码兼容 |

## 2.7 Web 大致布局

| 区域 | 方向 |
|---|---|
| 侧边栏顶部 | 新会话、全局搜索 |
| 侧边栏主体 | 按项目分组，加“无项目对话”组；可折叠、继续加载，保留置顶和排序 |
| 会话菜单 | Project 子菜单列出现有项目，并提供“从当前项目移出”；运行中可操作 |
| 草稿输入框 | 可选项目选择器，默认不选；选项目不清空文字；第一次发送才进入正式会话 |
| 已有会话输入区 | 显示实际工作目录；换项目待下一轮生效时给出简短提示，避免归属与实际目录不一致造成误解 |
| 设置入口 | 固定入口；通用、模型、MCP、Skills、Agents、联网搜索、关于，共七页 |
| 空状态 | 直接给输入框，不再要求先打开项目 |

切换会话按执行目录连接实例，侧栏归属只负责组织会话。创建、重命名、归档、变更归属后刷新列表；窗口重新激活或重连时同步服务端数据。不要仅把当前浏览器已加载的会话当作搜索数据源。搜索输入做防抖，避免每敲一个字都查一次全量历史。

## 2.8 范围与取舍

- 共享默认目录会让多个无项目会话的产物放在同一目录，这是第一版接受的取舍；本轮不做每会话独立目录。
- 设置继续使用现有文件与写入入口，不做多 provider 配置库、项目配置编辑或 MCP 管理操作。
- 搜索不做模糊匹配、正则语法、语义检索或复杂评分；实现和测试围绕已经确认的字面规则。
- 不增加独立的后台任务迁移、调度或恢复系统。按当前轮结束、下一轮使用目标目录实现，不继续扩大少见场景的设计。
- 不新增 Web 快照恢复功能，不改 TUI 交互，不借本轮重构整个存储与运行时。
- 详细视觉、组件、动效与窄屏设计另文确定；本轮不写关键改动清单或模块级 improve 文档。
