# 4. 测试与验收标准

> 对照 [02](02-optimization-plan-and-change-scope.md) 验证已确认的行为。本文是后续实施的验收标准，本次文档更新没有实现或运行这些功能测试。

## 4.1 测试范围与运行方式

沿用项目现有的 unit、contract、integration、smoke 分类，文件命名为 `*.类型.test.ts` 或 `.tsx`。Web 组件测试沿用现有分类，不另建一套命名。参考 [Web 测试约定](../../../ohbaby-web/test.md)。

| 类型 | 重点 |
|---|---|
| unit | 默认目录解析、搜索匹配与排序、可见正文提取、设置字段过滤、Web 草稿状态 |
| contract | SDK 与服务端的目录字段、项目归属、搜索结果、设置快照一致 |
| integration | 真实数据库与 daemon 下的创建、移动、移出、历史搜索和设置读取 |
| smoke / 手工 | 浏览器里走完整流程，检查侧栏、输入框、菜单与设置 |

定向测试使用 `pnpm exec vitest run <具体测试文件>`。涉及重建共享 dist 的集成用例加 `--no-file-parallelism`。`pnpm test:unit`、`pnpm test:contract`、`pnpm test:integration` 等分类脚本运行整类测试，不能把追加路径当成定向过滤。

优先验证下面的主要行为，不为罕见后台任务情况增加独立测试矩阵。

## 4.2 关键场景

### 工作区：后端场景

| ID | 场景 | 类型 | 验证点 |
|---|---|---|---|
| T1 | 默认目录与 scope | unit + integration | 跟随 `OHBABY_HOME`；首次获取 scopes 幂等创建目录，新建权限 `0o700`；已有目录不改内容和权限；父级有 Git 仓库时仍以默认目录为 scope |
| T2 | 默认目录不作为项目 | integration | 启动、打开、历史会话和注册表聚合后，普通项目列表均不含默认目录；`defaultWorkspace.directory` 正确返回 |
| T3 | 在默认目录正常对话 | integration | 带该目录头创建、发送、读取历史成功；工具和权限沿用普通会话规则；实例接口缺头仍为 400；全局接口沿用 token 鉴权 |
| T4 | 旧数据兼容 | integration | 旧会话按原目录补齐归属；默认目录会话为无项目；原 ID、目录和历史不变；用户主动移出后重启，不会重新归入项目；迁移只执行一次；TUI 与 Web 新建会话的归属按规则写入（默认工作区为空，子代理继承父会话） |
| T5 | 空闲时移入或换项目 | integration | 无项目→A、A→B 都保持同一会话 ID 和历史；下一轮在目标目录运行，使用目标配置，模型能获得目录变更信息；源、目标实例和全局列表一致 |
| T6 | 运行时换项目 | integration | 当前轮在 A 时移到 B，侧栏归属立即变更，不中断回复；当前轮工具仍使用 A，下一轮使用 B；保存后的目标在重启恢复后仍正确；换项目前已排队、尚未开始的消息在 B 执行，A 不再领取；队列的目录和领取归属一并交接，目标实例已加载时也能领取；A 未结束时 B 忙重试且不提前改执行目录，A 结束后 B 自动开始；空闲时换项目同样在下一轮生效；目标自动续跑的下一轮也在 B；移动后仍用 A 的目录头发送，A 返回明确错误和目标目录、不执行，客户端换到 B 重发后成功；在 A 里给过"本会话总是允许"的操作，到 B 后重新询问 |
| T7 | 移出项目 | integration | 空闲和运行时都能移出；归属为空，实际 cwd 与历史保留；若之前选的目标尚未生效，移出会取消该切换，未启动的队列也交回当前实际目录；继续发送使用保留的目录，不跳到默认目录或已取消的目标 |
| T8 | 全局列表与分页 | integration | 跨两个项目和无项目返回活跃根会话，排除归档与子代理；隐藏项目的会话不在列表里但能被搜到；按更新时间排序；分页能继续读到旧会话，单页上限不等于总历史上限 |
| T9 | 历史正文搜索 | integration | 超过 500 个活跃根会话时仍能搜到最早会话的标题和正文；不依赖已加载侧栏数据，也不按固定正文长度截断；归档与子代理不参与 |
| T10 | 同一字段内全部命中 | unit + integration | `登录 报错` 命中同一标题或消息中的正序、逆序文本；拆在两条消息、或拆在标题与正文时不命中；首尾/连续空白不影响结果；同一助手消息被工具调用分成多个文本块时，关键词分在不同文本块也算命中 |
| T11 | 字面匹配与正文边界 | unit | `API timeout` 忽略英文大小写；`登录报错` 不命中“登录后出现报错”；`.`、`%`、`_` 按字面匹配；工具、思考、`synthetic` 文本与内部文本不参与 |
| T12 | 排序、去重与片段 | unit + contract | 标题命中优先于更新更近的正文命中；每组按会话更新时间倒序；多条消息命中只返回一个会话；片段来自实际命中内容，分页字段与 SDK 一致 |

### 设置：后端与目录联动

| ID | 场景 | 类型 | 验证点 |
|---|---|---|---|
| T13 | 六分区快照 | integration + contract | 返回模型、MCP、Skills、Agents、搜索、关于；缺项目配置也能读取；某分区失败只返回该分区的安全错误，其余正常 |
| T14 | MCP 状态与工具列表 | unit + integration | 连接状态、失败原因可见；工具过滤后按服务器展示名称和描述，“已加载”数量与列表一致；命令摘要不再丢弃工具数和错误信息 |
| T15 | 凭据不回传 | unit + integration | 模型及搜索凭据只返回配置状态和变量名；构造含 key 的诊断错误，整个响应也不得出现 key 原文 |
| T16 | 设置对应真实目录 | integration | A/B 配置不同；运行中换到 B 时当前设置仍为 A，下一轮生效后为 B；移出后仍为原目录；缺少来源元数据时不编造标签 |
| T17 | 复用当前连接与搜索保存 | integration | 未配置模型返回空；保存当前连接与搜索 key 后按既有全局作用域生效；不产生第二套配置存储或伪多 provider 列表 |

### Web：随对应功能批次验收

| ID | 场景 | 类型 | 验证点 |
|---|---|---|---|
| T18 | 新会话草稿 | Web unit + integration | 无项目环境可直接输入；点“新会话”不调用创建接口、不增加空会话；默认无项目；选择、更换项目保留输入文字 |
| T19 | 首次发送创建 | Web integration | 未选项目使用默认目录；选项目使用所选目录；第一次发送时创建正式会话；旧 `selectedDirectory` 不预选到新草稿 |
| T20 | 侧栏与恢复 | Web integration | 项目/无项目分组、置顶及现有排序可用；旧会话可继续加载；打开会话使用实际目录，移出后也不会错误连接默认目录；旧导航可恢复原会话 |
| T21 | Project 菜单 | Web integration + 手工 | 可选择已有项目和“从当前项目移出”；运行中可操作并保留流式回复；归属变化、实际目录和下一轮提示与服务端一致 |
| T22 | 全局搜索 | Web integration + 手工 | 输入关键词能找到未加载的旧会话；标题优先、正文片段和去重正确；打开结果恢复对应会话；不在前端截成最近 100/500 条搜索 |
| T23 | 七页设置 | Web unit + 手工 | 通用、模型、MCP、Skills、Agents、联网搜索、关于均可打开；当前连接可编辑；MCP 工具列表可见；作用域清楚；错误可重试 |
| T24 | 列表状态同步 | Web integration | 创建、重命名、归档、变更归属后同步列表；重新激活或重连后读取最新状态；无项目但使用原目录的会话不被错误重新分组 |

## 4.3 集成边界

- 全局列表、搜索、归属接口与实例内设置/对话接口各自沿用现有鉴权。项目归属和执行目录在 SDK 中分开表达。
- 跨实例续聊须验证数据库、实例内存与 Web 使用的是同一会话；运行中的回复不能因侧栏分组变化而丢失。
- 搜索应从已有消息结构提取可见正文，不直接搜索整份序列化 JSON。标题和正文使用同一匹配规则。
- MCP 设置列表使用实际加载工具；命令层保留原有字段，TUI 消费方式不受影响。

## 4.4 回归范围

- 普通 Git 项目的创建、恢复、归档，以及项目打开、隐藏、排序保持可用。
- 现有 `/status`、`/mcps`、`/skills`、`/models` 命令和 TUI 启动、切换会话保持兼容。
- 默认目录可写文件，沙箱仍以实际工作目录为依据。环境检测不误把父级仓库算作默认目录自身的仓库。
- 非 Git 目录的快照能力沿用现有模块测试；如修改相关代码，在临时默认目录验证创建与 restore。本轮不要求新增 Web 回滚入口。
- 旧客户端的普通目录对话接口保持兼容；不要求旧 UI 能表达新的项目归属功能。

实施阶段先跑相关定向测试和类型检查；合入前按项目既有要求完成 `pnpm typecheck`、`pnpm lint`、`pnpm test:unit`、`pnpm test:contract`、`pnpm test:integration`。涉及启动链路时补充现有 smoke 检查，避免重复运行与本次改动无关的测试。

## 4.5 发布验收

| 批次 | 标准 |
|---|---|
| 第一批：工作区绑定优化 | T1–T12、T18–T22、T24 通过；完成对应浏览器走查；会话移动保留身份和历史，无项目与目录不混淆，搜索覆盖完整历史 |
| 第二批：设置 | T13–T17、T23 通过；完成设置页面走查；凭据过滤断言存在且通过 |
| 文档同步 | 实施后同步[多项目运行时](../../../ohbaby-server/hono-app/04-multi-project-runtime.md)、[Web 架构](../../../ohbaby-web/architecture.md)和旧侧栏议题说明 |

工作区批次走查：打开无项目的 Web → 输入草稿并切换项目，确认文字保留 → 不选项目发送 → 把会话移到项目 A，继续发送 → 回复中换到 B，确认本轮不中断、下一轮使用 B → 移出 B，确认继续使用 B 的目录 → 搜索旧会话。

设置批次走查：打开七页设置 → 查看和保存当前模型连接与搜索 key → 核对 MCP 状态、工具列表及 Skills、Agents → 在无项目草稿和已有会话中核对目录与全局配置标记 → 换项目后验证设置跟随实际目录。

验收按已确认的“工作区先、设置后”顺序进行。第二批在第一批完成后验证 T16 的目录联动，不拆分临时验收。

默认目录的父级 Git 边界用临时目录自动化验证即可，不修改用户真实家目录或仓库。

## 4.6 重点检查

| 容易出错的地方 | 检查方式 | 范围说明 |
|---|---|---|
| 把无项目等同于默认目录 | T4、T7、T20 检查移出后的归属、目录与恢复 | 不引入额外会话类型 |
| 移动只更新一处状态 | T5、T6、T21 检查同一会话在实例和 UI 中连续可用 | 按当前轮/下一轮处理，不扩大为后台任务迁移 |
| 搜索误做跨消息 AND 或只搜近期 | T9–T12 使用分散关键词与较早历史 | 保持字面规则，不引入评分系统 |
| 设置对象或错误带出凭据 | T15 在整个响应中检查测试 key | 新增展示字段仍需走同一过滤规则 |
