# 系统代理跟随与跨平台网络一致性

日期：2026-10-01；实施更新：2026-10-02（Asia/Taipei）。状态：本地 `codex/system-proxy` 分支已实施并完成本机验收，等待用户审查；尚未合并或推送。

目标：ohbaby 默认遵守运行服务的电脑及运行用户的代理设置，允许显式代理环境变量覆盖；系统配置变化后，新请求采用新策略，失败原因可解释。

用户已确认行为原则、文档位置、KISS 约束，并于 10 月 2 日明确授权创建本地分支实施及真实 API 测试。00–04 保留规划时的讨论与建议；实际实现、验证结果及未完成的 Windows/PAC/SOCKS/Linux 桌面边界以 [05 验收记录](./improve-1/05-implementation-acceptance.md) 为准，不宣称完整系统代理兼容。

## 范围

- 本议题：进程级代理初始化、macOS/Windows 适配、环境变量覆盖、动态切换、SDK 实际出口、状态与错误、跨平台验收。
- 建议不在本轮实现：按模型厂商维护分流名单、自己实现代理/VPN、通用网络框架、任意子进程网络接管、重试预算重构。具体边界见 02 §2.8。
- Linux/WSL/容器按其自身运行环境界定；不冒充能继承 Windows 宿主或远端浏览器的系统代理。
