# 00 · 讨论记录与已确认要点

来源：2026-10-01 当前用户对话。这里只记录已确认内容；新增技术建议和未决取舍在 02。

## 背景

用户反馈 ohbaby 发消息出现 Request timed out，提出默认跟随本机代理，并要求对照 Pi、ZCode、OpenCode、Kimi Code、DeepSeek Harness 源码判断是否过度设计。随后明确要求兼容其他人的电脑和自己的 Windows，并使用 plan-code-improvement 撰写文档。

## 已确认行为

| ID | 用户确认的约束 |
| --- | --- |
| U1 | 默认根据操作系统实际配置选择代理或直连，不以 Clash/Shadowrocket 是否运行来猜测，不写死端口。 |
| U2 | 显式代理环境变量作为覆盖项，方便服务器和 CI；状态须明确显示“使用环境变量代理”。 |
| U3 | 系统配置变化后，新请求采用新策略；已开始的流式响应尽量自然结束；不能每发一个请求就执行系统命令。 |
| U4 | 代理连接失败报告真实原因，不静默改走直连。 |
| U5 | 模型端点不同，但配置跟随本机代理状态即可。用户当前 Zenmux 场景需要代理，智谱官网场景不需要。该观察不是所有用户、所有地区的永久连通性规则。 |
| U6 | 产品面向其他用户和 Windows，不能只为当前 Mac 做实现。 |
| U7 | 本轮详细分析、通俗讨论、提出建议并撰写规划文档。 |
| U8 | 文档采用本目录，并列关键待改文件。 |
| U9 | ohbaby 网络请求与本机配置一致；不针对 Shadowrocket、Clash Verge 等具体软件适配；保持 KISS，借鉴 Pi/OpenCode/Kimi Code。 |
| U10 | 请 Pi 使用 Copilot/Sonnet 5.5 调研方案和拟改代码，之后由子代理复核；允许读取 .env 密钥并使用 tests/models-4-tests.md 的模型做请求测试。 |
