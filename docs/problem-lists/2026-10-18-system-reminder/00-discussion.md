# 讨论与当前决议

> 2026-10-19 修订。本文与 02、04 是当前契约；历史方案及审核过程见 05。

## 1. 定位与边界

用户确认：“提醒器只是服务层（有则提醒）提醒的作用，不是 log 日志级别的提醒。”服务决定内容，公共入口负责作用域、固定顺序和消息生成。没有业务内容就不发，不把可选文件缺失或服务读取失败变成警告消息。

主、子代理共用机制，各读自己的 contextScopeId；Todo 同时按有效 workScopeId 隔离。子代理不接收主会话 mode、父 Goal、父 Todo 或父技能记录。

项目文件与可选全局文件统一作为说明加载：项目具体约定优先，全局作为默认。它们不叫长期记忆，不属于提醒；详见 [子代理议题](../2026-10-18-subagent-system-prompt/00-discussion.md)。

## 2. 六类提醒与 Goal 的关系

| 服务 | 子类 | 受众与触发 |
| --- | --- | --- |
| environment | 状态快照 | 主、子；环境变化或有效历史缺失时补发。包含本地日期 YYYY-MM-DD，不含时分秒或时区字段；子代理用 minimal |
| mode | 状态快照 | 主；每次准备请求核对，缺失或变化时补当前 plan／auto |
| mcp-catalog | 状态快照 | 主、子；本作用域菜单变化或缺失时补发 |
| todo | 可周期重复的状态快照 | 主、子；有未完成项，成功写入与最近有效提醒之后，均已有 10 条有效 assistant 消息；压缩后列表丢失则立即补发 |
| skill-usage | 压缩事件提示 | 主、子；已提交压缩后，曾用技能正文缺失时只提示名称与允许的重读入口 |
| step-limit | 仅本请求 | 主、子；最后一步收尾，不落普通历史 |

Goal 续跑在概念上属于事件通知，但仍走 goals 原有正文、displayText、准入与去重，不变成第七个 provider。user-steer、摘要、子代理结果也继续各走原来的消息类型。

“有效历史”指按现有输入、失败和压缩规则过滤后实际会进入请求的内容。快照去重看有效历史，事件去重看完整历史中已生效的事件；压缩正文不等于事件没发生。

## 3. 必要行为与按需内容

mode 与 step-limit 使用本步已知状态，保留简短、明确的文字，不能被辅助提醒的失败或裁剪带走。仍放不下时走现有压缩／容量错误处理。实际权限和步数由运行时代码控制。

固定系统提示词同时定义 plan 和 auto，当前模式由尾部提醒表达；plan → auto 明确旧 plan 约束结束。plan 可以写文档，不新增写入拦截。已经发送或正在 HTTP 重试的请求不因中途切换被重写。

技能目录只含名称和 description，正文继续由 `skill(name)`／`skill_resource(name,path)` 或用户显式技能命令按需加载。不增加 find-skills、技能热加载或正文自动恢复。skill-usage 表示“曾使用”，不表示当前任务必须继续使用；仅用户可调用的技能不能因此变成模型可调用。

Todo 为空、全部完成或从未建立时不催办。10/10 直接数过滤后模型能看到的普通 assistant 消息，每个原始消息 ID 计一次；摘要不计，不另建逻辑 step 记录。失败占位被过滤则不计，保留可见失败文本则计一次。

## 4. 简化后的消息规则

持久提醒保存为 synthetic user 消息，通过 `anchorAssistantId` 放在对应 assistant 之前。本次请求顺序是历史、protected inputs、提醒、request-only step-limit；恢复后顺序相同。历史提醒与它锚定的 assistant 归入同一压缩组，一起保留或退场；提醒自身未被压缩，且 anchor 是本次当前 anchor 或对应 assistant 在有效历史中时才可见。

只增加提醒的位置锚点，复用现有消息存储、prepared request 和输入准入。不要另造提醒冻结材料、inputIds 副本、工具结果发送证明或提醒准入状态机。

Anthropic 在整批 tool_result 后追加并列 text block；真实用户文本与提醒保持各自内容块，不写进 tool_result 正文。Responses 和兼容 Chat 也使用 user 文本。标签用于展示，可信来源看 metadata，用户粘贴标签不产生宿主权限。

## 5. 失败、内容大小与缓存

各服务在生成时采用固定的小内容格式；可选服务取数失败就省略本次，不推进已提醒状态。不设每个提供者 50 ms 超时，不做通用预算降级或多轮裁剪。具体规则见 [02](./02-optimization-plan-and-change-scope.md)。

提醒计入现有预算；摘要沿用同一 prepared 材料，压缩成功后重新检查缺失状态。已存入并用于请求的正文不再缩短，不回写旧工具结果，不靠剪整份 payload 腾空间。沿用 [既有缓存与压缩契约](../2026-10-10-compact-cache-and-tool-output/06-overall-acceptance.md)，不承诺固定缓存命中率。

先验收子代理提示词，再做提醒消息与投影、mode／step-limit、环境／MCP、Todo 和 skill-usage。当前不做通用 hooks、日志告警、长期记忆、权限或压缩算法重写。
