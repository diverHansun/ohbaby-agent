## 已确认的边界

使用现有消息存储、prepared request、输入准入及压缩事务。只增加提醒所需的来源 metadata 和 assistant 锚点，不增加请求冻结表、通用 hooks、提醒准入状态机或预算降级框架。

提醒不授予权限、不代表用户授权、不属于日志告警。主、子作用域隔离。模型输出、工具结果和已发送的提醒正文不因后续提醒而回写。

## 开始时的检查

文档规则完整，未发现需要重新决策的产品分歧。初始骨架尚未由 lifecycle／composition 启用。只读审查发现两个需在第一批修正的问题：摘要准备比较使用原时间顺序，而上下文已按 anchor 排序；anchor owner 的可见性判断没有使用当前模型来源。相应测试与处理将在批次完成时记录。

## 实施中确认

MCP 原菜单只有单工具准入限制，没有菜单总条数上限。用户已确认本批新增 20 个完整名称的展示上限，附省略数量并保留现有搜索入口；不改加载上限。00、02、04 已同步，属于服务生成格式，不增加通用预算系统。

## 第一批：存储、重放与协议转换

完成提醒的 synthetic user 持久化、assistant 预分配锚点、按 owner 排序与压缩分组。候选、测量、摘要前缀和最终请求共用既有消息结构；只保存最终选定的提醒。孤立记录不参与重放或去重。HTTP 重试沿用 prepared request，新准备分配新 anchor。

修复了摘要前后排序不一致，以及原生状态在切换模型后不可见时仍保留提醒的问题。已生效事件与当前快照分别去重：事件在正文退场后仍保留事实，快照缺失则可补发。取消发生在压缩提交之后时，保留已提交结果，不再保存本次提醒。

Anthropic 在既有 messageBoundary 各段内部合并相邻 user 回合，完整 tool_result 在前、提醒 text block 在后。Responses 和 Chat 保留 user 文本块；三协议均剥离内部来源字段。未改写旧工具结果。

验证包括 SQLite 关闭／重开后的请求前缀一致性、保存失败不发送、重试复用、stale／overflow 新 anchor、摘要前缀和 cache_control 落点、退场事件去重。12 个定向测试文件共 570 项通过；agent 包类型检查与改动文件 ESLint 通过。独立子代理审查未发现阻塞问题。生产服务提供者尚未接入，C9／C10 与业务验收留后续批次；全仓和真实接口验收尚未执行。

## 第二批：mode 与 step-limit

主代理系统提示词固定定义 plan／auto，不再随当前权限模式切换。mode 提供者只读取现有内存状态，向主代理生成简短快照；相同状态去重，plan → auto 明示旧约束结束。plan 可以写规划文档，权限实现保持原样。主、子系统提示词均说明提醒不构成用户授权，不扩大任务或权限。

step-limit 改为最后一步请求尾部的 user 提示，不写入历史。现有步数上限和本步工具禁用继续由 lifecycle 执行。生成的 prompt 资产已同步。

12 个定向文件共 284 项测试通过，覆盖模式切换前后 system 稳定、子代理不读取主模式、缺失快照补发、最后一步请求角色及工具限制。类型检查、prompt:check、格式检查通过；改动 ESLint 无错误，保留 composition 的 7 条既有警告。独立子代理审查通过。环境／MCP 的旧入口将在下一批一起迁移。

## 第三批：environment／MCP 统一入口

环境检测对象保存在已有 run snapshot 中，日期由每次 prepare 开始时的本地日期决定；同次准备在压缩前后使用同一日期。主代理保留完整字段，子代理省略 OS version。环境使用执行目录，项目说明仍使用 projectRoot。检测失败静默省略，不把读取权限错误当成“非 Git 仓库”。

MCP 继续读取现有作用域菜单与加载状态，最多列 20 个完整名称，保留省略数量和搜索入口；加载上限不变。完整菜单参与状态 key，未展示名称变化也能被观察。

新 run 统一停止旧 runtime part 挂载，删除无生产调用的字符串拼接入口；没有自定义 provider 的双路径。已有 runtime part 不回写，仍按原样参与模型历史。恢复 run 没有发起用户消息时，也能从新入口补快照。界面按可信 metadata 隐藏内部提醒，用户自己输入的标签文本仍正常显示。

17 个定向文件共 336 项测试通过，类型、格式检查通过；ESLint 无错误，7 条既有 composition 警告保持不变。删除的旧测试主要验证已取消的首次插入与插入竞争；系统快照、父子隔离、SQLite 恢复、项目说明和 51 次工具调用／反复压缩的约定保留或迁移到了新入口。独立审查核对了迁移映射，未发现阻塞问题。

## 第四批：Todo

复用成功 todo_write 的历史恢复逻辑，同时取得列表与原始 assistant ID，不新增计数账本。按模型有效历史中的普通 assistant 消息计数，写入之后与最近有效提醒之后均满 10 条才周期提醒；提醒所锚定的回复计入，写入所在回复不计入。压缩已提交且当前列表正文缺失时立即补发。

主代理使用实际 run 的 Todo workScope，子代理只读取自己的 contextScope。列表沿用现有最多 10 项、每项 100 个 Unicode 字符的限制，提醒仅展示未完成项，进行中的事项在前，不新增摘要或裁剪算法。有效历史中的工具正文和提醒正文共同决定列表是否仍可见，单有 metadata 不算可见。

本批同时修复快照去重读取 ignored／空正文提醒 key 的问题，避免无效提醒阻止补发。8 个定向文件共 128 项通过，覆盖两侧 9／10 边界、同列表多周期、等价成功写入、失败／并行工具、普通与 Goal 切换、压缩提交后的补发。类型、格式检查通过，ESLint 无错误；独立审查通过。摘要自然语言不作为最新列表的可信来源，不增加语义解析。

## 第五批：skill-usage 与 slash 正文来源

新增事件型提供者，使用最新有效摘要的 compactionId 去重。从本作用域历史读取成功 skill 工具调用的实际名称，以及 slash 正文上的 skillUsage metadata；对照本次有效正文和 protected inputs 判断是否缺失。最多列最近使用的 20 个完整名称及允许的重读入口，不加载 SKILL.md 或参考资料。正文缺失与提醒已生效分别判断，压缩退场不抹掉已生效事件。

重读入口取决于当前工具能力、userInvocable 和 disableModelInvocation。仅用户可调用的技能只提示主代理请用户从 /skills 选择；子代理不把主会话的 slash 入口当成自己的能力。

服务端成功展开技能后，在现有 naming_source JSON 中传递内部展开标记，最终把实际名称写到承载正文的 part metadata。正常启动、排队、steer、未改正文的重发与 SQLite 恢复都保留来源；编辑正文则沿用既有清源规则。公开 namingSource 继续用于命名，但会丢弃外部声称的内部标记。旧数据里只有命名字段的记录不追认为技能加载事实。没有增加表、队列字段或新的加载入口。

257 项定向单元／集成与 7 项真实接线合同测试通过，覆盖压缩事件、失败与隐藏正文、权限、父子同名隔离、来源传递和编辑／恢复。类型、格式检查通过，ESLint 无错误，15 条既有警告保持不变；独立审查通过。
