# 测试与验收

> 本文定义验收契约；实际执行结果见 [06](./06-implementation-acceptance.md) 和 [07](./07-live-acceptance.md)，区分确定性测试与真实模型抽测。缓存／恢复合并为 10 组，删除只为旧工具绑定和降级框架存在的用例。

## 1. 缓存、顺序与恢复

| 编号 | 场景 | 期望 |
| --- | --- | --- |
| C1 | 新增提醒、下一 run、重启重放 | 旧正文和工具结果不变；提醒文本与相对位置一致；不重新选择工具结果作为宿主 |
| C2 | protected inputs、排队 steer 与提醒同时出现 | 首次和恢复都为历史→本次 inputs→提醒→assistant；时间 retime 不改变既有请求成员关系 |
| C3 | HTTP 重试、stale-input 与溢出重准备 | HTTP 重试复用 prepared；新准备使用新 anchor；旧孤立候选不进入历史、不推进去重 |
| C4 | 准备失败、保存失败、发送后崩溃、失败 assistant 保留文本 | 保存失败不发送；无可回放 owner 的提醒不生效，有可见失败文本则按原规则投影；不声称远端 exactly-once |
| C5 | 切点靠近提醒／owner，手动压缩后重启 | 带 anchor 提醒与 owner 属于同一连续组，一起保留或退场；提醒仅在自身活动且为当前 anchor／owner 有效时可见；快照可补发，已生效事件不重发 |
| C6 | 普通请求与摘要分叉，包含多工具与提醒 | 同一 prepared 前缀、原生状态和工具定义；摘要尾部不跨 messageBoundary 合并；cache_control 落点正确 |
| C7 | 压缩失败、取消、提交冲突 | 原子提交和 pending 输入准入规则不变，不产生已提交压缩事件 |
| C8 | 三协议最终 wire；升级旧 tool_result＋steer 历史 | 角色／块顺序正确，metadata 不外泄，工具批次及正文不变；允许升级合并规则带来一次缓存变化，相同历史按新规则重复序列化必须一致 |
| C9 | 模式切换、最后一步、必要文字放不下 | system 稳定；新准备反映当前模式；step-limit 不进历史，必要文案不静默裁掉；容量处理沿用原流程 |
| C10 | 旧 runtime part、恢复 run 无发起消息 | 不回写旧消息；环境／MCP 缺失则从统一入口补发，不因首步旧挂载重复；之后能去重 |

## 2. 公共入口与业务行为

| 编号 | 场景 | 期望 |
| --- | --- | --- |
| E1 | 无内容、状态相同、可选取数失败 | 无多余提醒；失败不推进状态、不产生用户警告；不依赖 50 ms 定时测试 |
| E2 | 主、子／兄弟代理及 Goal Todo | sessionId、contextScopeId、workScopeId 隔离；子代理无 mode、父 Goal、父 Todo 或父技能记录 |
| E3 | 用户粘贴标签、外部正文含闭合标签 | 来源看 metadata，外部文本转义，不能冒充宿主或扩大权限 |
| E4 | 长 Todo、菜单和已用技能名单 | 生成时按服务格式限制；MCP 最多 20 个完整名称，省略数量和搜索入口保留，加载上限不变；名称／状态／协议结构完整，Todo 不新增 ID 字段，历史内容不二次裁剪 |
| P1 | Todo 两个基准之后分别有 9／10 条有效 assistant 消息 | 任一侧不足 10 则不周期提醒；两侧均满 10 才提醒；写入所在消息不计，提醒所锚定的回复计入后续间隔 |
| P2 | 并行工具、重试占位、可见失败文本、摘要与缺失基准 | 按模型有效历史中普通 assistant 的原始 ID 计一次；过滤掉的不计，可见失败文本计入，摘要／未响应 anchor 不计；基准缺失从有效历史起点数，不重建压缩前账本 |
| P3 | Todo 从未建立、为空、全完成，或压缩后未完成列表缺失 | 前三种不催办；最后一种不受 10/10 周期限制，补当前提示和 todo_read 入口 |
| P4 | 午夜跨天、子代理环境 | 日期在下一新准备中更新；不追加时分秒定时提醒；minimal 不含 OS 版本 |
| P5 | mode 切换、plan 写文档、最后一步工具调用 | plan→auto 明示旧约束结束；权限不变；步数／工具限制仍由代码执行 |
| P6 | MCP 菜单变化与 Goal 续跑 | MCP 从已有菜单源取数；Goal 正文、displayText、准入和去重保持原流程 |

## 3. 技能使用提示

| 编号 | 场景 | 期望 |
| --- | --- | --- |
| K1 | 正常技能目录与加载 | 仅名称／description，选中后按需读正文与资料；无 find-skills 或批量全文注入 |
| K2 | 模型 skill 调用和用户 slash 命令 | 都有可信使用记录；slash 来源落到实际正文 part，覆盖中途调用、排队、恢复，不依赖命名流程 |
| K3 | 压缩后正文缺失、仍可见、被其他历史过滤 | 根据最终可见 part 判断；缺失只提示名称／允许的重读入口，不自动恢复正文或参考资料 |
| K4 | 自动／手动压缩、提交后退出重启、多次压缩 | 使用已提交 compactionId；最新有效事件提醒一次，不追发旧边界 |
| K5 | 压缩失败、skill 调用失败、提醒未形成可回放历史 | 不虚构成功或推进事件；之后仍可在条件满足时提示 |
| K6 | 仅用户可调用的技能、父子同名技能 | 不扩大调用能力，不串作用域；历史使用不等于当前必须使用 |

## 4. 交付证据

扩充现有 serializer、prompt-cache wire、runtime input recovery 和 compaction 集成测试，不新建一套请求状态机测试。mode 文案与生成资产同步，`prompt:check` 通过。相关类型检查、Todo／skill 定向用例与 10-10 的旧输出稳定、摘要同源、原子提交用例保持通过。

三接口实际抽测覆盖工具调用、提醒、一次压缩和恢复；缓存 usage 只作观察，不承诺固定命中率。Anthropic 额外观察：工具结果后附并列提醒时，是否出现无正文的 end_turn、导致应继续的任务提前结束；记录模型版本、停止原因与可见输出。Claude 源码注释是模型特定的风险线索，不是本项目已复现结论；若抽测出现异常，保留请求样本再判断，不预先引入 tool_result 嵌入兼容分支。

报告区分旧会话升级时的一次输出形状变化、升级后相同历史的稳定重放，以及模型行为抽测。

本议题在子代理提示词独立验收后实施，不要求第一阶段提前通过新提醒用例。
