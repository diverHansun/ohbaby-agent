# LLM 请求整步重来

2026-11-18 开启。后端和前端实施完成，待审核，未提交。

长任务里的子代理经常中途失败。日志显示，失败都发生在第一次请求出错时，已有的 5 次重试一次也没用上。当前链路有两处已确认的缺口。模型开始输出后遇到断流，系统不会重试。流内错误可能没有 HTTP 状态码，Responses 转换 `response.failed` 时也会丢掉上游错误码。本议题在主会话、子代理和 Side Chat 共用的链路上补齐这两处，改一处，三边同时生效。

## 范围

- lifecycle 新增整步重来：模型开始输出后，因网络断开、缺终止事件、空闲超时或可重试的流内服务端错误而失败的步骤，丢掉半截输出，退避后重新请求这一步。
- 每步共用 5 次临时故障重试。上下文超长仍可触发一次强制压缩，且压缩前后的临时故障预算连续。
- 三种协议统一识别已知临时流内错误和缺终止事件。未知错误保留安全诊断信息。Anthropic 以 `message_stop` 确认流结束。
- 已保存的工具结果和待处理输入可供重试请求使用。子代理最终失败且实例仍开放时，给主代理附上继续执行的提示。
- 前端（Web 和 TUI）：重试等待时显示 `Retrying #n`，被取代的回答换成一行灰字 `Interrupted · retried`，不展示错误原因和次数上限。

摘要重试维持既有契约。
