# 测试与验收

> 后续实施验收契约，当前未执行这些实现测试。合并重复场景，保留能证明行为的断言。

## 1. 第一阶段

| 编号 | 场景 | 期望 |
| --- | --- | --- |
| S1 | 主、子代理分别只有 OHBABY、AGENTS 或 CLAUDE | 按候选顺序读取；子代理内容位于 addon 之后 |
| S2 | 同范围多个文件、配置子目录与旧路径并存 | 首个可用生效，不合并别名，不经旧 memory 再补一份；OHBABY_HOME 与显式路径选项不变 |
| S3 | 无文件、空文件、普通读取失败、扫描省略 | 跳过或回退；无空包装、新警告或启动阻断，扫描行为不被旁路 |
| S4 | 长文件 | 主、子均遵守每文件 50 × 1024 个 UTF-16 编码单元限制 |
| S5 | 只有全局、只有项目、两者都有 | 正确渲染范围；即使输入数组是 project→global，也固定输出 Global→Project，相同输入字节稳定；项目冲突约定优先，全局默认仍保留；正文伪造标题不能改变 scope |
| S6 | 子代理角色和组装顺序 | base→task→addon→说明；不含主代理身份、子代理目录或父 Goal；委派边界与禁止继续派生保留 |
| S7 | 子代理去子目录、worktree 或 sandbox 执行 | 说明使用会话的 projectRoot，环境与工具使用执行目录；不触发新的根解析 |
| S8 | 非 Git 会话、显式项目边界、恢复 run | 始终使用已保存的 session projectRoot；恢复不退回子代理工作目录 |
| S9 | 同一 run 修改说明文件，再开启新 run | 当前快照、重试和摘要 system 不变；新 run 读取新内容 |
| S10 | 正常 run、无快照 assemble、手动压缩、用量预览 | 相同说明入口，选中文件只出现一次，无独立 memory 读取／拼接 |
| S11 | 真实组合层生成三协议请求 | 唯一标记证明说明确实进入最终请求；原生状态与自动摘要同源契约不变 |
| S12 | 历史里有用户或工具的 `<memory>` 字面文本 | 不删除、不改写；只取消宿主自动追加 |
| S13 | 类型检查、loader 回调和测试夹具 | scope 贯通且 build 仍返回字符串；无失效 memory 字段、helper、mock 或新 resolver 接线 |
| S14 | 说明与用户要求或宿主权限冲突 | 固定包装明确权限、用户要求及委派边界，工具授权保持原状 |

修改 assembler.test.ts 两处旧“不带说明”断言，以及 provider.test.ts 的“不调用 loader”断言。更新 loader／renderer 的字符串夹具；保留 Goals 压缩测试的业务断言，仅移除 MemoryReader mock。生成资产与 `prompt:check`、相关类型检查和定向集成测试通过。

用临时项目与隔离全局目录捕获实际请求，再做小任务行为抽测。分别报告“内容已进入请求”和“模型遵守了约定”，不能互相替代。
