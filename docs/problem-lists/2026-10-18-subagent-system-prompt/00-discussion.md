# 讨论与当前决议

> 2026-10-19 修订。本文与 02、04 是当前契约；旧方案与审核过程只保留在 05。

## 1. 说明文件的定位

用户确认：项目内的 `OHBABY.md`、`AGENTS.md`、`CLAUDE.md` 是项目说明；全局文件保留为可选全局说明。两者都不叫长期记忆，也不属于 system-reminder。

- 宿主有可用文件就加载，没有就跳过，不要求模型主动重读，不新增缺失或普通读取失败警告。
- 项目具体约定优先，全局作为默认；不冲突的全局约定继续适用。它们不能覆盖用户当前明确要求、宿主权限规则或扩大委派范围。
- 每个范围沿用首个可用文件规则：OHBABY → AGENTS → CLAUDE，保留现有配置目录与旧路径回退，不合并别名文件、不新增 `agent.md` 别名。
- 长期记忆的提取、保存和检索留到后续。

用户反馈实际会话未注入；本地源码组装能生成文件内容，不足以证明那次实际请求已经收到。后续验收必须检查最终协议请求，不能只看 loader 返回值。

## 2. 子代理提示词

子代理组装顺序固定为 base、task、addon、custom instructions。保留角色定制、独立历史与 scope-local Todo，不加入主代理身份、子代理目录或父 Goal 规则。

修改 base 中“不要加载用户自定义指令”的旧文案，改为遵守宿主提供的可选说明；保留“不要创建更多子代理”。更新生成资产和固化旧行为的测试。

Explore 当前有 write、edit、bash，不额外裁剪其项目说明或改变工具权限。

## 3. 用已有信息，移除重复通道

直接把会话已有的 `projectRoot` 传到说明 provider。子会话由父会话项目根创建；即使子代理去子目录、worktree 或 sandbox 执行，说明仍来自该会话的项目根。工作目录继续用于工具执行和环境展示，不再从它重新推导说明来源。

主、子代理都只走 custom instructions。删除独立 `memory.load` 与 `<memory>` 拼接，以及随之失去用途的字段和接线；不新增跨加载器路径去重、来源排除或项目 resolver。

只保留落实项目／全局优先规则所需的 `{ scope, text }` 说明项，固定先渲染 Global、后渲染 Project，并显示对应标题；`SystemPromptProvider.build` 仍返回字符串。

## 4. 稳定性与阶段边界

同一 run 的系统提示词快照不变，文件修改在下一 run 生效。正常运行、无快照组装、手动压缩和用量预览遵循同一说明来源；自动摘要沿用 prepared 请求。沿用安全扫描和每文件 50 × 1024 个 UTF-16 编码单元的上限。

先完成本议题并独立验收，再接入提醒。主、子代理共用提醒机制，但不共享业务状态：子代理只收自己的 environment（minimal）、MCP 菜单、Todo、skill-usage、step-limit，不收 mode、父 Goal、父 Todo 或父技能记录。具体行为见 [提醒方案](../2026-10-18-system-reminder/02-optimization-plan-and-change-scope.md)。
