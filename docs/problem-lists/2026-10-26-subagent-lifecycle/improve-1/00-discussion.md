# 讨论记录与已确认选择

> 开始日期：2026-10-26；2026-10-28 收口并整理正式方案。本文件保留已确认决策与用户原话。
> 已确认行为以本文件为准；工程细化见 02，验收见 04。当前仅规划，不修改实现代码。

## 1. 背景与动机

用户遇到的主要问题是：子代理可能已经运行很久、接近完成，但停止主代理时也被一起取消。用户希望后台子代理继续完成工作，同时允许主代理接收下一项任务；后续轮次仍能接收旧子代理的结果并复用其上下文。

用户实际测试了 Claude Code 与 Codex，并提供了 [Codex 测试对话](https://chatgpt.com/s/cx_6adec23e78c0819199159f159984499b)。这些观察作为对应客户端的行为证据；本地开源核心代码不自动代表所有客户端的完整行为。

## 2. 已确认的运行规则

| 编号 | 决策 | 已确认内容 |
| --- | --- | --- |
| D01 | 保留前后台模式 | 保留会等待子代理结果、阻塞主代理当前调用的前台模式；默认使用后台模式。 |
| D02 | 派遣入口与模式 | 使用统一工具 `agent` 的 `spawn` action 派遣新子代理，提供选择前台或后台的参数，默认后台；在 system prompt 中说明默认行为。此前独立命名 `spawn_agent` 的选择由 D19 覆盖。 |
| D03 | 主输入框停止对象 | 主代理没有活动中的执行时，主输入框没有可停止的对象。判断依据是活动执行，而非是否恰好有 LLM 请求。 |
| D04 | 主代理可以结束当前轮 | 主代理没有独立工作可做、仅有后台子代理仍在运行时，允许结束当前轮和输出；这不表示用户交办的整个任务已经完成。 |
| D05 | 后台子代理跨轮运行 | 用户可以开始下一项任务，后续主代理轮次仍能接收先前子代理的结果，并复用已有子代理。 |
| D06 | 主代理 Stop 的影响范围 | 主代理有活动执行时，用户停止主代理，会同时停止本轮前台子执行；后台子执行继续运行。这次停止造成的前台中断通知不会重新唤醒主代理。 |
| D07 | 独立停止子代理 | 用户可以直接停止指定子代理；也可以向主代理发消息，由主代理调用 `agent(action="stop")` 停止子代理。此前独立命名 `interrupt_agent` 的选择由 D19 覆盖，停止与关闭的区别见 D22、D23。 |
| D08 | 后台结果按主代理忙闲交付 | 主代理空闲时，后台结果自动启动新轮次，即使主代理之前被用户手动打断；主代理忙碌时，结果进入当前执行的下一次模型请求，不强行中断当前执行。主代理正在处理新任务不妨碍接收先前任务的结果，交付内容应说明子代理及原派遣任务的来源。D06 所述前台中断通知不触发唤醒。 |
| D09 | 无工作后不反复自动启动 | 当子代理和主代理均已处理完工作后，不应无故自动重新开始执行。子代理自动监督保留，当前间隔提议见 D31。 |

结果交付沿用主会话的输入调度，不按“旧任务／新任务”再增加一套状态。单个主会话不同时启动两个主代理执行，是调度应保证的约束，不再作为额外的产品选项讨论。

| D27 | 安全清理后归还名额 | 执行结束或停止后，完成必要的资源清理再归还运行名额；不能在发出停止信号时就提前归还。创建失败、运行失败、正常完成、停止和关闭等路径都应可靠收尾，避免进程或其他执行资源残留、死锁、名额泄漏和重复归还；具体清理机制与验证要求留给正式方案和验收文档。 |
| D28 | 同一轮多个派遣 | 每次 `agent(action="spawn")` 创建一个子代理；主模型可在同一轮发出多个 `spawn` 调用，各自独立申请名额、独立返回，允许部分成功。单个派遣失败不触发对已成功派遣的整批回滚；本批次沿用单个派遣接口，不增加批量 action 或数组版派遣接口。 |
| D29 | `send` 默认不打断 | 对正在运行的子代理，`send` 默认不打断当前执行，消息在下一次模型请求组装输入时加入。需要立即停止时，明确调用 `stop`，之后有需要再用 `send` 恢复。将这套用法写入后续实现的提示词；当前只记录要求，不修改提示词或运行代码。 |
| D30 | `monitor` 按需读取执行记录 | `monitor` 对指定的一个或多个子代理读取已有执行记录，返回相关状态、操作、消息和工具记录等内容。由程序直接读取和整理，不额外调用模型，不等待任务结束，也不持续订阅。具体返回字段、内容预算和续读方式留待正式方案设计；已销毁实例的历史读取继续遵守 D24。 |

| D32 | 不扩展通用定时提醒 | 本批维持子代理自动监督，不建设通用定时提醒服务或工具；遵循 KISS 与 SWE 原则，避免没有实际需要的抽象、接口和改名。 |

| D34 | `send` 复用前后台参数 | `send` 复用 `spawn` 的前后台参数，默认后台。`spawn` 创建的子代理与后续 `send` 指定的目标是同一个实例；模式参数用于该目标子代理本次新执行，前台等待结果，后台启动后返回。对正在运行的目标发送消息不改变其当前执行模式，沿用 D29 的投递行为。此决定替代助手此前提出的“`send` 不设模式参数、续跑固定后台”建议。 |
| D35 | 监督从主会话空闲时计时 | 从主代理结束当前轮、进入空闲，且仍有后台子代理运行时开始监督计时，不从子代理创建时刻起算。用户中断后的定期唤醒限制继续遵守 D33。 |
| D36 | 右侧多页面 Tab 容器 | 按用户标注的 Codex 截图设计右侧页面容器：Subagents 是其中一个 Tab，集中承载子代理入口；文档与 Review 页面可作为并列 Tab；顶部提供添加页面入口，后续可选择内置浏览器、终端等页面；最右侧提供展开右侧栏的按钮。该结构不是每个子代理各占一个顶层 Tab，也不限定每种页面类型只能有一个 Tab。终端和浏览器的实现范围继续遵守 D12；文档、Review 也明确放到后续，见 D38。关闭 Subagents Tab 不停止或销毁子代理，不影响结果交付；Tab 关闭与 `agent(action="close")` 是不同操作。 |

| D42 | 执行结束后遗留的后台 shell | 与主代理现有规则一致：子执行**自然结束**时，它用 `run_in_background` 启动、仍在运行的 shell 任务继续运行，直到自身超时（最长 10 分钟），不占运行名额，结束时只禁止该执行再开新命令；子执行被 **stop** 时，终止本次执行启动的 shell，确认退出后再归还名额；**close** 或会话销毁时回收该实例的全部 shell。名额的清理条件只覆盖模型循环和本次执行仍在进行的工具调用。 |

| D44 | 定时监督连续无变化后停止 | 保留 D31 的 2/5 分钟间隔。连续 3 次监督唤醒期间都没有新事实，就停止定时唤醒。新事实指子执行开始或结束、有结果交付、出现新的审批请求；单纯的工具调用进度不算。之后有子代理结果、用户新消息或新的子执行启动，计数清零，重新从 2 分钟开始。卡住的子代理由程序的执行超时兜底（默认且最长 30 分钟，按实际工作时间计算，不含审批等待），超时结果照常唤醒主代理；审批阻塞时不反复唤醒。 |
| D45 | stop 后未消费的消息关闭并告知 | 子执行被 stop 时，send 已受理但还没进入模型请求的消息，按主代理现有规则关闭（留记录，关闭原因为 stopped），不自动带入下一次执行。主代理调用 stop 时，回执列出这些消息的原文；用户从 UI 停止时，记录挂在被中断的执行上，list 和 monitor 可见“有 N 条消息未处理”。主代理需要时自己在新的 send 里重写。失败、超时、close 同样按此关闭。替代 02 原先“下次 send 受控承接”的设计。 |
| D46 | 拆成四个 improve 依次实施 | improve-1：统一 `agent` 工具与子代理生命周期，外加 Web/TUI 同时认新旧工具名的最小兼容。improve-2：子代理实例读取与控制的后端，包括实例列表快照、带预期执行身份的单实例停止、详情定位、关闭后拒读；不建通用面板后端。improve-3：右侧 Tab 容器、入口页、Subagents 列表与详情的前端，Tab 状态只放前端，用页面类型 union 给终端、浏览器留扩展位。improve-4：主会话入口切到右侧栏，删除旧浮层及相关逻辑，做回归。顺序为 1 → 2 → 3 → 4；每个 improve 从最新 main 切一个本地分支，improve 内的批次以提交为单位，验收后合并回 main；improve-2 的接口类型确定后，improve-3 可从 improve-2 分支提前开始。improve-3 合并后到 improve-4 合并前，允许短暂存在两个详情入口。 |
| D47 | 派遣提示词补四条软约束 | 只改提示词，不写死数字规则，代码不截断结果。主代理提示加三条：spawn 的 prompt 是子代理唯一的上下文，要写清目标、已知事实、负责或只读的范围、结果要包含什么；派遣数量按任务复杂度决定，不默认派满；满额返回 `started: false` 时不立即重试，而是等结果、停掉或关闭不再需要的代理，或者自己做。子代理提示加一条：报告控制在约 1–2k token，长内容写进文件后返回路径。旧提示词里的 `subagent_status`、`subagent_close` 以及 60/120 秒等待，在实施时统一换成新语义并删除。 |
