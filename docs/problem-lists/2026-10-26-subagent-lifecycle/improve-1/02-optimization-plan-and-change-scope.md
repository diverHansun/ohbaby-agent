# 2. 优化方案与改动面

> 2026-10-28 正式规划稿。用户已确认的行为见 [00](00-discussion.md)，事实依据见 [01](01-problem-analysis-and-current-state.md)。
> 本文用于后续实施；本轮不修改实现代码。接口字段、计时重置等是基于确认行为的工程细化，不冒充新增的用户确认。

## 2.1 方案总览

子代理属于派遣它的主会话，可以跨多轮执行。保留稳定实例 ID，每次工作单独记录 execution。前台执行等待并跟随本次主执行的中断；后台执行由会话持有，不跟随普通主轮次结束或 Stop。原 `rootRunId` 保留追溯用途，但不能继续兼任后台存活、shell 清理和结果投递的唯一地址。

```text
主会话
  ├─ 唯一的主执行入口：用户消息 / 子结果 / 合法的监督到期
  ├─ 子代理实例：可复用上下文；close 后注销控制入口
  │    └─ 本次执行：mode + run + 名额 + 预算 + 实际资源归属
  ├─ 已有持久存储：消息、工具记录、execution、结果交付事实
  └─ Web 右侧容器：入口页 / Subagents 列表 ⇄ 实例详情
```

不新增全局代理池，不按“上一项任务/下一项任务”拆出一套业务状态。不重新实现主代理调度器；结果、用户输入和监督共用已有 `SessionExecutionGate` 及输入请求确认机制。

### 设计决策与代价

| 选择 | 解决的问题 | 不采用的方案 | 代价 |
| --- | --- | --- | --- |
| 一个 `agent` 工具，按 action 校验 | 模型入口统一、参数可验证 | 六套外部工具或描述文本中的隐式参数 | scheduler 必须按 action 区分读取与控制 |
| 会话持有后台执行，run 仅记录来源 | P1–P3：跨轮存活与交付 | 强迫主 run 一直等待；全局共享代理 | 调整结果归属、shell owner、收尾和恢复 |
| 六个实际执行名额，异步开始前预占 | P4：避免超卖 | 把 dispatch 常量改成 6；满额自动排队 | 所有退出路径必须确认清理并归还 |
| 运行中 send 投递下一模型请求 | P5：及时补充任务信息 | 结束后暗中启动另一 execution | 发送与收尾需有短的串行判定 |
| 保存历史与可运行实例分开 | P6：close 不等于删历史 | close 后根据旧 ID 重建 | 读取与控制权限、UI 投影必须分开 |
| 一个实例列表、一套详情 reader | P8：跨轮查看与右侧导航 | 每次 execution 一行；保留旧浮层并行入口 | 增加实例投影，重写外层布局 |

## 2.2 行为与接口契约

### A. 统一工具与参数

对模型只注册 `agent`，action 枚举为 `spawn/send/list/monitor/stop/close`。参数必须出现在 schema 中，服务端再次按 action 验证。优先使用与现有模型提供方兼容的对象 schema 加运行时动作校验；不为追求复杂的 JSON Schema 分支而增加模型适配层。

| action | 参数设计 | 行为与返回重点 |
| --- | --- | --- |
| spawn | 必填 `prompt`；可选 `name`、`description`、现有受支持的角色选择；`mode` 默认 background | 创建一个新实例并启动执行；返回稳定 `agent_id`、本次 `execution_id`、实际 mode、是否启动；前台还返回执行结果 |
| send | 必填 `agent_id`、`message`；`mode` 与 spawn 相同，默认 background | 运行中只投递消息；无活动执行时申请名额、以同一实例启动新执行；返回消息受理信息或新执行信息 |
| list | 无目标参数；按调用者所属主会话查询 | 返回未关闭实例概况：ID、名称、当前状态、当前/最近 execution、运行模式和简短进度事实 |
| monitor | 必填非空 `agent_ids` 数组，单个也用数组；可选续读游标 | 立即返回指定实例的已有执行记录，可一次读取多个；逐目标报告不存在或不可访问 |
| stop | 必填 `agent_id` | 中断此实例当前执行，保留上下文和实例；无活动执行时明确返回无需中断 |
| close | 必填 `agent_id` | 禁止后续控制、停止并清理现存执行、注销可运行实例；保留持久历史 |

- `mode` 使用 `foreground/background`，只描述**本次执行**，不是实例永远不变的属性。send 对运行中目标忽略模式切换意图，回执说明当前实际模式；不能因 schema 默认 background 而把运行中的 foreground 改掉。
- spawn 不接受已有实例 ID；send 不借缺失 ID 创建新实例；不添加 `resume`、`wait`、批量 spawn 数组或 `interrupt=true` 隐式操作。
- 拒绝不适用字段、无效 ID 与跨主会话控制。角色、超时等现有可用配置只保留实际仍受支持的字段，不恢复已经废弃的模型配置入口。
- 一轮多个 spawn 是多个独立调用，独立成功或失败。返回结构中的 `started: false` 与错误原因属于操作结果，不新增 agent 状态。满额写明“本次未启动”，不制造一个排队等待的 execution。
- `list/monitor` 为只读；其余为控制。统一工具不能因为名称相同就共享“只读”授权，也不能让 stop/list/monitor 等待一个 foreground 工具归还 dispatch 槽位。执行额度由 Host 管，工具调度只处理实际调用调度约束。

调用示例：

```json
{"action":"spawn","name":"检查测试","prompt":"检查相关测试并汇报结果","mode":"background"}
{"action":"send","agent_id":"agent-123","message":"继续检查失败原因","mode":"background"}
{"action":"monitor","agent_ids":["agent-123","agent-456"]}
```

提示词同步解释：后台是默认；没有独立工作时可以结束本轮；结果会自动送达；运行中 send 不打断；立即打断用 stop，需要继续再 send；stop 保留实例，close 不可恢复；需要细节再 monitor，不反复轮询它等待完成。

提示词同时落实 D41：完成后默认保留实例，以便通过 send 继续相关工作。确实不再需要复用，后续任务与此前任务关联较低，或经历很多轮后旧上下文已不适合后续工作时，可以 close，再通过 spawn 新建。不要为了主轮次收尾、已经拿到结果或释放运行名额而关闭已完成实例；名额已在执行清理确认后归还。“很多轮”是语义判断，不新增固定轮数、定时自动关闭或轮换服务。

### B. 实例、执行与六个名额

主会话是运行额度边界，前后台及现有允许的后代子执行共用六个，主代理不计入。不借本轮扩大嵌套派遣权限，也不能靠后代绕过额度。一个实例同时最多一项实际执行。

开始 spawn 或空闲实例的 send 时，先在短的同步/串行临界区中检查状态并预占名额，再做异步创建、上下文准备与模型启动。锁内不等待执行完成、清理或外部 IO。并发 spawn 独立申请；容量满立即拒绝。运行中 send 不占新名额，不建第二 execution。预占成功即确立该实例唯一的活动执行，异步启动中的后续 send 归入这次执行，不因模型尚未开始而再抢一个名额；这不要求新增 preparing 状态。停止/关闭若先于启动完成，迟到创建结果只进入清理，不能继续启动模型。

每个执行持有一个只能归还一次的 lease。资源准备失败时，先清理已部分创建的资源，再归还。正常完成、失败、预算结束、stop、close 通过同一收尾路径归还。实例完成后可以保留逻辑上下文，不占运行名额。

**资源清理完成必须有明确证据。** 不以 `status=interrupted`、active map 删除、主模型 Promise 返回或发出 abort 作为归还条件。现有 shell 的 confirmed/unconfirmed 事实应复用；`disposeScope()` 返回也不能直接等同已确认清理，因为当前实现允许 unconfirmed 返回。

清理顺序为：停止新工作准入 → 取消执行及其受管工具 → 等待模型/工具退出与受管进程回收 → 确认执行资源已解除 → 幂等归还。已有进程终止能力应使用有限等待、升级终止和退出确认；不要只写 finally 便声称不会泄漏。

若清理仍未确认，保留占用、记录可诊断的资源及错误，由既有资源回收机制继续处理；接口不能谎称“已清理完成”。对调用的等待要有界，不能把整个会话永久锁住。真实清理确认迟到时，由对应 execution 的回收完成路径自动且只归还一次，不要求用户再调用 stop/close/monitor；旧确认不能归还新执行的 lease。服务退出时统一回收；异常重启根据真实 owner 与恢复事实重建，不把旧内存计数写死为永久占用。这里不新增一个完整调度服务。

### C. send、stop、close

运行中的 send 写入该子执行的输入通道，在**下一次模型请求组装输入时**消费。当前模型请求不强行中断，当前 mode 不改变。消息纳入哪次请求及何时确认消费，复用已有请求成员和成功请求确认机制。

发送与执行收尾通过同一实例的短串行判定处理：仍可接收输入则让当前执行在结束前处理已受理消息；已经结束则按新执行分支申请名额。不能先回报“已发送”再静默丢弃消息，也不能在未申请额度的情况下暗中创建续跑 execution。显式 stop 到达后，尚未消费的消息保留为未处理记录，不单独触发自动续跑；后续明确 send 才可恢复。新执行需要有选择地承接此前已受理、未消费的 agent 消息，保留来源并防重复；不能仅依赖历史读取，因为现有过滤会排除从未尝试消费的运行时输入。只为这类消息建立受控承接，不全局放宽历史过滤。这是消息输入承接，不是等待容量后自动开工的执行队列。

stop 中断当前执行并等待必要收尾，保留实例 ID、历史及可恢复上下文。当前 execution 对外显示 interrupted；取消信号是实现手段，不另造“暂停中的模型请求”。send 是利用已保存上下文开始新执行，不承诺恢复网络请求或命令的机器执行位置。

close 先禁止新控制准入，再中断、清理及注销可运行对象。保留现有 `closedAt` 或等价持久关闭事实，重启后也不能根据旧 ID 重建。完整关闭回执必须在清理确认后；清理未确认时如实返回，不假报成功。重复 close 幂等返回已关闭事实，不重新创建对象。对不存在/已关闭 ID 的 send 返回目标不可用。

完成 close 后，list 和 UI 的实例列表及详情均不可见。主代理持有旧 ID 时，可通过 monitor 读取已存历史；这条路径不经过可运行实例加载、不生成新的 agent、不重新激活沙箱。

### D. 主执行结束、停止与结果交付

| 事件 | 主执行 | 前台子执行 | 后台子执行 |
| --- | --- | --- | --- |
| 主代理没有独立工作、结束本轮 | 正常结束；整个用户目标可仍未完成 | 活动的前台调用本来应被等待，不伪装成后台遗留 | 继续运行 |
| 用户停止活动中的主执行 | 中断本轮，禁止监督定时唤醒 | 停止本轮前台执行，相关中断通知不唤醒主代理 | 继续运行，后续结果仍可唤醒主代理 |
| 用户或主代理停止某个子代理 | 不向上中断主执行 | 仅停止指定目标的当前执行 | 同左 |
| 关闭 Tab / 折叠侧栏 | 不变 | 不变 | 不变 |
| 主会话被销毁或服务退出 | 按既有生命周期收尾 | 清理实际所属资源 | 同样清理；跨 turn 不等于跨进程永久运行 |

工具/进程 owner 绑定实际执行，主 run 的 shell seal/cancel 不再波及独立后台执行。会话整体关闭仍能枚举其实际子执行并清理。保留已经正确按 run 精确撤销的审批逻辑；后台需要审批时仍能在所属主会话中显示并操作。

后台自然终态形成结果交付事实，内容以任务结果为主，附 `agent_id/execution_id`、名字、原派遣任务摘要、终态及已有结果文件引用。不默认附完整工具轨迹。自然失败和超时同样需要让主代理知道。

交付采用现有 store 的未交付终态事实与输入确认能力，扩展为**按主会话查询和持有**，不另造通用消息总线：

1. 结果先有可恢复的保存事实，原 root 只用于追溯。
2. 主会话有活动执行，结果成为其下一次模型请求的输入；不打断当前请求。
3. 主会话空闲，经过同一个执行门启动一次主执行，使用该会话现有模型配置与上下文组装方式。
4. 结果交付使用稳定来源标识，绑定实际消费的请求；成功处理后才确认，不能以“发过事件”或 monitor 读过为交付完成。
5. 忙闲切换、请求失败、主 run 被中断时，尚未处理的结果保留在会话级待交付事实中；不因原 run 关闭而消失。多个同时到达的结果可以合并进入一次请求。
6. 保留待消费内容不等于重复获得自动唤醒机会。同一结果已触发的主轮次失败或被用户停止后，不因重复通知/事实重扫立即用它再开一轮；待下一次用户消息、新子执行结果或允许的监督启动时再纳入。复用来源标识与请求尝试归属记录此边界；请求内 provider 重试沿用已有预算，不新增无限结果重试循环。

前台结果直接作为工具结果交付，不同时再投递后台完成唤醒。主动 stop/close 的控制确认与自然完成报告分开，避免用户刚停止就被同一次取消回执立即唤醒；D06 的主停止引起的前台中断严格不唤醒。后台之后真正完成其他工作仍遵守 D08。状态记录始终可供 list/monitor 查看。

已有 Goal 不能在“只剩后台工作可等”时连续开主轮次绕过监督。保留 Goal 的独立工作推进、预算及显式终止规则；等待时使用同一个结果/监督入口。Goal 预算或整体终止清理按实际 Goal 归属查询，不能只查最后一个 rootRunId。普通主 Stop 不得被 Goal 旁路恢复，也不能因此取消后台。

### E. monitor 与结果分工

monitor 只读保存的会话与执行事实，返回每个目标的当前/最近执行信息、相关消息、工具名、参数与结果摘要、时间和错误。命令、文件路径等来自真实工具记录，不猜测补齐。模型提供方已输出且系统保存的 reasoning 可以按现有展示/权限规则读取；不承诺获得模型未输出的内部思考。

首版采用有界读取：默认每个目标最近 20 条记录，最多一次 6 个目标，总文本预算 16 KiB；超出时裁剪单条大输出并给出截断标记、已有完整输出引用及每目标续读游标。游标使用保存记录的稳定顺序，续读可以取更早记录；重新不带游标读取则取得最新快照。不接受等待时长或订阅参数。

读取正在运行、已完成、已中断，以及同一主会话中已 close 的历史都不触发模型调用、artifact 生成、结果已读/已交付修改或执行恢复。多目标中某个不可读，单独返回该目标错误，其余仍返回；不能泄露其他主会话的记录。

这些预算是实现默认值，集中定义并测试；不是新产品状态，也不为它们增加配置页面。Web 的实时详情继续使用 SDK watch，与模型 monitor 的一次性读取分开。

### F. 自动监督

采用首次 2 分钟、后续 5 分钟作为本方案实现基线。计时属于主会话：主代理结束本轮、真正空闲且仍有后台子执行在运行时才开始。不是从 spawn 时间起算，也不是每个子代理各建一个会唤醒模型的定时器。

| 情况 | 计时与模型行为 |
| --- | --- |
| 用户输入或子结果处理结束，主代理再次空闲且后台仍运行 | 首次空闲等待 2 分钟 |
| 仅因监督唤醒、处理完后再次空闲 | 下一次等待 5 分钟，以后同样按 5 分钟 |
| 主代理开始正常工作 | 取消旧计时机会；忙碌期间不堆积监督消息 |
| 用户中断主代理 | 禁止定期唤醒；后台结果或新用户消息仍可正常启动主代理 |
| 用户/结果合法启动新主执行并正常结束 | 进入新的空闲等待周期；若该执行又被用户中断，继续禁止定期唤醒 |
| 没有运行中的后台执行 | 不再计时 |
| 全部后台只等待用户审批且事实未变化 | 复用现有审批阻塞抑制，不反复调用模型复述同一阻塞 |

到期时重新检查空闲、后台运行、用户中断和会话存活条件，再通过主会话执行门唤醒；过期 timer 不能越过新 Stop。仅子工具进度变化不重置计时，避免长期永远不到期。超时预算检查、资源回收和漏事件核对仍由程序负责，不需要模型醒来才生效。

内部 `subagent-status` 是消息种类，不是旧工具 `subagent_status`。本轮保留内部持久化名称，更新提醒正文使用 `agent` 的 list/monitor；为统一外观改持久消息类型没有实际收益，不做该迁移。新工具 schema 中不暴露一个叫 subagent-status 的函数。

### G. Web 右侧容器与子代理阅读

本批只做右侧 Tab 容器、入口页和 Subagents。文档查看、Review、浏览器、终端延后；不放不可用的占位功能页面，不实现浏览器地址栏或网站推荐。

**容器：** 主区右侧增加可展开/收起、可调整宽度的区域；顶部有 Tab、关闭 Tab、添加页面和侧栏开关。第一次展开且没有打开页面时显示轻量入口页，提供“子代理”入口；已有页面时恢复当前 Tab。添加入口本批只列实际可用的页面。使用简单页面类型与局部状态，不建设插件注册框架。

**Subagents 页面：** 点击派遣入口优先复用本主会话已有的 Subagents Tab，没有则创建。Tab 使用独立 tabId，容器不把页面类型当全局唯一键；本批不把每个子代理各做成一个顶层 Tab。列表一行对应一个未关闭实例；同一实例 send 续跑十次也只有一行。列表按 Active/Done 分组，显示名称、实际状态、简短任务说明和时间。Active 包括正在执行、启动及尚未完成清理的执行，等待审批仍在 Active；Done 包括已完成、已中断、失败、超时且已结束清理的实例。具体状态标签仍保留，Done 不等于成功。空分组有空态，closed 不属于任何分组。

**详情：** 点击实例进入同一 Tab 的子会话，顶部提供返回子代理列表、稳定名称、当前状态和运行中可用的“停止”入口。详情只读，用户通过主会话安排后续工作，不为子代理增加直接输入框。保留消息、工具参数/输出、保存的 reasoning、分页、实时更新与阅读位置。列表选择按 `subagentId`，主历史入口额外携带可选 `anchorExecutionId`；历史定位不覆盖标题的当前状态。

**主会话入口：** 保留完整 agent 工具调用卡及其输入/输出；实际启动成功后追加“xx 子代理启动”快捷提示。点击自动展开右侧栏、打开 Subagents Tab 并定位该实例。入口依据结构化实例/执行元数据生成，不解析自然语言。spawn 与空闲 send 启动新执行可显示入口，运行中 send 仅显示消息投递回执。失败或满额不能显示启动成功。前台执行在运行时可依据已确认的启动事件提供入口，结束后工具输出照常补齐。

**替换旧交互：** 移除主会话里的子会话浮层、相对输入框测量定位、childExpanded、旧 Expand/Collapse、打开子会话便禁用主输入/隐藏审批等行为。复用 ConversationStream、消息展示、reader 与缓存，不同时保留两套详情入口。打开右侧详情不影响主输入和主会话运行。

**关闭与会话切换：** 关 Tab/收侧栏只释放阅读 watch，不调用 agent close 或 stop。会话切换清除旧选择并隔离缓存/事件，不把另一个会话的子代理带过来。窄屏让右侧阅读区域在有限空间中独占可用内容宽度，保留明确返回主会话入口；只是阅读布局变化，不暂停运行或禁用后台输入能力。键盘焦点按普通侧栏处理，不沿用旧模态焦点锁。

**closed 的 UI：** 实例关闭后从列表移除，正在显示它的详情返回列表，主会话中该实例的专用启动链接/子代理投影撤下；UI 不能再沿旧链接读取它。保留普通主会话工具调用记录作为原会话事实，不删除数据库或改写历史消息。该记录不再附可打开的 child 详情入口。主模型的 monitor 历史读取与 Web 可见性是不同契约。

### H. 协议与实例投影

SDK/HTTP/in-process 增加或调整实例列表投影，至少包含主会话归属、稳定 ID/name、实例状态、当前/最近 execution 引用、实际模式及是否仍有执行资源待收尾的事实。Active/Done 在 UI 派生，不存入 core enum。

列表不能直接复用按 execution 历史追加的合并方式。首版使用当前主会话全部未关闭实例的轻量权威快照，跨 turn，不能拿旧执行历史的默认 50 条第一页或当前 root 的统计代替。只有成功取得完整且属于当前会话选择的快照后才能替换列表；读取失败或不完整结果不能推导实例已关闭。未来如增加分页，分页缺项与实例移除必须分别表示。复用现有刷新机制，不为列表另造复杂事件总线。close 后刷新/失效必须覆盖只修改 closedAt 而没有 execution 更新的情况。工具结果与单实例控制回执可触发立即刷新。

Web 子代理停止提供独立的类型化 SDK/HTTP/in-process 控制入口，调用与 `agent(action="stop")` 相同的 Host 操作，不依赖主代理正在运行，也不调用主会话 abort。请求携带主会话、实例及预期 execution 身份；目标已完成或已经换成新 execution 时返回实际状态，迟到点击不能误停后续执行。回执区分中断已受理与清理已确认，随后刷新实例快照。

详情保留现有 watch/revision/分页协议，支持按实例选择和可选执行锚点。关闭后的 UI 详情接口拒绝继续读取并释放投影，主模型的授权历史读取仍可用。旧 execution 历史接口若 CLI 或历史记录仍在使用则保留，不因 Web 改用实例列表而全局删除。

## 2.5 API、迁移与兼容

1. 工具变更必须同步 schema、provider catalog、角色/嵌套权限、system prompt、scheduler 动作分类和 UI 元数据。默认后台必须在 schema、解析与提示词三处一致。
2. 历史 `subagent_run` 等记录仍可显示和关联已有实例/执行；它们不是继续注册旧工具的理由。历史消息中的旧名字不做全库文本替换。
3. 保留 `closedAt`、execution 与消息历史。仅为跨轮交付/资源归属确有必要时增加字段及迁移；不要为 Active/Done、工具改名或监控结果建立新状态表。
4. 未交付结果要能从已有 execution 与交付标记重新核对。请求失败不提前确认；monitor 不确认；原 run 关闭不丢弃。既有请求成员不可变、成功请求确认机制不能被弱化。
5. 重启恢复按实际 worker/进程 owner 修复执行与名额，不默认自动重放中断的命令。历史关闭实例继续不可恢复。跨轮运行不等于承诺机器休眠/服务重启后无缝继续物理执行。
6. 兼容当前会话模型选择与 Goal 预算。子结果唤醒使用主会话现有配置解析入口，不复制一份过时的全局模型选择规则。

## 2.6 风险与回滚

| 风险 | 实施约束 |
| --- | --- |
| 修改 root 传播漏掉 shell 或 Goal | 用实际 shell、审批、Goal 等待和退出验证，不只测 Host 状态 |
| 清理未确认便释放第七个执行 | lease 绑定已确认收尾；保留 shell unconfirmed 诊断与后续回收；不以定时器超时直接视作成功 |
| 结果事件与用户消息同时启动主代理 | 共用既有会话执行门；确认消费与来源去重；在收尾交界测试 |
| 统一工具扩大子代理权限 | action 级校验沿用角色边界，不因工具改名给原本禁用派遣的角色开放派遣 |
| UI 合并旧列表导致 close 后仍可见 | 实例权威快照替换、详情失效、历史入口撤下同时验收 |
| 旧 UI 删除误伤审批或 CLI | 分离读取内容与模态壳；保留仍被使用的 reader、样式和协议 |

实施分阶段提交，发布前通过整体验收。若需回退，先停止并确认回收新运行时持有的执行，再回退代码；不能让旧、新 owner 同时管理同一子执行。数据库做增量迁移，保留历史和关闭事实，回退前核对旧版本读取兼容性；不靠删历史表回滚。close 不可恢复是已确认的产品语义，不以回滚重新开放旧 ID。
