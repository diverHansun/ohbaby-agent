## 3. 已确认的两层处理

**Q1 已确认（2026-09-16）：原始失败消息过滤与断流正文带入，是两个层次。** 用户明确确认：

> “过滤 error/aborted”指过滤原始失败协议消息，确认！明确断流时，仍允许把已保存的可见正文提取为带中断说明的普通文本历史，确认！

据此采用以下规则：

- 保留原始失败记录供查看；`error/aborted` 消息不能经普通协议路径直接重放。
- 明确断流时，仅从已经落盘、用户可见的正文派生有中断说明的纯文本历史，不携带 reasoning、native state、不完整工具调用。
- 主动取消只投影取消事实，并保留此前已接受的完整工具事实；不把被取消请求的正文回传。
- 正常收到 `length/content_filter` 的正文属于另一类：请求有可靠终态、运行未完成，可以保留正文并说明原因。

本项语义决策已关闭，02 的断流正文分支及 04 的对应断言以此为准。随后用户已授权：对齐 Cursor 实施前反馈后按批次实施、测试、审查和本地提交；不 merge/push。

- 不优化摘要/prune、旧摘要累积、切点、保留比例、mask、thrash 阈值；不为数字好看回调占用估算。
- 不引入 previous_response_id、Conversations、后台 Responses、自动续写、流中提前执行工具、进程崩溃后自动重放写操作。
