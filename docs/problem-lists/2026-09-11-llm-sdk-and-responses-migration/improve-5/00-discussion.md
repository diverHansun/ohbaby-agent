## 0.2 已确认合同

| ID  | 项目     | 结论                                                                                                                                                    |
| --- | -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| K1  | 指标     | 同一主代理 session 的累计缓存读取 token 占累计可记账输入 token 的比例。先加 token，再除；不显示单轮比例，不平均各次百分比，不统计命中请求数或节省金额。 |
| K2  | 纳入粒度 | 按可信 Step 累计，正式替代旧整 Run 筛选。某一步缺明细，不撤销其他已知 Step；未知 Step 的分子和分母均不进入缓存累计。                                    |
| K3  | 未知和零 | 未返回读取明细是未知；明确返回有效的零是已知零。有读取明细、无写入明细不因此拒收。                                                                      |
| K4  | 显示     | 没有可信的正输入样本时 `hit —`；已知读取累计为零时 `hit 0%`；否则整数百分比。最近一次缺明细不覆盖已有累计。                                             |
| K5  | KISS     | Web/TUI 继续极简 `/status` 行。不增加范围说明、覆盖率、缺失数量、额外状态或提示字段；保留现有公开 DTO。                                                 |
| K6  | 生命周期 | 跨 Run 持续累计；换模型、手动/自动压缩不清空或回减。保留既有进程内生命周期，不新增跨重启恢复。                                                          |
| K7  | 子代理   | 不进入主界面累计；复用现有用量事件和消息记录做静默验证，保留主子代理共用上下文机制及 scope 隔离，不另建统计或压缩系统。                                 |
| K8  | 缓存控制 | 本批不改变 system prompt 组装、缓存前缀等命中规则，不改 `cache_control`、key、TTL 或 Responses 控制能力。                                               |
| K9  | 证据     | 固定样本证明各种明细组合和累计；集成测试证明事件、归属和展示；真实接口按实际返回核对，不要求非零命中，不为等到命中无限重试。                            |

“可信”沿用现有正常归一化得到的单步 TokenUsage 与读取 observed 信息，具体最低条件见 02；不增加置信度系统。没有数据时不能据此得出完整 session 的实际缓存比例，开发文档说明这一限制，前端无需增加提示。

## 0.4 历史关系与非目标

只替代旧 session-cache-hit 的 Run 级纳入门槛及依赖它的统计入口。旧方案曾是明确约定，不将其追溯认定为实现缺陷。新实现无需保留旧规则开关或双轨计算。

总 usage 聚合与 `usageComplete`、校准、窗口管理、消息 schema、原生 Responses continuation 限制仍按前序合同工作。title/summary 等辅助模型请求及子代理不合入主界面的缓存比例。

不新增所有 HTTP 尝试的计费账本、失败用量估算、缓存专用持久化、重启恢复、按模型拆分 UI、命中提升策略。子代理“有记录可验证”不等于所有中断都能恢复供应商未返回的数字。
