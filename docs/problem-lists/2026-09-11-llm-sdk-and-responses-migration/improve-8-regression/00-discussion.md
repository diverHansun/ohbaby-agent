# 已确认的讨论结论

时间：2026-09-17。来源：当前对话；本文件只冻结已确认事项。本轮后续四项选择已由用户确认，汇总见 [02 §1](./02-optimization-plan-and-change-scope.md#1-已确认的行为选择)。

## 1. 目标与范围

| ID  | 已确认规则                                                                                                                                                                   |
| --- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D01 | 沿用现有连接接口，增加完整三协议枚举校验和传递；Web 三选一下拉，TUI 增加协议行。                                                                                             |
| D02 | 缺省继续按 base URL 识别；OpenAI 形状地址默认 Chat Completions。显式协议优先，不能改 key 或窗口就重置成 URL 推断。                                                           |
| D03 | `/connect` 不要求填写推理强度。保存模型后识别该连接的推理能力，再决定前端控件。                                                                                              |
| D04 | 支持 medium 时默认开启 medium；不支持 medium 时选已确认的厂商默认档位；无可靠默认值时选最低支持档位，不额外弹出醒目提示。                                                    |
| D05 | 档位显示后端返回的原名，不改成中文档位名；用户可自行选择。                                                                                                                   |
| D06 | 不支持推理的模型不显示强度下拉；不能关闭的模型不提供关闭选项。                                                                                                               |
| D07 | Web 推理控件在输入框下方、发送提示左侧，即用户截图红框位置附近。                                                                                                             |
| D08 | TUI 不限于 `/connect`，同批检查其他文本编辑入口。编辑时用青绿色/茉莉绿方向，保留文字或光标提示，无彩色终端也可辨认。                                                         |
| D09 | 表单 Enter 进入编辑，再按 Enter 提交并退出编辑高亮。增加 PgUp/PgDn 导航；具体适用边界见 03。                                                                                 |
| D10 | 保存模型与启动任务由后端协调，前端不因配置保存/任务运行而禁用按钮。已有运行任务继续使用旧模型，本轮对话结束后下一轮使用新模型；新任务可等待旧运行环境结束再切换。            |
| D11 | 更新当前连接时准确匹配模型、协议与地址，不能覆盖另一个连接的能力资料。                                                                                                       |
| D12 | 补充竞态、陈旧响应、草稿覆盖、旧档位残留、超时、显式协议保留的测试。                                                                                                         |
| D13 | TUI 优先在 agent 进程中测试，确实无法检查的部分再请用户补测；Web 由 agent 启动开发版服务并做真实浏览器操作。真实模型来自 `tests/models-4-tests.md`，凭据从 `.env` 注入进程。 |
| D14 | 用 plan-frontend-design 写前端规划，保持轻量，避免把设计建议变成过于强硬的样式标准。完成后自检一致性、可实施性和验收标准。                                                   |

补充确认（本轮后续答复）：

- D15：推理强度按当前会话保存，不同会话独立；发送时固定到该条消息。
- D16：能力资料未知不主动阻止生成；实际发送，服务端报错按现有错误流程处理。
- D17：已启动任务完成本轮对话后再切模型。“一轮”按一次用户消息触发的完整执行理解，包含工具循环和续答，不是每个 HTTP 请求。
- D18：保存成功后，新任务接受等待旧运行环境结束再切换；前端仍可提交。

“最低档”以已确认支持的推理档位及其强弱顺序为前提；未知能力没有可供选择的最低档，不能擅自假设为 low，也不能把关闭当最低推理档。资料不足时仍允许请求，由服务默认行为决定生成；不宣称 medium 已应用。

## 2. 与前序工作的关系

- improve-1～7 已接入 SDK、三协议、自有消息结构、用量/cache、Context 和 Agent loop；本轮补产品连接入口和相应回归。
- improve-5.5 的全局默认开启/medium，在本轮产品默认选择中补充 D04 的例外规则；协议参数转换仍由后端处理。
- 沿用失败历史和 SDK 重试规则，不增加自动“继续生成”。
- 不修改压缩/prune 算法、完整窗口 95% 的自动压缩触发规则。
- 本次授权是写文档并自检。后续实施分批测试和提交，不自动合 main 或 push。

## 3. 用户原话摘录

> “没有可靠默认值默认最低档，不要明显提示，用户自行选择就行”

> “档位可以和后端返回的一致，不用做中文命名转换”

> “建议颜色是青绿色，茉莉绿，保留文字或光标提示”

> “建议前端不做禁用按钮”

以上最后一条约束配置保存与任务协调的交互；能力不存在时不提供无效档位，键盘可达和错误反馈仍应保留。
