# 前端设计：连接、推理选择与编辑反馈

采用 `plan-frontend-design` 的精简方式：本文件按目标、用例、布局、交互、数据、验收组织，不为小改动建立九份独立文档。后端合同只在 [02](./02-optimization-plan-and-change-scope.md) 定义，测试步骤只在 [04](./04-test-and-acceptance.md) 定义。

**约束与建议的区别：** 协议值不丢、档位原名、草稿不被覆盖、状态不撒谎、键盘可操作是验收要求。下面示意布局、提示用词、色值、圆角、间距、动画和组件拆分都允许开发时调整，以实际效果为准。02 的 Q1–Q4 已确认；具体布局和组件实现仍保留调整空间。

## 1. 目标、角色和任务

### 产品目标

用户无需改配置文件即可选择三种消息协议，保存后知道推理能力是否已识别，并能在发消息前选择有效档位；终端用户始终能辨认自己是在选字段还是编辑字段。

### 用户角色

首次配置连接的用户；维护多个会话/工作区的用户；主要通过键盘操作的终端用户。

### 核心任务

- F01 配置并恢复准确的模型连接。
- F02 查看可用推理选项并为后续消息选择档位。
- F03 任务运行期间保存新模型，理解当前任务与后续任务的区别。
- F04 在 TUI 中进入编辑、输入、提交或放弃。

### 职责边界

前端收集选择、做格式校验、展示后端结果、维护草稿和焦点。后端负责能力判断、档位排序/默认、协议转换、持久化、模型切换和运行准入。前端不能凭模型名称猜测能力，也不能将探测失败解释为不支持。

### 非目标

不重新设计整个聊天页，不新增模型市场/推荐页，不在 `/connect` 堆入推理参数表，不替换主输入编辑器，不强加新的表单框架。

## 2. 用例与用户流程

现有信息架构保持：Web 会话页 → `/connect` overlay；会话页 composer → 推理菜单。TUI 命令面板 → `/connect` 或 `/connect-search`；主 Prompt 可进入已有 queued edit。`/connect` 是产品命令，不伪装成新增浏览器路由。

| 用例                  | 对应任务 | 主流程和完成结果                                                                                           | 异常分支                                                                                                              |
| --------------------- | -------- | ---------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| UC01 配置连接         | F01      | 打开表单→读取现有值→选择三协议→保存→显示已保存及能力状态；重新打开保持协议。                               | 慢读取不覆盖已编辑值；保存失败留草稿；能力查询失败显示未知/重试，不冒充未保存；部分文件写入且恢复失败明确显示需修复。 |

## 3. 布局与视觉方向

### Web

保留现有 composer 与工具栏。推理控件靠近用户截图红框位置，即右侧发送提示前；窄窗口可以换行，不挤压输入正文。示意：

```text
[ 输入正文                                          Send ]
[auto mode] [full-access]           [medium ▾]  enter to send
```

示意不是像素合同。可加不改变值的“Reasoning”标签或图标；`medium/high/max` 等 effort 名称必须沿用后端原值，不译成“中/高”。按钮与现有 mode/permission 控件风格协调，鼠标和键盘都可打开、选择和关闭菜单。焦点关闭后回到触发控件。

不支持推理隐藏控件；固定开启且不能调节时无需可点击下拉，可用轻量文字说明。未知或检测中显示轻量“服务默认”状态，可重试检测；正常发送，不展示伪造档位，也不把旧会话偏好显示成已应用。没有厂商默认而选最低档是正常默认行为，不加弹窗/警告；未知或真正失败不是这一条“不要明显提示”的适用对象。

### TUI

编辑强调使用青绿色/茉莉绿方向，复用/增加小型语义 token。暗/亮主题分别选择可辨色值，不锁死 hex；不把全局 success 色改作编辑色。

- 浏览焦点：保留 `>` 等选中标记。
- 编辑焦点：输入值的青绿强调，加可见光标和/或短文字 `editing`；无色输出至少保留一种非颜色标记。
- 空字段也有可见输入位置；遮罩字段的光标不泄露密钥内容。
- 主输入框已有反色光标，优先改渲染颜色，保留其现有键盘行为。
- 队列编辑保留原有 editing、Enter save / Esc keep original 提示。

真实物理终端光标还是渲染层光标可由实现选择；不要两者同时闪烁。光标只属于显示，不能拼进输入字符串或保存数据。

## 4. 交互与状态

### 4.1 连接表单

| 状态                 | 用户看到什么                                   | 可以做什么                                 |
| -------------------- | ---------------------------------------------- | ------------------------------------------ |
| 首次读取/无配置      | 正在读取或空表单；旧值不能伪装为新值           | 开始输入，后到读取不能覆盖 dirty 字段      |
| 编辑草稿             | 所选协议及字段值                               | 修改、提交、放弃当前编辑                   |
| 保存中               | 就地保存状态，草稿不丢                         | 保持可操作；后端串行化，重复相同提交去重   |
| 已保存、能力检测中   | 已保存与检测中分别表达                         | 继续操作；当前 running 不因此被取消        |
| 已识别               | 展示有效能力、默认或用户选择                   | 选择实际支持的值                           |
| 能力未知/检测失败    | 简短原因、重试检测                             | 正常发送（服务默认），可重查，不显示假菜单 |
| 保存失败             | 错误说明，保留草稿与旧已保存值                 | 修改/重试，不把 optimistic 值显示为成功    |
| 部分保存且恢复失败   | 明确需修复，不宣称旧磁盘配置完全未变           | 可重试修复；后端阻止新任务采用不一致配置   |
| 已保存、初始化失败   | 配置仍显示已保存，另报暂不可运行               | 可修改连接或重试，不静默改用旧模型         |
| 已保存、等待模型切换 | 新配置已保存，旧任务仍运行；新任务可排队（Q4） | 继续编辑/提交，或取消对应任务              |

本节运行中保存合同针对模型 `/connect`：不以保存中或运行中为理由禁用该配置按钮/提交入口。`/connect-search` 本批只统一编辑反馈和导航，其搜索凭据运行中变更策略保持现有行为，不跟随模型切换扩大范围。前端对重复动作合并、后端保证顺序；无效输入仍给校验错误。断网时保留草稿，恢复后可显式重试。旧响应只更新它对应的操作状态，不覆盖更新后的草稿/模型。

### 4.2 TUI 键盘合同

| 场景           | 键                       | 行为                                                      |
| -------------- | ------------------------ | --------------------------------------------------------- |
| 配置表单浏览   | ↑/↓、PgUp/PgDn           | 上一个/下一个字段，沿用原循环规则                         |
| 文本字段已选中 | Enter                    | 进入编辑并显示编辑标记/光标                               |
| 文本编辑       | Enter / Esc              | 提交并退出 / 放弃未提交编辑并退出                         |
| 文本编辑       | PgUp/PgDn                | 不提交、不切走字段、不把控制序列拼进文本                  |
| 协议行         | Enter、方向键、Enter/Esc | 打开/进入三选一，选择，确认或放弃；不是自由文本协议名     |
| 主 Prompt      | 原有按键                 | 保持发消息/换行/移动光标行为，不套用表单的 Enter 退出规则 |
| queued edit    | 原有 Enter/Esc           | 保存编辑/保留原文，不改变租约和消息身份                   |

两份配置表单现有自动保存和 latest-save 队列保留。字段退出编辑不代表保存成功。窄终端、无色终端、打开关闭面板后的焦点恢复都要检查，但不以整屏字符快照锁定排版。

## 5. API 消费关系与状态管理

| 已有入口                              | 消费位置                         | 本轮变化                                                     |
| ------------------------------------- | -------------------------------- | ------------------------------------------------------------ |
| GET `/v1/model` / SDK current-model   | connect、页首/配置视图、composer | 增加公共能力视图及有效选择；没有敏感字段                     |
| POST `/v1/model` / SDK connectModel   | Web/TUI 配置表单                 | 三选一传递；持久化结果与能力/运行切换状态不混为一谈          |
| POST `/v1/model/context-window-probe` | 连接表单检测                     | 保留显式协议；若复用为模型资料查询，字段扩展保持旧调用方兼容 |
| POST `/v1/prompts` / SDK submit       | composer、TUI 主输入             | 携带当前会话在发送时固定的 reasoning，经队列持久化进入 Run   |
| 现有会话读取/更新通道                 | 会话选择、恢复                   | Q1 的会话偏好属于待新增合同，不能假设现成 setter 存在        |

能力重查可以复用现有 probe 服务并扩展 SDK 方法，或增加一个薄的只读能力查询；实施时择其简单者。不能建立三套协议专属管理 API。具体公共字段由 02 和 SDK 实施合同统一，组件不另建业务能力枚举。

数据策略：连接身份+请求代次识别响应；workspace/session 切换时丢弃不相干的在途 UI 更新；首次读取不得覆盖 dirty 草稿。能力数据进入已有 current-model/store 更新路径，不能只留在 connect overlay 内。各会话选择分别恢复，切会话不继承另一个会话的档位；检测结果不改变已绑定 Run，本次采用服务默认时不能显示成指定强度已生效。会话偏好与一次 submission 的快照分开，后者不随当前控件联动。

| 失败类别（不是要求新增这些错误码名） | 界面落点                                                           |
| ------------------------------------ | ------------------------------------------------------------------ |
| 非法协议、无效字段                   | 对应表单字段/行，草稿保留                                          |
| 持久化失败                           | 普通提交前失败显示失败、旧配置有效；部分写入恢复失败明确显示需修复 |
| 元数据鉴权/限流/超时/字段不全        | 已保存，仍可按服务默认生成，可重查；不显示“不支持”                 |
| 新模型不接受旧显式 effort            | 该次 submission 的原因和调整入口，不静默换档                       |
| 等待旧工作结束                       | 非失败等待状态，可查看/取消相应任务                                |
| 未分类服务错误                       | 简短错误和可用诊断标识，不假装成功                                 |

固定测试场景应覆盖 ready/none/binary/always-on/unknown、慢响应逆序、保存失败、切换等待、无色编辑、队列恢复；优先扩展现有 fixtures，不为这些场景引入新的 mock 平台。
