# LLM 契约 · 目标与职责

> 目标设计草案，不描述当前已实现状态。范围以 ../00-discussion.md 为准。

## 1. Design Goals

- G1：模型调用共享类型由 ohbaby 定义，供应商 SDK 演进不直接改变上层输入形状。
- G2：保持现有请求、工具执行、取消、重试、存储和估算行为；API 名称变化不暗中改变能力。
- G3：字段能区分快照与完整输入、原始参数文本与解析对象，不靠名字猜测可执行性。
- G4：控制复杂度，只增加必要的值类型和窄转换，不建立新框架。

## 2. Duties

- D1：表达现有模型消息、工具定义、调用/结果及明确支持的附加字段。
- D2：为各 adapter 提供独立于 Chat SDK 的输入；返回可累积的现有流事件及结果。
- D3：清楚表达完成/取消/供应商停止原因；由既有校验决定何时提供解析后工具参数。
- D4：给现有消费者提供唯一结果快照；公开入口迁移有完整替换记录。

## 3. Non-Duties

不替代持久 Message/Part，不执行工具，不新建重试策略，不接管 context/cache 策略，不实现精确计数或原生续接。内部能表达某项内容不等于所有 adapter 都支持。不保证任意第三方兼容网关接受任意扩展。
