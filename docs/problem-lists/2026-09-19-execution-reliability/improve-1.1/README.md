# improve-1.1：当前会话恢复与事件衔接

> 2026-09-21 登记，2026-09-22 按用户授权展开完整规划，09-23 对照 Fable 审核与后续确认修订。只改文档，未实施、未执行产品验收。实施顺序：improve-1 验收 → 本轮验收 → improve-2。本轮不改变其余轮次编号。

刷新或断线后，页面恢复当前会话已经产生的完整内容，包括尚未完成的正文、思考和当前执行事实，然后继续显示新的变化。恢复不重新播放每个字，不重新执行任务，也不要求整个项目停止输出。

## 范围与分工

| 本轮负责 | 保持独立 / 后续负责 |
|---|---|
| 当前会话的可靠基线、版本、实时衔接与历史分页 | improve-1 的审批集合、权限版本与审批就绪 |
| 实时/历史消息身份统一，当前完整输出可恢复 | improve-2 的工具阶段、模型尝试、耗时和执行结果保存失败策略 |
| 恢复、草稿、发送、Stop 分别按必要条件启用 | improve-3 的子代理只读界面、自动交付和 Steer |
| 只读恢复不触发队列调度或修复写入 | improve-4 的整树停止、退出、retained 和冷恢复治理 |

思考存储按最新确认调整：生成期间保留当前累计值，正常结束、Stop 或可处理失败时保存已收到的内容及真实结束状态，保存成功后可释放展示热缓存；已保存思考不自动进入后续模型上下文。进程崩溃不保证尚未保存的尾部。展示思考单独保存失败不停止 run；未保存的已结束内容有限保留，超限明确提示缺失，不影响模型执行所需内容。详见[本轮 D8–D12](00-discussion.md)。

当前会话优先；其他会话读摘要，早期历史按需加载。附加数据读取失败不拖垮已恢复的对话。审批继续沿 improve-1 独立恢复。默认 TUI 保持 in-process，独立 runtime 不承诺共享实时内容。本轮不移除 persistent-store 的主会话过滤，不提前开放子会话 UI。
