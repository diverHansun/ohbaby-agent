# improve-1.1：页面快照与事件续传一致性（待讨论）

> 登记日期：2026-09-21。用户已确认单独安排在 improve-1 验收后、improve-2 实施前。当前只记录目标、顺序和边界，具体方案后续讨论；未实施，不是实施契约。

## 目标与由来

页面首次打开、刷新或断线重连时，恢复的数据与随后收到的事件能够正确衔接：不漏更新，旧快照不覆盖新状态，持续流式输出不阻碍恢复。覆盖聊天、run、todo 等页面数据的具体范围，后续逐项确认。

来源是 [improve-1 方案审核](https://opncd.ai/share/0zpXXx6O)：全局事件序号随文字输出不断推进，要求读取快照前后全局序号不变可能耗尽重试。只改用审批版本号，又不能证明整份页面快照与全局续传位置一致。

## 已确认安排

- improve-1 先建立审批独立恢复的完整保证，不以完成本项为前置；审批恢复不能依赖整个后端停止产生消息。
- 本项接在 improve-1 后、improve-2 前，不延期到 improve-4 后。后续工具状态和子代理只读展示应建立在可靠的页面恢复机制上。
- 不预先决定统一投影、各域版本、文本 offset 或数据库事务方案；“一致性”目标不等于所有数据必须在同一事务中读取。
- 与 improve-4 分工：本项处理页面数据与实时事件的衔接；第四轮处理 Stop、服务退出、失主记录及冷恢复，不接管本项职责。
- 既有最终结果提取与文件工具增强仍按原安排推进，见 [独立前置待办](../prerequisite-follow-ups.md)。不改变 improve-2～4 编号。
