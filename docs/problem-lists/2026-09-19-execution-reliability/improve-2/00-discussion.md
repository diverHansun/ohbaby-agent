## 用户要求写入文档的超时处理表

| 工具类型 | 超时后怎么处理 |
|---|---|
| 我们启动的 Bash／本地子进程 | 自动请求退出；短暂宽限后强杀所属进程组，继续确认退出和收尾 |
| 网络／MCP 请求 | 取消本地请求，协议支持时发送远端取消；不声称远端副作用已撤销 |
| 进程内读写、扩展工具 | 传递取消信号；未结束的冲突操作继续保留限制，不能为了停止它而杀掉整个 serve |
| 子代理 | 中断该次执行并向下传播取消；整棵任务树的停止覆盖仍由第四轮核验 |

## 范围与保留边界

- 第一轮的真实身份、根会话审批聚合、独立 pending、取消撤销及审批恢复继续有效；整页快照与事件续传一致性由 improve-1.1 验收；TUI 保持 in-process，Web 使用 serve。
- 子代理面板、主代理忙时的后台结果交付、有限等待接口归第三轮；整树 Stop、跨进程/重启恢复归第四轮。
- 不要求正文流中断片刻就重新显示 Thinking；不新增闲置计时器、自动重试工具、自动后台化命令或审批自动到期。
- 无法停止的进程内操作继续受资源保护；2026-09-22 后续确认补充异常准入出口：清理异常实际挡住新调用时，该新调用返回普通工具错误，不伪造旧操作已停、不自动跳过保护。
- 后台 Bash 的显式派遣模式保持原有语义，不借超时修复改成持有整段作业的全局写锁；02 解释其边界。
- 本轮文档不声称前置轮次已实施；后续轮次已有独立规划时，以总路线为准。
- 2026-09-21 的并发决定修订了此前“完全保留既有读写限制”的边界；02/04 与独立前置 C 已统一更新职责、行为和验收要求；实现前仍需核对前置的实际代码与验收证据。
