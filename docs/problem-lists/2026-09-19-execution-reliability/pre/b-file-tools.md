# B. 独立文件工具增强

> 整项可靠性改造前置。2026-09-24 按用户要求独立记录。Read/Grep 主要行为与输出预算、Edit/Write 完整修改及独立预算原则、Read/Edit 严格 UTF-8 规则已确认；显式 path/include 组合按用户授权采用 rg 原生行为。其他编码边界、具体修改容量和内部资源契约仍需补齐，未实施。

## 已核实的现状

`tools/utils/text-files.ts` 的 `MAX_TEXT_FILE_BYTES = 1_000_000` 限制**整文件**，不是单页或内部读取块。先 stat 检查，再整文件 readFile，然后 read 工具才按行切片。输出另经截断，分页元数据可能与实际可见内容不一致。

| 工具 | 现状 | 已确认方向 |
|---|---|---|
| read | 原文件超限拒绝；行切片后可能再截断 | 大文件按需读取；超长单行可续读；分页不漏内容 |
| grep | 跳过超限文件，元数据记录 skippedLargeFiles | 大文本可搜索；扫描、输出预算分开；区分无匹配/部分结果/失败 |
| edit | 全文读入、匹配、生成 diff、写回 | 独立资源预算；完整内容校验；保留可靠写回和并发保护 |
| write | 覆盖旧文件先全文读取，创建新文件没有同样大小门槛 | 区分写入和差异预览预算；新建/覆盖行为一致且可解释 |

按 Read/Grep → Edit/Write 分批讨论和验收。四个工具各按自身职责设置资源边界，不再受同一个整文件大小常量约束。已确认规则见下文；尚需补齐的事项集中列在“实施前剩余事项”。

## 2026-09-24 已确认：可靠范围读取与超长单行续读

用户确认：“让现有 Read 的范围读取可靠，不需要文件索引服务、跨请求持有文件句柄或分页期间长期占锁，超长单行也能在 Read 内分段读完纳入 b”。

- Read 支持大文本分次读取；单次读取和输出有资源边界，不能因整文件超过现有 1 MB 门槛就拒绝小范围读取。输出预算见下文；扫描开销与取消规则仍需细化，不直接取消所有保护。
- 续读位置对应实际交付的内容。不能先按请求行数计算下一页，再截掉正文，让调用方跳过未展示的部分。
- 超长单行纳入 Read 的完整续读能力：一页放不下时明确展示片段，并允许下次从同一行未展示的位置继续，不能只截尾后跳到下一行。
- 每次调用独立完成并释放本次资源；不建设文件索引服务，不跨请求持有文件句柄，不在两次分页调用之间长期占锁。共享文件保护仍按 C 的职责划分。

对应的待实施验收要求：

| 场景 | 必须验证 |
|---|---|
| 超过现有 1 MB 门槛的文本读取小范围 | 能返回请求范围内的受限内容，避免先把整文件载入内存 |
| 请求行数尚未用完，输出先达到预算 | 续读从实际未展示的位置开始；不能按截断前的行数跳页 |
| 单行跨越多页 | 在文件未变化的前提下，按返回位置连续读取可覆盖完整行内容，没有遗漏或重复；所有分段仍属于原行 |
| 中文、emoji 或 CRLF 位于分块边界 | 分块不造成乱码、字符遗漏或虚增行号；BOM 与末尾无换行按明确的文本规则处理 |
| 一页结束或调用取消 | 本次操作实际结束后释放其句柄等资源；后续请求不依赖上次仍存活的句柄或锁 |

这些是规划要求，尚未实施或运行验收。具体编码规则仍待细化。分页间文件变化、续读接口、输出预算和总行数按下文已确认规则处理。

## 2026-09-24 已确认：文件变化后拒绝旧位置续读

用户确认：“可以利用文件身份、大小和高精度修改时间检测变化，避免为了校验每页而读取全文计算哈希，检测到文件变化，就拒绝使用旧位置续读，明确提示重新读取。”

- 续读时检查文件身份、大小和高精度修改时间等版本信息，不为每页校验读取全文计算哈希。字段表示应保留实际精度，不能转成低精度时间后声称仍是高精度比较。
- 检测到变化时，拒绝按旧位置交付下一页，明确说明“文件已变化，请重新读取”。不能把新版本的内容悄悄接到旧页后面，也不自动从头重读，由调用方决定新的读取请求。
- 末尾追加也属于文件变化，本轮不增加允许追加后继续的特殊模式。文件删除或不可读时返回相应错误，不能用旧版本信息假装续读成功。
- 该机制是基于文件元数据的变化检测，不是严格快照保证；不因此引入全文副本、跨页锁或后台版本服务。单次读取期间的检测时点和文件替换竞态，在接口与读取流程细化时补齐。

待实施验收覆盖：文件未变化时可续读；同大小修改且高精度时间变化时拒绝旧位置；同路径替换文件时检测身份变化；追加、截短后拒绝旧位置；拒绝时明确提示且不自动重读。另须验证每页校验不触发全文哈希或全文读取。上述均为计划要求，尚未执行。

## 2026-09-24 已确认：保留按行定位，增加无状态 cursor

用户确认：“保留现有 `offset + limit`，增加一个可选的 `cursor` 续读参数。确认首次按行定位，后续用无状态标记续读，这是 b 方案小幅度的职责扩展。”

- 保留 `file_path`、`offset` 和 `limit` 的按行读取入口，`offset` 仍表示从 1 开始的行号，不改为字节偏移。增加可选 `cursor`，由 Read 生成，调用方原样传回。
- cursor 携带续读所需的文件版本、下一段字节位置及行号信息，能从长行中间继续。服务端不保存分页会话；每次重新打开文件、检查版本、定位读取并释放资源，不为续读重复从文件开头扫描已读内容。
- `cursor` 与显式 `offset` 互斥，冲突时明确返回参数错误。每页 `limit` 的计数方式、标记编码和结果字段细节，在预算与协议细化时确定。
- cursor 只是续读信息，不是授权凭据。每次仍走现有路径解析和权限检查；校验标记格式、位置及其与目标文件的对应关系，错误标记不能静默回退为从头读取。
- 返回给模型的工具输出应包含可原样使用的续读标记和提示，不能只放在模型看不到的 UI 元数据中。标记对应实际展示内容的末尾；没有后续内容时不再给出可续读标记。

调用形式：

```json
{"file_path":"report.txt","offset":1,"limit":100}
```

需要继续时：

```json
{"file_path":"report.txt","cursor":"上次返回的续读标记"}
```

待实施验收覆盖：原按行调用仍可使用；整行和长行片段均能按 cursor 连续读取；释放上一请求所有资源后仍可续读；cursor 与 offset 冲突、无效标记、目标文件不符时明确报错；续读请求重新检查权限和版本；模型实际收到的正文、续读位置与提示一致。此节只确定 Read 的小幅职责扩展，不建设通用游标服务。

## 2026-09-24 已确认：默认 2,000 行，完整输出最多 50 KiB

用户纠正：“目前 8000 tokens 作为上限的方案已经去除了”，并确认“默认 2,000 行，完整输出上限 50 KiB”。此决定是 B 的当前方案，不再将 8,000 tokens 作为本方案的预算或叠加限制。

- `limit` 未提供时默认 2,000 行；保留现有按行参数范围。首次按行读取和 cursor 续读使用同一输出预算。
- 完整的 Read 工具 `output` 按 UTF-8 编码最多 50 KiB，即 51,200 字节。预算包含内容、行号、片段说明、续读标记及提示，不只计算原文件片段。
- 行数或字节预算先达到哪个，就结束本页。超长单行可以只返回其中一段，下一次用 cursor 接着读；不能为了凑完整行而突破输出上限。
- 生成页面时预留提示和 cursor 空间，正文、续读位置与提示一起确定；不在最后再次套用通用截断，让实际交付内容与续读位置失去对应关系。
- 这是行数和字节预算，不宣称等于某个模型的精确 token 数，不引入模型专属 tokenizer。

待实施验收覆盖：默认行数生效；较小的显式 limit 生效；普通按行请求和 cursor 请求的完整 output 均不超过 51,200 个 UTF-8 字节；中文/emoji 按字节正确计量且不切坏字符；达到边界时仍有完整可用的续读标记。还须覆盖超过旧截断字符门槛、但仍在新字节预算内的输出，验证旧限制没有继续截断本页。以上不是已通过的验收记录。

## 2026-09-24 已确认：总行数未知时省略

用户确认：“只有确实知道总行数时才返回，未知时省略，不能拿‘已扫描行数’冒充总行数。”

- 精确总行数不是每次 Read 的必返信息。为满足本页范围、判断是否仍有内容而读取必要数据；不为统计总行数额外扫描到文件末尾。

### 2026-09-24 显式 path/include 的行为补查

OpenCode `core/src/ripgrep.ts`、DeepSeek `tool-fs-search/src/grep.ts` 都仅在调用方提供 include 时添加 `--glob`。本机 rg 15.1.0 的帮助说明该参数优先于忽略规则；用临时目录中的 `.gitignore`、普通文件、隐藏目录、忽略文件和忽略目录做了定向检查，完成后临时目录已清理：

- 默认目录搜索遵循忽略规则；显式 `include=**/*.ts` 映射为 `--glob=**/*.ts` 时，会把可遍历目录中原本忽略的匹配文件纳入搜索。被排除目录是否会被重新遍历还取决于 glob 对目录的匹配，不能概括为任意 include 都能访问所有被忽略目录。
- 显式 `--glob=**/*` 在该夹具中同时重新纳入了被忽略文件和目录。因此，ohbaby 旧实现中的 `include ?? "**/*"` 不能原样变成默认 rg 参数，否则破坏已确认的默认忽略范围。
- 显式指定被忽略文件或被忽略目录作为 path 时，该夹具内目标可搜索；子目录内部的规则仍需按最终协议验证。rg 对显式文件还会忽略不匹配的 glob：指定 `.ts` 文件并加 `--glob=*.js`，仍然搜索该文件。
- 自动遍历时追加 `.git` 排除 glob 生效，但显式指定 `.git` 内单个文件仍会被 rg 搜索。默认遍历排除与显式目标的处理不可混为一谈，需要在接口约定中写清。
