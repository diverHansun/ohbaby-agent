# improve-4.1 目标与职责

> 2026-09-29。范围及子会话命名、slash 反馈方向已获用户确认；具体方案见 02，整体规划仍待审查。代码事实见 [01](01-problem-analysis-and-current-state.md)，已确认要求见 [00](00-discussion.md)。

## Goal

完成 execution-reliability 的本轮体验与可靠性收尾：正常会话切换不误报恢复，工具行减少冗余装饰，会话名称表达实际任务，slash command 的过程、结果和失败各有合适位置，完成或关闭后的临时状态能够清理干净。

## Duties

| ID  | 职责                                     | 应达到的结果                                                                                    | 涉及边界                                                         |
| --- | ---------------------------------------- | ----------------------------------------------------------------------------------------------- | ---------------------------------------------------------------- |
| G1  | 修复会话进入、视图初始化和同步反馈       | 健康切换不因进入动作本身制造版本冲突；首次读取与初始化顺序正确；正常加载与真正恢复区分          | agent 视图 owner / server 会话绑定 / SDK sync / Web              |
| G2  | 去除 Bash 工具行的感叹号图标             | 用户截图中的额外警告符号不再出现；错误正文、耗时、展开详情和可访问名称仍准确                    | Web 工具行展示；其他工具的同类装饰暂不扩大处理范围               |
| G3  | 优化主会话命名的素材和标题专用提示词     | 标题依据实际用户意图；首次 skill 调用不能被整份技能说明、目录信息挤掉命名素材；命名不阻塞主任务 | 命令展开前的用户输入 → 提交/队列 → 标题辅助请求 → 标题写回       |
| G4  | 梳理并统一子代理的命名语义               | 明确实例名、每次委派摘要和连续子会话标题的关系；名称与真实子代理身份一致                        | subagent 实例元数据 / 委派工具参数 / 子会话投影与 Web            |
| G5  | 清理 slash command 的重复和遗留状态卡    | 成功的空回执不污染聊天；保留有用结果和准确失败反馈；关闭、切换、重连后不复活或串会话            | command 事件 → server 路由 → Web invocation 关联、面板与临时状态 |
| G6  | 为收尾建立针对真实风险的验收             | 同时检查切换中间过程、请求素材、反馈归属、关闭后的状态、跨会话迟到事件；不能仅观察最终正常页面  | 单元 / 集成 / 编译客户端 E2E / 独立审查                          |
| G7  | 简化子会话阅读入口                       | 移除子会话向下箭头 / Jump to latest 按钮；保留滚动、阅读位置和分页                              | Web SubagentView / ConversationStream 的实际接线                 |
| G8  | 清理工具详情的缺失阶段提示并保持已有事实 | 缺少执行阶段数据时直接显示已有输入/输出；已有 execution 不能在历史或独立结果展示中丢失          | Web 工具卡 / SDK投影 / 持久历史读取                              |

G3 与 G4 不是“主子会话都新增同一种命名请求”的既定方案。当前只有主会话单独发辅助命名请求，子代理名称来自正常委派的参数；详见 01。

## Non-Duties 与保留约束

- 不改既有主/子执行 system-prompt assembler、层次顺序、上下文组装、工具菜单稳定规则及 prompt cache 策略。标题专用 system prompt 单独研究，不混入执行 prompt。
- 不因本轮展示调整改变 Stop、queued / retained、Steer 的执行语义、权限审批或资源保护。
- 不为消除 Recovering 提示跳过执行安全检查、忽略视图版本不一致或把普通 GET 变成持久恢复入口。
- 不把“清理卡片”解释为删除聊天消息、工具结果、后端命令事件、审计事实或权限交互。
- 不提前新增子代理标题 LLM 请求、命名模型设置页、后台命名任务平台或通用命令状态管理框架。
- 不以改名为由批量重命名既有历史会话；历史策略若有变化需另行明确。
- 保持默认 TUI in-process 和 Web serve 形态；不借此改为统一 daemon。
- 用户已授权方案审查后实施、测试和本地分批提交；先经指定 Pi 和子代理复核，再建 improve-4.1 分支。未授权 merge 或 push。

## 已发现但需要验证后定范围的事项

| 项目                                  | 当前证据                                      | 处理原则                                               |
| ------------------------------------- | --------------------------------------------- | ------------------------------------------------------ |
| 快照逐 Run 点查询成本                 | Pi 指出代码路径；没有本轮实测延迟结论         | 先量查询数量和耗时，不把循环直接认定为性能回归         |
| AI 标题与人工改名的窄竞态             | 写回为先读再更新，已有保护但不是原子 CAS      | 先用可控交错验证，再决定是否需要最小原子保护           |
| 标题 200 token / 5 秒与特定模型的适配 | 用户明确将输出预算放宽至约 200 tokens         | 标题请求局部调整；独立提示词无工具说明，以真实样本验证 |
| 命令重连丢终态、迟到结果串会话        | 静态路由链路与 reducer 证据，未完成服务端 E2E | 纳入后续确定性集成场景，不宣称已全部复现               |

## 已确认的产品选择

1. 保持现有命名请求数量，优化命名输入与标题提示词；子代理不增加独立标题 LLM 请求。
2. 主聊天任务行显示每次要做的事，子会话保持同一名称与身份。
3. skill 的重复运行/成功卡移除；查询命令保留可关闭结果窗口；失败在输入附近或原操作面板反馈，关闭、切换与重连后不留旧卡。
4. Bash 感叹号去除，slash 触发后的残留状态清干净。
5. 移除子会话中的向下箭头按钮；旧工具详情重复显示阶段缺失提示的问题纳入本轮，缺失时安静展示已有信息，不能伪造阶段/耗时或忽略真实读取丢失。

普通慢加载按 02 的内容区推荐默认值实现，header 保持准确任务/连接状态；用户已授权方案审查后实施。不得因此推断用户要求隐藏真实恢复失败。

6. 主会话标题输出预算为 200 tokens；命名 system prompt 独立设计，不含工具组装或工具 description。
