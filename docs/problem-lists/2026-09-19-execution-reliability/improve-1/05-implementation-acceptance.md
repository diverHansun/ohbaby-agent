## 5.2 已落地行为与修正

审批以真实 run/call/source 标识独立登记。manager 的 pending、终态缓存和健康状态独立于 UI；主/子执行使用实际 runId 和原始调用 signal。adapter 根据可信父链冻结 root 与祖先，删除或关系失效时撤销对应请求。always 只写真实来源 session 的规则；Full Access 影响后续准入，不回答既有 pending。

审批投影采用同步关键提交和独立 root revision。REST/RPC/SSE 传递 epoch/root/bindingGeneration；同 root 的页面共享待批视图，页面断连不撤销后台请求。Web、TUI 使用独立基线及连续增量，聊天历史或模型查询不再作为审批就绪条件。四次累计查询、超时、退避、缓冲上限、重连及失效范围均有确定性测试。

本轮检查中修复的真实问题包括：祖先异步读取期间删除的登记竞态；共享子会话实例的 contextScopeId/description 来源标签；全局 unavailable 的旧 generation 污染；Web 失败订阅者影响健康订阅者；SSE 失败退避期间迟到选择结果恢复 ready；Remote 迟到 RPC 绑定回滚及重复 recovery；本地 SDK RPC 错误序列化订阅回调/AbortSignal；TUI 迟到应答回调污染新请求；批量撤销期间重入 always 放行另一请求。各项 RED/GREEN 记录见 evidence，而非仅凭代码审查结论。
