# 00 讨论记录与已确认决策

> 来源：2026-09-19 本任务中的用户讨论。结构化摘要；以下用户原话保留关键约束。规划不实施产品代码。

## 已确认决策

| ID | 决策 |
|---|---|
| D1 | 同一 serve、同一授权范围、同一根主会话的多个 Web 页面均可处理审批；首个有效回答生效，其他页面同步 |
| D2 | TUI 保持 in-process；不自动 attach daemon，不新增跨 runtime 审批共享。独立 runtime 的同会话并发执行仍受数据库 claim 约束 |
| D3 | 根主会话汇总自身及所有后代子代理的审批，标明来源；业务身份始终是真实子会话/工具调用，不能改写成主会话 |
| D4 | 后续子会话按树状关系只读展示运行状态及输入输出；用户不能直接发 prompt；审批回根主会话。本轮只铺身份和路由基础 |
| D5 | 页面关闭、刷新、断网、切换项目都不取消任务；运行后端仍存活且调用仍有效时，保留审批。取消/失败/到期后的调用撤销请求，迟到批准不能重启调用 |
| D6 | 所有已经产生的待审批请求独立可回答，不强制先后顺序。UI 排序不是后端执行资格；不新增全部批准 |
| D7 | 始终允许只记到实际发起请求的会话，按规则匹配，不传播到父会话、兄弟或项目；不改变现有运行时内存保存方式 |
| D8 | 拒绝只结束当前工具请求；其他待审批保留，不等于停止代理 |
| D9 | 审批卡片移除 Cancel run；停止操作与审批分开。主会话 Stop 目标覆盖该树活动任务，中断保留历史和实例；全覆盖核验归第四轮 |
| D10 | 本轮先理清后端，配套最小客户端接线；不提前制作子代理面板、不重写调度、不承诺服务重启后原审批续接 |
| D11 | 每轮参考 kimi-code、opencode、pi、claude-code、codex、deepseek-harness；注明实际代码和适用边界。正式文档完成后用子代理检查一致性、可靠性与验收 |

## 用户确认摘录

- “页面A和页面B都可以处理任意一处回答即可；另一处同步显示，推进即可”
- “tui不连daemon，是in-process设计”
- “审批需要在主会话页面” / “这个子代理的运行状态和主会话的主代理一样可见，本批先不做，但为这一措施做铺垫”
- “前端页面关闭、刷新、断网或切换项目，都不等于取消任务”
- “确认让所有已经产生的待审批请求独立可回答，不强制按先后顺序”
- “审批集中展示，授权仍只作用于实际发起请求的那个会话”
- “从审批卡片中移除‘Cancel run’，确认！”
