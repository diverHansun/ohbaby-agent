# 00 讨论记录与已确认决策

> 来源：2026-09-19 本任务中的用户讨论。结构化摘要；以下用户原话保留关键约束。规划不实施产品代码。

## 已确认决策

| ID | 决策 |
|---|---|
| D1 | 同一 serve、同一授权范围、同一根主会话的多个 Web 页面均可处理审批；首个有效回答生效，其他页面同步 |
| D2 | TUI 保持 in-process；不自动 attach daemon，不新增跨 runtime 审批共享。独立 runtime 的同会话并发执行仍受数据库 claim 约束 |
| D3 | 根主会话汇总自身及所有后代子代理的审批，标明来源；业务身份始终是真实子会话/工具调用，不能改写成主会话 |
| D4 | 后续子会话按树状关系只读展示运行状态及输入输出；用户不能直接发 prompt；审批回根主会话。本轮只铺身份和路由基础 |
| D5 | 页面关闭、刷新、断网、切换项目都不取消任务；运行后端仍存活且调用仍有效时，保留审批。取消/失败/到期后的调用撤销请求，迟到批准不能重启调用 |
| D6 | 所有已经产生的待审批请求独立可回答，不强制先后顺序。UI 排序不是后端执行资格；不新增全部批准 |
| D7 | 始终允许只记到实际发起请求的会话，按规则匹配，不传播到父会话、兄弟或项目；不改变现有运行时内存保存方式 |
| D8 | 拒绝只结束当前工具请求；其他待审批保留，不等于停止代理 |
| D9 | 审批卡片移除 Cancel run；停止操作与审批分开。主会话 Stop 目标覆盖该树活动任务，中断保留历史和实例；全覆盖核验归第四轮 |
| D10 | 本轮先理清后端，配套最小客户端接线；不提前制作子代理面板、不重写调度、不承诺服务重启后原审批续接 |
| D11 | 每轮参考 kimi-code、opencode、pi、claude-code、codex、deepseek-harness；注明实际代码和适用边界。正式文档完成后用子代理检查一致性、可靠性与验收 |
| D12 | 2026-09-21 确认：本轮建立审批独立恢复的完整保证；页面全量快照与事件续传一致性另列 improve-1.1，第一轮验收后、第二轮实施前处理，具体方案后续讨论 |
| D13 | 2026-09-21 确认：借鉴 Codex 显式携带执行上下文的做法，runId 从执行源头传递；scheduler 只携带，不查库、不猜测、不用 callId 兜底。sessionId 标识会话，runId 标识该会话的一轮执行，callId 标识一次工具调用，三者不可互相替代 |
| D14 | 2026-09-21 确认：S1＋S2 设置内部验收点，核心与生命周期验证通过后再进入 S3；使用真实 scheduler、permission manager 和主/子执行生命周期配合可控 provider。接口、多页面及恢复验证在 S3/S4 完成，整轮统一验收交付，中间状态不单独发布或合入 main |
| D15 | 2026-09-21 确认并修正 E2E 方式：关键浏览器场景由 agent 自行启动真实 serve、连接测试模型并操作浏览器验证，不以固定脚本测试代替。固定的是验收目标，操作根据实际页面进行；单元/集成/contract 自动测试保留，agent 浏览器验收不能写成无人参与的 CI 自动门 |
| D16 | 审批卡片保持 KISS：简短标明实际来源/授权作用的代理对象即可，主代理请求标明主代理。不增加长篇授权说明、联动放行数量或二次确认弹窗；保留必要的请求内容，D7 的实际来源会话授权范围不变 |
| D17 | 同一工具调用的多次审批复用现有标题和原因，说明本次实际授权内容，不新增“第几步／共几步”等展示；每次 ask 使用独立 permissionId，不按 callId 合并，不因上一次回答而直接复用决议。D7 的合法规则匹配仍适用 |
| D18 | 保留现有禁止把子会话当主会话使用的限制。前端只有根主会话页面可审批；子会话对应的子代理界面没有审批渠道，不展示审批卡片或按钮。后端同样校验根主会话范围，不能仅靠前端隐藏；第三轮只读子页沿用此约束 |
| D19 | 普通展示或连接错误不撤销审批；单请求错误只影响该请求；只有严重一致性故障才停止受影响范围的审批处理。附带运行状态查询失败不能触发全局撤销；调用本身取消、失败或到期仍按 D5 撤销 |
| D20 | 审批按钮以当前会话的审批同步完成为可操作条件，不单凭连接恢复启用；审批自身已同步时，聊天历史或其他状态读取失败不应继续锁住审批按钮。同步状态须绑定当前连接及会话范围，后端仍逐次校验请求有效性和回答范围 |

## 用户确认摘录

- “页面A和页面B都可以处理任意一处回答即可；另一处同步显示，推进即可”
- “tui不连daemon，是in-process设计”
- “审批需要在主会话页面” / “这个子代理的运行状态和主会话的主代理一样可见，本批先不做，但为这一措施做铺垫”
- “前端页面关闭、刷新、断网或切换项目，都不等于取消任务”
- “确认让所有已经产生的待审批请求独立可回答，不强制按先后顺序”
- “审批集中展示，授权仍只作用于实际发起请求的那个会话”
- “从审批卡片中移除‘Cancel run’，确认！”
