# 语音输入：非功能约束

## 1. Quality Priorities

按重要程度排：

| 顺序 | 质量 | 为什么排这里 |
|---|---|---|
| 1 | 隐私与密钥安全 | 音频是用户的声音，key 能花用户的钱。出事不可逆 |
| 2 | 不丢输入 | 用户说了一分钟，结果什么都没插进去，比慢更伤人。包括开头几百毫秒不能丢、出错时要说清楚 |
| 3 | 延迟 | 停止到出字要快（G1），但网络慢时宁可多等几秒，也不要丢字 |
| 4 | 资源占用 | 一次录音只占一条连接和一个 `AudioContext`，用完就放 |

冲突时的取舍：延迟和不丢输入冲突时（比如结束超时要设多长），选不丢输入，所以结束超时给到 15 秒，而不是 3 秒。

## 2. Operational Constraints

### 2.1 时限与上限

| 项 | 值 | 谁执行 | 到了怎么办 |
|---|---|---|---|
| 单次录音上限 | 5 分钟（**待用户确认**） | 浏览器 | 自动停止，按正常停止处理（照常识别、插入），提示"已达到 5 分钟上限" |
| daemon 音频上限 | 6 分钟的数据量（16000 × 2 × 360 = 11,520,000 字节） | daemon | 回 `too_long`。这是兜底，正常情况下浏览器先停 |
| 等 `start` 消息 | 连接建立后 10 秒 | daemon | 回 `bad_request` 并关闭 |
| 开始超时 | 收到 `start` 到识别任务就绪，10 秒 | daemon | 回 `timeout` |
| 结束超时 | 收到 `finish` 到拿到最终文字，15 秒 | daemon | 回 `timeout` |
| 浏览器等结果 | 发出 `finish` 后 20 秒没有回复 | 浏览器 | 按"连接断开"处理。比 daemon 的结束超时多 5 秒，正常情况下先收到 daemon 的 `timeout` |
| 待发队列 | 不单独设上限 | 浏览器 | 队列只在收到 `started` 之前增长，而开始超时（10 秒，约 100 块、320KB）一定先到，到时整次录音按 `timeout` 结束。不丢块，符合"不丢输入" |

### 2.2 延迟预算（云端，10 秒以内的语音）

G1 要求停止后 2 秒内出字：

| 环节 | 预计 |
|---|---|
| 浏览器发出最后一块音频和 `finish` | ≤ 100ms |
| 浏览器 → daemon（本机） | 可以忽略 |
| daemon → 百炼，百炼处理完剩下的音频并回 `task-finished` | 大部分时间在这里。音频是边说边传的，停止时百炼手里只剩最后不到一秒没处理 |
| daemon → 浏览器，插入输入框 | 可以忽略 |

这个预算在实施时用真实 key 测一次（见 [test §4](test.md)）。达不到时先查网络，不要为此打开中间结果。

### 2.3 运行环境

| 约束 | 说明 |
|---|---|
| 安全上下文 | 浏览器只在 `localhost` 或 HTTPS 下允许用麦克风。用局域网 HTTP 地址打开 Web 时，麦克风按钮显示为不可用，悬停说明原因（见 [前端 04 §5](frontend/04-interaction-and-states.md)） |
| 只限本机 | 语音连接和终端一样，daemon 绑定非回环地址时拒绝 |
| 浏览器 | 需要 AudioWorklet 和 WebSocket，当前主流桌面和手机浏览器都支持 |
| 采样率 | `AudioContext` 用浏览器默认采样率，由 AudioWorklet 自己降到 16kHz。不在创建 `AudioContext` 时指定 16000，因为部分浏览器不允许把麦克风接到采样率不同的 `AudioContext` 上 |
| 并发 | 不限制。每个标签页各自一条连接，互不影响。同一个标签页同一时间只有一次录音 |

### 2.4 隐私与安全

| 约束 | 做法 |
|---|---|
| key 不出 daemon | 设置接口只返回 `apiKeyConfigured`；语音协议里没有 key；key 只出现在 daemon 发给百炼的请求头里 |
| 日志里没有敏感内容 | daemon 日志不记 key、音频、识别出的文字 |
| 音频不落盘 | 浏览器和 daemon 都只在内存里处理 |
| 用户知道音频去了哪 | Audio 设置页写明"录音会发送到阿里云百炼识别"（见 [前端 03 §4](frontend/03-ui-layout-and-style.md)） |
| 录音状态看得见 | 录音时输入框里有波形，麦克风按钮变成停止按钮；浏览器自己的录音标记也会亮。结束、取消、出错后必须释放麦克风，标记要熄灭 |

## 3. Reliability & Observability

### 3.1 失败处理

| 原则 | 做法 |
|---|---|
| 失败要说出来 | 每一种失败都对应前端 04 的一条提示，不静默丢弃 |
| 清理不能漏 | 浏览器：任何结束路径（完成、取消、出错、切会话、组件卸载）都要停麦克风轨道、关 `AudioContext`、关连接。daemon：任何结束路径都要取消识别任务、清计时器 |
| 不自动重试 | 识别失败时不重试，因为音频已经发出去了，重试要重新录。由用户决定要不要再说一次 |
| 出错时保住草稿 | 识别失败不碰输入框，用户已经打的字原样保留 |

### 3.2 日志

daemon 每次录音结束时记一条日志，用现有的日志工具：

| 字段 | 用途 |
|---|---|
| 结果 | `completed`、`cancelled` 或错误码 |
| 音频时长 | 由字节数算出 |
| 停止到出字的耗时 | 收到 `finish` 到发出 `completed`，用来核对 G1 |
| 百炼的 `task_id` | 出问题时可以拿去阿里云控制台查 |
| 百炼的错误码和错误信息 | 仅失败时 |

不记文字、不记音频、不记 key。

## 4. Trade-offs & Deferred Requirements

| 项 | 现在怎么做 | 暂缓什么 | 什么时候再考虑 |
|---|---|---|---|
| 中间结果 | 不显示 | 边说边出字 | 用户反馈"不知道它听没听到"时。协议可以加一个可选事件 |
| 断线续传 | 不做，断了就报错 | 网络抖动时自动重连百炼 | 有用户在网络差的环境长时间录音时 |
| 用量统计 | 不记 | 显示本月识别时长 | 有人关心费用时 |
| 并发上限 | 不限 | 限制同时录音的数量 | 出现滥用时（本机工具，可能性很低） |
| 本地识别性能 | 不涉及 | 本地模型的内存、速度、首次下载 | App 阶段，按 [00 §3.1](00-discussion.md) 在旧机器上实测 |
