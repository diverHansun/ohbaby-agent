# 0. 讨论与已确认要点

> 本文记录 2026-11-23 讨论后确认的结论，被否决的方案不再展开。

## 0.1 用户提出的问题

ohbaby 的 LLM 输出渲染需要优化，重点是 Markdown：字体大小不整齐，表格和内嵌 Mermaid 也应该好好显示。做法要借鉴 `code-cli/` 下的 opencode、deepseek-harness（下文简称 dsh）和 ZCode。

表格、流式和 Mermaid 各自单独成议题，本议题只管排版。

## 0.2 已确认的决定

| 编号 | 决定 |
|---|---|
| C1 | 拆成四个独立议题：统一排版、表格、流式 Markdown、Mermaid |
| C2 | 只做 Web，不做 TUI |
| C3 | 正文 14px，行高 1.7 |
| C4 | 标题 H1 20px、H2 17px、H3 15px、H4 到 H6 14px，字重都是 600 |
| C5 | 行内代码约 13px（0.93em），代码块 13px，行高 1.6，表格 13px |
| C6 | 段落下间距 12px，标题上间距 20 到 24px，下间距 8px |
| C7 | 中文加粗要修。先看 dsh 和 ZCode 怎么修：dsh 自己写了一条窄规则，所以我们也自己修，照搬它的判断规则，不加新依赖 |
| C8 | 02 不写关键改动清单 |

## 0.3 明确不做

- 不换 `marked`，不引入 Streamdown，不写自己的解析器。
- 不做用户可调字号。
- 不动会话导出页的样式，它是另一套有意设计的衬线风格。
