# 4. 测试与验收

## 4.1 测试策略

- **中文加粗**是解析逻辑，写单测，放在 `apps/ohbaby-web/src/ui/shared/MarkdownBlock.unit.test.tsx`。
- **排版**是视觉结果，项目没有 CSS 断言的约定，也不为此新建。用 `.claude/launch.json` 里的 `ohbaby-web-mock` 启动，在浏览器里读计算后的样式并截图。mock 数据里没有合适的长文时，给 `apps/ohbaby-web/src/dev/mock-scenarios.ts` 加一条覆盖所有元素的样例。

## 4.2 排版验收

| 编号 | 场景 | 通过标准 |
|---|---|---|
| S-1 | 聊天里的 H1 到 H6 | 字号 20/17/15/14/14/14px，字重 600 |
| S-2 | 聊天正文、行内代码、代码块 | 14px，约 13px，13px；代码块行高 1.6 |
| S-3 | 文件预览和命令弹窗显示同一段 Markdown | 在基准字号相同时，标题、代码、列表的字号和间距与聊天一致。命令结果里的代码块用代码字体，错误通知的纯文本 `pre` 样式不变 |
| S-4 | 压缩摘要（基准 13px）里的标题 | H1 19px、H2 16px，不会比周围大太多 |
| S-5 | 助手消息后面紧跟工具行，以及最后一段和操作按钮之间 | 间距和改动前一致，没有贴在一起 |
| S-6 | 用户气泡以段落、列表、代码块、引用结尾 | 底部内边距一致，没有多余空白 |
| S-7 | 点编辑用户消息 | 编辑框和气泡的文字字号一致，不跳动 |
| S-8 | 触屏宽度和 `hover: none` | 消息操作按钮和代码块 Copy 都常显，Copy 不盖住代码 |

每个场景在桌面宽度和 375px 手机宽度下各看一遍。ohbaby 现在没有深色模式，不用测。

## 4.4 对抗性审查要点

- 搬完规则后，`.ohb-message-body p` 还在吗？删掉它会影响非 Markdown 的段落。
- `.ohb-message-actions` 的触屏规则还在 `messages.css` 吗？`.ohb-streaming-text` 还有 `overflow-wrap` 吗？
- 行内代码的 `0.93em` 有没有漏到代码块里？`.ohb-code-block pre code` 必须保持 `font-size: inherit`。
- 表格里的行内代码会连乘缩小，确认看起来仍然清楚。
- 兜底返回的 token 是否仍经过 `DOMPurify`？内容里带 HTML 时不能绕过清洗。
