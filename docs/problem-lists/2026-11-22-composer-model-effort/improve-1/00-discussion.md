# 讨论记录与已确认要点

> 2026-11-22 与用户讨论定稿。正式方案见 01–04。

## 1. 背景与动机

现在 Web 输入框底部右侧并排放着两个控件：模型按钮（`ModelMenu`）和思考强度下拉框（`ReasoningControl`，原生 `<select>` 加脑袋图标）。用户提供了 ohbaby、Cursor、Codex、Claude Code 四张截图做对比，后三者都把模型和思考强度做成了一个入口。

合并有两个好处：

- 少一个控件，底部一行更清爽，也符合"无卡片、无胶囊、自然图标、少即是多"的 Web 风格。
- 腾出宽度。姊妹议题 [语音输入](../../2026-11-22-voice-input/README.md) 要在这一行放波形，宽度很紧。

## 2. 已确认：目标与范围

| 决策项 | 结论 |
|---|---|
| 入口 | 模型和思考强度合并成一个按钮 |
| 按钮文字 | 模型名在前，思考强度在后，强度用次要的灰色 |
| 菜单结构 | 模型按提供方分组列出；下面一行"Effort ›"，点进去是当前模型支持的强度列表。这是 Claude Code、deepseek-harness 的做法 |
| 不用的样式 | 不用滑块（ZCode），不用分段按钮（kimi-code），也不做胶囊 |
| 端 | 只做 Web，不做 TUI |
| 后端 | 不改。每个模型的设置条目已经带了思考能力（`UiSettingsModel.reasoning`），前端直接用 |
