## 4.2 后端验收（S 组）

| 编号 | 场景 | 通过标准 |
|---|---|---|
| S-1 | `sessionManager.rename` | 标题变了，`updatedAt` 没变，发了 `SessionEvent.Updated` |
| S-2 | `renameSession` 改主会话 | 返回新标题；`getSnapshot` 里这个会话的标题是新的；发出 `session.updated`；会话索引被通知失效；全局列表里这个会话的排序和 `updatedAt` 不变 |
| S-3 | 标题带首尾空白和换行 | 存成去掉首尾空白、连续空白合成一个空格的结果 |
| S-4 | 标题归一后为空 / 超过 120 字符 | 报错，标题不变 |
| S-5 | side chat / 子代理会话 / 别的工作区的会话 | 分别报错，标题不变 |
| S-6 | 新标题和旧标题相同 | 直接返回，不写库，不发事件 |
| S-7 | 先改名，LLM 自动标题后到 | 标题保持手动改的名字 |
| S-8 | 用 `createPersistentUiStateStore`（线上用的那个），会话运行中改名，等这一轮结束 | 快照和会话表里都是新标题 |
| S-9 | 空会话先改名再发第一条消息 | 不生成临时标题，也不调用 LLM 起名，标题保持手动改的名字 |
| S-10 | `PATCH /v1/sessions/:id/title` | 成功返回 `{ ok: true, session }`；`title` 缺失或不是字符串返回 400；未鉴权 401；未注册客户端 409 |
| S-11 | `normalizeSessionTitle` | `"  a \n b  "` 得到 `"a b"`；全空白得到 `""` |
| S-12 | 第一条消息已被接收（显示临时标题）、还没开始跑时改名 | 之后不再被临时标题或 LLM 标题覆盖 |
| S-13 | 命令记录 | `renameSession` 被记录，记录里没有标题文字 |

## 4.3 Web 验收（W 组）

| 编号 | 场景 | 通过标准 |
|---|---|---|
| W-1 | 菜单 | 第一级在 Pin 下面有 `Rename`，按 `r` 也能触发 |
| W-2 | 点 Rename | 菜单关闭，这一行变成输入框，有焦点，文字全选；行尾按钮不显示 |
| W-3 | 双击标题 | 进入同样的编辑状态 |
| W-4 | 输入新名字按 Enter | 输入框消失，行上立刻显示新名字，焦点回到这一行；发出一次改名请求，带会话目录 |
| W-5 | 按 Esc | 恢复原名，不发请求，焦点回到这一行 |
| W-6 | 点输入框外面 | 保存，同 W-4，但焦点留在点到的地方 |
| W-7 | 清空或没改动后保存 | 恢复原名，不发请求 |
| W-8 | 输入法组字时按 Enter | 不保存，继续编辑 |
| W-9 | 请求失败 | 行恢复原名，出现错误通知 |
| W-10 | 请求进行中，全局列表刷新或实例索引同步带回了旧名字 | 行上仍是新名字；请求结束后 `pendingRenames` 清空 |
| W-11 | 改名的是当前打开的会话 | 顶栏标题跟着变 |
| W-12 | 编辑时侧边栏变为禁用 | 退出编辑，不发请求 |
| W-13 | 编辑时列表重排，输入框所在的行被挪动 | 仍在编辑，焦点回到输入框，不发请求 |
| W-14 | 编辑时窗口失去焦点 | 仍在编辑，不发请求 |
| W-15 | 编辑时在输入框里按 Shift+F10 或右键 | 不打开会话菜单 |

## 4.5 对抗性审查要点

- 有没有哪条写标题的路径还在刷新 `updatedAt`？
- 改名后内存里的 `UiSession` 和会话表是否一致？有没有发 `session.updated`、让索引失效？
- 自动标题的两道检查在手动改名后是否仍然生效？
- 输入框里的 Enter、Esc 有没有冒泡到行或抽屉的按键处理？
- 列表重排、切换窗口时会不会把半截名字存下来？
- `pendingRenames` 在失败路径上有没有清掉？
- 中文输入法组字时的 Enter 有没有被当成保存？
- 乐观更新失败时是否恢复了原来的整行，而不只是标题？
