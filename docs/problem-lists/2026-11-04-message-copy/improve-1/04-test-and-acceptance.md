# 4. 测试与验收

> 对应 [02](02-optimization-plan-and-change-scope.md) 的 Stage 1、2。测试与源码放在同一目录，命名 `*.unit.test.ts(x)`，用 `pnpm test:unit` 运行。

## 4.1 测试范围

| 类型 | 覆盖什么 |
|---|---|
| unit | 剪贴板降级、取正文、复制按钮挂在哪条消息上、代码块按钮 |
| 浏览器走查 | 悬停与焦点显示、触屏常显、复制结果、局域网 `http://` 访问时的降级（mock 场景和真实 daemon 各走一遍） |

## 4.2 关键场景

| ID | 场景 | 类型 | 验证点 | Stage |
|---|---|---|---|---|
| T1 | `writeClipboard` 在 `navigator.clipboard` 可用时 | unit | 调用 `writeText`，返回 `true` | 1 |
| T2 | `navigator.clipboard` 不存在或 `writeText` 抛错 | unit | 退回 `execCommand("copy")`；也失败时返回 `false`；按钮显示“Copy failed”，不显示勾号 | 1 |
| T3 | 取正文 | unit | 只含 `text` 片段；`reasoning`、`tool-call`、`tool-result` 都不出现；多个文本片段之间有空行 | 1 |
| T4 | 一轮有多条 assistant 消息（过渡文字、工具调用、最终答案） | unit | 只有最终答案那条有复制按钮；复制内容只有最终答案的正文 | 1 |
| T5 | 没有最终答案的轮次（失败、以工具调用结束、仍在流式输出） | unit | 不显示回答的复制按钮 | 1 |
| T6 | 用户消息与 steer 消息 | unit + 浏览器 | 都有复制按钮，复制原文；悬停或 Tab 聚焦时出现；触屏模拟下常显 | 1 |
| T7 | 代码块 | unit | 经过真实的 DOMPurify 后每个 `<pre>` 里仍有按钮；点击后复制内容等于代码文本，不含按钮文字；代码里的 `<`、`&` 等字符原样复制 | 2 |
| T8 | 局域网访问（可选） | 浏览器 | daemon 监听非 `localhost` 地址时，用 `http://` 打开，消息复制和代码块复制仍然可用；无法复制时显示失败提示。不具备这个环境时跳过，降级逻辑已由 T2 覆盖 | 2 |

## 4.3 回归清单

| ID | 项 | 验证点 |
|---|---|---|
| T9 | 折叠与展开 | 执行过程的折叠、思考过程的展开不受操作栏影响 |
| T10 | 布局 | 用户气泡、助手正文、右侧面板打开时，操作栏不遮挡内容、不引起横向滚动 |
| T11 | 设置页与命令结果 | About 的复制按钮行为不变；命令结果弹窗里的代码块出现复制按钮，可以正常复制 |

## 4.4 发布门

| 项 | 标准 | 如何验证 |
|---|---|---|
| 类型与格式 | 通过 | `pnpm typecheck`、`pnpm lint`、`pnpm format:check` |
| 单元测试 | T1 至 T7 通过 | `pnpm test:unit` |
| 浏览器走查 | T6、T9 至 T11 通过，附截图；T8 有条件时走查 | 内置浏览器 |
| 文档 | Stage 2 第 3 步的文档已同步 | 评审 |

## 4.5 对抗性审查要点

| 攻击面 | 防御 | 残余风险 |
|---|---|---|
| 复制内容和界面显示的不一致 | 复制内容取自消息数据，答案判定复用 `projectRunProcesses` | 无 |
| 恶意 Markdown 伪造复制按钮 | 委托处理只认渲染器写入的 `data-code-copy` 按钮，复制的是同一 `<pre>` 里 `<code>` 的文本，不执行任何脚本 | 模型输出里如果自己写了带 `data-code-copy` 的按钮，点了也只会复制旁边代码块的文本，无害 |
| 复制失败被当成成功 | `writeClipboard` 返回 `false` 时显示失败提示 | 无 |
