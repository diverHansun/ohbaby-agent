# 讨论记录与已确认要点

> 2026-11-04 与用户讨论定稿。第 2 至 4 节是讨论中确认的结论；第 5 节是写规划时根据代码勘测补充的决定，随整套文档提交用户审查。推理过程见 [01](01-problem-analysis-and-current-state.md)，实施方案见 [02](02-optimization-plan-and-change-scope.md)。

## 1. 背景与动机

现在 Web 上的消息和代码块都没有复制按钮。用户只能手动拖选，会把思考过程、工具卡片和时间标签一起选进去，代码块也要自己对准边界去选。

## 2. 已确认：目标与范围

| 决策项 | 结论 |
|---|---|
| 复制什么 | 只复制正文，不复制思考过程，也不复制工具执行过程 |
| 用户消息 | 复制这条消息的原文 |
| AI 回答 | 只复制这一轮的最终答案，也就是 Web 折叠后显示的那条回答。中间穿插的过渡文字（例如“让我先看看”）算执行过程，不复制 |
| 代码块 | 每个代码块单独一个复制按钮 |
| 端 | 只做 Web。TUI 不新增复制命令 |

## 3. 已确认：边界

| 项 | 处理 |
|---|---|
| TUI 复制 | 不做 |
| 复制表格为 Markdown、复制整个会话 | 不做。整个会话可以用现有的 `/export` |
| 选中文字后“引用到输入框” | 不做 |

## 4. 已确认：与关联议题的关系

| 议题 | 关系 |
|---|---|
| [撤销重发](../../2026-11-04-conversation-undo/improve-1/00-discussion.md) | 本议题搭的消息操作栏要给它的 Edit 按钮留位置 |
| 会话 fork | 本议题搭的消息操作栏要给 fork 按钮留位置 |

## 5. 规划中补充的决定

| 编号 | 决定 | 一句话理由 |
|---|---|---|
| P1 | 剪贴板写入函数返回成功或失败，失败时不显示“已复制”；`navigator.clipboard` 不可用时退回 `execCommand("copy")` | 局域网用 `http://` 访问 daemon 时不是安全上下文，`navigator.clipboard` 不可用；静默失败会让用户以为复制成功了 |
| P2 | 取正文用一个新函数，只取 `text` 片段；现有的 `visibleMessageText` 不动 | 现有函数会把思考过程一起拼进去，而且别处在用 |
| P3 | “最终答案”沿用 `run-process.ts` 现有的判定，不另写一套规则 | 复制按钮出现在哪条消息上，要和折叠后显示的那条一致 |
| P4 | 新建一个消息操作栏组件，本议题只放复制按钮，留出位置给撤销重发的 Edit 和 fork 按钮 | 三个议题的按钮都在同一处，先搭好容器，后面的议题只往里加按钮 |
| P5 | 桌面端悬停或获得焦点时显示操作栏，触屏设备常显 | 常显会让长对话很杂；触屏没有悬停 |
| P6 | 代码块按钮由 Markdown 渲染器输出，容器上统一处理点击 | Markdown 现在渲染成一段 HTML 字符串，不是 React 组件；DOMPurify 默认会保留 `button` 和 `data-*` 属性 |

## 6. 用户确认记录

- 2026-11-04：用户确认“只复制正文（不复制思考过程和执行过程）”，并确认 AI 回答只复制最终答案。
- 2026-11-04：用户纠正“TUI 不用增加 `/copy`，仅 Web 端需要复制的相关 UI 组件”，并要求复制与撤销重发分成两个议题。
- 第 5 节 P1 至 P6 随整套文档提交用户审查。
