# 讨论记录与已确认要点

> 2026-10-25 与用户讨论定稿。D3、D6、D7 的细化说明是文档审查时根据代码补充的，没有改变原决定的方向，用户已于同日确认。推理过程见 [01](01-problem-analysis-and-current-state.md)，实施方案见 [02](02-optimization-plan-and-change-scope.md)。

## 1. 背景与动机

Web 侧栏可以归档会话，但归档以后就再也找不到了：没有归档列表，不能恢复，也不能真正删掉。第一版归档设计（`docs/ohbaby-web/session-archive/README.md`）当时明确把这些留给以后。

用户提出：

- 在 Settings 里新增 Archived，参考 Cursor 和 Codex。
- 归档的会话可以恢复到原工作区；原工作区不在了，就恢复到无工作区。
- 可以永久删除归档的会话。删除只能“先归档、再删除”。

勘测时发现现有归档有漏洞：运行中的会话被归档后任务不停；永久删除的代码存在但从没被调用，而且会留下孤儿数据。这些一起在本轮修补。

## 2. 已确认：决定

| 编号 | 决定 |
|---|---|
| D1 | 接口：`GET /v1/sessions?status=archived` 列出已归档会话（复用现有列表和分页）；`POST /v1/sessions/:id/unarchive` 恢复；`DELETE /v1/sessions/:id` 永久删除 |
| D2 | 只能删除已归档的会话，由服务端强制；对未归档的会话调用删除返回 409 |
| D3 | 运行中的会话不能归档，服务端返回 409；Web 上运行中或等待审批的会话禁用归档按钮。“运行中”包括：会话自己有活跃运行或排队的消息，以及它的任何后代会话（子代理）有活跃运行 |
| D4 | 恢复时，原工作区文件夹还在就回到原工作区；文件夹不在了就清空归属，会话进入 Recents |
| D5 | 恢复到原工作区时，如果该工作区在侧栏里被隐藏了，重新显示它 |
| D6 | 恢复时如果会话的下一轮目录已经不存在：会话留在原工作区时，下一轮切到工作区目录；会话进入 Recents 时，下一轮切到默认目录（都写入 pending working directory）。这是“移出工作区保留原运行目录”规则的唯一例外 |
| D7 | 不加 `archived_at` 列，归档时间用 `updated_at`。归档后的会话不会再运行，`updated_at` 基本不变（少数延迟写入可能更新它，只影响列表排序，可以接受）；恢复时更新 `updated_at`，会话出现在侧栏顶部 |
| D8 | 永久删除在一个事务里删掉会话和它的所有后代会话（递归），以及 `goal_record`、`subagent_execution`、`subagent_instance` 里没有外键级联的相关行；提交后尽力清理快照 git 引用，失败只记日志 |
| D9 | Archived 是 Settings 的第 6 个分区：平铺列表，按归档时间倒序；每行显示标题、工作区名（没有就显示 `No workspace`）和归档时间，带 Restore、Delete 两个按钮；删除前用 `ConfirmDialog` 二次确认；分页沿用现有机制 |
| D10 | 本轮不做：一键删除全部、归档列表搜索、归档后的 Undo 提示、TUI 里的恢复入口、子会话单独归档、自动归档 |

## 3. 已确认：范围与分工

| 项 | 结论 |
|---|---|
| 分批 | 同一轮内 4 个 Stage：后端核心（归档修补、恢复、删除）；服务端与 SDK 接口；Web Archived 分区；文档同步 |
| 分工 | Stage 1、2 由用户实施；Stage 3、4 由 agent 实施 |
| 前置 | 在 workspace-naming 之后实施，字段使用新名字 |
| 关键改动清单 | 写入 02 |
| 文档落点 | `docs/problem-lists/2026-10-25-archived-sessions/improve-1/` |

## 4. 已确认：边界

| 项 | 处理 |
|---|---|
| 归档仍然只针对根会话 | 子代理会话随根会话一起被隐藏，不单独归档 |
| 归档本身的交互 | 不变：侧栏菜单和悬停按钮，不弹确认，乐观移除 |
| 软删除 | 不做；删除就是物理删除 |
| 设计文档中“5 个分区”（D12）、“不做归档列表浏览界面”、“没有 Undo 因为没有取消归档接口” | 本议题修改，Stage 4 同步 |

## 5. 参考项目

deepseek-harness 拒绝归档运行中的会话、恢复后回到原位置；ZCode 在设置里做归档管理，并在数据层强制“只能删除已归档的会话”；kimi-code 删除时会清掉会话目录和索引；opencode 删除会话时递归删除子会话。详见 [03](03-reference-projects.md)。
