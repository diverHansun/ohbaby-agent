# improve-2 讨论结论与已确认边界

> 2026-10-12 定稿。来源为整体规划 [plan/00](../plan/00-discussion.md) 与 [plan/02](../plan/02-optimization-plan-and-change-scope.md) 的既有确认；本批不新增待定项，也不恢复已撤回的 raw 旧结论。
> 业务代码尚未改变。

## 1. 本批要做什么

让工具结果第一次进入模型请求后保持稳定，普通请求与摘要请求看到同一份投影。复用现有结构，不新造一套输出处理管线。

## 2. 已确认结论

| 决策项 | 结论 |
| --- | --- |
| 投影来源 | 复用 `ToolPart` 正文／metadata、现有 serializer 与 `tool-metadata-projection`，普通请求和摘要共用同一函数 |
| 入模定型 | 首次入模即定型；已发送的正文、引用与说明在重试、后续 step、重启后保持一致 |
| 分页与引用 | Read 续读游标必须与实际交付内容一致；已有可读引用继续使用 |
| 错误与状态 | completed／error／aborted 的正文、退出码、callId 配对不丢；错误正文不重复拼接；错误携带的结构化 metadata 不能丢 |
| 子代理 | 只把实际回传主代理的正文或文件引用计入主上下文；子代理内部历史不计入 |
| 捕获完整性 | 原始捕获不完整时如实标注；不宣称未捕获的全文可恢复 |

## 3. 本批不做

| 项 | 说明 |
| --- | --- |
| 统一工具额度 | 不新增单条 8K／批次 20K 额度或共同上限分配算法 |
| 预览生命周期 | 不新增预览的创建／发送／冻结状态 |
| 通用落盘服务 | 不要求所有工具新建落盘服务；沿用已有结果文件与 Read 分页 |
| 数据库召回工具 | 不新建历史召回系统 |
| 压力改写旧结果 | 不保留“按当前压力继续缩短已发送结果”的常规路径；prune 移除归第 3 批，mask 整体清理归第 5 批 |
| Shell／Bash 改造 | 独立议题，与本批无依赖 |

## 4. 与整体规划的关系

触发线、摘要额度、重试与原子切换等语义仍以 [plan/02](../plan/02-optimization-plan-and-change-scope.md) 为准：自动摘要按 `currentTokens / contextLimit` 触发，不含输出预留帽；带 50% 帽的 `usageRatio` 只服务 mask 触发，随第 5 批 mask 删除。本批不碰触发与预算逻辑，只保证工具结果投影稳定。
