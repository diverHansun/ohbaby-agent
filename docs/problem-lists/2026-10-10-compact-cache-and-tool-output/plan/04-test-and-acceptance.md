# 测试、阶段验收与审查

> 依据[00](./00-discussion.md)、[01](./01-problem-analysis-and-current-state.md)、[02](./02-optimization-plan-and-change-scope.md)。本文件是待实施的验收目标，不是已经通过的结果。
> 使用仓库已有 Vitest、集成测试和协议契约测试；不新建测试框架，不以覆盖率数字代替风险验证。

## 1. 验收分层

- 单元／契约测试：预算、实际投影、边界、字段与缓存策略，用可控样本验证精确行为。
- 数据库／调度集成：持久化恢复、原子切换、Stop 竞态、新输入、重复 compact、跨入口重试。
- 有界真实 API 探测：在独立 ohbaby 服务和会话验证实际字段、usage／cache、摘要质量与多次续接。

每批完成自己的必要检查，**包括本批相关的真实 API 探测**；实网测试是每批的收尾动作，不是某一批（尤其不是第五批）的交付物。第五批做的是全部入口的贯通回归，不补交前三批本该证明的正确性。局部测试通过不等于新流程已可以单独发布。

## 4. 真实 API 与上下文探测

用户已经授权在阶段验收启动 agent 自己的 ohbaby 服务进程，用真实 api-key 发真实请求，凭据和可用模型从仓库`tests/models-4-tests.md`读取。使用独立测试数据目录、端口和会话，不停止或占用用户现有服务。key 在进程内加载，不放进参数、日志、文档、fixture 或审查提示。

**每批做完就走这一步，不攒到第五批。**按阶段选择代表性模型与协议，控制样本数量，不默认遍历全部模型或灌满 1M 窗口：

1. improve-1 核对真实 usage、reasoning 子项、模型能力与实际输出参数；记录提供商未返回哪些明细。
2. improve-2 在服务中读分页、错误和子代理结果，恢复会话后核对正文与引用，无额外通用裁剪。
3. improve-3 核对普通请求与摘要的实际协议字段、用量和 cache 身份，并验证完整输入所需的触发与容量保护；不能只看上层 options。
4. improve-4 用包含已知约束、文件引用、错误、未完成任务与后续修正的历史做多次压缩，检查可继续性与旧信息继承；同时核对压缩提示、压前／压后占用与刷新时机；最终失败终止、跨入口不另开额度和用户继续的边界用可控故障验证，不靠反复真实调用制造失败。
5. improve-5 串起压前普通请求、摘要、压后首个普通请求及后续正常请求；验证手动／自动、失败停止、用户继续与无重复工具副作用。

缓存证据分别报告客户端共享前缀是否稳定、服务端是否真实返回 cache read／create、输入规模和时间。服务端 miss 要区分 TTL、未写入边界、端点不支持与客户端改写；不能要求固定命中率。压后首请求建立新缓存，不要求旧历史完整命中，也不额外发请求预热。

记录真实模型、协议、窗口能力来源、实际输入／输出／reasoning／cache 用量、结束原因、是否应用摘要、压前压后占用估算及估算来源。未知用量保持未知。64K／200K／1M 离线边界通过不能写成这些规模都做过实网测试。

## 5. 摘要内容验收

使用可核对的事实清单做样本：早期限制仍有效；用户明确修正被继承；助手建议未变成批准；已完成、未验证和未知结果正确区分；真实命令／文件／任务 ID 保留；后台任务未冒称完成；不会因为摘要内容机械停止不受影响的工作。

自动检查覆盖有效正文、协议、长度、调用关系和提交范围；人工／审查样本检查语义连续性。七节模板帮助组织内容，但缺一个完全相同的标题不是再花一次请求修正的理由。语义完整性不能仅靠标题存在证明，也不新增线上摘要审核模型。

## 6. 审查、清扫与交付记录

按“已确认需求→现状问题→方案规则→实际验收”核对。用户已要求子代理与 Fable 复核：先独立找反例，主代理验证关键事实并记录取舍；模型意见不是通过证明。设计审查和实施验收分开，参考项目只支持局部选择。

第 3 批取消 prune 时即按引用链清理专属配置／事件／函数／测试及 SDK、CLI、Web 消费处；保留共用事务、旧记录读取、scope 和配对保护，迁移仍有效的失败回归。同批完成受影响的类型、契约和行为检查，不只凭文本搜索无命中宣称清理完毕。第五批再复核剩余旧机制，检查 scope、子代理和手动入口是否遗漏；对照 SWE 检查职责重复、二次预算解析、多层重试、无用状态和通用框架。

各批验收记录后续放对应 improve 目录，包含实际变更、测试、实网结果、兼容与回退限制、未解决问题。plan 不提前生成验收通过结论，也不新建文档自检报告文件。
