# Context 模块验收

> 完整用例与实网要求见[议题 04](../04-test-and-acceptance.md)。本文列 Context 负责的部分，不另设阈值或通过标准。

| 用例组 | 模块应证明什么 | 实施批次 |
| --- | --- | --- |
| A1～A5 | 实际投影计数一致、输出预留与发送同源、模式 A 接入前未读 parts 不退场，接入后的显式遗漏例外按 E7 验证、标准 usage 不重计 | 1 |
| B1～B3 | 现有工具正文／metadata 投影稳定，配对、错误与分页引用不丢，无通用二次裁剪 | 2 与 5 贯通 |
| C1～C5 | 摘要材料同源、末尾追加指令、完整容量保护、至多两次实际请求；准备到摘要发送之间不执行前置 prune，失败／提交前 Stop 不留裁剪退场；网络断流可用剩余一次机会，半成品不提交，不执行工具／不修正重发 | 3；C4 在 4、5 继续验收 |
| D1～D6 | 一份滚动摘要、合法切点、超大组与新输入、最终正文与压后容量、原子切换和恢复 | 4 |
| E1～E8 | 90%及必要提前、手动 busy／重复／Stop、失败结束当前运行、跨入口不重试、旧机制清除、压缩提示与压后占用刷新、模式 A 丢弃历史头、模式 B 收缩保留段 | 3 接入 E1 并完成 E5 的 prune 清理，4 完成 E3／E4／E6～E8，5 清理剩余机制并贯通全部 |

优先扩展已有 token-estimation、native-context、compaction-atomic、compaction-hard-crash 和 tool-metadata-projection 测试。用可控 parts 与故障注入证明不丢信息和事务语义；真实 API 证明协议实际行为与 usage，不能互相替代。

审查重点：测量和发送是否又各算一次；成功摘要读取、原文保留和退场范围是否对应，未读退场是否全部有模式 A 遗漏记录；新输入是否被旧计划误处理；失败是否从 force 再调用；是否又加入无需求依据的 token 限制或预览状态。

本 plan 不声称任何新增行为已通过。实际测试与验收证据后续写入对应 improve 目录，Context improve-7 入口只记录模块变化。
