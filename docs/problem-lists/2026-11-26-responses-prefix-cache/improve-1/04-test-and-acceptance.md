# 怎么判断改对了

1. 通过适配器截取请求，验证规范模型名和带路由前缀的模型名、相似模型名、没有基础指令、连续和尾部 system。检查每段文字只出现一次，工具调用与结果保持顺序。
2. 使用生产适配器向官方及 Magpie 的 GPT-6.2 Responses 发送流式请求，每组用全新的长合成文本。固定模型、前缀和工具设置，依次重复问题、更换短尾问题、切到新档、重复、切回旧档。每轮记录 HTTP、答案、实际档位、缓存读取量及总输入量。
3. 同档换题后，GPT-6.2 Sol 的两条主路由应能读回大部分前缀，目标超过 90%。首次切档单列，只要用户要求的档位确实发出即可。预热后再次请求及切回旧档分别记录。
4. 对 Magpie 的 Chat 和 Anthropic，以及清单中各协议的代表端点做同类检查。有些端点只上报部分用量或支持固定档位，报告里标清。百分比为缓存读取 token 除以总输入 token；Anthropic 总输入包含未缓存、写入及读取三部分。
5. 验收记录区分热请求与冷启动，保留上游拒绝、错误和缺失用量。运行适配器测试和项目测试。双模型分别复核代码、范围及实验结论。

增加一组真实工具往返。保留第一轮的原生输出，回填工具结果并追加本轮 system，要求第二轮准确复述随机生成的工具结果。逐请求保存供应商可用的缓存读取和写入计数，缺失字段留空。
