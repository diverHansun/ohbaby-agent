# 讨论记录与已确认要点

> 2026-11-04 与用户讨论定稿。第 2 至 4 节是讨论中确认的结论；第 5 节是写规划时根据代码勘测补充的决定，随整套文档提交用户审查。推理过程见 [01](01-problem-analysis-and-current-state.md)，实施方案见 [02](02-optimization-plan-and-change-scope.md)。

## 1. 背景与动机

用户想在一段对话的某个节点“分个岔”：保留到这一轮为止的上下文，换个方向继续问，又不想破坏原来的会话。现在只能新建会话从头讲一遍，或者在原会话里继续，把原来的走向搅乱。

## 2. 已确认：目标与范围

| 决策项 | 结论 |
|---|---|
| 做法 | 学 deepseek-harness（下称 dsh）：fork 是把切点之前的历史复制成一个新会话 |
| 切点 | 某一轮已结束对话的末尾，包含这一轮的完整回答 |
| 来源记录 | 在新会话的 `session.data` 里记一份最小的来源信息：来源会话、切点所在的 prompt、继承了多少条消息。不使用 `parent_id`（它是子代理专用的） |
| 侧栏 | fork 出来的会话和普通会话平级显示，不嵌套在源会话下面 |
| Web 入口 | 两处：每轮最终答案下面的 fork 按钮；会话行菜单里的 fork（从最近一轮已结束的对话 fork） |
| TUI 入口 | 新增 `/fork`，从最近一轮已结束的对话 fork |
| 标题 | 照 dsh：`原标题 (1)`、`原标题 (2)` 依次递增 |
| goal | 不带过去 |
| 新会话继承 | 工作区、运行目录、agent、模型、reasoning 设置 |
| 不带过去 | 排队的 prompt、正在运行的那一轮、子代理实例 |

## 3. 已确认：边界

| 项 | 处理 |
|---|---|
| 从一轮对话的中间 fork | 不做。只能在一轮结束之后的位置 fork |
| 从用户消息 fork（“在这条之前分岔”） | 不做。需要改某条消息时用撤销重发 |
| 在侧栏里显示 fork 关系、从 fork 跳回源会话 | 不做 |
| 复制源会话的文件或快照 | 不做。fork 共用同一个工作目录，文件本来就是同一份 |

## 4. 已确认：与关联议题的关系

| 议题 | 关系 |
|---|---|
| [消息复制](../../2026-11-04-message-copy/README.md) | 回答下面的 fork 按钮挂在它的消息操作栏上 |
| [撤销重发](../../2026-11-04-conversation-undo/README.md) | 复制时跳过已撤销的消息 |
| side chat | 会复用本议题的复制逻辑；side chat 会话不能再 fork |
| 会话存储区 | fork 出来的会话有自己的存储区，不复制源会话的文件 |

## 5. 规划中补充的决定

勘测时发现、讨论阶段没有覆盖到的细节，理由见 01 和 02。原则是只复制“不复制就会出错”的东西，不为将来多复制。

| 编号 | 决定 | 一句话理由 |
|---|---|---|
| P1 | 接口以目标 prompt 定位：`POST /v1/sessions/:sessionId/fork`，请求体 `{ promptId? }`。给了 `promptId` 就切在这个 prompt 那一轮的末尾；不给就用最近一个已结束的 prompt | Web 回答按钮知道自己属于哪个 prompt；会话行菜单和 TUI 不需要知道 |
| P2 | 复制五张表的行：`message`、`part`、`prompt_submission`（含并入别的轮次的 `steered` prompt）、`current_run_input`、`run_ledger`。别的都不复制 | 少了 prompt 记录，Web 无法按轮分组；少了当前轮输入记录，steer 和子代理结果会从模型上下文里消失；后者有外键指向 run 记录 |
| P3 | 所有被复制的行都换新 ID。ID 改写用一条规则：复制行的文本列和 JSON 字符串，凡是值**完全等于**某个旧 ID 的，一律换成新 ID。消息 ID 按源会话的顺序编号生成，两个客户端请求 ID 直接生成新值 | 不用逐个字段列举（`parentId`、`runId`、`runtimeInput`、提醒锚点、`steer_receipt` 等），以后新增字段也不会漏 |
| P4 | 工具调用的 `callId` 不改 | 模型原生状态（加密推理等）回放时要求 `callId` 对得上 |
| P5 | 切点之后才发生的压缩，会在切点之前的片段上留下“已压缩”标记，而摘要消息不在复制范围里。复制时清掉这类标记：片段的压缩时间晚于最后一条被复制消息的时间，就去掉 | 否则这些片段在新会话里既不显示原文，也没有摘要替代，模型上下文会缺一块 |
| P6 | 复制在一个同步数据库事务里用 SQL 完成，照 `archive.ts`、`workspace-move.ts` 的写法；新会话的统计按复制结果直接写好 | 现有的会话创建接口设不了模型、reasoning、统计，消息存储也没有批量写入；一个事务保证要么全有要么全无 |
| P7 | 源会话不需要空闲。fork 只读源会话已提交的行，不占用它的执行闸门 | fork 不修改源会话；dsh 也允许在源会话运行时 fork 最近一轮已结束的对话 |
| P8 | 源会话必须存在、是根会话、未归档。错误码与状态码复用现有的 `SESSION_NOT_FOUND`（404）、`SESSION_NOT_ROOT`、`SESSION_ARCHIVED`（409）；没有可用的切点时返回新错误码 `FORK_TARGET_INVALID`（400） | 与撤销重发议题、现有会话接口保持一致 |
| P9 | 标题在服务端算：去掉源标题末尾的 ` (n)`，在现有会话里找同名的最大序号，加一 | 一次请求就能拿到最终标题，不用像 dsh 那样再发一次改名请求 |
| P10 | fork 成功后，Web 和 TUI 都切换到新会话 | 用户点 fork 就是想在新会话里继续 |
| P11 | 新会话里，源会话子代理的卡片仍然显示结果文字，但打不开子代理对话；模型读源会话的子代理大结果文件时要弹确认（子代理结果搬迁议题之后，文件在源会话的存储区里）。本轮接受，不处理 | 子代理实例和执行记录不复制，处理它们要牵出子代理的整套生命周期，不值得 |
| P12 | 源会话里如果有当时没被处理的 steer，新会话里会同样显示为“未处理”的提示卡片。本轮接受 | 这是复制历史的如实结果；为它单独过滤反而让两个会话看起来不一致 |
| P13 | `session.data.fork` 要加进会话类型的读写转换里 | 现有的 `encodeData` 只写回四个固定字段，不加的话会话下次更新时来源信息就丢了 |
