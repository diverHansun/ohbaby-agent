# Skills 后端实施与验收

本轮后端在本地分支 `codex/skills-ux` 实施，起点为 `f20eaada`。Web 和 TUI 的界面由前端实施。

## 前端接入

- 发送 `/review 原话` 后，会话消息投影返回一个可见 text part。它的 `text` 已是完整的 `/review 原话`，`metadata.skillMarker.name` 是标准技能名。只输入 `/review` 时也会返回这个 part。
- 提交记录的 `text`、排队编辑、未消费 steer 的预览及 rewind 返回的 `restoredText` 都使用可编辑的 slash 原文。旧版已展开的提交记录通过原有技能名和请求字段回填，旧消息历史继续沿用原来的显示方式。
- 编辑时仍引用原技能，而该技能已不可用，服务端返回 HTTP 400 和 `REWIND_SKILL_UNAVAILABLE`。SDK 直接显示服务端提供的技能名和错误说明，原消息保留。排队期间技能消失则按普通文本发送。
- 默认权限下，内置 `skill` 和 `skill_resource` 直接读取已注册技能。普通 `read` 可读取当前上下文已加载技能的目录。显式 deny、外部写入和脚本执行沿用各自的审批规则。

## 后端验证

| 场景 | 已验证的行为 |
|---|---|
| 首发、消息投影和模型请求 | 持久化消息含两个 part。模型收到技能正文、两个换行及原话。UI 事件和历史投影只显示用户输入。 |
| 多行与空原话 | 混合大小写的名字会规范化。命令后直接换行、正文内的缩进和空行可保留。空原话也能显示技能名。 |
| 编辑与重发 | SQLite 环境可将普通消息编辑为多行技能调用。原技能失效时先返回错误，历史保持可读。 |
| 排队与 steer | 内存和 SQLite 的并发编辑测试都写入最新输入。重复 steer 返回原回执。排队时被删的技能会降级成普通文字。 |
| 默认权限 | 用真实工具、文件和沙箱验证了首次调用、同一 run 中追加技能、重开后端、fork 后读取外部参考文件。另一个上下文的历史无法授予当前上下文读取权限。 |
| 写入失败与重试 | 第二个 part 写入失败时会清理整条消息。重新提交同样的输入可以成功。重放同一个 `clientRequestId` 按既有幂等协议返回原回执。 |

集成测试使用可控的模型响应检查请求和工具结果。Web 徽标、气泡样式、TUI 上色及真实模型的界面联调由前端阶段验收。

## 双模型审核

Pi 使用 Magpie 目录中的 `auto/gemini-4-neon` 和 `auto/claude-opus-5-5`，推理级别均为 `high`。

- Claude 建议普通消息沿用原有 steer 路径。后端已把预展开收窄到带校验标记的 slash 输入，并为同一轮读取、持久化恢复和上下文隔离补上测试。
- Gemini 指出，默认放行技能读取后，需要保留按具体资源工具和已解析文件路径设置的显式拒绝。工具规则和路径规则均已补上匹配及回归测试。未提供输入账本时，信任恢复也与模型历史使用相同的筛选条件。

审核意见修正后，全仓类型检查通过。`pnpm test` 运行了 775 个测试文件，9,210 项测试通过，28 项跳过。
