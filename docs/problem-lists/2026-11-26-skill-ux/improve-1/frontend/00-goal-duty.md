# 00 目标与职责

> Web 前端设计，精简模式。后端方案见 [../02](../02-optimization-plan-and-change-scope.md)，已确认的决定见 [../00](../00-discussion.md)。

## 1. 产品目标

用户用 slash 调用 skill 时，在输入框、消息气泡和编辑框里看到的都是"技能标记加自己写的话"，不再看到几百行 SKILL.md。一眼能认出哪条消息用了哪个 skill；长的用户消息默认收起，不再占满一屏；编辑带 skill 的消息时，skill 还在，改完重发照样生效。用户自己写的话在气泡里原样显示，不按 markdown 渲染；发送和停止按钮改成亮蓝色，一眼能找到。

做到以下几点算成功：

- 用 slash 发出的消息，气泡里没有 SKILL.md 的任何内容。
- 输入框、气泡、编辑框里的技能标记长得一样，用户不用学第二遍。
- 超过一屏的用户消息不再把对话挤走，需要时一下就能展开。
- 气泡里的用户文字和用户输入的一模一样，复制出来也一样。

## 2. 用户角色

使用阶段：

| 阶段 | 说明 |
|---|---|
| 日常用户 | 已经装了 skill，常用 slash 调用 |
| 刚装 skill 的用户 | 从 `/skills` 弹窗或命令面板里找到 skill，第一次调用 |
| 回看历史的用户 | 翻旧会话、用搜索跳到某条消息，或编辑之前发过的消息 |

权限身份：单一身份，本地工具，没有权限区分。

## 3. 核心任务

- T-01 用 slash 选一个 skill，写上要说的话，发出去
- T-02 在对话里认出哪条消息调用了哪个 skill
- T-03 展开和收起很长的用户消息
- T-04 编辑一条带 skill 的消息，改完重发

## 4. 职责边界

前端负责：

- 按消息字段显示技能标记，按渲染高度决定折叠。
- 用户消息按纯文字显示，保留换行和空格。
- 在确定是 skill 的入口（命令面板选中、`/skills` 弹窗 Insert、编辑框打开、编辑重发失败回填、草稿恢复）生成技能标记，并把标记当成一个整体删除。
- 提交时把标记和原话拼成 `/技能名 原话` 交给后端。
- 发送 slash 时沿用现有流程，先在前端用命令目录解析，找不到就直接报错。
- 显示后端返回的错误，比如编辑重发时 skill 已被删除。

前端不负责：

- 判断一条消息最终有没有触发 skill。这由后端的展开函数决定：排队期间 skill 被删，后端按普通文字发送，前端照字段显示。
- 拿命令目录去猜手敲或粘贴进来的 `/xxx` 要不要显示成标记。
- 读取或拼接 SKILL.md。前端永远拿不到正文。
- 判断消息是不是 slash 调用。只认后端写的 `skillMarker`，不解析文字开头。
- 记住折叠状态。

## 5. Non-goals

本期不做：

- 一条消息里放多个技能标记。
- 标记上的 ×、删除后的恢复按钮。删了就重新敲 `/` 选回来。
- 富文本输入框，以及斜体等更多样式（另开议题）。
- 助手回复的折叠。
- 记住每条消息的折叠状态。
- 折叠和展开的动画。
- 排队列表、失败行和排队编辑里的技能标记。这几处仍是纯文字 `/技能名 原话`。
- 发送、停止按钮（主输入框、编辑框、旁聊页）以外，其他用 `--accent` 的按钮和元素改色。
- 用户气泡里的裸网址自动变链接。改成原样显示后不再有这个效果，是已知的退化。
- 发送后正式消息到达前的占位行（`PromptProjectionRow`）显示技能标记。这一下会先看到纯文字 `/技能名 原话`，接受这个闪动。
- 旧会话迁移。旧消息照常显示全文，只是长了会被折叠。
