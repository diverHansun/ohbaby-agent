# 04 交互与状态

> 页面结构以 [03](03-ui-layout-and-style.md) 的四张线框为准，用例见 [01](01-use-cases-and-user-flows.md)，组件契约见 [05](05-components.md)。代码路径省略前缀 `apps/ohbaby-web/src/`。

## 1. 组件级状态

### 技能标记（`SkillToken`）

只用来显示，不能聚焦，不能点击，也不能被鼠标选中。气泡、主输入框、编辑框里都只有一种状态：

| 状态 | 视觉 | 触发 |
|---|---|---|
| 默认 | `--skill-ink` 色的魔杖图标加技能名 | 有标记时 |

发送时输入框立刻清空，标记也一起清掉；发送失败时标记和原话一起还回来（05 的 `pendingSkill`）。

### 折叠开关

| 状态 | 视觉 | 触发 |
|---|---|---|
| 收起 | `Show more` 加向下箭头，`--text-dim` 色 | 消息超过阈值，默认 |
| 展开 | `Show less` 加向上箭头 | 点开关，或搜索跳到这条消息 |
| hover | 和默认一样，没有变化 | 鼠标悬停 |
| focus-visible | 出现现有的焦点外环 | 键盘 Tab 到开关 |

切换时没有动画，高度直接变。

### 发送类按钮（主输入框的 Send、Stop，编辑框的 Send，旁聊页的 Send、Stop）

现有的状态和行为都不变，只换颜色：

| 状态 | 视觉 |
|---|---|
| 默认 | `--signal` 底（亮蓝），`--signal-contrast` 图标或文字（白色）；Stop 中间是实心白色方块 |
| hover | `--signal-hover` 底 |
| 编辑框的 Send | 上面有文字，默认就用 `--signal-hover` 底，hover 用 `--signal-strong` 底，保证白字对比度 ≥4.5:1 |
| 按下 | 和现在一样轻微缩小（只有主输入框的 Send 有） |
| 禁用 | 和现在一样：灰底、`--text-dim` 图标 |
| 发送中 | 和现在一样显示转圈，宽度不变 |

### 带标记的输入区（主输入框和编辑框共用）

| 状态 | 表现 |
|---|---|
| 没有标记 | 和现在完全一样 |
| 有标记、原话为空 | 标记在左上角，光标在标记后面；不显示占位文字 |
| 有标记、有原话 | 第一行从标记后面开始，第二行起从最左边开始 |
| 写满后内部滚动 | 标记跟着第一行一起滚动，滚到下面时看不见标记，滚回顶部时标记回来 |
| 主输入框发送后 | 和现在一样立刻清空，可以接着写下一条 |
| 编辑框发送中 | 和现在一样只读，标记和文字都保留 |

## 2. 状态矩阵

### 2.1 用户消息气泡（`MessageRow`）

| 状态 | 气泡表现 | 用户能做什么 |
|---|---|---|
| 普通消息，不长 | 按纯文字显示，换行和空格原样保留，markdown 符号不渲染 | 复制、编辑 |
| 普通消息，超过约 12 行 | 露出前 8 行左右，截断处有 `…`，最后一行是 `Show more` | 展开、复制、编辑 |
| skill 消息，有原话 | 线框 ①：开头是标记，后面接原话 | 复制、编辑 |
| skill 消息，没有原话 | 只有标记 | 复制、编辑 |
| skill 消息，很长 | 标记在第一行，其余同"超过约 12 行" | 展开、复制、编辑 |
| 刚发送、提交记录还没变成消息（占位行 `PromptProjectionRow`） | 短暂显示纯文字 `/技能名 原话`，不带标记（已知闪动） | 等待 |
| 发送中（乐观消息） | 和正式消息长得一样，也带标记 | 等待 |
| 排队期间 skill 被删，消息按普通文字发出 | 没有标记，显示纯文字 `/技能名 原话` | 复制、编辑 |
| 升级前的旧 slash 消息 | 没有标记，照常显示全文；长了会折叠 | 展开、复制、编辑 |
| `skillMarker` 和文字开头对不上 | 不显示标记，照常显示全部文字（防御性处理，正常不会出现） | 同普通消息 |
| 搜索跳到这条消息 | 自动展开，定位到这条消息 | 收起 |
| 展开后窗口变宽，不到阈值了 | 开关消失，显示全文 | — |
| 收起后窗口变窄，超过阈值了 | 出现开关，变成收起 | 展开 |
| 正在编辑 | 气泡整个换成编辑框，见 2.3 | — |
| 旁聊里的用户消息 | 原样显示和折叠规则一样；引用选中文字时开头的 `> ` 直接显示；旁聊没有 slash，不会出现标记 | 展开 |
| 子代理页面的"From parent"提示 | 继续按 markdown 渲染，折叠规则一样 | 展开 |
| 含很长的网址或路径 | 自动断行，不撑破气泡；网址不可点 | 复制 |

复制得到的永远是 `/技能名 原话`（就是消息文字本身），和折叠状态无关。

### 2.2 主输入框（`ComposerInput`）

| 状态 | 表现 | 用户能做什么 |
|---|---|---|
| 空 | 和现在一样 | 输入 |
| 没有标记时敲 `/` | 和现在一样，面板列出命令和 skill | 选择 |
| 在面板里选中 skill（回车、Tab 或点击） | 面板关闭；刚才敲的 `/xxx` 被换成标记；光标在标记后面 | 写原话 |
| 在面板里选中命令 | 和现在一样 | — |
| 有标记，原话为空 | 线框 ③，不显示占位文字；Send 可用 | 写原话、发送 |
| 有标记，在原话开头敲 `/` | 面板只列 skill；没有匹配的 skill 时面板不出现，`/` 当普通文字 | 选中一个替换原标记，或继续打字 |
| 有标记，光标在原话最前面、没选中文字，按退格 | 标记消失，原话不变，光标在最前面 | 继续编辑 |
| 同上，但正在用输入法组字，或者有选中的文字 | 按普通退格处理 | — |
| 点发送 | 和现在一样立刻清空，标记和原话都暂存起来 | 写下一条 |
| 发送成功 | 暂存的内容丢弃 | — |
| 发送失败（网络等） | 标记和原话一起还回输入框，显示错误；如果用户已经开始写下一条，按现有 `pendingText` 的规则处理 | 重试 |
| 命令目录里找不到这个 skill | 当场报错，和其他发送错误的表现一样，标记和原话还回输入框 | 删掉标记或换一个 skill 再发 |
| 运行中按回车（排队或 steer） | 和现在一样；排队列表里显示纯文字 `/技能名 原话` | — |
| 排队期间 skill 被删 | 不提示；轮到它时按普通文字发出，气泡没有标记 | — |
| 运行中，输入框里只有标记 | 按钮是 Send（排队），不是 Stop；只有标记也算有内容 | 排队发送 |
| 编辑排队中的消息 | 填进输入框的是纯文字，不生成标记 | 编辑 |
| `/skills` 弹窗点 Insert | 和现在一样替换整个草稿：只剩标记，原话为空，焦点在输入框 | 写原话 |
| 刷新后恢复带标记的草稿 | 标记加原话，不检查 skill 是否还在 | 继续 |
| 刷新后恢复升级前的旧草稿 | 纯文字 | 继续 |
| 编辑重发失败，回填 | 标记是编辑的那条消息的 skill；原话在前，原来的草稿接在后面，中间空一行；原来草稿里的标记变成纯文字 `/旧技能名` | 修改后重发 |
| 手敲或粘贴 `/code-review 原话` | 纯文字，不生成标记 | 照常发送，后端仍当 skill 处理 |
| 命令目录加载失败 | 和现在一样显示错误，面板不出现 | 继续当普通文字输入 |

### 2.3 编辑框（`UserMessageEditor`）

| 状态 | 表现 | 用户能做什么 |
|---|---|---|
| 打开带 `skillMarker` 的消息 | 线框 ④：标记加原话，提示行显示现有提示 | 修改、发送、取消 |
| 打开没有 `skillMarker` 的消息（包括旧 slash 消息） | 和现在一样，纯文字 | 同上 |
| 在原话开头敲 `/`（有没有标记都一样） | 面板只列 skill | 选中后生成或替换标记 |
| 面板打开时按 Esc | 关闭面板，编辑框保留 | 再按 Esc 取消编辑 |
| 面板打开时按回车 | 选中当前 skill，不发送 | 继续编辑 |
| 面板没打开时按 Esc | 和现在一样取消编辑 | — |
| 退格删除标记 | 规则同 2.2 | — |
| 删掉标记后发送 | 按普通消息发送 | — |
| 只有标记、没有原话 | Send 可用 | 发送 |
| 发送中 | 和现在一样只读，Send 显示转圈 | 等待 |
| 后端报 skill 不存在、改名或不允许用户调用 | 提示行换成后端给的错误文字（原样显示，没有 `Something went wrong:` 前缀），编辑框不关，历史、正在跑的 run 和排队区都不动 | 改、删标记、取消 |
| 提交被拒（截断已经发生） | 编辑框关闭，按 2.2 的"编辑重发失败，回填"处理，回填的是点发送那一刻编辑框里的标记和原话 | 在主输入框里重发 |
| 发送成功 | 编辑框关闭，新消息带着标记出现 | — |
| 命令目录加载失败 | 面板不出现，`/` 当普通文字 | 继续编辑 |

## 3. 交互规则

**选中 skill 不再直接发送。** 现在在面板里对 skill 按回车或点击，会立刻把 `/技能名` 发出去（`useSlashPalette.ts` 的 `runSlashCommand`）。改成：对 skill，回车、Tab 和点击都只是生成标记，再按一次回车才发送。命令（`/compact` 等）的行为不变。

**键盘：**

- 退格删除标记：光标在原话最前面、没有选中文字、不在输入法组字中，三条都满足才整体删除。
- 全选后删除，只删原话，标记还在；再按一次退格才删标记。
- 面板的上下键、PageUp/PageDown 和现在一样。
- 编辑框里 Esc 的顺序：先关面板，再取消编辑。主输入框的 Esc 和现在一样。
- 折叠开关是一个按钮，Tab 能到达，回车和空格都能切换。

**焦点：**

- 生成标记后，焦点留在输入框，光标在原话最前面。
- 删除标记后，光标在输入框最前面。
- `/skills` 弹窗点 Insert 后，弹窗关闭，焦点回到主输入框。
- 点 `Show more` / `Show less` 后，焦点留在开关上。收起时如果开关滚出了视口，不自动滚动。

**提交：**

- 提交给后端的文字永远是 `/技能名 原话`（原话为空时是 `/技能名`），和现在手敲的格式一样。只在调接口那一刻才拼，状态里一直分开存技能名和原话。
- 原话里的换行原样提交。
- 防重复提交沿用现有逻辑。

**无障碍：**

- 标记带 `aria-label="Skill: 技能名"`；图标本身 `aria-hidden`。
- 折叠开关带 `aria-expanded`，并用 `aria-controls` 指向消息正文。
- 标记和折叠状态都有文字表达，不只靠颜色。
