# 03 布局与样式

> 精简模式，简写。视觉遵循现有 Web 页面：token 见 `apps/ohbaby-web/src/ui/styles/tokens.css`，整体设计见 `docs/ohbaby-web/ui/`。本文只补本次新增的技能标记、用户气泡原样显示、长消息折叠、编辑框和发送类按钮的变化。代码路径省略前缀 `apps/ohbaby-web/src/`。

## 1. 设计原则

| 原则 | 截图上看什么 | 反例 |
|---|---|---|
| 技能标记是文字的一部分，不是一个控件 | 标记和原话在同一行，字号相同；没有底色、边框、阴影和圆角 | 胶囊形徽标、带灰底的小卡片 |
| 三个地方长得一样 | 主输入框、气泡、编辑框里的标记，图标、颜色、字号、间距一致 | 输入框里是胶囊，气泡里是纯文字 |
| 折叠开关安静 | 开关就是一行小字加箭头，靠左下；hover 前后截图没有差别 | 渐变遮罩加居中按钮；hover 出现底色 |
| 不改动原有气泡 | 气泡宽度、圆角、底色、操作行（复制、编辑）的位置和改动前一致 | 为了放标记把气泡加宽，或者把操作行挪进气泡 |
| 用户写什么就显示什么 | 用户气泡里的 `**`、`#`、`>`、反引号原样出现，换行和行首空格都在 | `**加粗**` 变成粗体；列表符号变成圆点；代码块套上灰底 |
| 蓝色只给"发送"和"skill" | 页面上的蓝色只出现在技能标记和发送类按钮（主输入框的 Send、Stop，编辑框的 Send，旁聊页的 Send、Stop）上；审批 Allow、弹窗主按钮仍是黑色 | 顺手把所有主按钮都改成蓝色 |

## 2. 视觉方向与来源

- 基准是现有 Web 设计：白底、中性灰、强调色少用，只有悬浮元素有阴影（`tokens.css` 开头的注释）。
- 参考 kimi-code 的做法（见 [../03](../03-reference-projects.md)）：气泡开头放技能标识，长消息用 `Show more` / `Show less` 收起。区别是我们不要徽标的底色和边框，只留图标和文字。
- 能在截图上核对的特征：
  1. 标记只有图标和技能名两样东西，颜色和正文不同，没有任何外框。
  2. 图标是 lucide 的 `WandSparkles`（魔杖加小星星），线性图标，默认描边粗细，大小和技能名的字号一致。
  3. 折叠开关的文字比正文小一号，颜色比正文浅。
  4. 编辑框沿用现有样式：白底、细边框、底部一行提示、右下角 `Cancel` 和 `Send`。
  5. 发送类按钮是亮蓝底、白色图标；Stop 中间是实心白色方块。
- Web 目前只有浅色主题，不需要做深色模式。

## 3. Design Tokens

**必须定：**

- 组件样式只引用 `tokens.css` 里的变量，不写字面量颜色。
- 技能标记的颜色用一个新的语义变量 `--skill-ink`，定义在 `tokens.css` 里，图标和技能名共用。不能直接用 `--accent`：浅色主题下它是 `#18181b`，和正文颜色一样，标记就不显眼了。
- `--skill-ink` 在气泡底色 `--user-bg` 和白底 `--bg` 上，对比度都要达到 4.5:1 以上。所以它不能引用 `--signal`：亮蓝在 `#f4f4f5` 上只有约 3.4:1。
- 发送类按钮（主输入框的 Send、Stop，编辑框的 Send，旁聊页的 Send、Stop）改用新的语义变量 `--signal`、`--signal-hover`、`--signal-contrast`（按钮上的图标和文字）。只改三条样式规则（`.ohb-send-button`、`.ohb-stop-button`、`.ohb-message-editor-send`）；旁聊页用的就是前两条，不用另改。`--accent` 的值和其他用到它的地方不动。注意 `.ohb-button-primary` 现在和 `.ohb-send-button` 写在同一条规则里，要拆开，否则弹窗主按钮也会跟着变蓝。
- Stop 按钮里的方块保持实心（`<Square fill="currentColor">`），跟着 `--signal-contrast` 变成实心白色。
- 发送类按钮禁用时仍是现在的灰色（`--bg-selected` 底、`--text-dim` 字）。
- `--signal-contrast` 在 `--signal` 上的对比度不低于 3:1（WCAG 对图标和控件的要求）。主输入框和旁聊页的 Send、Stop 是纯图标按钮，满足这一条即可。编辑框的 Send 上有文字，要达到 4.5:1：白字在亮蓝上只有约 3.7:1，所以它默认用 `--signal-hover`，hover 用 `--signal-strong`（见 [../00 F4](../00-discussion.md)）。
- 用户气泡的文字元素用 `white-space: pre-wrap` 和 `overflow-wrap: anywhere`。后者现在只挂在 `.ohb-markdown` 上，要补到新元素上，否则长网址和长路径会撑破气泡。字体、字号、行高和现在气泡里的正文一致。
- 折叠开关的文字用 `--text-muted`，字号 12px 到 13px。实现时发现 `--text-dim` 在 `--user-bg` 上对比度约 4.4:1，不到 4.5:1，所以深一档（2026-11-27 调整）。
- 编辑框的错误提示沿用现有的 `.ohb-message-editor-hint.is-error`，不新建样式。

**给方向（初值，实现时可调）：**

- `--signal` 初值亮蓝 `#3b82f6`（用户从三档里选定）；`--signal-hover` 稍深一点，比如 `#2563eb`（白字约 5.2:1）；`--signal-strong` 再深一档，比如 `#1d4ed8`，只给编辑框 Send 的 hover 用；`--signal-contrast` 是白色，在亮蓝上约 3.7:1。
- `--skill-ink` 单独取 `#2459b8`，和审批卡片里 shell 命令的颜色（`--syntax-command`）同一个蓝，和 `--signal` 同色系、更深。在 `#f4f4f5` 上的对比度约 6:1，在白底上约 6.6:1。
- 图标和技能名之间约 4px，标记和后面原话之间约一个空格宽（6px 左右）。
- 技能名用正文字重，不加粗。看着不够显眼时可以用 500，不要更粗。

## 4. 布局与线框

已和用户确认。`[W]` 表示魔杖图标。

### ① 气泡里的技能标记

```
              +------------------------------------------+
              | [W] code-review  please review this PR,  |
              | focus on error handling                  |
              +------------------------------------------+
                                           (copy) (edit)

                                     +------------------+
                                     | [W] code-review  |
                                     +------------------+
```

- 标记在气泡最前面，原话紧跟在同一行；换行后从气泡左边开始，不和标记对齐缩进。
- 原话按纯文字显示，用户敲的换行、空行和缩进都保留。
- 没写原话时只有标记，气泡宽度随内容收缩，和短消息一样。
- 标记本身不换行。技能名很长时整个标记占一行，原话从下一行开始。

### ② 长消息的收起和展开

```
  Collapsed                                Expanded
  +--------------------------------+       +--------------------------------+
  | [W] code-review  line 1        |       | [W] code-review  line 1        |
  | line 2                         |       | ...                            |
  | ...                            |       | line 20                        |
  | line 8 cut here ...            |       | Show less ^                    |
  | Show more v                    |       +--------------------------------+
  +--------------------------------+
```

- 开关在气泡里，最后一行，靠左。
- 收起时只露出前 8 行左右，截断处能看出"后面还有"（`…`）。
- 技能标记在第一行，收起时照常显示。

### ③ 主输入框

```
+------------------------------------------------------------+
| [W] code-review  please review this PR_                     |
| second line starts at the left edge                        |
|                                                            |
| (existing toolbar, unchanged)                      [Send]  |
+------------------------------------------------------------+
```

- 标记压在输入区左上角，和第一行文字基线对齐；第一行文字从标记后面开始，第二行起从最左边开始。
- 输入框写满开始内部滚动时，标记跟着第一行一起滚走、滚回来，不固定在左上角。
- 输入框高度、工具栏、发送按钮的位置和形状都不变，发送按钮的颜色改成亮蓝（运行中显示的 Stop 也一样，中间是实心白色方块）。旁聊页的 Send、Stop 同样变色。
- 命令面板的位置和样式不变。

### ④ 编辑框

```
              +------------------------------------------+
              | [W] code-review  fix the wording_         |
              |                                          |
              | ! Skill "code-review" is not available   |
              |                         Cancel   [Send]  |
              +------------------------------------------+
```

- 标记的位置和主输入框一样。
- 底部那行平时显示提示，出错时换成错误文字，编辑框不关闭。
- `Send` 按钮改成亮蓝，和主输入框一致；`Cancel` 不变。
- 编辑框里的命令面板只列 skill，样式和主输入框的面板相同。

## 5. 响应式

沿用现有气泡和输入框的宽度规则，本次不新增断点。窄屏下：

| 宽度 | 气泡里的标记 | 输入框和编辑框 | 折叠 |
|---|---|---|---|
| 手机（<640px） | 标记不拆开；放不下时独占一行 | 第一行缩进随标记宽度变化 | 按渲染后的实际高度判断，变窄后行数变多可能变成需要折叠 |
| 平板和桌面 | 同上 | 同上 | 同上 |

## 6. 内容与文案

### 术语表

| 概念 | 界面用词 | 代码里 | 不用 |
|---|---|---|---|
| slash 调用的 skill 在界面上的样子 | 技能标记（文档里）；界面上只显示技能名，不出现"技能标记"几个字 | skill token，组件名 `SkillToken` | 胶囊、徽章、chip |
| 折叠开关 | `Show more` / `Show less` | — | 展开全文、Read more |
| 技能名 | 显示 skill 的标准名，比如 `code-review`，不带 `/` | `skillMarker.name` | 显示 SKILL.md 里的标题 |

### 写法规则

- 界面文案用英文，和现有 Web 一致。
- 编辑重发的错误文字由后端给出，前端原样显示，不另写一套。
- 无障碍标签：标记的 `aria-label` 是 `Skill: code-review`；折叠开关是一个按钮，带 `aria-expanded`。

## 7. 视觉验收口径

硬指标：

- `--skill-ink` 在 `--user-bg` 和 `--bg` 上的对比度不低于 4.5:1；`--skill-ink` 和 `--signal` 是两个不同的值。
- `--signal-contrast` 在 `--signal` 上不低于 3:1。
- 组件样式里没有字面量颜色。
- 用户气泡里没有 markdown 生成的元素（`strong`、`ul`、`pre` 等）；"From parent"提示除外。
- 折叠开关的点击区域高度不低于 24px（文字本身小，可以用内边距撑开，但看起来仍是一行字）。

方向性判断（浏览器截图）：

- 四张线框：区域位置、标记位置、开关位置是否一致。
- 第 1 节每条原则的"截图上看什么"逐条核对。
- 第 2 节的五条特征逐条核对。
- 主输入框、编辑框、旁聊页的 Send 和 Stop 各截一张，确认是亮蓝底、白图标，Stop 的方块是实心的；审批 Allow 和弹窗主按钮仍是黑色。
- hover 折叠开关前后各截一张，确认没有变化。

方向内的合理调整（比如蓝色的明暗、间距差一两像素）算通过，调整后的值回写本文。拿不准时交给用户判断。

## 8. 实现约束摘要

| 必须遵守 | 初值可调 | 自由发挥 |
|---|---|---|
| 四张线框的结构；第 1 节六条原则；标记没有底色、边框、阴影；`WandSparkles` 图标；新增语义变量 `--signal` 和 `--skill-ink`，两者分开取值，不改 `--accent` 的值；只有发送类按钮改蓝（含旁聊页），`.ohb-button-primary` 不变；Stop 方块实心白；`--skill-ink` 对比度 ≥4.5:1，`--signal-contrast` ≥3:1；编辑框 Send 默认用 `--signal-hover`，白字对比度 ≥4.5:1；用户气泡纯文字、`pre-wrap`、`overflow-wrap: anywhere`；折叠开关 hover 无变化、无动画；`Show more` / `Show less` 文案；编辑框错误沿用现有提示行；标记上不放 ×；标记跟着第一行滚动 | `--signal-hover`、`--signal-strong` 的深浅（编辑框 Send 的文字对比度不能低于 4.5:1）；`--skill-ink` 的具体深蓝；图标和文字、标记和原话的间距；技能名字重（400 或 500）；开关字号（12 或 13px） | 图标和文字的基线微调；第一行缩进的测量方式 |

冲突时的优先级：本节"必须遵守"和用户的明确要求，高于 kimi-code 的参考做法，再高于实现者自己的判断。
