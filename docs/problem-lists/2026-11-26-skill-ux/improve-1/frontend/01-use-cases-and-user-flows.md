## 1. 信息架构

本次不加页面，也不改路由。改动都在会话页里：

```
会话页（ui/session/SessionScreen.tsx）
├── 对话流（ui/conversation/ConversationStream.tsx）
│   ├── 用户消息气泡（MessageRow）      ← 技能标记、原样显示、长消息折叠
│   └── 编辑框（UserMessageEditor）     ← 点"编辑"后整个替换气泡；技能标记、命令面板
├── 主输入框（ui/composer/）            ← 技能标记；Send、Stop 改成亮蓝
│   └── 命令面板（useSlashPalette）
├── 排队列表（PromptQueue）             ← 不改，仍显示纯文字
└── /skills 弹窗（ui/commands/CommandResultModal.tsx） ← Insert 后输入框出现技能标记

旁聊页（ui/side-chat/SideChatPage.tsx）
├── 复用对话流                          ← 原样显示和长消息折叠自动生效；旁聊没有 slash，不涉及标记
└── 复用输入框和按钮样式              ← Send、Stop 一起变成亮蓝
```

| 区域 | 主要任务 | 前置条件 | 核心 |
|---|---|---|---|
| 主输入框和命令面板 | T-01 | 已打开一个会话，或在新对话草稿里 | 是 |
| 用户消息气泡 | T-02、T-03 | 会话里有用户消息 | 是 |
| 编辑框 | T-04 | 这条消息允许编辑（和现在的规则一样） | 是 |
| `/skills` 弹窗 | T-01 的另一个入口 | 至少装了一个 skill | 否 |

权限：单一身份，没有权限区分。

### 术语草稿

| 概念 | 界面用词 | 说明 |
|---|---|---|
| slash 调用的 skill | 技能标记（代码里叫 skill token） | 魔杖图标加技能名 |
| 折叠开关 | `Show more` / `Show less` | 界面是英文，和现有 Web 文案一致 |

## 2. 用户流程

### T-01 用 slash 调用 skill 并发送

```
在主输入框敲 /
↓ 命令面板弹出，列出命令和 skill
↓ 选中一个 skill（回车、Tab 或点击）
↓ 输入框最前面出现技能标记，光标在标记后面
↓ 写原话（可以不写）
↓ 回车发送
├── 成功 → 输入框清空；气泡里是技能标记加原话
├── 命令目录里找不到这个 skill（比如草稿恢复时它已被删）→ 当场报错，标记和原话还在输入框里
├── 排队期间 skill 被删 → 轮到它时后端按普通文字 `/技能名 原话` 发给模型，气泡里没有魔杖标记，也不另外提示
├── 断网或请求失败 → 输入框点发送时已经清空，失败后技能标记和原话一起还回输入框，显示错误
└── 发送中连按回车 → 和现在一样，不会重复发
```

其他填入入口：

- `/skills` 弹窗里点 Insert：关闭弹窗，输入框出现技能标记。
- 刷新页面后恢复草稿：草稿里单独存了技能名，恢复后仍是标记加原话。升级前存下的旧草稿是纯文字，照常恢复成纯文字。
- 编辑重发失败回填（见 T-04）。

只有上面这几个入口和命令面板会生成标记。手敲、粘贴、排队编辑都按纯文字处理（见第 4 节）。

已有标记时：

- 只写标记不写原话，Send 照样可用。
- 在原话开头敲 `/`，命令面板只列 skill；选中后替换原来的标记。

删除标记：

```
光标在原话最前面、没有选中文字
↓ 按一次退格
├── 不在输入法组字中 → 整个标记删掉，输入框只剩原话
└── 正在输入法组字 → 不处理，交给输入法
```

删掉以后想要回来，再敲 `/` 从命令面板选。

### T-02 认出调用了哪个 skill

```
看对话流
↓ 用户消息带 skillMarker
├── 有原话 → 气泡开头是技能标记，后面接原话，换行后从最左边开始
├── 没有原话 → 气泡里只有技能标记
└── 没有 skillMarker（普通消息、升级前的旧 slash 消息、排队期间 skill 被删的消息）→ 照常显示文字
```

用户自己写的话都按纯文字原样显示，保留换行和空格，不按 markdown 渲染。`**加粗**` 显示的就是两个星号加文字。

点"复制"得到的是 `/技能名 原话`。

### T-03 展开和收起长用户消息

```
用户消息渲染出来
↓ 实际高度超过约 12 行
├── 否 → 正常显示，没有开关
└── 是 → 只露出前 8 行，截断处显示 …，左下角显示 Show more 和向下箭头
        ↓ 点 Show more
        → 显示全文，开关变成 Show less 和向上箭头
        ↓ 点 Show less
        → 回到折叠状态
```

- 点气泡正文不会展开。
- 搜索跳到这条消息时自动展开。
- 窗口变宽变窄导致行数变化时，按新的高度重新判断。
- 折叠状态不保存：刷新页面、切换会话、往上翻历史重新加载后，都回到折叠。

### T-04 编辑带 skill 的消息并重发

```
在用户消息上点"编辑"
↓ 气泡换成编辑框，最前面是技能标记，后面是原话
↓ 改原话；也可以删掉标记，或敲 / 换一个 skill（编辑框的命令面板只列 skill）
↓ 点发送
├── 成功 → 历史从这条消息截断，新消息带着技能标记出现
├── skill 已被删除、改名或不再允许用户调用 → 编辑框底部的提示行改为显示错误，历史不截断，编辑框保持打开
├── 截断成功但发送失败 → 和现在一样，文字回填到主输入框，技能标记在最前面，原有草稿接在后面
└── 点取消 → 回到原来的气泡
```

旧消息（升级前发的 slash 消息）没有 `skillMarker`，点编辑时不显示标记，编辑框里是纯文字：后端能还原出 `/技能名 原话` 时就是这串文字，否则是原来的全文。发送后按 B4 的规则处理。

## 3. 用例

### UC-SKILL-01 用命令面板选 skill 并发送

**前置条件**：已装至少一个允许用户调用的 skill。

**主流程**：

1. 用户在主输入框敲 `/`。
2. 命令面板列出命令和 skill，用户选中 `code-review`。
3. 输入框最前面出现技能标记 `code-review`，光标在标记后。
4. 用户输入"帮我看看这个 PR"并回车。
5. 气泡里显示技能标记加"帮我看看这个 PR"。

**异常流程**：

- 不写原话直接回车 → 照常发送，气泡里只有技能标记。
- 发送时报错 → 显示错误，技能标记和原话都还回输入框。
- 排队期间 skill 被删 → 后端按普通文字发出 `/code-review 帮我看看这个 PR`，气泡里没有魔杖，是一条普通消息。

**完成结果**：

- 气泡里没有 SKILL.md 的任何文字。
- 气泡开头是魔杖图标加 `code-review`，颜色是蓝色（`--skill-ink`），没有底色和边框。
- 复制这条消息得到 `/code-review 帮我看看这个 PR`。

### UC-SKILL-02 从 /skills 弹窗插入 skill

**主流程**：用户打开 `/skills` 弹窗，选中一个 skill，点 Insert。弹窗关闭，输入框最前面出现技能标记，焦点在输入框里。

**异常流程**：输入框里已经有文字 → 和现在的 Insert 行为一致，整个草稿被替换，只剩标记，原话为空。

**完成结果**：输入框里的技能标记和 UC-SKILL-01 第 3 步一样。

### UC-SKILL-03 整体删除技能标记

**前置条件**：输入框或编辑框里有技能标记。

**主流程**：光标移到原话最前面，按一次退格，标记整体消失。

**异常流程**：

- 有选中文字 → 按普通退格处理，只删选中的文字，标记不动。
- 正在用输入法组字 → 不处理。
- 光标不在原话最前面 → 按普通退格处理。

**完成结果**：标记消失，原话完整保留，光标在输入框最前面；发送时按普通消息处理。

### UC-SKILL-04 草稿恢复

**主流程**：输入框里有技能标记加原话，刷新页面。恢复后仍然是技能标记加原话。

**异常流程**：

- skill 在这期间被删了 → 照样恢复成标记，不做检查；发送时前端在命令目录里找不到它，当场报错，和 UC-SKILL-01 的发送报错一样处理。
- 升级前存下的旧草稿 → 恢复成纯文字。

**完成结果**：草稿内容一字不差。

### UC-MSG-01 展开和收起长用户消息

**前置条件**：一条用户消息渲染高度超过约 12 行。

**主流程**：

1. 消息只露出前 8 行，截断处显示 `…`，左下角显示 `Show more` 和向下箭头。
2. 用户点 `Show more`，显示全文，开关变成 `Show less` 和向上箭头。
3. 用户点 `Show less`，回到折叠。

**异常流程**：

- 点气泡正文 → 不展开。
- 用搜索跳到这条消息 → 自动展开。
- 窗口变宽后不到 12 行 → 不再显示开关。
- 消息里有技能标记 → 标记在第一行，折叠时照常显示。

**完成结果**：折叠时消息只占 8 行左右；开关只是一行文字加箭头，没有卡片、阴影、hover 变化和动画。

### UC-MSG-02 编辑带 skill 的消息并重发

**前置条件**：这条用户消息带 `skillMarker`，且允许编辑。

**主流程**：

1. 用户点"编辑"，编辑框最前面是技能标记，后面是原话。
2. 用户改原话，点发送。
3. 历史截断，新消息带着同一个技能标记出现。

**异常流程**：

- skill 已被删除、改名或不再允许用户调用 → 编辑框底部的提示行改为显示错误，历史不截断。
- 用户删掉标记再发送 → 按普通消息发送。
- 用户在编辑框里敲 `/` → 命令面板只列 skill；选中后替换原来的标记。
- 截断成功但发送失败 → 文字回填到主输入框，技能标记在最前面，原有草稿接在后面，并显示错误。

**完成结果**：新消息的技能标记和原消息一致；模型按 skill 的最新内容回答（后端每次重新读取 SKILL.md）。

## 4. 已确认的边界情况

1. 用户手动敲完 `/code-review ` 而没有通过命令面板选中时，输入框保持纯文字，发送后后端仍然当 skill 处理，气泡照常显示标记。只有面板选中和 01 第 2 节列出的程序填入会转成标记。
2. 粘贴一段以 `/技能名` 开头的文字，按纯文字处理，不转标记；发送后后端照样当 skill 处理。
3. 排队列表和失败行不显示标记，仍是纯文字 `/技能名 原话`（见 00 的 Non-goals）。编辑排队中的消息时，填进输入框的也是纯文字。
4. 排队期间 skill 被删，不会产生失败行，消息按普通文字发出，气泡没有标记（../00 B2）。
5. 用户气泡原样显示时的几种情况（../00 F5）：
   - 旁聊引用选中文字时会在前面加 `> `，气泡里直接看到 `>`，这就是实际发出去的内容。
   - 子代理页面的"From parent"提示是模型写的 markdown，继续按 markdown 渲染。
   - 裸网址不再可点。
6. 发送后、正式消息到达前，有一个很短的占位行显示纯文字 `/技能名 原话`，随后变成带标记的气泡。
