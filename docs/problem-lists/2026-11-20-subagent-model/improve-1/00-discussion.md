## 1. 背景与动机

用户提了三个问题：

1. Settings 的 Models 面板里可以选 Default，但它不会改变主会话的模型（主会话的模型在 prompt 框里选）。那 Default 是做什么的？是给 side chat 或者会话标题用的吗？
2. 如果 Default 不重要，要不要去掉？
3. 能不能在 Models 里给子代理单独配模型，让子代理和主代理用不同的模型？

调查结论（详见 01）：

- Default 管的是“还没选过模型的会话”，包括新会话：这类会话每一轮都用当时的 Default。会话选的模型被删掉时，也退回 Default。在 prompt 框里选过模型的会话被固定住了，改 Default 对它没影响，所以看起来像“不起作用”。
- 标题、压缩摘要、side chat 和子代理都跟着这一轮实际用的模型走，不直接读 Default。
- 子代理现在只能继承父会话这一轮的模型和思考档位，Agent 配置里也明确禁止写 `model`。

## 2. 已确认：目标与范围

| 编号 | 决策项 | 结论 |
|---|---|---|
| D1 | Default 要不要保留 | **保留**，语义不变：新会话和没选过模型的会话用它；会话选的模型被删后退回它。理由：新会话总要有一个起始模型，删除后也要有兜底；参考项目都保留了全局默认 |
| D2 | Default 的说明 | 在 Settings 的 Models 页补一句简洁清晰的说明，让用户看出 Default 只管新会话和没选过模型的会话。这一条落实的是 session-model D13 当时计划、但没有做的那行说明 |
| D3 | 子代理模型怎么配 | 做**一个全局设置**，放在 Settings 的 Models 面板里：默认是“跟随会话”，也可以指定模型列表里的任意一个模型。对所有子代理角色都生效 |
| D4 | 生效顺序 | 指定了子代理模型，就用它；设为跟随会话，就继承父会话这一轮的模型和思考档位，也就是现在的行为 |
| D5 | 子代理的思考档位 | 在 Settings 的子代理模型选项里设，和子代理模型一起保存。跟随会话时不单独设，继承父会话 |
| D6 | 上下文窗口、输出上限、能力探测 | 和主代理一样，都在 Models 的模型编辑器里配置和探测。子代理设置只引用某个模型条目，不另存这些参数 |
| D7 | 主代理与子代理的分工 | 主代理的模型和思考档位在 prompt 框里选；子代理的模型和思考档位在 Settings 里配。两边互不影响：在 prompt 框里切换不改子代理设置，改子代理设置也不改任何会话 |
| D8 | 做哪些端 | Web 和 TUI 都做。TUI 在现有的 `/models` 面板里加入口，不新增斜杠命令，交互借鉴 kimi-code 的 `/subagent-model` |
| D9 | 文档 | 放在 `docs/problem-lists/`；02 不列关键改动清单 |

## 3. 待用户审核的细节建议

| 编号 | 决策项 | 建议 |
|---|---|---|
| D10 | 指定的子代理模型被删了 | 删除时同时把子代理设置改回跟随会话；Web 的删除确认框加一句提示 |
| D11 | 指定的子代理模型变得不完整（只会出现在手改 `model.json` 或迁移来的旧条目上） | 设置保留，但子代理这次退回继承父会话的模型，并发一条提示；Settings 里这一行显示 “Needs setup”，让用户去修。主代理的任务不会因此中断。key 失效不算不完整：子代理请求会鉴权失败，主代理收到一次工具失败，这可以接受 |
| D12 | 什么时候生效 | 子代理每开始一次新的执行时读取当时的设置，包括新起一个子代理，以及给空闲的子代理发消息。正在运行的那次执行不换模型 |
| D13 | 子代理档位和模型能力不兼容 | 省略档位表示使用所选模型的默认档位。显式选择整体应用，保存和执行前都按实际请求校验。之后模型能力变了（例如重新探测），运行时仅对本次执行改用同一模型的默认档位，并发提示。已保存的档位保留 |

## 4. 本轮不做

- 按子代理角色（generic、explore、research）分别配模型。以后需要时在本轮的全局设置上加一层，顺序变成“角色设置 → 全局设置 → 继承”，本轮的设计不用推翻。
- 让主代理调用子代理工具时自己挑模型（工具参数里的 `model`）。
- 给标题生成等后台任务单独配一个便宜的小模型（opencode 的 `small_model`）。
- 每个会话单独设置子代理模型。
- Agent 配置里的 `model` 字段。现有代码禁止在 Agent 配置里写模型，本轮不改。
