## 1. 目标与文档分工

本次升级解决 goals 在长任务中的请求挂起、预算恢复、旧轮次竞争、用户插话和运行状态展示问题。沿用 GoalStore、GoalService、driver 与现有执行端口，不重建一套 agent runtime。

## 2. 已确认决议

### 决议 1：续跑正文与展示文本分开

- 续跑指令继续写入普通 user-role text part，模型读取完整正文。
- 给 goal 提交路径补 `displayUserText`，持久化为既有 `metadata.displayText`。实时回显与历史重读都显示简短的续跑提示。
- 不使用 `appendModelContextPart`，不新增 kind，不修改 `getMessageOrigin` 或压缩分类。
- 提醒正文、展示文本和轮号取自同一次准入快照，不能由 driver 在等待准入前提前生成。

早期的 model-context 方案已撤销：发起消息上的既有 runtime kind 有去重语义，会与环境信息、MCP 工具菜单的附加相互覆盖。displayText 是现有展示能力，可直接复用。

**取舍**：这次只改变显示文字，消息仍是用户角色，不宣称已实现系统消息身份。短提示沿用产品现有英文风格，具体文案属于实现细节；不把讨论中的中文示例当作新本地化规范。会话标题应来自 objective 或完整输入，不能来自短提示。

### 决议 2：通用请求空闲超时

- 在 `core/llm-client` 加通用请求空闲看门狗，保护普通 run 和 goal run。
- 覆盖建立流、等待首个事件及流中间长期没有事件的路径。
- 超时与用户主动取消要区分；是否重试还受已有的部分输出与工具副作用规则约束。
- 不做语义化停滞检测；1000 轮系统安全阀保持不变。

参考 deepseek-harness 与 ZCode 的请求层兜底。不能把“abort 后自然走现有重试”当成已经成立的事实，也不把整个 goal 回合设为固定时长超时。

### 决议 3：两轴预算与统计

| 项目 | 已确认结论 |
| --- | --- |
| 硬预算 | 轮次、活跃时长；默认均不设置 |
| token 预算 | 删除配置、计算与工具单位，不保留隐形限制 |
| 时间到顶 | 当轮内转 `blocked`，中断对应的 goal 执行；不等轮末 |
| 系统安全阀 | 1000 个已准入 goal 轮，独立于显式预算 |
| token 统计 | 保留总用量与缓存命中统计，不作为预算或完成依据 |
| 子代理用量 | 不归集；不把压缩摘要请求混入 goal 主 run 统计 |

活跃时长沿用当前定义：状态为 active 的全部时间，包括工具执行、重试和等待用户队列。paused / blocked / complete 不累计。严格用户优先可能让 goal 长时间等待，等待也会耗尽时间预算；本次不另建“纯执行时长”计数器。

预算更新后应重新安排截止定时器。旧定时器不能打断新 run；任何用量、失败、取消或异常回写都必须核对所属目标。完成轮漏记、失败/取消时已有 usage 被丢弃的问题纳入总体改造，但不估算 provider 未报告的 token。

### 决议 4：保留权威目标，删除非活跃自动注入

- objective 每个 goal 轮全文重发；保留 6000 上限，不摘要、不静默截断。
- 保留对不可信文本的转义与标签包裹。转义防止文本伪造标签边界，不宣称能彻底阻止提示注入。
- 删除 `renderGoalContextNote` 及 paused 轻提示的拼接与专用开关。
- “非活跃不注入”指不再因为 goal 状态而向普通输入新增 goal 文本；不删除历史目标文本，不禁用 `GetGoal`，不删除静态规则。
- `base.md` 的静态 Goal mode 规则继续常驻，避免按状态改写 system 前缀。
- 接受静态规则与续跑规则的适度重复，不建立同步抽象；修改状态术语时同时核对两处。

缓存只承诺不因本次改造额外改写稳定前缀，不保证具体命中率或计费倍率。压缩、模型和 provider 的缓存策略仍会影响实际命中。

### 决议 5：CLI / Web 展示轮次与活跃时长

- CLI 常驻条显示状态、轮次、活跃时长；设置轮次预算时可显示 `7/20 turns`。
- Web 常驻 chip 保持简短，Goal 面板展示轮次与活跃时长。
- `UiGoal` 增加 `turnsUsed`、`wallClockMs` 及用于分母的可选 `turnBudget`，不搬整个预算报告。
- 常驻 UI 和每轮自动提醒不含 token；`/goal status` 与 `GetGoal` 保留统计明细。
- 用量变化要更新投影，但不能每次更新都发一条生命周期 notice。
- blocked 必须经过 adapter、SDK、CLI、Web 正确呈现，并可从现有恢复入口操作。
- 不加进度条、百分比、新色相或复杂组件；blocked 沿用单色的形状区分。

时长刷新沿用现有快照与事件，在可用量更新时显示最新后端值；本阶段不承诺逐秒走字。若后续需要持续走字，应单独说明成本与刷新规则，不能把前端估算当作预算权威。

### 决议 6：完成仍由模型自报

- 不引入独立 verifier，不加完成证据硬门禁。
- `completionCriterion` 只用于注入和显示，不是可执行校验程序。
- `UpdateGoal` 的 `reason` 只对 blocked 有效，complete 不记录理由。
- 保留简短完成通知，不建立完成历史界面。

完成判断与最终 usage 到达可能先后不同。02 必须把“停止续跑”和“最终结算后清除”分开说明，保证完成不会因崩溃重新变成可恢复的目标，也不能让旧目标的尾部用量记到新目标上。这是记账正确性约束，不增加第二个完成判定者。

### 决议 7 + 12：按准入计轮次，旧轮次不能污染当前目标

- 只有获得本 session 执行权、通过目标身份/状态/预算核对的 goal 轮才计数。
- 未准入返回 `not_admitted`，不计轮次；等待对应条件变化后重试，不能忙循环。
- 准入时使用最新 objective、进度、预算，同时生成模型正文与展示文本。
- 与用户提交共享执行权互斥；仅在 `activePromptsBySession.set` 后增加检查，不足以防止两条路径同时通过空闲检查。
- 记账核对 goalId；状态回写还要识别本次执行所属的生命周期，覆盖 failed、cancelled、外层 catch 和截止回调。
- 不加持久化 revision。需要识别同一目标暂停/恢复前后的旧执行时，用最小的进程内代号或等价身份。
- 手动压缩造成的忙碌应等待压缩结束，不把正常竞争转为 runtime error。

已准入轮即使随后失败或取消也计一轮；准入不是“模型一定完成一次请求”。准入持久化后发生崩溃，重启保留已准入计数并归一化状态，不承诺跨进程精确一次执行。

### 决议 8：普通输入优先 steer，下一轮让位给用户队列

1. 普通输入先接受并持久化，再在 claim 之前尝试 steer 到正在执行的 goal run。接受与分流必须处于受保护的 session 提交顺序中。
2. 成功 steer 不中断、不暂停 goal，不创建新 run，也不新增 goal 轮次。
3. 目标已封口、已关闭等预期竞争保留同一队列项；存储失败、身份冲突和内部异常如实报错，不伪装成成功。
4. goal 正忙时，排队项保持 queued，不提前 claim 后占住全局 session 容量等待。
5. **当前 goal 轮结束后，已排队用户消息先运行；下一 goal 轮等用户队列清空再准入。** 不设置让 goal 插队的配额。
6. 显式 stop、`/goal pause`、runtime error 和重启归一化仍可导致 paused；普通输入不再触发暂停。
7. 不引入 dsh 的 armed/disarmed 激活层；真的进入 paused / blocked 后仍需显式恢复。
8. 放宽未消费 steer 的提示范围，覆盖各种关闭原因及恢复路径，并提供可辨认、可重发的入口。

steer 复用当前 run 的 Todo scope、reasoning 设置和剩余 step，不承诺每条消息都有独立回答。未 steer 的消息仍走普通 run。接受不等于模型已处理；本地 attempt 标记也不等于 provider 确认收到。正常完成已有 pending-input 防护，重点补异常关闭与恢复。

顺序要求是 session 接受顺序，不依赖同毫秒内随机 UUID 排序。前一条已回退排队时，后一条不能通过自动 steer 越过它。重试同一 clientRequestId 复用原决定，不能改投另一个 run。

### 决议 9：blocked 独立状态，模型同因连续三轮才可阻塞

| 状态/动作 | 触发与恢复 |
| --- | --- |
| active | 创建或用户显式恢复；可自动续跑 |
| paused | 显式暂停/stop、当前执行失败、重启时 active 归一化；用户恢复前仍需检查预算 |
| blocked | 预算到顶、安全阀到顶、模型连续三轮同因报告阻塞；经同一 resume 入口恢复 |
| complete | 模型自报完成；不可 resume，最终清除当前目标 |
| cancel | 清除目标，不是第五个状态，也不是暂停 |

- `UpdateGoal` 仅接受 complete / blocked；移除 active / paused，模型不能自我恢复。
- 三轮门禁只约束模型 blocked，自身的预算与安全阀立即生效。runtime error 直接 paused。
- 同因使用 `reason.trim().toLowerCase()`；计数器只在内存，最终 blocked 状态和原因持久化。
- “三轮”按已准入 goal run 计，每轮最多贡献一次；无报告的轮打断连续性，换因重新从一计数，换目标、从停止状态显式恢复或重启后清零。active 上的幂等 resume 不属于新的恢复，不重置审计链。
- 普通用户 run、steer 和 not_admitted 不新增审计轮。具体工具调用必须绑定 run 身份，不能在同一轮调三次绕过门禁。
- 删除历史 `blocked → paused` 归一化及 `GoalStoredStatus`；保留 `pauseReason` 字段名承载停止原因。

参考归因更正：Codex 的内存计数主要处理执行失败/无活动，模型三轮要求是提示规则；Claude Code Best 的 blockedAttempts 按调用计数。本项目的“连续三个 goal 轮”是自己的已确认约束，不宣称照搬了某家的完整实现。字符串换说法可能延后阻塞，属于已接受的局限，不称其为天然安全。

### 决议 10：不做 fork / 会话继承

当前没有 fork 能力，不为假想 fork 建立 goal 或 Todo 继承机制。保留重启归一化；参考项目的 deferral / activation 不能仅因存在就搬过来。

### 决议 11：不做多目标队列

每个 session 仍只有一个当前目标，不增加 `/goal next`。普通用户消息队列与多个 goal 的队列是两回事。

### 决议 13：resume 可同时调整多个上限

| 用法 | 语义 |
| --- | --- |
| `/goal resume` | 保留当前预算，检查后恢复 |
| `/goal resume 100 turns` | 轮次总上限改为 100，时间上限保留当前值 |
| `/goal resume 3h` | 活跃时长总上限改为 3 小时，轮次上限保留当前值 |
| `/goal resume 100 turns 3h` | 一次提交两项总上限，通过检查后一起生效并恢复 |

- “默认”指未提供的维度沿用当前配置；原来未设置则继续未设置，不重置其他维度。
- 新上限是自 goal 创建以来的**总额度**，不是追加额度，不清零已用量。
- 使用合并后的预算检查所有到顶维度及系统安全阀，再原子持久化预算和 active 状态。校验与写入不能被并发预算更新插队。
- 失败时预算和状态都不改，错误列出阻塞维度、已用量和可执行下一步。
- 单维也可用；若另一维仍到顶，提示一次提供两维，避免两条单维命令互相卡住。
- `SetGoalBudget` 只设置预算，不恢复 paused / blocked。
- 安全阀不能抬高。到 1000 轮时引导 `/goal cancel` 后新建；`/goal replace` 只改 objective，不重置 goalId、计数或预算；正文实际改变使旧 executionEpoch 失效，同文 no-op 不失效。
- 恢复与旧 driver 退出重叠时，最终必须恰有一个有效 driver，不能出现 active 却无人驱动。

现有自然语言调用 `SetGoalBudget` 后再 resume 的两步路径仍可用。本次提供更直接的用户命令，不声称原来完全无路可走，也不新增 `/goal budget`。

### 决议 14：completionCriterion 单独封顶

- `MAX_GOAL_COMPLETION_CRITERION_LENGTH = MAX_GOAL_OBJECTIVE_LENGTH`，值为 6000。
- 与 objective 相同，trim 后按 JavaScript UTF-16 `.length` 检查；超限拒绝，不截断。
- 在 `GoalStore.create` 校验，且必须先于任何替换、清除或持久化修改，覆盖 `replace: true`。
- 不设 objective + criterion 联合上限，不增加 criterion 编辑功能。
- criterion 在每轮提醒中只出现一次；查询输出不属于自动注入次数。

借鉴 Kimi 的同值上限形状，拒绝其静默截断。Codex 关于“截断可能把限制变成授权”的注释支持保留完整约束，但其 700 字节限制服务于另一条溯源消息，不能套作续跑目标上限。

## 3. 边界与关联议题

范围包括 goals、adapter 与 prompt scheduler 的执行准入、既有 steer 接入、SDK/CLI/Web 投影、通用 llm-client 空闲超时，以及相应设计文档更新。

不改 run-manager 的底层并发政策、sandbox 租约、权限审批、数据库引擎、多智能体编排和压缩算法。不加独立事件总线、独立数据库、通用注入系统、持久 revision、独立 verifier 或停滞检测。

与 `2026-10-10-compact-cache-and-tool-output` 保持独立：复用其稳定前缀、压缩与 protected input 机制，并做交互回归；不把本规划描述成已完成该议题的全量复审。

历史设计记录保留，在后续相关实现批次加 superseded 说明；新的模块现状文档与实现同步修改。本轮不提前把目标行为写成已实现。
