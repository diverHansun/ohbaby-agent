## 本批在整体中的位置

按 [README 的五批地图](../README.md)，第 1 批只做通用请求空闲看门狗：建流与每次 next 的有界退出，以及它与重试、取消、部分输出规则的衔接。它不依赖 goals 状态改造，但第 2 批的运行失败回归和第 3 批的时间截止都要与它共存。plan/04 的 W1–W7 主要由本批负责，其中 W4 的「goal 时间截止」部分随预算截止机制在后续批次组合验证。

## 继承的已确认结论（resolution 2 与 plan/02 §2.7）

1. 通用请求空闲看门狗放在 `core/llm-client`，保护普通 run 和 goal run，不做 goal 特例；不做语义化停滞检测；1000 轮系统安全阀不变（决议 2）。
2. 覆盖建立流、等待首个事件和流中间长期没有事件的路径；只对尚未完成的建流或 next 等待计时，不把消费者处理事件的时间算成 provider 空闲；每次新等待重新计时，结束、失败或取消时清理（§2.7）。
3. 超时与用户主动取消要区分；超时只取消当前 attempt 的子控制器，不 abort 代表用户取消的共享请求 signal（§2.7）。
4. 是否重试受已有部分输出与工具副作用规则约束：没有已提交输出且满足既有重试条件时，走已有有界重试与退避；已有部分输出、工具调用或副作用时，不无条件重放整步。仅改 retry predicate 不足以绕过现有 `user_aborted` 与 partial-output 分支（§2.7）。
5. 所有 `observer.next` 路径都要覆盖，包括首事件、usage-only 事件后的等待和主循环；超时错误带可识别的重试分类（§2.7）。
6. provider 不响应 abort、`iterator.next` 或 `iterator.return` 永不返回时，调用方仍须在有界时间内退出，清理不能成为第二个挂点；超时后迟到的 resolve、reject 或 chunk 不得污染后继 attempt，也不能产生未处理 rejection（§2.7）。
7. 优先复用 `RequestAttemptObserver` 和既有 attempt 结构，不把超时参数穿过每层业务端口，不新增 SDK 与应用层叠加的重试循环（§2.7）。
8. 当前 SDK 未必暴露 SSE 心跳，未观察到的心跳不能声称会重置看门狗；不把 ZCode 的 600 秒直接当作本项目参数；阈值、允许范围和配置入口由本批核查 provider 行为后固定（§2.7、plan/04 §4.8）。
9. 看门狗可单独停用其新增包装，但不得顺带撤销现有取消与重试保护（§2.8 回滚约束）。

## 本轮工程约束（依用户授权修订，非逐项原话）

| 建议 | 内容 | 依据或替代 |
| --- | --- | --- |
| 默认阈值 | `600_000` ms（10 分钟）常量，按保守工程默认固定，不做 per-retry 递增 | 建流等待包含提供方排队与预填充，长思考也可能长时间没有可观察 chunk，阈值要留出足够余量。不做实施前的实网核查门槛；后续实网观察如显示合法静默更长，只调常量。每次建流起就完全无活动时，默认 6 次尝试约需 60 分钟再加退避才耗尽；有活动会重置计时，因此这也不是所有请求的总时长上限 |
| 配置入口 | 请求级可选 `idleTimeoutMs`，默认取常量 | 沿现有 `retry` 选项先例（同一层、同一形状）。本批不进 `model.json`、不加 env、不做 UI：当前配置层没有任何超时字段，加一个要走 validation、manager、`LLMConfig`、client 投影多层改造 |
| 原始事件活动 | provider 边界加可选 `onActivity` 回调，适配器在能观察到原始 chunk 或事件处调用，用于重新计时 | 部分 chunk（例如只有 role 或空 delta）不产出归一化事件；只按归一化事件重置会误杀仍然活着的连接。不声称 SDK 未暴露的心跳会重置 |
| 模块形状 | 新增 `core/llm-client/idle-watchdog.ts` 与配套单测；超时用独立错误类并在 `isRetryableProviderError` 加一支 | 沿 `retry.ts` 的先例：纯逻辑小模块 + 独立单测，便于用 fake timers 测边界 |
| 部分输出 | 有部分输出时按既有规则不重放；不把超时并入 `transport` 源 | 遵守 §2.7 与 plan/04 W3。摘要路径「部分输出后能否重试」的语义保持现状，不在本批偷偷扩展 |

## 本批不做（边界）

- 不改 goals 状态、预算、blocked、计轮、统计、steer、UI 和 CLI/Web 投影。
- 不做语义化停滞检测、不新增第二层重试循环、不假设 SDK 心跳、不把超时参数穿过 lifecycle 或 goals 端口。
- 不新建通用超时包或配置框架；不把「有界退出」写成「所有超时都必然自动恢复」。

## 留待后续

- 阈值按保守工程默认固定为 10 分钟，不作为实施门槛；后续实网观察如显示合法静默更长，允许只调常量并重跑边界用例。
- W4 的「goal 时间截止与超时竞争」完整体现（截止把目标置 blocked、迟到失败不得覆盖）依赖预算截止机制，待实现该机制的后续批次组合验证；本批只验证用户 stop 与外部 abort。
- 本批实施完成后，按仓库惯例撰写 `05-implementation-acceptance.md`。
