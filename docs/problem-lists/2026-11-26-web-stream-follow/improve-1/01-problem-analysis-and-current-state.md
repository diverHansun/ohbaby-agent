## 对照代码和 Chrome 回放

4096 返回的主 JS 与本地构建产物哈希一致。构建的源码映射中，滚动相关文件与提交 `7da41993` 对应文件一致。以下实验用独立配置的无头桌面 Chrome 158.0.8127.89，挂载该版本的 `ConversationStream` 和项目构建的 CSS，用 380 像素宽的占位侧栏限制正文宽度。测试直接给组件提供模拟消息，通过 Chrome 输入接口发送滚轮和点击，读取浏览器实际排版后的尺寸。它覆盖消息组件、原生输入、布局和过程折叠，未回放模型或服务端事件。

### 第一种：画面还不能滚动，一次上滑就会关闭跟随

先显示一条提问，此时可视区和内容高度都是 689 CSS 像素。依次追加 32 行工具记录、一段分批增长到 75 段的回答，最后结束运行并折叠过程。下表中的距离均指消息区距底部还有多少 CSS 像素，0 表示正在显示最新位置。

| 初始操作 | 32 行工具记录出现后 | 正文增长后 | 过程折叠后 |
| --- | ---: | ---: | ---: |
| 不操作 | 0 | 0 | 0 |
| 内容不足一屏，向上滚一次 | 1,398 | 4,109 | 2,325 |
| 内容不足一屏，向下滚一次 | 0 | 0 | 0 |

上滑组三次回放结果一致。Chrome 收到了滚轮事件，当时顶部偏移仍是 0，没有产生位移。代码里的 `leaveBottom` 已经把跟随开关改成了关。后续工具行和正文照常进入页面，安排滚到底部的函数看到开关已关就直接返回，所以开头一直留在屏幕上。只要用户之后手动滚回底部附近并触发滚动事件，仍能恢复跟随。[取消跟随、重新跟随和内容增长处理](../../../../apps/ohbaby-web/src/ui/conversation/ConversationStream.tsx) · [底部距离判断](../../../../apps/ohbaby-web/src/ui/conversation/streamScroll.ts)

### 第二种：一次没有位移的输入，让自动折叠被当成用户上滚

等长回答已经贴底后，点击一下普通正文，或在底部继续向下滚一次。两种输入都会把 `userScroll` 设为真。输入本身没有滚动消息区，这个标记就留到了下一次 `scroll` 事件。运行结束后，32 行工具过程折叠，允许的最大顶部偏移从 4,109 降为 2,325。浏览器自动减小偏移，`onScroll` 看到“偏移变小”加上遗留的输入标记，误判用户在往上读，关闭了跟随。

向下滚的那组尤其能说明问题：折叠完成时，页面离底部仍是 **0 像素**，跟随已经关了。实验随后额外增加 20 段正文来检测开关，此时距底变成 716 像素。点击正文的那组是 746 像素，不操作的对照组始终为 0。这次额外增长是实验探针，原会话没有观察到结束后又收到正文。这条路径可以解释收尾时脱离底部；它需要内容先收缩，单凭结束折叠不能解释运行中段就停在首屏。

### Page Down 与原窗口的证据边界

在折叠后的长回答开头，点击正文再按 Page Down，可以复现顶部偏移保持为 0。按键送到了外层 `.ohb-root-conversation`，实际滚动的是内层 `.ohb-stream`。实验中临时把焦点移到内层，单次 Page Down 也没有产生位移，因此尚不能把焦点认作唯一原因。此场景中随后一次向下滚轮输入未得到自动化接口确认，页面也没记录到这次滚轮；物理滚轮是否受阻仍未确定。独立的长列表对照中，滚轮可以真实上翻并返回底部。[主会话外层](../../../../apps/ohbaby-web/src/ui/session/SessionConversation.tsx)

## 修复建议与验证结果

只改临时实验构建，分别验证了两个条件。

1. **内容没有超出视口时，忽略退出跟随的手势。** 相同上滑回放从三次全部停在顶部变为三次全程贴底。长列表从底部上翻 640 像素后，追加三行工具记录，顶部偏移仍为 758；手动滚回底部后继续正常跟随。这个条件单独使用时，第二种误判仍可复现。
2. **区分内容缩短和用户上滚。** 实验在原本正在跟随、旧偏移已经超出新布局允许上限时，忽略此次位移上遗留的输入标记。配合第一项重放，正文点击、到底继续下滚两组在折叠及后续增长时都保持距底 0；主动回看旧内容仍能停住。这个条件验证了定位方向，上线前还应覆盖折叠与真实用户滚动同时发生、拖动滚动条、触控和历史分页的情况。

建议优先把以上两组回放作为 Chrome 回归用例，再调整 `leaveBottom` 和 `onScroll`。本次运行的滚动、阅读位置和过程折叠测试共 23 项，全部通过。现有组件测试使用模拟尺寸和合成事件，无法验证浏览器因内容缩短而产生的实际位移。相邻 OpenCode 的 `packages/app/src/session/timeline/virtualizer.tsx` 在处理向上滚轮时也会检查实际可滚范围（第 927–940 行），并在指针松开时结束本次手势（第 1005–1017 行）。其「回到最新」按钮可以作为独立的恢复入口参考。[现有测试](../../../../apps/ohbaby-web/src/ui/App.unit.test.tsx) · [早期滚动交互约定](../../2026-07-13-web-stream-scroll-and-composer-placeholder/README.md)
