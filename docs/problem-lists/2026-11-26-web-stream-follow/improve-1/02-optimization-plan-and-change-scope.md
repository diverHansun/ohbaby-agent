# 消息区的跟随与回看

用户在等回答时，应能持续看到刚出现的工具记录和正文。主动往上读时，应能一直读同一段。两种状态沿用消息区现有的“跟随底部”和“保留阅读位置”。

| 用户动作或页面变化 | 屏幕应怎样响应 |
| --- | --- |
| 消息尚未超出视口，用户向上滚动 | 停在原处；内容逐渐变长后继续显示最新消息。若还有历史页可加载，沿用列表原有的加载规则。 |
| 长列表中，用户向上回看 | 立即暂停跟随，让新消息在下方增长；阅读中的消息保持在原位置。 |
| 用户自己向下滚回底部附近 | 恢复跟随；沿用已有的 80 CSS 像素判定。 |
| 用户本来在底部，点正文或继续向下滚，随后过程折叠 | 浏览器会把超出新范围的旧滚动位置收回来。继续跟随，后续高度变化也能贴底。 |

改动落在 `ConversationStream` 的 `leaveBottom` 和 `onScroll`。前者检查消息区是否有可滚动距离。后者在处理输入标记前检查上次位置能否落在当前滚动范围内，避免把布局收缩记作用户回看。用户真实上滑和手动折叠仍由各自现有的处理函数决定。阅读锚点、历史分页及发送新提问使用既有接口。

全部输入来自浏览器。实现复用当前的跟随标志、上次滚动位置和消息区尺寸。现有页面布局已能表达这两个阅读状态，本轮不需要增加按钮或修改服务端协议。
