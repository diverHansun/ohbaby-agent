# 第一轮实施与验收

2026-11-26，两种错误退出跟随的操作都已在修复版通过 Chrome 端到端验收。

## 实际改动

生产代码只涉及 [ConversationStream.tsx](../../../../apps/ohbaby-web/src/ui/conversation/ConversationStream.tsx)。`leaveBottom` 在内容放得下一屏时保留跟随。原有滚轮、触控及键盘处理继续检查是否需要加载历史。

`onScroll` 在三个条件同时成立时丢弃上一次输入留下的标记：原先正在跟随、旧偏移与新上限的差值大于 1 CSS 像素、当前仍靠近底部。最后一项沿用既有的 80 像素判定。Chrome 点击正文后的首次折叠事件可以落在新底部上方 30 像素，只识别恰好贴底会漏掉此例。此处清除标记也避免向消费者误报一次用户主动回底。随后照常保存阅读位置。

真实向上滚轮会先同步退出跟随。对于已有输入标记、列表同时收缩的情况，组件测试也验证了用户最终落在新底部以上 120 像素时能继续读原处。若拖动与布局收缩恰好同时发生且落点在底部附近，仅凭几何信息不能还原两者的先后。

## Chrome 端到端结果

在隔离工作区启动实际 daemon，Chrome 打开编译后的 Web，通过输入框发送提问。可控模型分批输出，每次运行共收到 6 次模型请求，5 次实际文件读取的结果回到模型。浏览器收到 SSE 数据，数据库记录运行成功。旧产物为 `index-BQsUXjo3.js`，修复产物为 `index-3PuCJ5BX.js`。点击和继续向下滚分别使用独立浏览器配置与数据库。

| 实际操作 | 修复前 | 修复后 |
| --- | ---: | ---: |
| 不足一屏时上滚，等消息区由 806 像素增长到 2,360 像素 | 距底 1,554 px | 距底 0 px |
| 有意上翻 480 px，随后正文增长 501 px | 顶部偏移保持 1,074 px | 顶部偏移保持 1,074 px |
| 自己滚回底部，随后正文再增长 286 px | 距底 0 px | 距底 0 px |
| 在底部点正文后收起过程，再将可视高度从 806 缩到 636 像素 | 距底 200 px | 距底 0 px，能看到回答末尾 |
| 在底部继续向下滚后，同样收起过程并缩小视口 | 距底 170 px | 距底 0 px，能看到回答末尾 |

缩小视口用来区分“折叠瞬间碰巧落到底部”和“仍在跟随之后的布局变化”。独立复跑修复版点击场景得到相同结果。生产构建和测试实例都在临时目录，验收后已停止测试 daemon 并清理测试数据库与 Chrome 配置。

## 自动化与边界

[组件回归测试](../../../../apps/ohbaby-web/src/ui/conversation/history-autoload.unit.test.tsx)覆盖短页上滑、底部点击后收缩、底部滚轮后收缩，以及收缩时用户真实离开底部。前三例在旧代码上均失败。最终 Web 测试共 105 个文件、1,344 项全部通过，Web 类型检查及改动文件的格式、ESLint 检查通过。

本轮验证了桌面 Chrome 的鼠标滚轮、点击和窗口尺寸变化。没有实机触控测试。原 Chrome 标签页首次丢失跟随的输入仍无法追溯；Page Down 的单独现象见[问题分析](01-problem-analysis-and-current-state.md)。
