# 讨论记录与已确认要点

> 2026-11-20 与用户讨论定稿。证据与推理见 01，方案见 02，验收见 04。

## 1. 背景与动机

用户在 Web 上打开一个很长的会话（`~/Downloads` 目录下的 `session_1794834837609_a4f1aq1`），往上翻时看不到早期的消息。顶部出现 `Load earlier messages` 按钮，点了以后仍然看不到正文。用户希望去掉这个按钮和文字，加载时只显示一个小 spinner，前端保持轻量。

在此之前，Codex 用这个会话做了只读排查（浏览器复现、接口检查、数据库核对），结论是：

- 滚到顶部不会触发分页，只有点按钮才会请求上一页。
- 按钮能翻页，但拿不到旧正文。主会话在 SQLite 里有 101 条消息记录，早期的原文都还在。两次点击都返回 HTTP 200，第一页 44 条消息全部没有内容，第二页返回 0 条。后端读取历史时过滤掉了已压缩的正文。
- 第一条能看到的内容前面有 19 个零高度的消息行，每行仍然占 26px 间距，第一条正文因此被推到滚动区顶部往下约 602px 的位置。

本次核查确认了以上三点，并补充了根因：项目里关于已压缩内容有两套互相矛盾的规则，详见 01。

## 2. 已确认：目标与范围

| 编号 | 决策项 | 结论 |
| --- | --- | --- |
| D1 | 已压缩内容给不给人看（方案 A） | UI 投影一律显示原文。`time.compacted` 只决定发给模型的上下文，不决定给人看什么。摘要消息照旧显示为压缩分隔线，不显示摘要正文 |
| D2 | 改在哪一层 | 改 `messageToUiMessage` 这一个投影入口。主会话的首屏、实时更新和历史分页一起生效，TUI 也跟着生效。子代理历史里那两处“先清掉压缩标记”的补丁随之删除 |
| D3 | 压缩点之前的旧回答能不能分叉 | 能。`findForkableMainRun` 去掉同一个过滤，和 UI 看到的保持一致。复制历史那层已经支持切到压缩点之前 |
| D4 | 压缩点之前的用户消息能不能编辑重发 | 不能，后端已有的拒绝保持不变。前端在压缩分隔线之前的用户消息上不显示编辑按钮，判断规则和后端一致 |
| D5 | 怎么加载更早的历史 | 上滑接近顶部时自动加载上一页，一页不够就接着加载，去掉按钮。在滚动处理里判断滚动位置来触发。讨论初期推荐过 IntersectionObserver 哨兵，比较后改用这种方式，原因见 03 §3.3 |
| D6 | 加载中显示什么 | 只显示一个小 spinner，不显示任何文字。给读屏软件留一个看不见的状态文案 |
| D7 | 加载失败怎么办 | 不提示，spinner 消失。至少隔 2 秒后，用户再次上滑接近顶部时自动重试。子代理对话详情原有的通用错误条（错误文字和 Retry 按钮）保留，翻页失败时照旧显示 |
| D8 | 历史失效时怎么办 | 去掉 `Earlier history changed…` 提示和 `Refresh earlier history` 按钮。已经翻过历史时，消息只是被挤出热窗口，不清掉已加载的页，也不改游标。热窗口外的旧消息真被改了、视图换代、断线重连后重新拉了基线，才标记失效，下次接近顶部时自动重新拉取。后端保存思考内容时，只在这条消息不在热窗口里才发失效 |
| D9 | 空消息 | 没有可显示内容的消息行不占位置，也不占行间距 |
| D10 | 影响范围 | 主会话、Side Chat、子代理对话共用 `ConversationStream`，三处一起改 |
| D11 | TUI | TUI 代码不改。修完后在 TUI 里翻一遍长会话，确认显示正常 |
| D12 | 文档落点 | `docs/problem-lists/2026-11-20-web-history-paging/improve-1/`。改动点少，不建模块级 improve 文档 |
| D13 | 关键改动清单 | 02 写关键改动清单，承重项标到符号和行号快照 |
| D14 | 什么时候自动接着拉下一页 | 只有游标真的往前走了（或已确认没有更多）才接着拉。加载函数返回 `true` 或 `false` 告诉列表有没有进展；没有进展就停下，等用户再滑，不会空转 |
| D15 | 分叉时压缩标记怎么去留 | 看对应的摘要有没有一起复制：被复制的消息里找到最后一条压缩摘要，压缩时间比它晚的标记都去掉。不再拿压缩时间和最后一条消息的时间比，避免同一毫秒时出错 |
| D16 | 每页的大小 | 每页 50 条限制的是条数，工具输出原样传，一页可能有几百 KiB。本轮不加大小上限，验收时测量第一页、第二页的响应大小和滚动流畅度，测出问题再开下一轮 |

## 3. 已确认：边界（不做的事）

| 项 | 结论 |
| --- | --- |
| 虚拟列表 | 不做。现在的问题不在渲染性能 |
| 按字节限制每页大小 | 不做，先测量（D16） |
| 新接口、新字段、数据表变更 | 不做。分页接口和游标都是现成的。只把几个加载函数的返回值从 `void` 改成 `boolean`（D14） |
| 给 `UiMessage` 加“已压缩”标记 | 不做。UI 不需要区分已压缩和未压缩 |
| 允许回退到压缩点之前 | 不做，后端拒绝规则不变 |
| 压缩分隔线的样式和文案 | 不动 |
| 加载失败的提示、按钮或文字 | 不新增。子代理详情原有的错误条保留，见 D7 |
| TUI 的加载方式和样式 | 不动，见 D11 |
