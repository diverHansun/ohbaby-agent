# 讨论记录与已确认要点

日期：2026-09-29。来源为本次用户对话和截图；以下整理有效结论，不复原未记录的对话。

## 背景

用户希望 Web 在运行时保留可读的执行过程，完成后让最终回复更突出。原生实心三角显得笨重，thinking 与整轮过程需要使用大小不同的线条箭头。

本次先讨论、调查参考项目，再写入 `docs/problem-lists/`。暂不开发。

## 已确认的展示规则

| 情况 | 展示方式 |
| --- | --- |
| 运行中 | 过程正常显示，最终回复流式输出期间也不提前整轮收起 |
| 正常完成、有最终回复、没有中途补充消息 | 全部输出结束后，自动收起该 run 的过程 |
| 失败、手动停止、异常中断 | 整轮过程保持展开 |
| 中途补充过消息，或没有最终回复 | 正常展示，不提供整轮折叠操作 |
| 没有过程可收起 | 只显示耗时，不提供空的折叠操作 |
| 消息没有明确关联到该 run | 按原样显示，不通过位置或时间猜测归属 |

用户消息、最终回复始终可见。中间回复、thinking、工具调用和结果、子代理派遣等可见过程内容，在满足条件时收起，仍能再次展开查看。

“过程保持展开”指外层过程没有被整体隐藏，不要求所有 thinking、工具详情同时打开。reasoning 完成后保留并局部折叠；局部控件继续可用。

## 已确认的耗时与箭头

- 正常完成并有最终回复时，`Total {time}` 位于最终回复前。
- 时间与箭头是同一点击区域；箭头隐藏时，时间仍可点击。
- 收起使用向右线条箭头，展开使用向下线条箭头。
- thinking 使用约 12px 箭头，整轮使用约 16px 箭头。
- 箭头跟在文字后面，初始间距为 8px。观感参考当前工具标题与用户截图，避免过近或过远，不把箭头推到整行最右端。
- 隐藏箭头时保留布局位置，hover 前后文字不跳动。
- thinking 箭头常显；耗时旁箭头在 hover 或键盘聚焦时显示；无 hover 的触屏设备常显。
- 数值是实现起点，验收时用真实页面截图检查，并结合用户反馈微调。

用户提供的间距参考图已保存在议题目录。参考的是文字与线条箭头的关系，不据此将现有 `Total` 文案改为“用时”，也不把截图的物理像素直接当成 CSS 像素。

## 范围与概念

复用现有 run 身份、prompt 完成状态和 steer 关联。一个排队 prompt 被独立执行时形成新 run；steer 是补充到当前 run 的输入，不为展示而重定义 run。

不新增“归属不明”或“没有最终回复”等运行状态。它们只影响前端是否生成折叠入口。无 `final_answer` 标记的模型不需要特殊后端适配；本方案等待整体完成，不在首个最终 token 到来时折叠。

不修改模型请求、持久化方式、SDK DTO、工具卡既有默认状态、TUI。reasoning 的“保留”指可用内容仍可展开查看，不借此新增跨刷新持久化承诺。

方案附大致文件清单即可，不列逐行改动表，不扩大改造范围。用户原话：

> 补充大致的文件清单即可，不要过度设计，这应该不是大范围的修改
