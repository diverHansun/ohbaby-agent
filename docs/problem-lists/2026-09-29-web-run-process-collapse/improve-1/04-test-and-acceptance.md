# 测试与验收标准

本文件是后续实施的验收契约，以下均为待验证要求，不表示规划阶段已经通过。沿用 [docs-test](../../../../docs-test/README.md) 和 [Web 测试设计](../../../ohbaby-web/test.md)，不另建项目测试体系。

## 分层与范围

- 纯资格判断、正文与过程划分若提取为辅助函数，用 colocated unit 测试验证消息集合和顺序。
- 用 jsdom 组件测试验证流式到终态的变化、手动点击、可访问属性、用户与正文不被隐藏。复用现有 typed DTO fixture。
- 浏览器验证 CSS、真实布局、hover、触屏、键盘与滚动。无需为了几个 CSS 数值编写解析 CSS 文本的测试。
- 使用可控消息和完成事件，不依赖真实模型的随机输出，不重新调用收费模型 API。

## 关键场景

| ID | 场景 | 验证结果 | 阶段 |
| --- | --- | --- | --- |
| T1 | reasoning → 中间回复 → 工具 → 最终回复流式 → succeeded | 最终回复仍 streaming 时不整轮折叠；全部完成才收起；Total 在正文前，用户和完整正文可见 | 1 |
| T2 | prompt 成功事实先到，最终消息随后定稿；或反过来 | 无提前收起、闪现空回答或重复 Total；不靠超时等待猜测 | 1 |
| T3 | 只有最终正文，没有任何过程 | 只显示耗时，无空按钮、无箭头，无 `aria-expanded` | 1 |
| T4 | 只有工具/思考/空白尾消息，没有最终正文；前面有“正在检查” | 全部正常显示，不把旧进度文本当最终回复 | 1 |
| T5 | 最终 assistant 同时带 reasoning 与多个 text parts | 收起只隐藏 reasoning；全部正文保留一次；展开恢复思考，不重复正文 | 1 |
| T6 | failed、cancelled、interrupted，含部分回复和工具结果 | 外层保持可见，原错误/停止文案存在；局部控件按原规则工作 | 1 |
| T7 | 有明确 user-steer；或先收到 steer receipt，消息稍后到 | 该 run 不整轮折叠；补充消息原位显示；不产生第二条 Total | 1 |
| T8 | 普通 queued prompt，未转 steer | 排队用户行始终可见；当前 run 仍可正常折叠；下一 run 独立判断 | 1 |
| T9 | 混有无 runId 的消息、其他 run 消息、普通系统通知 | 未关联消息保持显示与顺序，不因相邻位置被吞入；已有内部噪声仍隐藏 | 1 |
| T10 | 单条 reasoning 的实时投影路径与 part 路径 | 流式时展开，结束后局部收起，内容仍可取回；SVG 替代原生 marker，手动展开不因无关更新重置 | 1 |
| T11 | 用户手动展开已完成 run，再刷新同轮数据或加入下一轮 | 已展开内容保持；新 run 不继承上一轮选择；session 间状态隔离 | 2 |
| T12 | 工具调用与结果、派遣入口经过收起/展开 | 不重复工具卡、不丢输出、派遣入口仍可打开子会话；局部状态不被无关重挂载重置 | 2 |
| T13 | 分页/历史加载，终态与消息不完整 | 不猜测缺失正文；补齐后按相同规则呈现；不移动无归属消息 | 2 |
| T14 | acceptedAt 不同于 createdAt，或 endTimeSource 为 recovery | 延续原计时口径；恢复时间继续显示未知，不冒充真实耗时 | 1 |
| T15 | 根/子会话复用，子会话缺少主 prompt 完成记录 | 不误折叠，不改变 fromParent、消息原顺序与委派定位 | 2 |
| T16 | 上方阅读、底部跟随、显式定位隐藏过程、焦点落在过程内 | 保持可解释的阅读位置；定位先展开；隐藏时焦点转到可见入口 | 2 |

“保留”与“隐藏”的断言应检查实际可见性及可再次展开，不只检查 DOM 是否存在或 `textContent` 是否包含文本。不要把合法的 CSS 隐藏误判为内容丢失。

## 浏览器视觉验收

由实施/验收 agent 打开真实 Web 页面，观察并保留能复查的截图；结合用户建议调整最终间距。不能仅凭 JSX 或 CSS 推断“看起来正确”。

1. 同屏查看短 thinking、带结束后缀的长 thinking、短耗时、分钟级耗时和现有工具行。两档箭头可分辨，线条风格一致；8px 为初始 gap，以视觉距离而非截图物理像素硬套 CSS 值。
2. 文字、间隙、箭头均可点击；耗时箭头不可见时点击时间仍能展开。鼠标移入移出时文字不挪动，箭头不跑到阅读列最右端。
3. Tab 聚焦时箭头和焦点样式可见，Enter/Space 正确切换，`aria-expanded` 与实际一致。收起内容没有隐藏的可聚焦元素可被 Tab 访问。
4. 在无 hover 的触屏模拟下箭头常显，一次点击完成切换。窄屏与 200% 缩放下不挤扁图标、不出现双 marker、不横向溢出。
5. 长过程收起前后，分别验证底部跟随与用户向上阅读；不跳回顶部、不误触发历史加载、不让焦点消失。
6. 显式打开派遣消息锚点时先展开相关过程，仍定位到正确消息。根/子会话切换、浮层与放大页保持原行为。
7. 减少动态效果模式下取消非必要过渡；普通模式不添加大段高度动画。

验收记录最终 gap、两档图标尺寸、桌面/触屏截图及用户反馈。8px、12px、16px 允许为观感微调，不以“数字未变”替代视觉判断。

## 执行入口

后续开发首先运行相关测试与 Web 类型检查；若新增同目录测试文件，把它们纳入以下测试入口：

```sh
pnpm exec vitest run apps/ohbaby-web/src/ui/conversation
pnpm --filter ohbaby-web typecheck
pnpm --filter ohbaby-web build
```

提交、PR、合并阶段继续遵循项目 [CI 规则](../../../../docs-test/ci-strategy.md)。涉及子会话装配或事件归约时补跑对应既有测试；无相关改动不扩展到模型 API 测试。

## 集成与回归边界

只消费现有 SDK 数据，不增加协议快照或持久化迁移。重点保护已过滤的内部子代理输入、Todo 噪声过滤、工具 call/result 配对、Markdown 消毒、command notices、审批交互、stop/steer 调度、历史顺序及阅读定位。

## 验收门槛与对抗性检查

以下问题任何一项成立都不能判定完成：

- 只凭停止流式就折叠，失败也被当成成功；用已有 succeeded 事实和定稿数据共同约束。
- 用户消息、最终正文或无 runId 消息被隐藏；检查消息与 part 层面的控制范围，不接受基于相邻范围的猜测。
- 最终消息带 reasoning 时留下整个思考块，或误收全部正文；用混合 parts 用例验证。
- 每次刷新都把手动展开收回；用同 run 重渲染和新 run 更新验证。
- jsdom 测试通过却发生真实滚动跳动、触屏入口不可发现或 hover 位移；浏览器结果是该部分必要证据。

残余限制：历史数据缺少完成事实或明确关联时，本轮选择保持正常展示，不能保证所有旧会话都生成折叠入口。没有修改后端来补这些数据，也不新增“未知”提示。

实施结束后按 02/04 独立验收，再创建 `05-implementation-acceptance.md`，说明实际改动、验证结果、视觉微调和仍存在的限制。
