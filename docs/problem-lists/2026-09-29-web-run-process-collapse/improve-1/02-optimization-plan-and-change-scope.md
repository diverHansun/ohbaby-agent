# 优化方案与改动面

本文件供后续开发会话实施；当前会话只写文档。产品约束以 [00](00-discussion.md) 为准，验证方式见 [04](04-test-and-acceptance.md)。

## 方案总览

在现有消息流上增加一个轻量的整轮过程披露功能。前端读取已有 prompt 完成结果和消息身份，保留消息原顺序，只改变相关过程内容的可见性。折叠不会删除消息、改变模型上下文或向后端写入状态。

普通成功轮次的最终布局如下。展开时过程回到正文之前，耗时控制行始终紧邻最终正文之前；用户消息和最终正文不进入控制范围。

```text
收起：用户消息 → Total 36s  › → 最终回复
展开：用户消息 → 过程内容 → Total 36s  ˅ → 最终回复
```

上图箭头只是示意，实现使用 SVG 线条 chevron，不使用文本字符。

## 折叠条件与身份

### 什么时候自动收起

同时满足以下条件才生成可折叠的整轮过程：

1. 当前 session 存在与该 run 明确关联的主 prompt，状态为 `succeeded`，已有结束时间。
2. 该 run 的可见输出已定稿，没有明确处于 streaming 的消息或未结束的过程内容。最终正文流式输出期间继续展示过程。
3. 能从该 run 的已到达消息中确定一份可保留的最终正文。
4. 该 run 没有已接受的中途补充输入。
5. 最终正文之外确实存在可见过程内容。

整体成功来自 prompt 结果，不能由 `isRunning === false`、`UiRun.status.kind === "idle"`、单次模型请求结束或 `finishReason === "stop"` 单独推断。不设延时猜测“已经输出完了”。若完成事实先到、正文定稿后到，等二者齐备再折叠。

failed、cancelled、interrupted 均不自动整轮折叠。有 steer 或没有最终正文时正常展示，本轮不添加这些情况下的外层手动折叠功能；thinking 和工具详情的局部控件仍可使用。

### 消息如何归属

- 优先使用消息明确的 `runId`，并在当前 session 内与主 prompt 的 `runId` 对齐。
- steer 使用已有 `runtimeInputKind: "user-steer"` 及 run 关联，或 `steerReceipt.acceptedTargetRunId`。receipt 可先于对应消息到达，仍应阻止该 run 整轮折叠。
- `steered` prompt 自身的 endedAt 仅表示补充输入已接受，不能当作主 run 的结束时间，也不增加第二条 Total。
- 排队消息尚未被接受为 steer 时，不把它算作当前 run 的补充输入；它始终正常显示。将来独立执行时按自己的 run 判断。
- 没有明确关联的消息保留原位，不靠文本、时间邻近或两条 user 消息之间的范围推断。不把别的 run 的消息一起包入隐藏容器。
- 沿用当前噪声过滤，不恢复原本不显示的内部子代理通知或 Todo 工具消息。command notices、审批界面不纳入过程折叠。

不新增运行状态、SDK 字段或后端查询。子会话复用现有组件；没有主 prompt 完成事实时保持原展示，不为折叠功能扩展子会话协议。

## 最终正文与过程如何划分

这里只做展示选择，不判断正文在语义上是否“真正回答了问题”。选择顺序采用现有时间线顺序，不另按文本或时间戳重新分组。

1. 整体成功完成后，检查该 run 最后一个 assistant 输出消息是否有非空 text，且不是仍带工具调用的中间步骤；显式 streaming/error 消息不能作为定稿正文。
2. 如果最后输出只有 reasoning、工具调用或空文本，不向前寻找一句旧的进度说明冒充最终回复，直接按“没有最终正文”正常展示。
3. 保留被选中消息中的全部最终 text parts，沿用 Markdown 与消毒渲染。当前 SDK 只有 text/reasoning/tool-call/tool-result，本轮不设计未来多模态答案协议。
4. 之前明确属于同一 run 的中间回复、reasoning、工具调用和结果、派遣入口，作为过程内容。
5. 最终消息自身的 reasoning 也属于过程内容。仅有“thinking + 最终正文”的轮次仍有可折叠过程；不能因为二者共用 messageId 而一起隐藏或一起留在外面。

呈现可在 MessageRow 内增加小范围的内容选择，或提取局部渲染辅助函数；不得篡改原消息 DTO、复制一份可写消息状态或另建工具配对逻辑。保持原有 message/part/tool key，避免开关外层时重置工具状态或重播内容。

部分历史只按已有可靠数据呈现。只有结束记录却没有最终正文时不推断；加载更多后信息齐全，可按正常规则产生折叠入口。单纯 `historyHasMore` 为 true 不意味着所有已加载轮次都不能折叠。

## 耗时位置与计时含义

- 有可确定的最终正文：终态耗时放到它前面；满足折叠条件时作为控制按钮，否则是普通耗时文本。
- 没有最终正文：保留当前正常时间线和结束提示位置，不把耗时放到旧的进度说明前伪装成结论。
- 失败/停止的状态文案和 recovery 的 `End time unknown (recovered)` 继续保留，不伪造真实完成时间。
- 没有过程：只显示原有耗时文本，无箭头、无 `aria-expanded`、无空按钮。
- 继续使用 PromptDuration 的 acceptedAt/createdAt/endedAt 口径；本轮只改位置与交互，不把 Total 偷换成模型耗时或纯运行耗时。
- 不额外增加运行中的 Total 计时器。既有 Thinking 等待指示器保持原行为。

## 箭头、间距与点击区域

| 项目 | thinking 披露行 | 整轮耗时行 |
| --- | --- | --- |
| 图标 | 约 12px 线条 chevron | 约 16px 线条 chevron |
| 方向 | 收起向右，展开向下 | 收起向右，展开向下 |
| 位置 | 在完整标题文字右侧 | 在完整 `Total {time}` 右侧 |
| 初始间距 | 8px | 8px |
| 显示 | 常显 | 有 hover 的设备：hover / focus-visible 显示，其余隐藏；触屏无 hover 时常显 |
| 操作区域 | summary 文字和图标一起可点击 | 时间和图标合为一个原生 button，隐藏图标时仍可点击时间 |

优先复用已有 `lucide-react` chevron，统一线条风格，不增加图标依赖。图标不可被挤扁；移除 reasoning 原生 marker，避免实心三角与 SVG 同时出现。

采用随内容宽度排列的文字与图标，不使用 `justify-content: space-between` 把图标推到行尾。隐藏图标只改变透明度，保留尺寸和间距。鼠标命中范围包含文字、间隙和箭头，不要求瞄准细线。

reasoning 的标题可能有 interrupted、failed、saving 等后缀，箭头跟在完整标签之后。长标签和窄屏不能压缩箭头。现有工具行 14px 图标、10px gap 和全宽摘要布局不随本轮改动。

使用可见键盘焦点，原生 Enter/Space 操作，整轮按钮正确设置 `aria-expanded` 和与受控内容的关联，SVG 为装饰元素。隐藏内容不可继续进入 Tab 顺序。无 hover 的设备通过媒体查询显示箭头，不要求先点一下才发现按钮。

8px 与两档尺寸是用户同意的初始规格；最终用真实浏览器查看文字、SVG 实际笔画、缩放与触屏效果后微调。验收记录实际采用值，无须为几像素调整引入配置系统。

## 展开状态与阅读位置

整轮自动收起发生在首次具备完整条件时。用户随后展开的状态，在当前会话组件存活期间按 session/run 身份保留；普通重渲染、新一轮消息到达或同一轮快照刷新不覆盖手动选择。页面刷新后可重新按默认规则呈现，不增加后端或 localStorage 持久化。

局部 reasoning 正常结束时收起并保留内容；之后手动展开不应被无关渲染反复重置。外层展开时不强制打开每张工具卡，也不清除其已有状态。

沿用现有阅读模式：正在跟随底部时，完成后的最终回复仍留在阅读区；用户已经向上阅读时，不强行拉到底部。若当前阅读锚点或键盘焦点落在即将隐藏的过程里，使用该轮耗时入口作为可见替代锚点，并在必要时接管焦点，避免焦点留在隐藏节点内。显式跳转某条过程消息时先展开所属过程，再执行现有定位。

不为整轮高度做复杂动画。箭头/透明度可沿用已有短过渡，减少动态效果设置下取消非必要动画。浏览器验证实际滚动，不用 jsdom 的布局结果替代。

## 兼容、风险与回滚

无 API 或数据库迁移。只读已有字段；老消息字段不完整时继续正常显示。消息无明确 runId 不会被收起，是保守的展示结果，不新增告警或“未知状态”标签。

主要风险是终态先于正文到达、把中间文本误当结论、误隐藏同消息中的正文、重复渲染重置手动展开，以及隐藏节点造成滚动或焦点跳动。04 分别覆盖这些行为。

回滚只需恢复 Web 原呈现逻辑和相应样式，不恢复数据库或修改会话历史。状态全部留在前端，回滚不会改变消息事实。

## 不在本轮

不做首个 final token 前折叠、模型 phase 识别、额外 LLM 请求、后端状态扩展、跨刷新折叠记忆、steer 多段展示、整个时间线架构改造、工具卡视觉重做或 reasoning 持久化改革。它们不是预定的 improve-2。
