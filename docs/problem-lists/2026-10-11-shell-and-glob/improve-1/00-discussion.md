# 讨论记录与已确认要点

> 来源：2026-10-11 当前会话的多轮讨论。只记录已确认结论；具体工程设计见 [02](02-optimization-plan-and-change-scope.md)。

## 背景

Shell 已经调用真实系统解释器，但只继承进程环境。之前针对 LLM / Search 的系统代理适配没有自动传递给独立子进程，可能出现主代理请求成功、Shell 中 curl 请求失败的情况。

## 已确认的目标与范围

| 项           | 结论                                                                               |
| ------------ | ---------------------------------------------------------------------------------- |
| 分批         | improve-1 做网络；improve-2 做 Shell / Glob 和解释器平台适配；本次同时撰写两套文档 |
| 网络来源     | 继承显式代理配置，自动适配系统静态 HTTP / HTTPS 代理                               |
| 本机含义     | 运行 ohbaby 后端的主机与当前用户；远程 Web 会话使用后端主机网络                    |
| 子进程       | 主代理、subagent 启动的 Shell 及 MCP stdio 进入同一网络配置传递流程                |
| 配置优先级   | 显式配置优先，不能被系统发现的代理覆盖                                             |
| 无法可靠应用 | 允许本次 Shell / MCP 启动失败，明确说明网络配置问题                                |
| 已运行进程   | 保留启动时环境，不擅自重启后台 Shell / MCP                                         |
| 本地工具     | Read / Glob / Grep 等本地操作不因代理异常失效；内部 ripgrep 不接代理启动门禁       |
| 文档交付     | 附关键待改文件、函数和清单；后续实施可以删除或重构不再需要的代码                   |
| SWE          | KISS、复用现有模块，不为所有子进程搭建通用框架，不设计过多兜底                     |

## 不在本批

PAC 自动代理及其脚本执行；通用 SOCKS / 企业认证新增支持；Linux 各桌面的系统代理发现；任意外部程序的全流量接管；已运行进程环境热更新；解释器切换、Shell 语法分析、Glob 引擎改造。

显式环境变量的继承不等于外部程序一定遵守这些变量。受支持的 HTTP / HTTPS 路径需要真实验证；程序自身明确覆盖网络配置属于该程序行为。

## 关联约束

保留主进程当前代理异常时拒绝外部请求、允许本地控制连接的规则。Subagent 审批、会话归属及后台任务清理不因本批改变。

## 用户确认记录

> “网络问题：继承显式代理配置＋自动适配系统静态 HTTP/HTTPS 代理，不做pac自动代理”

> “代理配置无法可靠应用时，接受该次 shell/MCP 启动失败”

> “需要关键文件和清单”

> “不要过度设计，遵循swe原则，kiss”

用户随后确认三个平台的 Shell 选择、Glob 保留现有行为，并授权开始撰写文档、子代理审查及 Pi `copilot/opus-5.5 medium` 审查。评审建议作为证据输入，由主代理核对后纳入方案。
