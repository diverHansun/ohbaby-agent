2026-11-11。来源是本轮 Web 走查及随后与用户的讨论。行为已确认；02 中具体的存储与投影安排属于据此提出的规划，仍由本轮文档审查把关。

## 1. 背景

Side Chat、Fork、Rewind 后端完成后，用户完成了 Web 和 TUI 实现。Web 走查复现主会话和 Side Chat 没有 AI 正文，Thinking 反复出现、消失。真实请求确认 Zenmux 返回限流，同时应用的重试状态和错误展示存在缺口。

用户要求：

> 错误提示的后端字段 / 错误提示的 UI 显示时机（什么时候显示？显示在哪里？什么时候消失）。

> spinner 应该跟随什么状态进行合理显示。

> 遵循 SWE 原则，KISS，不要过度设计。前端不给用户造成焦虑，仅显示必要关键的信息，但后端字段可以适当记录全。

## 2. 已确认行为

| ID  | 决策                                                                                                                            |
| --- | ------------------------------------------------------------------------------------------------------------------------------- |
| D1  | 自动重试期间只显示普通等待状态，不弹错误卡片；默认不显示次数、倒计时、HTTP 状态码或内部错误码。                                 |
| D2  | 等待动效表达当前模型步骤正在等待可展示输出；不能直接绑定整个 `run.running`，也不能只绑定单次 HTTP 请求。                        |
| D3  | 重试期间保留同一行，同一次请求链的等待计时不归零；正文、Thought 或工具进度已在表达进展时，不叠加模型等待行。                    |
| D4  | 最终失败后，在所属轮次末尾显示一份简短原因和下一步；Side Chat 的错误只出现在自己的会话。                                        |
| D5  | 失败提示不按时间自动消失，随历史滚动，可手动关闭；当前浏览器标签页刷新后保持关闭，后端记录不删除。                              |
| D6  | 已输出部分内容后中断，保留已有内容并说明中断；本轮不新增自动重发或自动续写。                                                    |
| D7  | 用户主动停止用正常停止状态；工具失败但模型仍可继续时，错误留在工具反馈内，不升级为整轮失败。                                    |
| D8  | 排队、审批、工具执行、压缩、连接恢复使用各自状态；连接反馈补充见 D13，刷新不能把已结束的运行恢复成无限等待。                    |
| D9  | 复用现有错误契约和请求关联。诊断记录可以更详细，但要筛选、脱敏，不能把全部原始请求或响应传到 UI。                               |
| D10 | 同一个错误在 prompt、run、message 中可以有各自的数据形态，但原因和状态必须一致；`retryable` 不作为自动重发指令或 spinner 开关。 |
| D11 | 界面沿用英文文案和现有轻量样式；动效遵守减少动态效果设置。                                                                      |
| D12 | 测试围绕真实缺口，复用现有测试；E2E 直接用命令和浏览器操作，不新增需要长期维护的 E2E 脚本。                                     |
| D13 | daemon 断线约 10 秒仍未恢复时，停止转圈并显示静态“已断开”；后台继续自动重连，后续自动尝试不反复重启动画。                       |

Web 的“关闭后刷新保持关闭”不扩展为跨设备已读系统。TUI 没有浏览器标签页语义，本轮只对齐活动阶段和终态结果，不新增关闭历史错误的快捷键。

## 3. 已确认边界

- 保留目前每个普通模型步骤的重试预算及退避策略。
- 保留已有正文、reasoning、工具调用碎片或完成信号后不自动重放的边界；`firstTextAt` 仍只记录首正文时间。
- 不新增通知总线、重试框架、错误日志数据库、全局错误面板或详情弹窗。
- 不重做 Fork、编辑重发、审批及普通工具错误的交互；这里只保证它们不会被模型等待状态覆盖。
- 规划阶段先讨论；2026-11-11 用户已授权按本轮方案实施后端，见第 9 节。
