# 4. 测试与验收

## 4.1 测试策略

- **增量和补全**是纯逻辑，写单测，放在 `apps/ohbaby-web/src/ui/shared/markdown-stream.unit.test.ts`。
- **消息接入**写组件测试，沿用 `MessageRow.unit.test.tsx`、`ConversationStream.unit.test.tsx` 的方式。
- **观感和滚动**用 `.claude/launch.json` 里的 `ohbaby-web-mock` 或真实 daemon，在浏览器里走一遍流式输出。

| 编号 | 场景 | 通过标准 |
|---|---|---|
| U-1 | 含标题、列表、表格、代码块、引用、setext 标题的文档，按 1、2、3、5、8、13、40、200 字符分块输出 | 结束时冻结 HTML 加结尾 HTML 等于全量渲染结果 |

## 4.5 对抗性审查要点

- 冻结片段和结尾片段都经过 `DOMPurify` 了吗？这是唯一的安全防线。
- `useLayoutEffect` 里有没有被改成异步更新？异步会破坏自动滚动。
- React StrictMode 下 effect 重复执行时，内容会不会重复追加？相同文本必须不产生冻结片段。
- `.ohb-streaming-text` 的三处都删干净后，工具面板的 `pre` 样式还在吗？
- 委托锚点和折叠回退写阅读位置时，清空 `blockIndex` 和 `blockOffset` 了吗？否则会按旧的块恢复。
- 从 `StreamingMarkdown` 切回 `MarkdownBlock` 时，复制按钮的 token 是否仍能通过校验？
