# 讨论结论

## 用户反馈的问题

用户在会话里观察到，ohbaby 的模型很少用 read、list、glob、grep，查看文件和搜索代码时总是用 bash。默认权限下 bash 每次都要审批，原生工具却可以直接用，所以这样既慢又烦。用户想知道原因到底是模型能力不够，还是我们给模型的工具引导没做好。

## 调查后确认的结论

- 工具注册和传输链路没有 bug，原生工具的名字、描述和参数都完整发给了模型。
- 主要原因是引导不到位：bash 描述里没说"查看文件请用 read"，原生工具的描述写的是实现细节而不是用法，路径参数的描述还让模型以为原生工具读不了工作区外的文件。
- 模型偏爱 shell 是放大器。原生工具的能力缺口（grep 不能带上下文行等）会把模型推回 bash。
- 证据和分析见 [01](01-problem-analysis-and-current-state.md)。

## 用户确认的方向（2026-11-27）

1. **不完全禁止 bash 查看文件。** bash 仍然可以用 `cat`、`head`、`tail`、`sed -n`，但要像 kimi-code 那样讲清原因：能用 read/list/glob/grep 完成的，先用内置工具。bash 主要用来跑命令、跑任务，以及做内置工具做不到的事。
2. **同时优化工具描述和系统提示词。**
3. **只读 bash 建议免审批。** 因此 grep、glob 的能力也要补强，bash 的权限设计也要调整。
4. **分三轮做：**
   - improve-1：工具描述和系统提示词优化（本轮）
   - improve-2：内置工具能力升级
   - improve-3：只读 bash 免审批；bash 命令本身的能力优化没必要就不做
5. **文档放在 `docs/problem-lists/` 下。** 工具描述和系统提示词部分要有关键改动清单。
6. **工具描述要请三个模型协助优化。** 通过 calling-pi 调用 `magpie/claude-opus-5-5`（medium）、`magpie/auto-gemini-4-neon`（high）、`magpie/openai-codex/gpt-6.2-astra`（high），参考 code-cli 下 kimi-code、ZCode、claude-code 的提示词和设计。其他任务在实施中和实施后，可以调用 `magpie/auto-gemini-4-neon`（high）审核。
7. **先写方案初稿，再逐条讨论细化。**

## 逐条讨论中确认的结论

- **D1 引导写在哪里（2026-11-27 确认）**：三处分工，各司其职。bash 描述是主力，写映射表、理由和例外；原生工具描述第一句写"什么时候用、替代哪个命令"；系统提示词只写一条总规则，括号里举四组最常见的对照，不复制整张映射表。
  - bash 描述里的顺序：第一句说明解释器，然后是路由映射、理由和例外，再是 PowerShell/Windows 说明，最后是后台和超时。只能跑前台命令的分支也带上映射。
  - 本轮不在 bash 结果末尾附提示，登记为后续候选（02 §2.8）。
- **D2 引导理由（2026-11-27 确认）**：只写现在成立、放开只读 bash 后也成立的理由，跟在每条映射后面写，不单独写一段"为什么"。保留五条：read 带行号、能接着读；glob 跳过 `.git` 和常见的依赖、构建目录，grep 跳过 `.git` 和 `.gitignore` 忽略的文件；edit 匹配不上就失败；原生工具明确知道访问哪个路径，复杂 bash 命令每次都要审批；原生工具审批后也能访问工作区外路径。删掉"输出有上限""显示成文件链接""敏感路径检查"三条，因为 bash 也有输出上限和敏感路径预检，Web 端也没有文件链接。不写"bash 要审批"。
- **D3 语气（2026-11-27 确认）**：中等强度。标题语用祈使句"use the dedicated tools instead of shell commands"，末尾加一句出口：原生工具做不到，或者用户点名要 shell 命令时，可以用 bash。不用大写强调。实测显示太软时，只加强标题语。
- **D4 打包查询（2026-11-27 确认）**：只做查看的 bash 里 72% 是把多个查看命令串成一条，123 次用了 echo 分隔符。bash 描述照 kimi-code 的写法，点名不要用 `&&` 或 echo 分隔符拼查看命令，改为并行调原生工具。范围只限查看，拆分其他 bash 命令登记为 improve-3 之后的候选。统计脚本加 `bash_packed` 指标。
- **D5 子代理规则（2026-11-27 确认）**：子代理 base 加一个 `# Tool Use` 小节，放在"Doing Your Task"之后，内容和主代理总规则相同。explore、research 的任务提示不再重复。按角色统计，有工具规则的 explore 子代理 bash 查看只占 7%，没有规则的 generic 子代理占 63%。research 用 curl 和 python 抓网页是另一个问题，只登记不处理。

- **D6–D12、D14（2026-11-27 定稿）**：用户让我和 Gemini（high）把剩下的提示词细节商量定，只把关键问题拿回来问。逐条结论见 02 §2.2，文案见 02 §2.3。要点：Self-Configuration 改成用 `write` 建文件；路径参数写明工作区外也能用、首次要批准；PowerShell 提示列出 `Get-Content`、`Select-String` 等等价命令；每个缺描述的参数补一句，已对照代码核对；顺手清理几处和新文案矛盾的旧说法。
- **D13 原生工具不展开 `~`（2026-11-27 确认）**：核对时发现的真实 bug，会话库里有两次失败。用户决定放进本轮，做 Stage 0：单独一个代码提交，先于文案改动合入。D6、D7 里涉及 `~` 的措辞依赖它。这是本轮唯一改变代码行为的地方。

- **验收方式（2026-11-27 确认）**：用 `tests/models-4-tests.md` 里列的模型，API Key 用 `.env` 里对应的变量；做模型请求测试和端到端测试即可，不出固定题，不写自动化脚本，细节由实施会话决定。统计脚本只做事后观察。
