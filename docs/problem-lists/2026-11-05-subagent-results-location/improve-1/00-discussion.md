# 讨论记录与已确认要点

> 2026-11-05 与用户讨论定稿。第 2 至 4 节是讨论中确认的结论。第 5 节是写规划时根据代码勘测补充的决定，随整套文档提交用户审查。现状证据见 [01](01-problem-analysis-and-current-state.md)，实施方案见 [02](02-optimization-plan-and-change-scope.md)，参考项目见 [03](03-reference-projects.md)。

## 1. 背景与动机

子代理的最终报告超过 50KiB 时，系统会把全文导出成文件，再把路径交给父代理去读。这个文件现在放在平台数据目录 `~/Library/Application Support/ohbaby/storage/subagent-results/` 下，和会话存储区 `~/.ohbaby/sessions/<id>/` 分在两处。读它还要走一条专用的放行通道。

会话存储区设计好之后，用户提出在其他议题实施前先调整这个位置，并参考 code-cli 下的项目。讨论中还发现了一个问题：子代理提示词让子代理把长日志写进文件，却没说写到哪，结果这些文件都写进了用户的工作区。

## 2. 已确认：目标与范围

| 决策项 | 结论 |
|---|---|
| 议题 | 单独开一个议题，不并入会话存储区模块 |
| 位置 | `~/.ohbaby/sessions/<根会话ID>/subagents/<subagentId>/<executionId>.output` |
| 目录名 | `subagents/`，照 claude-code |
| 粒度 | 每个子代理一个目录，每次执行一个文件，和 kimi-code 一样。同一个子代理被 `send` 多次时，旧结果不会被覆盖 |
| 只导出报告 | 不额外导出对话记录或 `metadata.json`：两样数据库里都有，界面上也能看 |
| 扩展名 | 保留 `.output` |
| 权限 | 默认 `default` 权限档位下，`subagents/` 默认只读：`read`、`grep` 读取不弹审批，模型改写需弹审批，Bash 访问仍按外部路径审批；具体确认见 §7.4 |
| 谁能读 | 整个根会话都能读，包括主会话、所有子代理和 side chat。现在只有发起调用的那个作用域能读 |
| 专用读取通道 | 删掉 `authorizeInternalRead`，由存储区的只读权限代替 |
| 父代理收到的内容 | 不改。不超过 50KiB 给全文，超过了只给路径、字节数和估算 token 数，不加预览 |
| 子代理提示词 | 需要保存的完整日志和长篇分析写进 scratch，文件名区分任务；`explore` 保留只读要求。复查确认由存储区第一期完成主、子代理基础提示词改动，本议题做集成回归，见 §7.2 |
| `forceFile` | 删掉。它没有调用方 |
| 旧数据 | 不做兼容。本项目在快速迭代，还没有发布过正式版本 |

## 5. 规划中补充的决定

勘测代码时发现、讨论阶段没有覆盖的细节，理由见 01 和 02。

| 编号 | 决定 | 一句话理由 |
|---|---|---|
| P1 | 路径里的会话 ID 用执行记录的 `rootSessionId` | 存储区按根会话分。子代理不能再创建子代理，所以它现在和 `parentSessionId` 的值一样，但 `rootSessionId` 的含义和存储区的归属一致 |
| P2 | 在 `A/paths/session-storage.ts` 加 `resolveSessionStorageRoot(options?)`（返回 `<OHBABY_HOME>/sessions`）和常量 `SUBAGENTS_DIR = "subagents"`。结果导出用前者作存储根，键为 `[rootSessionId, "subagents", subagentId, "<executionId>.output"]` | 现有的 `Storage` 和 `PathResolver` 不用改。路径穿越检查、原子写入、符号链接检查照旧在这个根下工作。ID 由系统生成，`PathResolver` 的键校验已经挡住 `/`、`..` 这类穿越，不再另加存储区那套字符集校验 |
| P3 | 导出时建目录改用 `mkdir(dirname(path), { recursive: true, mode: 0o700 })`，代替现在的 `resolver.ensureParent(path)` | 正常情况下父会话运行过，会话目录已经在了。万一目录被删，重新建出来也是 0700，不会变成默认权限 |
| P4 | 删掉 `composition.ts` 的选项 `resultStorageRoot`。结果导出的根固定用 `resolveSessionStorageRoot()`，和存储区回调登记可信路径时算的是同一个位置 | 两处各自算路径，就可能不一致：文件写在 A 处，可信路径登记在 B 处，读的时候又要弹确认。测试照仓库约定用 `vi.stubEnv("OHBABY_HOME", ...)` 指到临时目录。`cleanupDeletedSessionFiles` 保留可选的 `sessionStorageRoot`（存储区第一期加的），daemon 不传，只给测试用，不会造成两处不一致 |
| P5 | `cleanupDeletedSessionFiles` 删掉 `subagent-results/<id>` 那一段和 `resultStorageRoot` 依赖 | 存储区第一期已经会删 `sessions/<id>`，子代理报告就在里面 |
| P6 | `OHBABY_STORAGE_ROOT` 和 `PathResolver` 的默认根不动 | 快照还在用它（`A/snapshot/diff-engine.ts:70`）。本议题只是不再把它用于子代理结果 |
| P7 | 数据库里旧记录的路径还指向旧位置，不写迁移代码 | 现有逻辑在记录的路径和新算出的路径不一致时会重新导出（`result-artifacts.ts:153-157`），下次送达时自动写到新位置。旧会话历史里写着的旧路径，读取时按外部路径确认 |
| P8 | `deleteSession`（`SessionEvent.Removed` 触发）和墓碑逻辑不改，只是路径换了 | 它管的是数据库里的导出状态，和目录清理是两回事 |

### 7.1 已确认：独立文件落点，不改变 cwd

用户澄清：“我的意思是临时文件、报告这些放到每个会话自己的目录，操作项目时还是用用户的 workspace，不需要改 cwd。”

- 保留原运行目录规则：有 workspace 时仍操作用户项目，没有 workspace 时仍沿用原默认目录。本轮不引入每会话 cwd，不做项目副本或 worktree。
- agent 的临时文件、报告和中间产物默认放进本会话 `scratch/`；正常项目修改和用户指定的项目文件按任务要求写入。
- 不重定向工具的相对路径。要写进 `scratch/`，模型需要使用对应路径。
- 用户要求进一步借鉴参考项目的 system prompt；后续确认的规则与注入方式见 §7.2。

已同步会话存储区的目标、架构、概念、数据流与运行目录验收场景。子代理结果搬迁仍依赖会话存储区第一期，不改变实施顺序。

### 7.2 已确认：基础提示词写规则，环境提醒给路径

用户明确：“固定规则分别放进主、子代理的基础提示词”，并确认“基础提示词写规则，环境提醒给路径，主子代理都覆盖”。

- 固定规则分别放在 `prompts/primary/base.md`、`prompts/subagents/base.md`，不新增公共提示词模块。
- 具体 scratch 绝对路径放在现有 environment 提醒中，覆盖主代理和全部子代理角色。
- 规则说明按需保存临时文件、报告和中间产物，保留正常项目文件的落点和只读角色的约束；不要求每次汇报额外生成文件。
- 本次确认的主子代理提示词改动由会话存储区第一期完成，包含改写子代理原有的长日志提示、生成提示词资源和验证实际请求。结果搬迁议题 Stage 3 改为核对和回归，不再重复安排同一改动。
- 具体规则见[会话存储区 dfd-interface §2.2](../../../services/session-storage/dfd-interface.md#22-告诉模型第一期)，参考依据见 [03 §3.9](03-reference-projects.md#39-实施前复查提示词与运行目录)。

### 7.3 已确认：同一根会话共享 scratch

用户确认：“同一根会话共享 scratch，不给每个子代理强制建独立目录。”

- 主代理和所属子代理使用同一个 `sessions/<ownerId>/scratch/`，不强制建立 `scratch/<subagentId>/`。
- 沿用已确认的提示词规则，以任务相关文件名区分文件、避免覆盖其他代理的文件；共享目录不扩大角色权限，`explore` 仍遵守只读要求。
- 此决定针对 agent 自己写的临时文件、中间产物与报告，不改变系统导出的 `subagents/<subagentId>/<executionId>.output` 结构。
- 已同步存储区的决定表、归属说明、目录模型及 S5 验收场景。

### 7.4 已确认：default 权限档位下的两档文件权限

用户确认：“scratch 可读写，系统报告和工具原文默认只读，改写需要弹出审批（默认 default 模式）。”

- `scratch/` 给 agent 读写；`subagents/` 和 `tool-results/` 给模型直接读取，模型改写时先弹审批。批准前以及拒绝、取消后均不执行写入。
- 这里的 `default` 对应现有权限档位 `Level`，不等同于 `plan`/`auto` 运行模式；不借本议题调整其他权限档位。
- “默认只读”是工具调用的审批规则，不是文件系统只读属性。系统自身保存报告和工具原文不走模型写入审批；用户显式授权仍沿用现有机制。
- Bash 访问系统文件仍按上一项讨论的外部路径规则审批；直接读取优先使用 `read`、`grep`。
- 已同步存储区的权限说明、S3/S3b，以及子代理结果搬迁的决策表与 T5。

### 7.5 已确认：随根会话保留，永久删除时清理

用户确认采用“随根会话保留，永久删除时一起清理，暂不做定时清理”。

- `scratch/`、`subagents/`、`tool-results/` 都跟随所属根会话保留。
- 一轮任务结束、子代理结束或关闭、会话归档及恢复、移动 workspace 均不自动清理这些文件。
- 永久删除归属根会话时，清理它的整个会话存储目录；不删除其他根会话目录和用户 workspace 中的项目文件。
- 暂不做定时清理，不增加过期时间、清理定时任务或清理索引。归档或长期未使用的会话会继续占用磁盘，这是本次明确接受的取舍。
- 已同步存储区的决定表、生命周期、删除流程及 S8/S9；子代理结果搬迁的 T9 同步核对清理范围。

### 7.6 已确认：初始化建目录，保存失败如实返回

用户要求参考 Claude 和 Kimi：“初始化时创建，对输出保存失败返回失败结果，不假装文件已保存。”

- 在会话运行初始化时准备 scratch 目录与可信路径，先于首轮模型请求和工具使用，不推迟到第一次写临时文件时才创建。
- 环境提醒反映实际准备结果，不能仅拼出路径就宣告可用。准备失败时明确说明不可用，不默认回退到用户 workspace。
- 系统输出保存失败时明确返回保存失败的信息，不返回保存成功提示或成功文件路径；能保留的内联结果仍可返回，不把保存失败混同为工具或命令本身执行失败。
- 子代理长报告沿用现有失败说明：原文仍在数据库，但结果文件不可用。第二期工具输出也采用如实报告失败的原则。
- 已同步存储区初始化、环境提醒、输出保存流程与 S2/S6/S10/S13；失败后的会话继续策略沿用原方案，不新增重试服务或持久化可用状态。

### 7.7 已确认：两项权限例外纳入第一期修正

用户确认：“这两个权限例外不再接受，纳入第一期一起修正，复用现有审批机制，不要过度设计。”

- 系统文件的保护判断先于普通 workspace 或上级可信目录的自动放行。即使 workspace 是 `~` 或 `~/.ohbaby`，改写本会话系统文件仍需对应授权；Bash 访问同样按已确认的审批规则处理。
- 用户批准读取，只授予读取权限，不能顺带允许写入或 Bash 目录访问。修正可信路径登记，也修正“始终允许”保存的会话规则，避免另一条授权路径仍放行写入。
- 复用现有调度器、Bash 预检与审批规则结构，区分读、写和 Bash 目录访问的规则身份；不新增权限服务、数据库表或另一套审批交互。
- 保留用户明确批准写入或 Bash 访问的能力，以及现有拒绝规则和 `full-access` 语义。scratch 默认可读写的规则不变。
- 由会话存储区第一期修正并验收，子代理结果搬迁以此为前置条件，不留到后续权限重构。现状证据见 [01 §1.10](01-problem-analysis-and-current-state.md#110-复查发现只读根不能覆盖上级可写根)，具体方案见[存储区 architecture §2](../../../services/session-storage/architecture.md#2-design-pattern--rationale)，验收见 S3c、S3d 与 T5b。

### 7.8 本轮复查收敛

完成 §7.7 文档同步后，主代理自检与子代理只读复核未发现存储区第一期及结果搬迁仍需用户取舍的新阻塞项。已澄清 T8：初始化未登记可信路径、后来成功导出，与持续写盘失败是两种测试条件；后者由 T1b 验证。

再次对照 Kimi 的 `toolResultTruncationService.ts:131-144` 与 DeepSeek Harness 的 `packages/spill/spill-local/src/index.ts:149-159`：两者都在现有存储作用域内保存输出、返回定位信息。本项目继续复用现有路径、导出和审批机制，不增加统一产物服务或索引。子代理结果仍保持既定的 50KiB 阈值、无预览和按执行保存；失败执行的部分结果仍留在下一轮候选。

以上是文档复核结论，不代表功能已实现或测试已通过。实施顺序不变：会话存储区第一期通过验收，再做子代理结果搬迁，之后推进存储区第二期。
