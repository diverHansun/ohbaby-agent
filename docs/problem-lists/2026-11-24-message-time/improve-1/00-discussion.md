# 0. 讨论与已确认要点

> 本文记录 2026-11-24 讨论后确认的结论，被否决的方案不再展开。

## 0.1 用户提出的问题

侧边栏会话行尾的相对时间（如 `5m`、`3h`）用处不大，还和等待审批圆点抢位置。用户希望删掉它，改为在会话消息里显示时间，精确到分钟，和复制、Fork 按钮放在同一行。

## 0.2 现状核实

- 侧边栏时间由 `SessionRow.tsx` 调 `relativeTime(updatedAt, now)` 生成，`Sidebar.tsx` 用 `useMinuteClock` 每分钟刷新一次。
- 侧边栏的顺序由服务端按 `updatedAt` 给出，和时间的显示无关。
- `relative-time.ts` 还被设置页归档列表、子代理列表、文件列表和文件预览使用。
- 消息下方的操作行是 `MessageActions`：只在可复制的用户消息和回答上出现。平时 hover 才显示，最新一条回答常显。
- 消息数据 `UiMessage` 自带 `createdAt`。回答另有可选的 `completedAt`，但只在实时流里有，刷新页面后就没了；每一轮的结束时间 `timing.endedAt` 会存库，刷新后不变。
- 时区：
  - 数据库（SQLite）里的时间列都是 `INTEGER`，存的是毫秒时间戳。时间戳表示的是一个绝对时刻，本身不带时区。
  - 服务端用 `toISOString()` 转成带 `Z` 的 UTC 字符串，再发给 Web。
  - ohbaby 没有自己的时区设置，配置、代码和文档里都找不到。
  - 现有的绝对时间显示都按运行环境的本地时区：Web 归档列表用 `Intl.DateTimeFormat(undefined, …)`，TUI 会话列表用 `getHours()` 这类本地取值。
  - 测试没有固定 `TZ`，跑测试的机器在哪个时区，就按哪个时区算。

## 0.3 已确认的决定

| 编号 | 决定 |
|---|---|
| C1 | 删掉侧边栏会话行的相对时间。排序照旧按 `updatedAt` |
| C2 | 在消息操作行里显示时间，精确到分钟 |
| C3 | 回答的操作行是「复制 · Fork · 时间」，时间放最后；用户消息的操作行靠右，时间放在图标外侧（最左边），即「时间 · 复制 · 编辑」 |
| C4 | 时间按"年 → 月日 → 时间"的顺序写，纯数字，24 小时制，不用 "Yesterday" 这类词 |
| C5 | 顺序不变，省掉和今天相同的部分：今天写 `14:32`，今年写 `11-24 14:32`，往年写 `2025-11-24 14:32`。页面开着跨过零点时，日期要跟着变，所以需要一个按天更新的时钟 |
| C6 | 只做 Web，TUI 不加消息时间 |
| C7 | 显示的时间和用户在操作系统里设置的时区一致。存储和传输不改，还是 UTC 时刻；只在浏览器显示时，用本地取值（`getFullYear`、`getMonth`、`getDate`、`getHours`、`getMinutes`）换算成系统时区。"今天""今年"也按系统时区判断，跨零点刷新的时钟按本地零点算。不新增 ohbaby 自己的时区设置 |

## 0.4 按默认处理（讨论中未提异议）

- 时间的显隐跟着操作行走：最新一条回答常显，其他消息 hover 才显示，触屏设备常显。
- 用户消息用 `createdAt`（发送时间）；回答用这一轮的结束时间 `timing.endedAt`（答完的时间），恢复出来的轮次退回 `createdAt`。审查发现 `completedAt` 刷新后会消失，所以改用存库的轮次结束时间。
- 鼠标悬停在时间上，用 `title` 显示完整的日期时间。
- 样式用 11.5px 小字、`--text-dim` 颜色，不做胶囊。
- 子代理页和 side chat 也用 `ConversationStream`，会一起显示时间。
- 侧边栏删掉时间后，`Sidebar.tsx` 里的 `useMinuteClock` 和 `now` 参数一起删掉；`relative-time.ts` 保留。
- 格式化函数的单测用本地时间构造输入，比如 `new Date(2026, 10, 24, 14, 32)`，不写死带 `Z` 的字符串。这样在任何时区跑，结果都一样。

## 0.5 明确不做

- 不改侧边栏的排序规则。
- 不动设置页归档列表的相对时间。那是管理列表，看"多久前归档的"有用。
- 没有操作行的消息（如压缩摘要、空回答）不单独补时间。
