## 1. 目标与共同约束

- 当前保留 React/Ink；只按实际收益复用官方 `@earendil-works/pi-tui`，不引入 pi 的其他业务包。不把全量 controller 拆分或安装依赖作为阅读问题修复的前置条件。
- 默认 MainScreen 体验，优先 macOS，主验收终端已确认 Ghostty。Ghostty 版本、是否经 tmux/SSH 尚待补充；不修改用户终端配置来掩盖应用缺陷。
- 上滚阅读时应能停留在历史，运行中和完成后都要验收。不得靠删除历史、停止真实状态同步或冻结错误数据换取安静。
- 保留用户认可的历史相关按键体验。普通 PgUp、slash 候选 PgUp/PgDn、输入历史 ↑/↓、Ghostty 原生回滚是不同机制；实际映射见 01，未经讨论不重新占用。
- 内部运行时输入继续进入模型上下文和持久化；用户时间线按来源筛选，保留真实用户输入、user-steer、普通 system notice 及正常 assistant 引用。
- reasoning 正文默认隐藏，完成后不留逐段 Thought；活动状态使用 working phrases。审批、失败、重试必须表达真实状态。
- 读类工具摘要，修改/执行类必要 diff 和输入输出；短内容完整，长内容预览并由 Ctrl+O 原位展开。工具展开不与第一轮基础降噪捆绑。
- 已确认六个区域方向，见 plan/00。底栏两行，只含会话项目路径、模型＋effort 值、上下文百分比与当前 token/窗口总量、模式/权限值，不含 effort/Permission/Context 标签及 session ID；模型/effort 获取不到显示 unknown。Earlier history may be stale 不在 TUI 提示。
- 对齐 Web 信息层级和语义色；终端使用行列、缩进、ANSI 和现有 token，不建 CSS 层、跨端设计系统或通用渲染框架。
- 各批次自行验证，不把测试推迟到最后。后续 02 按用户要求列关键文件和符号，按需给行号快照，不列全量文件或实施进度表。

## 2. 修订后的候选批次

| 批次                      | 用户能感受到的结果                                     | 主要工作及边界                                                                                       |
| ------------------------- | ------------------------------------------------------ | ---------------------------------------------------------------------------------------------------- |
| A：阅读稳定与内容可信     | 上滚不被拉回，内部 JSON 不再占据时间线，结束后界面安静 | Ghostty/Ink 输出反馈环；历史与活动区域责任；无变化刷新；内部消息投影；historyStale 正确性            |
| B：基础信息层级与视觉降噪 | 用户消息不刺眼，工具和底栏更易读，活动提示克制         | 用户色块、工具名/状态配色、Thought 清理、短句稳定性、底栏分组与 stale 提示移除；与 A 共同控制高度    |
| C：输入与决策交互         | 输入、审批和队列编辑可靠，Tasks 简洁                   | 编辑器必要修复/复用验证；按需要提取提交与队列行为；审批排版、真实权限范围、草稿/焦点恢复；Tasks 小修 |
| D：工具预览与原位展开     | 修改可看懂，长输出可追溯，实时与恢复一致               | 分类摘要、diff、输出预览、原位展开；补必要展示字段，避免猜测旧内容或后台作业终态                     |
| E：整体验收与维护         | 多场景组合可用，升级和遗留事项明确                     | Ghostty 真机、深浅色/低色彩、中文、缩放、复制、恢复、并行任务；pi 版本和升级回归（若采用）           |

pi-tui 验证穿插在消费其能力的批次中。纯宽度/截断、Markdown 不依赖全面拆业务；Editor 先核对输入、焦点、硬件光标和刷新所有权。不存在“为了后续可能采用 pi，先改完所有组件”的必经阶段。

## 3. improve-1 的范围与实施顺序

主题为 **Ghostty 阅读稳定、显示内容可信与基础降噪**，按此前建议覆盖 A/B 中与该目标直接相关的内容。以下保留路线摘要；正式 Stage、完成定义和关键文件以 improve-1/02 为准。

### Stage 1：建立问题基线

将本轮隔离证据转成针对 macOS 默认路径的行为测试：短/长动态帧、动画开/关、相同内容重渲染、App 实际订阅触发。记录 Ghostty 真实上滚场景，覆盖输出中、审批中、结束后后台轮询。

补内部消息来源与 historyStale 的行为基线。过滤在时间线划分/提交前生效，防止隐藏系统消息仍改变 live tail 归属。沿用 Web 来源契约，未知来源不能按正文关键词删除。

完成判断：区分“实际发送清回滚指令”“React 重渲染”“用户真的被拉回底部”。FakeTTY 不能代替 Ghostty 真机验收。

### Stage 2：验证并确定最小修复策略

先在 Ink 路径上验证：正常更新不反复清回滚；无可见变化时不产生终端噪声；历史与活动区域输出责任明确，完整动态区域有真实行数约束。

Static 是候选，不能只开环境变量。需一起验证已完成消息晚到修正、更早历史前插、会话切换、恢复、窗口缩放、多行输入。现有 committed 消息允许更新，不能声明天然不可变。若原生历史与修正难以兼顾，报告具体冲突再讨论输出策略；不私自切换 AltScreen，不让 pi 与 Ink 同屏争用终端。

轮询优化不得仅凭主 run 完成就停掉后台子代理、审批或任务终态更新。可见内容不变与业务没有变化要分开判断；优先减少无意义通知和终端写入，不新建事件总线或第二份状态源。

### Stage 3：落实同一阅读目标下的降噪

- 内部 subagent-status / subagent-result 原文不进入普通时间线；底层事实保留，可见结果由既有产品视图和主代理回复承载。
- 修复 historyStale 无旧页仍置位且无法清除的情形；此内部状态不在任何 TUI 位置提示。真正旧页需要刷新时在内部处理，不能只删除文案而不修逻辑。实际操作失败、审批、提交结果未知仍需有可操作的表达。
- 同一提交在权限往返后保持 working phrase 稳定，活动动画只选一种；终态和不可见区域停止无意义动画。具体动画形式待确认。
- reasoning 默认隐藏，完成后无逐段 Thought；保存/同步失败按真实错误表达，不保留空标题。
- 用户消息采用中性底色＋细侧线；工具少量分类色只强调名称；底栏显示会话项目路径、模型＋effort、上下文占用率和 permission，不显示 session ID。未知模型/effort 如实显示 unknown。

六个区域的设计方向和底栏字段已确认；具体色值、响应式线框及动画初值尚未冻结。首轮范围见 improve-1/02，permission/Tasks 的完整细化留到 C，不顺手重做全部面板。

### 建议推迟的内容

大规模提交/队列 controller 改造、pi Editor 替换、全局焦点框架、新详情浏览器、完整工具 diff 数据链、Tasks 负责人/依赖关系、默认 AltScreen。已有异步提交会话风险保留登记；影响本轮触碰路径时先复现再纳入，不将推断写成已确认缺陷。

## 4. 后续批次职责与注意事项

### C：输入、权限与 Tasks

本批次现已进入 [improve-2/02](../improve-2/02-optimization-plan-and-change-scope.md) 的 Stage 0–4 规划；下文为原路线摘要，新增交互细节以该轮前端 03/04 为准。官方源码调查后决定本轮不接 pi Editor，Markdown 与全局文本复用随 D 再评估。

2026-10-02 Tasks 增量讨论：用户建议运行中展开，run 结束或 interrupt 等停止时收起/隐藏。目前推荐“确认停止后默认隐藏、Ctrl+T 可回看”，具体状态与未确认的样式选择见 [improve-2 前端 04 §4](../improve-2/frontend/04-interaction-and-states.md#4-tasks-生命周期与手动查看)。这替代下文原“保留紧凑列表”的默认态建议，不改 improve-1 的历史范围，也不意味着运行中长列表的高度问题已经解决。

保留 recovery/store/权限引擎；按“换编辑器是否仍需这段行为”决定提取提交、队列编辑及租约。普通提交等待模型信息期间切会话的风险要定向验证。中文输入法、字素、粘贴、历史、补全和焦点分别验收。

审批说明谁发起、做什么、允许范围和真实按键后果。不可照抄参考项目的 Always 范围；不可无条件把 Esc 标为拒绝，当前无 deny 选项时会回退第一项。Tasks 保留紧凑列表与 Ctrl+T；进度计数、当前项强调、续行对齐是小修候选，不新增任务管理系统。

### D：摘要、diff 和原位展开

Read/Glob/Grep 的数量、范围、完整性来自可信字段；Edit/Write 区分预览与实际执行。Write 正式写入后的前后 diff 数据缺口仍存在，不能靠 TUI 事后读取文件还原旧版本。Bash 不是统一写类工具，也不因返回成功就判定后台作业结束。

Subagent 调用摘要不横铺整段内部 prompt；有可靠标题时使用，否则展示工具名、对象和状态。当前已确定 Ctrl+O 原位切换已加载工具结果，不需要选择调用、进入页面或返回操作。保持草稿与焦点；内容采集截断和 UI 预览裁剪分开说明。历史工具的展开必须先通过 improve-3 Stage 1 的真实输出验证。

### E：维护收尾

将各轮测试结果串成用户路径：发送 → 阅读流式 → 上滚 → 审批 → 返回草稿 → 查看历史/工具 → 恢复会话。Ghostty 为主，Windows 既有兼容不主动破坏。若引入 pi，记录精确版本、公共 API、减少的维护责任及升级回归；本地 0.87.1 只是源码快照。
