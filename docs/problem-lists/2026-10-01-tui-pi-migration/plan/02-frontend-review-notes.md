## 1. 样式与布局的责任归属

用户提出的 CSS/组件建议，在本议题中对应 Ink 的布局属性、终端行列、ANSI 样式与语义 token。MainScreen 没有浏览器 DOM，不照搬 fixed/sticky、像素断点、阴影和 CSS 动画。

| 批次 | 本批次应解决的前端问题 |
| --- | --- |
| A：阅读稳定与内容可信 | Ghostty 回滚、完整动态帧预算、刷新与历史修正、内部消息来源和历史提示有效性 |
| B：基础视觉降噪 | 用户消息、工具颜色、reasoning/活动状态与底栏；宽度/换行等 pi 候选按需验证 |
| C：输入与决策交互 | 输入、审批、队列、Tasks 的局部布局与焦点；沿用 A/B 的空间及样式责任 |
| D：消息与工具 | 基于上述约定设计摘要、diff/输出预览、详情与状态呈现 |
| E：整体验收 | 检查组合后的阅读、输入、复制、缩放和低色彩表现 |

批次 A/B 先明确整体空间和信息层级，批次 C/D 有新需求时回写约束，避免两套尺寸规则。示例终端尺寸可从 80×24、120×40 起步，再覆盖更窄、更矮窗口；这是待确认的样例，不是产品只支持这两种尺寸。

## 2. 以当前 Ink 为验证对象

现有 [入口](../../../../packages/ohbaby-cli/src/tui/index.tsx) 使用 Ink 增量渲染；[历史区](../../../../packages/ohbaby-cli/src/tui/components/transcript/committed-transcript.tsx:65) 默认只在 Windows TTY 使用 Static，macOS 走动态 Box。当前安装的 Ink 6.6.0 在上一帧输出高度达到终端行数时进入清屏分支。不能用 pi MainScreen 的实现细节描述当前 Ink 的行为，也不能以“增量渲染已开启”证明不会闪烁。

[metrics.ts](../../../../packages/ohbaby-cli/src/tui/layout/metrics.ts) 固定预留 10 行，只限制活动尾部不足以约束完整动态帧；历史、输入、审批和提示都会占行。其最小内容宽度 24 加左右 padding，在极窄终端可能超过实际列数。批次 A 应讨论完整动态区域的空间预算和降级优先级，批次 D 再验证长历史与内容预览的组合，不先承诺固定 dock 或原生 scrollback 永不改变。

Static 已输出项不能靠普通 props 更新原地修正；重置或重印历史也有终端副作用。动态 Box 路径的刷新范围和代价需测量。两种路径都需要考虑晚到结果、恢复修正和工具展开/收起；不能以冻结错误历史换取稳定输出。

## 3. 组件边界与焦点

建议先以三类职责讨论内容组件，名称只是示意：

| 职责 | 主要内容 | 不承担的工作 |
| --- | --- | --- |
| 工具摘要行 | 名称、对象、状态、必要元信息 | 执行工具、获取权限或自行猜结果 |
| 内容预览块 | diff/输出裁剪、行号、增删标记、可用详情提示 | 重新读取文件推算旧内容、保存第二份业务结果 |
| 工具展开投影 | 按 Ctrl+O 在原调用处切换已加载结果的显示密度 | 新建阅读页、改写历史事实或建立通用工具插件框架 |

可用少量按工具类型的格式化函数选择这些呈现。共享确有共性的布局与操作，不要求所有工具只有一个巨型组件，也不为每个工具建立完整独立体系。

当前 [OverlayCard](../../../../packages/ohbaby-cli/src/tui/components/dialog/overlay-card.tsx) 是内联带边框容器，不自带模态、遮挡和焦点管理。[connect-panel](../../../../packages/ohbaby-cli/src/tui/components/dialog/connect-panel.tsx:320) 等有 `isActive: true`，只能证明挂载时注册输入处理，不能单凭这点判定发生抢焦点；需核对父组件挂载互斥及全局快捷键。

批次 C 明确主要输入上下文的单一所有者及切换规则。可从 prompt、panel、permission、subagent 等现有场景归纳，但不提前冻结枚举或新建焦点框架。分别讨论 Esc、Ctrl+C、Enter 和全局快捷键的含义，避免独占面板打开时误提交或后台组件响应同一按键。

## 4. MainScreen 下的工具展开

2026-10-03 已确认：工具直接输出到主时间线，Ctrl+O 只切换紧凑/展开。此前工具项列表、独立详情和替换输入区的候选已否决；不增加选择目标、进入/退出阅读的流程。具体契约见 [improve-3 前端 03](../improve-3/frontend/03-ui-layout-and-style.md) 与 [04](../improve-3/frontend/04-interaction-and-states.md)。

展开仍按会话/消息/调用身份组织，不能因并行调用或晚到修正显示到别的工具。保留草稿与光标，审批等独占面板期间不处理全局 Ctrl+O。历史补载与展开是不同动作。

完整可用内容指实际保存的内容：源头截断、diff 预算省略、旧历史未保存和 UI 预览是不同情况。没有更多数据时不提供误导性的全文入口；不新增剪贴板依赖。MainScreen 中已输出历史能否原位改高，由 improve-3 Stage 1 的真实 Ink/Ghostty 技术验证门确认，不假设 Static 可通过 props 更新。

## 5. 状态用多个维度表达

以下是批次 D 应覆盖的设计维度，不是要求新增 SDK 枚举：

| 维度 | 需要区分的情况 | 展示要求 |
| --- | --- | --- |
| 调用生命周期 | 待审批、待运行、运行、完成、失败、取消 | 必要的文字/标记，不只靠颜色 |
| 输出可用性 | 尚无输出、已知有输出、终态确实无输出、缺字段 | 未知不写成 no output |
| 内容完整性 | 完整、采集截断、预览裁剪、diff 省略、旧记录缺失 | 可组合标识，不把“截断”当作执行终态 |
| 后台作业 | 已启动仍运行、终态、最新状态未知 | 工具返回成功不等于作业执行成功 |

[bash.ts](../../../../packages/ohbaby-agent/src/tools/bash.ts:236) 后台模式立即返回快照，前台模式等待终态；[shell-job-registry.ts](../../../../packages/ohbaby-agent/src/tools/shell-job-registry.ts:475) 有 jobId、status、truncated 及终态信息。按实际提供的作业事实呈现，不默认新增实时日志通道。若要持续刷新后台状态，先核对现有读取接口与会话/上下文归属，再单独确认范围。

需要在具体设计时建立“SDK 已有/待补字段 → 展示”的小表，覆盖实时、恢复和旧历史。当前工具调用和结果关联能力可复用，不另起平行状态机。

## 6. 样式方向与宽度降级建议

优先复用 [现有 theme tokens](../../../../packages/ohbaby-cli/src/tui/theme/tokens.ts)，其中已有 diff、status、tool、workingSpinner 等语义。确有不同视觉责任时再补行号、上下文或待审批样式，不为了建议清单新增一套 token。

- 用户输入、正文、工具过程有清楚层级；常见成功读操作降低视觉重量，失败和待审批保留可识别提示。
- 工具摘要优先轻量行，预览用少量缩进或分隔；完整边框主要用于需要明显交互边界的面板，不把每个工具都装成卡片。
- diff 使用增删符号和行号，即使无颜色也可理解；背景色只是候选，必须在深浅终端验证。续行不重复源代码行号，避免将显示换行误读为实际文件行。
- 根据实际显示列宽截断，长路径优先保留可辨识目录和文件名；不同路径若同名仍需区分。不要沿用 `.length` 固定字符数裁剪。
- 窄窗口优先减少装饰、间距和次要元信息，保留操作对象、执行状态及必要的失败/审批信息。不能只剩图标和文件名而丢失用户判断依据。
- 正文阅读宽度与代码/diff 宽度可分别讨论；不冻结 60/80/100 列断点或 100–120 列正文宽度。宽度规则需同时考虑中英文、长命令及横向空间不足。

与 Web 对齐的是语义与视觉层级，Web 状态文档也要核对适用范围，不能直接移植 DOM/CSS 或将其状态名当作 TUI 的业务事实。

## 7. 动画与 pi 嵌入的验证边界

working phrases 每轮稳定、动画只在活动区域存在，结束或卸载停止计时器，保留 OHBABY_TUI_NO_ANIM。不默认叠加 spinner 与扫光。是否共享时钟取决于实际同时运行的组件数量和测量结果，当前不把“全局统一时钟”列为必做架构。

局部复用 pi 时明确每个输出边界由谁测宽、换行和截断，尽量避免应用内重复算法，同时验证 Ink 自身处理与候选输出兼容。不能保证强行换用一个字宽函数就能控制 Ink 内部逻辑；也不能未经验证固定 `wrap="truncate"`，以免隐藏有效内容。交互组件另需核对原始输入与 Ink 已解码输入的差异。

首版 Pi 审阅受进程文件访问限制，未能读取并列 pi 源码，因此其关于 pi 公共 API 的意见仍是风险提示。主代理此前直接读取过本地官方包与入口，但最终采用的发布版本仍需在实际接入对应能力时验证。


## 8. 新截图对应的设计判断

本节六个区域的方向已由用户确认；底栏及历史提示以最新文字要求为准。具体响应式线框、色值和状态细节仍为讨论稿。用户截图中的命令与系统文字只作视觉材料，不执行。终端明暗背景由用户决定，不硬编码整个画布。

### 8.1 用户消息：借鉴 OpenCode 的完整区域和轻强调

截图中的 ohbaby 短蓝块像文本选区，代码确实只按文字宽度铺背景。OpenCode 参考图使用中性面板、细侧边线与一致内边距；Pi 参考图铺满一整行蓝灰区域，也比零碎色条完整。用户已选择“OpenCode 式中性底色＋细侧线”：低对比中性背景、柔和侧线、正常正文色。具体色值和间距尚未确定，完整线框仍待讨论。色彩能力不足时优先保持文字与角色可识别，不能降级为刺眼 ANSI blue 色块。

参考源码：OpenCode `packages/tui/src/routes/session/index.tsx:1398`；pi coding-agent `src/modes/interactive/components/user-message.ts:42` 与 theme/dark.json。截图 Pi 为 0.99.2，本地 tui package 为 0.87.1；这两类证据不冒充同一版本。

### 8.2 工具：类别、执行状态和摘要分开

Web 当前 read 为 gold、edit/write 为 green、其他为 blue；TUI 全部使用 tool.name 的 gold。用户已确认沿用 Web 的少量分类强调，只给工具名轻着色，路径/命令用清晰中性色；失败另用状态文字和颜色表达。此前“工具名也全部中性”的候选不再作为本轮选定方向。具体色值与分类映射仍待细化，不为每种工具建立一套颜色。

不要直接照搬 Web 的名称子串匹配作为新分类规范；明确 Read/Glob/Grep、Edit/Write、Bash 和 fallback 的映射，并把类别色与执行结果分开。绿色 Write 名称不代表写入成功。Subagent 不把整段内部 prompt 当标题；无可靠任务标题时只显示工具/对象/状态。

参考：Web `apps/ohbaby-web/src/ui/conversation/tool-card.tsx:230`；OpenCode `routes/session/index.tsx:1874`；pi coding-agent `components/tool-execution.ts:156`。后者是产品层实现，不是 pi-tui 成品工具卡。

### 8.3 Prompt 与底栏：分组而非长句

用户已确认输入区借鉴 Pi 的轻边界。底栏仅显示四组信息：**会话对应的项目路径、模型＋effort 值、上下文占用率与 token 数/窗口总量、模式/权限值**；不显示 session ID。模型与 effort 获取不到时显示 `unknown`。这替代此前“模型是否常驻待定”“底栏保留排队数量”的提案；排队和错误在对应交互区域呈现，不添加为第五组常驻信息。

用户已确认两行布局，省略 effort、Permission、Context 标签，只显示对应值；上下文采用小写 k/m 的“百分比 当前 token/窗口总量”。示意中的模型、effort 和数据仅为样例，不是默认值：

```text
  ──────────────────────────────────────────────────────────────────
  > 当前草稿
  ──────────────────────────────────────────────────────────────────
  ~/Projects/code-cli/ohbaby-agent                     auto/default
  claude-opus-5.5 · high                                2% 20k/1m
```

用户已确认轻边界方向；上下分隔线是候选线框，具体间距和宽度尚未确认。路径可用 `~` 缩写和中间省略，保留可辨识项目名；底栏两行结构已确认，常用窄窗口先缩短路径/模型展示并保留状态值；极窄列数的降级另行验收，不能无界换行或隐藏权限。两行同样纳入完整动态区域预算，不以常驻固定高度 dock 为前提。

数据与显示的核对结果及建议：

| 字段 | 已有事实 | 需要遵守或细化的规则 |
| --- | --- | --- |
| 项目路径 | `UiSession.projectRoot` 已存在且可缺省 | 取当前会话路径；不能偷偷用启动 CLI 的 cwd 代替。缺失时建议显示 `Project unknown`；新会话未绑定时的取值另定 |
| 模型 | Web 的 `selectContextModel` 有 usage.modelId 与 configuredModel 两种来源，未知时现有 Web 文案为 model pending | TUI 按用户要求缺失显示 unknown，不声称 Web 现有模型占位也是 unknown。建议底栏表达当前选用模型，不能直接把历史用量模型当成新的选择；切换后的归属与刷新要核对 |
| effort | Web `ReasoningControl` 使用能力识别结果，匹配会话偏好，否则采用已确认的默认配置 | 未知显示 unknown；已知 off/on 或不支持与未知不同，建议分别显示 off/on/n/a。不得凭模型名称猜 high，旧会话偏好不兼容新模型时不能直接展示 |
| 上下文 | Web 按 session 读取后端 currentTokens、contextWindowTokens、contextWindowRatio | 显示如 `2% 20k/1m`，不带 Context；比例和数值必须一致，使用原始数据计算再格式化。缺失不是常态，必要时建议只显示简短占位，不伪装成 0%。切会话不能沿用上一会话值 |
| 模式/权限 | 现有 permission.mode/level 两个字段 | 按用户要求直接显示 `auto/default` 等真实值，不加 Permission 前缀；mode 在前、level 在后。缺失时不能假设已有自动授权 |

源码入口：[UiSession](../../../../packages/ohbaby-sdk/src/snapshot.ts:88)、[Web 模型选择](../../../../apps/ohbaby-web/src/ui/session/selectors.ts:291)、[Web effort](../../../../apps/ohbaby-web/src/ui/composer/ReasoningControl.tsx:129)、[Web 上下文](../../../../apps/ohbaby-web/src/ui/shared/ContextUsage.tsx:85)、[reasoning 公共类型](../../../../packages/ohbaby-sdk/src/connect-model.ts:123)。这些取值规则用于后续实施契约，当前没有新增接口或请求。

上下文数据链路已核对：后端 [contextUsageToContextWindowUsage](../../../../packages/ohbaby-agent/src/core/context/context-window-usage.ts:26) 输出当前 token、窗口总量及二者比值；[Web eventReducer](../../../../apps/ohbaby-web/src/api/daemon/eventReducer.ts:412) 接收 context.window.updated 并按 sessionId 更新，selector 再选当前会话。Web 打开用量详情时还会 [主动查询](../../../../apps/ohbaby-web/src/ui/session/SessionScreen.tsx:972)；[后端读取](../../../../packages/ohbaby-agent/src/adapters/ui-inprocess.ts:2848) 优先使用缓存，没有缓存时为有效主会话计算并发布结果。TUI 复用这份数据和既有 SDK/store，不自己累加 token，也不因常驻底栏新增高频轮询。

注意数值示例：`2k/1m` 约为 0.2%，`20k/1m` 约为 2%。Web 当前百分比采用整数四舍五入；TUI 低于 1% 时建议保留一位小数或显示 `<1%`，具体精度后续验收确定。格式化缩写不应反过来影响比例计算。后端字段是上下文估算快照，不承诺逐 token 精确实时更新。

**Earlier history may be stale 不在任何 TUI 位置提示**，也不换一句话搬到历史顶部。内部历史失效判断、必要的刷新和失败时保留内容仍需正确；实际加载失败、同步中断、提交结果未知、审批等待与 stale 标记不是同一种情况，仍在对应操作处给出必要反馈。

### 8.4 Permission：现有纵向结构小改

用户已确认保留纵向选择并区分发起者、操作、授权范围和按键后果。具体顺序建议为“需要确认 + 来源 → 操作/命令 → 选项 → 一行按键提示 → 实际发送或错误状态”。标题少量警示色，正文中性，不把命令全染黄。不再展示 [allow]/[deny] 这种内部 intent。

```text
Permission required · Main agent
Run shell command

  <完整待执行命令，按实际宽度换行>

› Allow once
  Always allow  <真实授权范围>
  Reject

↑↓ select · Enter confirm · Esc <实际行为>
```

这里的尖括号是讨论中尚未确定的事实，不能原样成为产品文案。长命令不能截掉决定后果的部分；空间不足时需可读的完整查看方式。Always 的真实范围和 Esc 无 deny 情形须先核对，不能把样式调整变成权限语义改变。

参考 OpenCode `routes/session/permission.tsx:254`、`:359` 的操作字段和分组；pi 的对应材料是 `coding-agent/examples/extensions/permission-gate.ts` 与 `components/extension-selector.ts`，不是 pi-tui 权限 SDK。

### 8.5 活动状态与 Tasks
