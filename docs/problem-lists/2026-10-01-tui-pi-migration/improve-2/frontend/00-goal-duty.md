# improve-2 前端：目标与职责

2026-10-02，TUI 增量设计，随 [本轮方案](../02-optimization-plan-and-change-scope.md) 提交审阅。本文档树补充用户可感知行为，不另立工程计划，不照搬 Web 路由/CSS/浏览器验收。

## 1. 产品目标

写下一段话时，中文和 emoji 能完整编辑；切会话或处理审批后，能继续原来的草稿。发送、排队和审批发生延迟时，用户能分清是在等待、失败还是结果未知，不会把动作作用到另一个会话。

## 2. 用户角色

本地 CLI 单一操作身份。日常用户关心输入与任务进展；排错时需要辨认请求来源、失败和重试后果。Main agent/子代理是审批请求来源，不是操作界面的用户角色；真正授权仍由后端判断。

## 3. 核心任务

| 编号 | 任务 |
| --- | --- |
| T-01 | 编辑、粘贴并提交完整文本 |
| T-02 | 切换会话后继续草稿，编辑或重发队列项 |
| T-03 | 看懂审批并作出明确选择，回到之前输入 |
| T-04 | 快速看懂 Tasks 的已完成数量与当前工作 |

## 4. 职责边界

TUI 管输入、光标、可见窗口、选择、准确提示和按键归属。SDK/recovery 管提交接收、幂等、恢复、租约、运行控制；权限引擎决定可选项和授权规则；Todo 事实来自已有快照。显示截断不能变成存储截断，界面不能将未知结果显示为成功。

## 5. Non-goals

无新渲染器、完整工具详情、全局文本能力替换、持久草稿数据库、编辑器高级功能、任务管理平台或新的权限政策。沿用 improve-1 的两行底栏、轻边界和活动提示，本轮不重设计它们。
