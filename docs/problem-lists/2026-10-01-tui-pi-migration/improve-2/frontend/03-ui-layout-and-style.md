# improve-2 前端：布局、线框与文案

> 2026-10-03 接续修订：本文 Ctrl+R 相关提示由 [improve-3 前端 04](../../improve-3/frontend/04-interaction-and-states.md) 取代：自动恢复，删除手动重试键和文案。审批预算、Ctrl+C 及草稿规则继续有效。

以下是本次提交审阅的增量线框。继承 improve-1 已确认的轻边界、两行底栏和中性配色，不把此草案标成用户逐项批准。行列示意不固定终端像素和绝对位置。

## 1. 设计原则

| 原则             | 终端上看什么                           | 反例                           |
| ---------------- | -------------------------------------- | ------------------------------ |
| 当前任务优先     | 审批时先看操作与选择；输入时光标可见   | Tasks 把审批操作挤到屏外       |
| 保留上下文       | 回到输入后原文与光标仍在               | 拒绝审批后草稿被清空           |
| 状态靠文字与位置 | 选中项有 `>`，错误有解释               | 仅靠红绿或高亮表示允许/拒绝    |
| 辅助信息克制     | 范围说明靠近选项，提示只列当前能用的键 | 每行追加内部 intent/epoch 字段 |

## 2. 方向与来源

沿用 [improve-1 线框](../../improve-1/02-optimization-plan-and-change-scope.md#210-简要布局状态与实现约束) 与 [plan 前端补充](../../plan/02-frontend-review-notes.md)。参考 pi 的单列编辑/选择与文本分层，不复制其完整宿主。识别特征：轻水平边界、无厚面板套框；正文正常文字色；强调只用于当前输入/选择/进行中；路径和命令保持中性。

## 3. 语义与密度

复用 theme 的 text、dim、accent、warning、error、success；关键操作正文不用 dim，范围和键提示可以弱化但仍可读。普通行不加空白，区域之间最多一行初始留白；短屏优先去留白。禁止叠加新动画，继承前轮关闭动画能力。终端字体由用户选择，不安装字体、不创建 CSS token 层。

## 4. 关键线框

### 活跃 run 的 Tasks / 长草稿

```text
Tasks  2/5 completed
  ✓ Inspect input
  ● Fix grapheme editing
    and preserve cursor on return
  ○ Verify approval flow
──────────────────────────────────────────────────────
> Draft text with cursor here...
  Another visible draft line
  lines 18–19/200
──────────────────────────────────────────────────────
~/Projects/code-cli/ohbaby-agent           auto/default
claude-opus-5.5 · high                    2% 20k/1m
```

范围提示仅在草稿超出窗口时出现，标记的是可见显示行，不混用逻辑行总数；示例仅说明层次。光标随左右/行首行尾移动驱动窗口，整个文本仍可到达。原文不插入 `...` 或隐藏 marker；真实文本的省略只属于显示投影。底栏格式由 improve-1 决定。

投影需先扣除前缀列宽；tab 初值为显示时展开至 4 列 tab stop，原文保留 tab。行尾空格光标也占一列，满行时可进入下一显示行，不能被右边界裁掉。最终以实际 Ink 物理行数/光标位置验证，不能仅宣称采用了某个 width 函数。

### Tasks 停止与手动收起

运行中默认展开；本轮手动收起可显示一行 `Tasks 2/5 completed · Ctrl+T expand`。确认 run 停止后，这一行也默认隐藏，最终回复下面直接接输入区和两行底栏。用户停止后按 Ctrl+T 时显示 `Tasks · Stopped` 和仍保留的状态，不把中断后 in_progress 改成完成。生命周期完整规则见 [04 §4](04-interaction-and-states.md#4-tasks-生命周期与手动查看)。

这是 2026-10-02 的增量建议，停止后“隐藏”仍可由用户改为保留摘要；未更改产品代码。长列表仍服从同一高度预算，自动展开不等于无限增加动态行数。

### 队列编辑

```text
Editing queued prompt
──────────────────────────────────────────────────────
> Text being edited...
  Enter save · Esc cancel edit
──────────────────────────────────────────────────────
<same two-line footer>
```

retained 模式分别显示 Send / Retry original send；未知结果时原文只读，可用 ←/→、Home/End 浏览完整内容，Enter 仍只重试原操作。lease 失效显示 `Edit lease expired; your text is kept`，不能继续显示可保存。保留原普通草稿在内存，不把两个草稿同时铺开。

### Permission / 长正文

```text
Permission · Bash
From: Main agent
Run command in the current project
  <actual description, command or pattern if provided>
  <content continues within the local viewport>
  1/3 · PgUp/PgDn read

> Allow once
  Allow matching requests in this session
  Reject
Enter select · Esc=reject · ↑/↓ move
<same two-line footer>
```

这是现有可用字段的示例，不保证所有工具都有命令/pattern。范围说明贴近内置 Always 项；请求属于子代理时明确是该子代理所属 session，不能把“this session”误解为父会话。无 deny 时底部改为 `Enter select · Esc does not submit`；按 Esc 后留在审批，不自动跳回 Prompt。

审批取代可交互 Prompt 的显示；草稿保留但不画活动光标。Tasks/装饰优先让位。来源、请求标题、选项、按键和两行底栏属于 chrome；标题/来源过长时显示中间省略，全文同时放进可翻页正文。正文中的描述/可用范围信息全部可达。请求移除才恢复原输入或展示下一请求，不闪现空输入框。

## 5. 尺寸与空间优先级

预算来自 improve-1 同一布局入口。正常顺序：当前交互的动作/光标 → 两行底栏 → 交互正文 → 辅助 Tasks/历史活动区；不是每个区域各自宣称最低高度。

| 尺寸                     | 行为                                                                                                                                      |
| ------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------- |
| 120×40、80×24            | 单列；短输入自适应，多行输入初始最多 6 个显示行，再由父预算缩减；审批正文占剩余空间                                                       |
| 60×20                    | 去额外空行，路径/模型按前轮规则省略；输入可降至 1 行；审批保留动作，把长正文翻页                                                          |
| 80×12 / 小于正常支持尺寸 | 使用前轮退化路径；最少 1 行正文＋动作仍能容纳时继续；连必要操作区都放不下时显示尺寸不足，暂停 Enter/Esc 审批提交，扩大后恢复选择/正文位置 |

短屏必须算整个 App，而非只数 PermissionDialog。当前源码中 Ctrl+G 提示、单独的 Ctrl+C/同步提示、SubagentWait、TodoPanel 和禁用 Prompt 仍可能占行；Header 仅在空会话显示 Logo，不能把它算作每次审批固定开销。下表为 80×12 的建议上限，交给实际 Ink 测量验证：

| 区域                                     | 行数 | 短屏处理                                                                    |
| ---------------------------------------- | ---- | --------------------------------------------------------------------------- |
| 标题＋来源                               | 2    | 各一行有界摘要，全文进入正文                                                |
| 正文阅读窗口                             | 2    | 含操作描述与当前选项全文；余量不足可减为 1 行                               |
| 页码/同步/错误状态                       | 1    | 合并呈现，长错误全文纳入阅读窗口，不追加无限错误行                          |
| 纵向选择窗口                             | 3    | 多项滚动选择，长 label 全文在正文，选择行不无限换行                         |
| 动作提示                                 | 1    | 如 Enter select · Esc=reject · ↑↓ · PgUp/PgDn · Ctrl+C stop；不另叠停止提示 |
| 两行底栏                                 | 2    | 保留前轮格式                                                                |
| Header/辅助栏/Tasks/Prompt 正文/额外留白 | 0    | App 收起这些区域；数据/草稿不删除；真实等待/错误整合进当前状态区            |
| 合计                                     | 11   | 为 12 行终端保留 1 行输出余量；以父输出策略实际需要为准                     |

60 列下键提示若需 2 行，正文从 2 行让出 1 行；不能让各组件分别换行后再算超高。键提示展示真实可用的操作后果，不重复渲染 App 原提示；接续 improve-3 自动恢复后不再出现 Ctrl+R。尚未提交的活动 transcript 使用父布局同一预算，短屏可分配 0 行，存储与已输出历史保留。实际父布局可用高度连必要操作区也容不下时才显示尺寸不足；这是实施验证门，不是已经通过的测量结果。

任何尺寸都不能为了塞内容裁掉原文或自动替用户选择。若选项很多，使用局部选择窗口保留当前项有界标识，↑/↓ 切换，不只保留前三项。单项 label/说明也可能超过一屏：其全文放入同一个审批正文阅读区，明确标注 Selected option，仍用 PgUp/PgDn 读取，不加第二套翻页键。切 choice 时定位到该选项说明开头，请求原始正文仍在同一阅读序列中可返回。固定区不承诺容纳超长完整 label。整个面板受同一高度预算约束。

Tasks 展开先验证 Stage 0 的实际输出方案；若没有全量可达且不溢出的路径，这是本轮尚需小范围交互取舍的技术门，不自动归责前轮。需记录规模/尺寸和失败场景再补线框，不能假定能力已存在或趁机增加任务管理模式；独立输入/草稿阶段不受其阻塞。

## 6. 术语和文案

沿用当前英文 UI，本轮不引入国际化系统；设计说明用中文。Tasks 是任务列表，draft 是未发送文本，queued 是已接收待运行，retained 表示保留待用户重新发送；它们不能混称“已发送成功”。

| 状态           | 推荐表达                                                                                           |
| -------------- | -------------------------------------------------------------------------------------------------- |
| 同步阻止发送   | 接续 improve-3 后沿用其单一同步状态，草稿保留，不显示 Ctrl+R；自动路径落地前沿用既有可工作恢复提示 |
| 重发回执未知   | `Send outcome unknown. Retry the original send.`，同时给当前有效操作                               |
| 无 deny 的 Esc | `No reject option. Choose an option explicitly.`                                                   |
| 审批同步       | `Synchronizing approvals...`                                                                       |
| 过期请求       | 短暂显示请求已失效/同步中，不显示已批准                                                            |

Esc=reject 以文字明确后果，并可用 warning 强调；翻页不会产生“退出阅读”的新 Esc 语义。macOS 的 PgUp/PgDn 可在较宽提示或帮助中补充 Fn+↑/↓，以 Ghostty 真机确认映射，不因此加 Space 等新键。

普通内置选项不暴露 `[allow]`/`[deny]` 之类实现字段；未知自定义选项保留原 label 和可用说明。Always 不写“永久允许”。不新增 stale 提示。

## 7. 视觉验收口径

用真实 Ghostty 在深浅背景、低色彩、关闭动画下核对线框和状态；必须能一眼区分光标/审批选择/错误，正常正文可读，完成 Tasks 仍能辨认。长中文续行与正文齐头；重点信息不靠颜色；窄屏动作仍可达。模拟输出只证明字符/控制序列，不替代真机观感。

## 8. 实现约束摘要

| 必须遵守                                                                            | 初值可调                                      | 可由实现决定                                 |
| ----------------------------------------------------------------------------------- | --------------------------------------------- | -------------------------------------------- |
| 原文/草稿保护、单一焦点、纵向审批、准确范围与键义、单一预算、两行底栏、完整内容可达 | 输入默认最多 6 个显示行、区域留白和中性色强弱 | 局部 helper 命名、边界字符细节、范围提示简写 |

优先级：用户明确要求与本表行为约束 > 参考项目/Pi 建议 > 实现者审美。调整初值记录在实施提交说明或验收 05；不得以“视觉优化”改变快捷键后果、授权范围或异步归属。
