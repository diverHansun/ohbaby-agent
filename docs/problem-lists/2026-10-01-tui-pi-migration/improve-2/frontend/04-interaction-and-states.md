## 1. 状态矩阵

| 区域/状态                    | 用户看到什么                                                  | 可做什么/结束条件                                                                                        |
| ---------------------------- | ------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| Prompt 空/有草稿             | 输入光标；长文本显示窗口范围                                  | 编辑；空白不提交                                                                                         |
| Prompt 同步中                | 保留原文，明确同步原因                                        | 可编辑；普通提交受 recovery.canSubmit 限制，保留既有允许的命令处理                                       |
| 发送前准备                   | 已捕获原归属的提交快照，提示 Preparing…；编辑区可继续写下一份 | 同一次意图只准备一次；后续独立输入按原串行序列处理；切换取消未转交的准备                                 |
| 已转交/回执未知              | 输入可开始下一草稿；已有 pending 状态说明未知结果             | 沿原 requestId 查询回执，不重发；接续 improve-3 后自动查询，不把新草稿替换为旧请求                       |
| 准备取消/明确拒收            | 原归属显示未发送说明，文本保留在进程内提交快照/输入历史       | ↑ 取回文本、↓ 回当前草稿；显式再提交才产生新意图，不自动重发                                             |
| Queue 获取/保存中            | 当前项与进行中状态                                            | 不重复变更；失败在原归属显示                                                                             |
| Queue 正常编辑               | 编辑文本，Enter save / Esc cancel edit                        | 保存成功或取消后恢复进入前草稿及光标                                                                     |
| Queue 租约失效               | 修改文本保留，明确不可保存                                    | 可阅读/复制；Esc 返回原草稿；需重新取得有效租约才可保存                                                  |
| Retained 重发未知            | 第一次重发文本只读，提示 Retry original send                  | ←/→、Home/End 浏览全文，不续租/改原文；Enter 重试同 operationId/文本；Esc 回普通草稿，不声称取消后端发送 |
| Permission 同步中/无 context | 实际请求内容＋同步状态                                        | 可阅读正文；不可发送任何 choice                                                                          |
| Permission 就绪              | 来源、操作、纵向 choices、实际键提示                          | 选择/翻页/提交；空 choices 无提交入口                                                                    |
| Permission 发送中            | 原选择＋Sending…                                              | 阻止重复提交，不乐观显示允许成功；读正文可继续                                                           |
| Permission 失败              | 原内容/选择＋错误和下一步                                     | 原身份有效时 Enter 显式重试；过期则 resync                                                               |
| Permission 结束/被撤销       | 请求撤下，或切下一请求                                        | 回原草稿/光标；不把撤销显示成拒绝成功                                                                    |
| 尺寸不足                     | Resize terminal to review this request                        | 暂停审批提交；扩大后恢复，不清正文/草稿                                                                  |
| Tasks 活跃/手动收起          | 默认展开；手动收起为一行摘要                                  | Ctrl+T 切换，同一 run 数据更新不覆盖选择                                                                 |
| Tasks 已停止/空数据          | 停止默认隐藏；有数据可手动回看，空列表不渲染                  | Ctrl+T 查看/隐藏；不自动修改 Todo 状态                                                                   |

按 Enter 冻结已捕获的快照，编辑器继续接收下一份输入。prepare 取消或明确拒收后，原文本留在原会话输入历史及对应未发送说明；不覆盖用户正在编辑的新草稿。多份失败按原顺序保留，用户通过既有 ↑/↓ 逐项取回；当前草稿按已有 history draft 机制保存。未发送说明仅列简短文本预览和原因，不整段铺开。普通 unknown 显示 Query original receipt / Do not resend，不能混成明确失败；Ctrl+X 仅停止本地跟踪，不证明服务端未执行。

## 2. 按键归属

同一输入事件只能触发一个语义动作。保留现有模式判断，测试真实 useInput 的激活关系；不能假定一个 handler 内 return 会阻止另一个 handler。

| 上下文                     | Enter / Esc                                               | 导航及其他                                                               |
| -------------------------- | --------------------------------------------------------- | ------------------------------------------------------------------------ |
| 普通 Prompt                | Enter 发送，Shift+Enter 换行；Esc 沿用可控 run 的双击停止 | ↑/↓ 输入历史；←/→ 字素/跨行；Home/End 行首尾；Tab 补全；普通 PgUp 补历史 |
| Slash 候选                 | 沿用原命令提交；不另设取消协议                            | ↑/↓ 候选，PgUp/PgDn 候选页；不得补历史                                   |
| 普通草稿的 Steer           | 保留 Enter 普通发送                                       | Ctrl+↑/↓ 调整 Steer 目标，Ctrl+S 按原允许条件 steer；Alt+↑ 进入队列选择  |
| Queue 选择                 | Enter 获取租约，Esc 退出选择，不触发全局停止              | 普通 ↑/↓ 选队列项；Ctrl+D 仅删除当前选定项                               |
| Queue 编辑                 | Enter 保存/重发，Esc 取消编辑，不触发全局停止             | 普通编辑键保持；retained 首次重发后冻结该份文本，Enter 仅恢复原操作      |
| Permission                 | Enter 当前 choice；有 deny 的 Esc 拒绝；无 deny 不提交    | 原 ↑/↓/←/→/Tab 切 choice；PgUp/PgDn 正文，不能同时控制输入/历史          |
| Command panel / 子代理浏览 | 当前面板处理输入，Prompt 禁用                             | 本轮不重排其键位；面板返回恢复之前上下文                                 |

Ctrl+T 在普通上下文按 §4 切 Tasks（不再要求条目数大于 5），不在审批/命令/队列编辑里触发双重动作。审批存在时 Ctrl+G 不应把另一个可交互层盖在审批上；如子代理浏览器先开着，先保持该面板并显示审批等待提示，关闭后再进入审批，不能两个同时收键。以现有面板生命周期实现，不创建焦点栈平台。

Ctrl+C 沿用 App 控制身份：有可信可控 run 就停止它；审批来源与当前 control 不匹配时不误停、不提交 choice；确认 idle 才退出。若其他 interaction/command panel 已独占输入，继续其现有语义。恢复查询和 Ctrl+X 放弃 pending 只作用于原恢复域；接续 improve-3 后去除 Ctrl+R 手动入口；审批时不得趁输入事件重发另一会话数据。

## 3. 审批细节

默认选择保留现有 allow 优先；不把这次快捷键修正扩成默认拒绝策略。`cancel`/`abort` 仍按当前规则过滤；无 deny 不能回退到第 0 项。没有拒绝选项时，Esc 保持当前请求并给出说明；这不等于自动取消或关闭审批。

请求 identity 包含 requestId/root/epoch/bindingGeneration；变化时选择按初始规则重设，页码归零，旧错误/发送结果不写入新请求。choices 内容或顺序变化时用 choiceId 保持/校验选择，旧 choice 不存在则重新选择且不自动提交。两次快速 Enter 最多产生一次在途回应。

翻页后 Esc 仍按提示拒绝（有 deny 时），不变成返回阅读；无 deny 时继续不提交。长正文翻页不改变选择；新请求从第一页开始。同请求 resize 保持正在读的内容附近，限制 offset 在有效范围。超长选项全文进入同一正文阅读序列；用户切 choice 时定位该选项说明，之后 PgUp/PgDn 可继续读请求正文/选项。审批过程中不显示活动输入光标；最后一个请求结束才恢复草稿，工作短句按 improve-1 的同一 run 规则保持。

## 4. Tasks 生命周期与手动查看

2026-10-02 增量建议：用户提出运行中展开、停止后收起/隐藏。这里暂推荐停止后完全隐藏，保留 Ctrl+T 回看；这是建议稿，未把用户给出的两个停止样式当作都已选定。它替代此前“默认紧凑 5 项、只在超过 5 项时可切换”的行为提案。

| 事件/状态                       | 自动表现                                                     | 手动选择与数据规则                                                         |
| ------------------------------- | ------------------------------------------------------------ | -------------------------------------------------------------------------- |
| 当前会话新 run 有 Todo          | 默认展开，显示 completed/total 与可见进行中项                | Ctrl+T 收成一行摘要，再按展开；不要求超过 5 项                             |
| 同一 run 普通 Todo/流式更新     | 更新事实，不重设展开状态                                     | 用户已收起就保持；首次晚到 Todo 默认展开，除非用户已作本轮选择             |
| 所有 Todo 完成，但 run 仍在输出 | 保留列表和 completed/total，直至真正停止                     | 完成项不再呈现活动效果；不因列表完成就终止 run                             |
| 等审批/交互面板                 | 临时隐藏 Tasks，让位给决策与输入                             | 属于暂停展示，不是停止；离开面板恢复本轮展开/摘要选择                      |
| 发出 interrupt，尚未确认停止    | 保留原状态，沿用真实 Stopping 提示                           | 不修改 Todo 状态；停止失败也不先隐藏；第一次 Esc 仅 armed 时无显隐变化     |
| 确认 run 完成/中断/失败终止     | 默认隐藏全部 Tasks，不留摘要行                               | 未完成项仍是 pending/in_progress，停止不等于完成                           |
| 停止后想回看                    | Ctrl+T 打开当前会话已有 Todo，标注 Tasks · Stopped；再按隐藏 | 只读显示后端现存数据，即使 visible=false；不恢复已清空列表，不伪造归属历史 |
| 运行状态暂时未知/断线恢复       | 不把 unknown 判成停止或新 run，不自动重开                    | 同一绑定保留上次选择，用既有恢复提示表达未知；不借旧 run 推断当前运行      |
| 真实新 run 开始                 | 恢复本轮默认展开                                             | 上一 run 的手动收起不永久继承；同 run 审批往返不是新 run                   |
| 切会话                          | 先校验 session/run/epoch，再呈现目标会话数据                 | 不闪现上一会话 Todo；返回同 run 可恢复选择，终态旧 run 不自动展开          |
| 子代理结束                      | 只更新其对应事实                                             | 不能因子代理结束就隐藏仍在运行的父会话 Tasks                               |

Goal 的后端 visible 在自动续跑间隔可能仍为 true。本提案按用户所说的“run 停止”决定 TUI 默认显隐：可信当前 run 终态到达时隐藏，真实下一 run 开始时展开；不能仅凭 Goal active 强制一直显示，也不把短暂 runtime.idle、同步缺帧当作终态。不同控制源冲突时先等待身份一致的同步结果。后端 Goal 的工作范围与调度不改。

Ctrl+T 只在普通 Prompt 所在上下文可用，审批/命令/队列编辑拥有输入时不抢键。运行中是展开↔单行摘要，停止后是隐藏↔只读展开，不承担翻页，也不触发任何任务执行请求。已有数据为空时不画空卡片，按键也不发送请求。

计数来自 full todos，正常展开保持原顺序；空间不足才用已有最多 5 项的紧凑筛选作降级，并明确 `+N more`，不能假装显示了全部。20 项长列表的完整阅读路径仍需按 Stage 4 的技术门验证；生命周期改动只消除停止后的占位，不能代替运行中的高度设计。内容换行从 marker 后正文起点对齐，状态不只靠颜色；停止回看中保留原状态文字/标记，但不做活动动画。
