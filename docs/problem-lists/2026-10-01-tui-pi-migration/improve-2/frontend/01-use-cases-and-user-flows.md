# improve-2 前端：用例与用户流程

## 1. 信息架构

MainScreen → 当前交互区（Prompt / 队列选择或编辑 / Permission）；Tasks 为辅助阅读区。命令面板、子代理浏览器保留原入口，不在此重做。没有 URL 路由；模式切换和 session identity 是上下文入口。

| 区域 | 入口 | 任务 | 前置条件 | 核心 |
| --- | --- | --- | --- | --- |
| Prompt | 主界面、审批结束返回 | T-01/T-02 | 当前输入模式可用 | 是 |
| 队列编辑 | 原 Alt+↑ 进入，↑/↓ 选择、Enter 获取编辑租约 | T-02 | 有可操作队列项 | 是 |
| Permission | 当前绑定权限请求到达 | T-03 | 请求在同步状态中；发送还需 ready/context | 是 |
| Tasks | 当前 run 默认展开；停止后默认隐藏，Ctrl+T 可回看 | T-04 | 当前会话真实任务数据与可信运行状态 | 是 |

单用户界面无登录角色矩阵。审批 choice 只由后端提供，缺失/过期时不可在客户端合成授权。

## 2. 用户流程

```text
写草稿 → 发送前准备 → recovery 接管 → 接收回执/运行或排队
           ├─准备期间切会话 → 原提交快照留在原归属，不投递到新会话
           └─已接管后结果未知 → 原请求恢复，不生成新发送

写草稿 → 选队列项 → 获取租约 → 编辑 → 保存/重发 → 恢复原草稿
                        ├─失效 → 保留修改文本，提示不可保存
                        └─Esc → 释放租约、恢复编辑前草稿

写草稿 → 审批出现 → 阅读正文/翻页 → 选择 → 发送 → 请求移除 → 原草稿
                                      └─失败 → 留在原请求，显式重试
```

## 3. 用例

### UC-INPUT-01 完整输入（T-01）

前置：Prompt 当前可编辑。用户输入/粘贴 → 移动/删除 → Enter。完成结果是编辑过程中不拆字素、展示窗口可走到全文，发送 payload 与当前原文按既有 trim 规则一致。空输入不发送；同步中显示原因并保留草稿；长粘贴不自动提交。

### UC-DRAFT-01 跨会话继续（T-02）

用户在 A 将光标放到中段 → 切 B 输入 → 回 A。完成结果为 A/B 文本与光标分别保持。异步请求的失败不能清除或覆盖另一会话的新草稿；进程退出后不承诺未发送草稿恢复。

已经按 Enter、但准备被取消或明确拒收的文本，以原归属的未发送记录显示；普通 ↑/↓ 输入历史可取回全文，编辑后再提交是新意图。当前编辑内容在历史导航前按已有 draft 机制保留，↓ 返回；不自动把失败文本盖到新草稿上。普通 unknown 记录只允许查询回执，恢复状态未明确前不能把它当成可重新发送的失败稿。

### UC-QUEUE-01 修改队列（T-02）

用户带着普通草稿进入队列 → 选项 → Enter 取得 lease → 修改 → Enter 保存/重发 → 返回原草稿。获取失败仍保留原草稿；租约失效保留编辑文本且阻止未经授权保存；Esc 取消编辑回到进入前文本和光标。retained 重发结果未知时只可重试第一次文本及 operationId，不把修改后的文本冒充原操作。

### UC-PERMISSION-01 阅读并选择（T-03）

审批出现 → 看到来源/操作/可选项 → 长正文 PgUp/PgDn → 选择后 Enter。完成结果为只发送实际选中 choice，请求移除后回到原草稿；有后续审批则进入下一请求。无 deny 时 Esc 不发送，留在当前请求并提示显式选择；失效则同步，网络失败保留选择。

### UC-TASKS-01 看进展（T-04）

用户在运行中默认看到列表，可按 Ctrl+T 手动收起；确认停止后默认隐藏，有需要再按 Ctrl+T 查看保留的数据。审批往返不重置手动选择。完成结果为计数基于全列表，多个可见进行中项都能识别、长行续行对齐；空列表不渲染，停止不把未完成项改成完成。展开内容可达性继承 [Stage 0](../02-optimization-plan-and-change-scope.md#23-阶段与完成定义) 的实际布局契约，不能“展开”后静默丢弃多余任务。
