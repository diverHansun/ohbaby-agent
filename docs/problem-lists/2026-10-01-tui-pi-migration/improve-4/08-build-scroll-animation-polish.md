# improve-4：构建去重、滚动成本与等待动画节奏

日期：2026-10-04。实施基线 `f5de4b5c`，沿用本地 `improve-4`。用户先要求排查讨论，确认方案后授权实施、测试和子代理审查；本轮不调用 Pi，不 push 或 merge。

## 已确认的问题与范围

- `Some chunks` 来自 Web 的 Vite 构建。主 JS 约 515.33 kB，gzip 约 152.61 kB，略超默认 500 kB 提醒阈值。它不是 TUI 渲染问题，构建没有失败。根构建遍历 Web，而 CLI 构建内部又执行 Web 构建，导致同一次根构建中重复输出。此次只消除重复构建，保留体积警告，不为消除黄字拆包或提高阈值。
- 上一轮已经修复连续滚动事件丢失和历史阅读位置被打断。本轮关注成本和粒度：未变长消息仅因滚动仍反复进行 Markdown 排版，滚轮每次移动 3 行，TTY 使用 Ink 默认 30fps 上限。
- 等待文案的星形图标每 100ms 换形、1 秒循环；光条每秒前进 20 个字素位置，两种动画共用 tick。用户希望星号更慢、光条稍快。

## 实施

### 构建职责

根 `build` 按依赖顺序构建 CLI 之外的 workspace，然后执行 CLI `build:package`。CLI 独立 `build` 一次性选择自身依赖与 Web，完成后同样执行 `build:package`。后者沿用 CLI 编译、声明生成及 Web 资源复制，不自行重复构建依赖。

完整入口仍是根 `pnpm build` 或 `pnpm --filter ohbaby-cli build`；`build:package` 是编排内部使用的本包打包步骤，前置依赖和 Web 已由调用者准备。没有新增构建框架、环境标记或缓存协议。

### 滚动

`MessageRow` 使用组件内 `useMemo` 复用格式化结果和 React 子树，依赖消息、有效宽度、主题、reasoning 状态和工具展开状态。滚动位置变化继续更新可视区和消息锚点，但不重新解析未变化的正文。缓存随组件卸载释放，不使用全局内容缓存，不拆分 Markdown 源码。

滚轮每个报告从 3 行调整为 2 行；连续事件累计、上滚固定阅读位置、回到底部恢复跟随的规则保持。交互 TTY 的绘制上限改为 60fps；这是上限，不是持续强制刷新或保证实际达到 60fps。

### 动画

继续使用一个定时器，刷新间隔 50ms。星号每 200ms 换形、2 秒循环；光条每秒前进 25 个字素位置，保留 600ms 循环停顿、现有宽度和颜色。只调整等待文案动画，工具执行的点阵 spinner 保持原行为。

`OHBABY_TUI_NO_ANIM=1`、首段正文出现、运行结束和卸载时的静态/停止行为保留。真实 Ink 测试限制刷新次数、单次 patch 字节数和每秒写入量，避免更快的光条造成无界输出。

## 验证与审查

新增滚动投影回归先验证旧代码失败：5 次滚动触发 5 次重复 Markdown 排版。修复后不再重复排版，同时断言可见内容确实移动，文本更新与 resize 会失效重算，历史阅读位置和最新内容都正确。

动画回归覆盖 50ms 单时钟、200ms 星号帧、2 秒循环、25 字素/秒和 600ms 停顿。实际等待指示器约每秒 20 次内容更新、4.7 kB 写入；隐藏、结束和卸载后零写入。性能数字来自本机受控测试，不是所有终端的保证。

### 滚动现场对照

100×32 模拟 TTY 使用真实 Ink 和生产布局，每 16ms 输入一个滚轮报告，共 90 个；另一个场景交织 45 次正文追加。基线是本轮讨论阶段的旧实现，最终配置包含缓存、2 行步长和 60fps 上限。输入报告数量一致，滚动距离因步长调整不同。

| 场景 | 旧实现 | 最终配置 |
| --- | --- | --- |
| 600 行、约 2 万字符，不变正文的重复 Markdown 排版次数 | 90 | 0 |
| 同一长正文滚动，画面输出间隔中位数 | 57.0ms | 33.3ms |
| 长正文加 45 次追加，Markdown 排版次数 | 180 | 45 |
| 长正文加追加，画面输出间隔中位数 | 57.4ms | 42.7ms |

长正文的 Ink 全长绘制仍约每帧 13ms，本轮没有增加可见行渲染器或再次拆分 Markdown。测量分别记录 React、Markdown、Ink 和实际 stdout write；不能把这些结果当作终端 GPU、触控板或原生复制的 GUI 验收，也不承诺持续 60fps。原始数据：`/tmp/ohbaby-scroll-perf-final.out`，交织场明确为 `stream: true`。
