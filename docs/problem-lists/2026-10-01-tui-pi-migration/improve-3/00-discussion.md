## 2. 已确认目标与范围

| 项目     | 结论                                                                                                 |
| -------- | ---------------------------------------------------------------------------------------------------- |
| 技术路线 | 保留 React/Ink；引入官方 pi-tui 的 Markdown、显示宽度和 ANSI 换行/截断能力，先验证后接入             |
| 工具输出 | 直接进入原有终端时间线；Read/Glob/Grep 摘要，Edit/Write/Bash 展示有意义的内容                        |
| 长内容   | 相对该类工具的预览预算而言；不是独立内容类型，不由“历史消息”身份决定                                 |
| 展开     | Pi 式 Ctrl+O：第一次展开工具详情，再按一次恢复正常紧凑 TUI；不展开 reasoning、不加载历史、不切阅读页 |
| 主动重绘 | 用户在明确说明清屏/原生回滚替换代价后确认学习 Pi；允许主动切换时必要的一次清屏重印，普通刷新仍须稳定 |
| 文件修改 | Edit 单列真实 diff；Write 新建展示内容、覆盖展示真实前后 diff；不伪造旧内容                          |
| Markdown | 改善助手正文阅读，与工具输出共同验证宽度、流式和终端复制                                             |
| 恢复     | 去除 Ctrl+R 和相关提示，系统自动尝试；发送结果未知只能查询原请求，不能自动重新发送                   |
| 信息密度 | 短内容直接读，长内容有预览；只在确有省略或异常时显示必要说明                                         |

## 3. 本轮不做

不引入 pi Editor、pi 终端渲染器、其他 pi 业务包、React→pi renderer、通用焦点/插件/工具浏览框架。不新增工具列表、分页阅读页、详情 overlay、外部编辑器或复制按钮依赖。不为尚未执行的流式参数计算猜测性 diff。不重做审批、Tasks、队列或模型自动重试策略。

## 4. 前轮修订与实现初值

本轮取代 plan 中未定的独立详情入口，以及 improve-2 中 Ctrl+R 手动恢复的目标要求。前轮对未知提交不重发、草稿不被覆盖、原始身份校验的要求继续有效。

Bash 预览末尾约 5 个显示行，Write 新建预览约 10 行，diff 从首个实际变化处显示上下文，是讨论中的实施初值；不是新增用户配置，也不是所有工具共用一个字符数阈值。最终行预算、窄屏和完整可达性见前端 03/04。

“直接输出到 terminal”指正常会话内联输出，终端写入仍由 Ink 统一管理；不让工具或 pi Markdown 直接绕过宿主写 stdout。

Ctrl+O 的大写是书写约定，不要求 Shift。两种状态都是同一个正常运行的 TUI，任务与事件继续进行；返回正常视图指恢复紧凑显示，不是恢复任务或还原旧终端滚动位置。
