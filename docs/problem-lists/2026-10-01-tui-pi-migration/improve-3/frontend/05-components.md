# improve-3 前端：组件契约

这是责任划分，不要求为每行新建一个类或文件。优先在已有 tool-part、message-row、render 和 recovery 边界演进。

## 1. 组件分层

| 层                             | 责任                                            | 不负责                           |
| ------------------------------ | ----------------------------------------------- | -------------------------------- |
| App/现有交互上下文             | toolsExpanded、键位归属、布局预算               | 解释工具 metadata、计算 diff     |
| MessageRow/ToolBlock（概念名） | call/result 配对结果的呈现，状态与标题          | 自行取历史、执行工具、读磁盘     |
| 少量工具呈现函数               | 读/搜索摘要、diff、代码文本、命令输出、通用后备 | 注册插件、业务成败判定           |
| Markdown/text helper           | 内容＋宽度＋主题 → ANSI 行                      | 监听 stdin、启动 pi TUI          |
| session-recovery               | 查询已有状态、自动接续、原身份保护              | 重发未知业务动作、替代 transport |

## 2. 关键输入输出

工具块输入：当前调用和匹配结果、有效内容宽度、expanded、既有 theme。执行状态来自 SDK，不因行数或 expanded 变更。输出为可测的显示行/Ink 内容；没有“展开某工具”新回调，各块消费同一模式。

Markdown helper 输入：原文、宽度、主题；输出 ANSI 行。缓存若有，必须同时包含内容、宽度和主题；未闭合 Markdown 的流式续写可以重排该条内容，不能封存错误版后永不更新。

diff renderer 输入：执行层保存的 diff、显示宽度、expanded。输出单列增删与行号；不是 diff 计算器。tab 仅在显示投影展开，换行后的缩进按真实列宽计算，不改变原数据。

## 3. 状态与视觉语义

所有工具块共用前端 03 的正文、muted、类别、error 与 diff 语义。错误和 dry-run 有文字，不能只换颜色。省略说明只在实际存在隐藏内容时出现。组件不添加每条 Ctrl+O 教程或新的进度 spinner。

## 4. 组合与生命周期

身份至少含当前会话/消息/调用的可靠归属；不能以相同 tool name 复用旧结果。卸载清理局部缓存和订阅。ToolBlock 不建立计时器；后台工作和恢复由现有业务层调度。

工具组件与审批组件职责分开。长审批仍按 improve-2 的局部正文窗口工作，不能复用成工具阅读页。Tasks 使用原有生命周期和 Ctrl+T，不接入 toolsExpanded。
