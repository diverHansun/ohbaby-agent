# improve-3 前端：布局与视觉

本轮沿用用户确认的“正常输出到 terminal、长内容原位展开、少提示”。以下线框把已讨论的结构整理成实施契约，未新增页面；前轮用户消息、working phrase、审批、Tasks 和底栏结构继续继承。

## 1. 设计原则

| 原则         | 终端截图观察点                    | 反例                             |
| ------------ | --------------------------------- | -------------------------------- |
| 结果紧邻操作 | 命令或文件名下就是结果            | 看结果必须离开对话进入列表       |
| 正文优先     | 工具名轻强调，路径和正文清楚      | 全行饱和色、每条结果附数行提示   |
| 变化可读     | diff 有增删符号、行号、上下文     | 改一行却整份文件全红全绿         |
| 状态可信     | 失败、dry-run、后台启动有文字区别 | 仅绿点表达成功，后台启动称已完成 |

## 2. 方向与来源

Pi 的连续终端输出和 Ctrl+O；OpenCode 的工具分类密度和单列 diff；本地 CCB 的克制预览。来源及限制见 [参考](../03-reference-projects.md)。具体颜色沿用 ohbaby 语义 token，不复制参考项目的整套主题。

终端字体由用户配置，不新装字体或图标库。Markdown 标题用有限强调，不模拟 Web 大字号。工具结果不增加动画。

## 3. 语义 token 与密度

正文/路径使用普通文字色；次要计数和省略标记用 muted；读/搜索、修改、执行按前轮分类色只强调工具名；error、warning 与执行类别分开。diff 使用 added/removed/context 语义，保留 `+`/`-`，无色时仍可辨。

缩进使用终端列，初值为工具正文相对标题缩进 2 列。同一调用内部不加空白卡片边框；相邻逻辑块按已有阶梯使用 0 或 1 空行。长内容没有单独背景大面板。所有缩进/行号/省略标记占用真实列宽。

## 4. 关键线框

### 4.1 正常内联输出

```text
  Read src/main.ts · 1–80
  Grep "session" src/ · 12 matches

  Edit src/config.ts
    …
      8   export const config = {
  -   9     retries: 2,
  +   9     retries: 3,
     10   };

  Bash pnpm test
    Test Files  4 passed
    Tests       28 passed

  助手回复正文……
  ────────────────────────────────────────────
  > 当前草稿
  ────────────────────────────────────────────
  ~/project                       auto/default
  model · high                     2% 20k/1m
```

紧凑预览只显示一套行号：删除用旧行号，增加和上下文用新行号；增删符号区分替换前后，同号是正常现象。紧凑态不显示 `@@` 标头；文件前面确有未展示内容时，可用一行 `…` 表示。保存的原始 diff 和展开态仍保留正确 old/new hunk 范围，不能为简化界面改写 patch 事实。示意并非宽度精确快照。

### 4.2 长输出与展开

```text
  Bash pnpm test
    ... 24 lines omitted
    FAIL src/example.test.ts
    Expected: 3
    Received: 2
    Tests  1 failed, 27 passed
    exit 1
```

Ctrl+O 后同一调用位置显示完整可用输出，再按恢复正常紧凑 TUI。主动切换可按 Pi 的方式一次清屏重印已加载会话；展开态仍正常运行，不新增阅读页、面板标题或返回键。`exit 1` 仅在有可信退出码时出现，错误说明不被预览裁掉。省略数只在能准确计算时写数字，否则用简短 `…`。

### 4.3 持续恢复状态

```text
  > 保留的当前草稿
  Syncing session…
```

状态使用既有单一提示位置，不增加一层恢复面板。短暂后台恢复不额外闪提示；因同步影响提交时才说明。真正断线用 `Reconnecting…`，发送确认未知用 `Confirming submission…`；不能在无自动任务时一直声称“正在恢复”。

## 5. 宽度、预览与可达性

| 内容            | 紧凑初值                                               | 展开                                                       |
| --------------- | ------------------------------------------------------ | ---------------------------------------------------------- |
| Read/Glob/Grep  | 一条摘要；长路径/条件按显示列缩写                      | 展示已保存结果正文及完整必要调用信息，不重新读取文件或扫描 |
| Bash            | 命令摘要最多 2 个显示行；输出末尾约 5 个显示行         | 完整可用命令及全部已保存输出；后台仍仅展示已有事实         |
| Write 新建      | 开头约 10 个显示行                                     | 该次已确认新建的可用内容                                   |
| Edit/Write 覆盖 | 从首个实际变化 hunk 开始约 10 个显示行，保留少量上下文 | 全部已保存 diff，不承诺完整文件内容                        |
| 未知工具        | 必要调用摘要和约 5 行结果                              | 原始可用结果；不展开任意内部 metadata                      |

命令、路径和搜索条件本身也可能很长。紧凑摘要按上表限制，省略处用一个简短 `…`；展开时显示完整必要调用信息，不展开内部子代理 prompt 或任意 metadata。命令摘要与输出正文分别计算预览预算，标记紧邻被省略部分，不重复快捷键提示；标题、状态、错误和标记仍全部计入父布局预算。裁剪只改变显示，不修改执行参数或已保存输出。

“长”表示排版后超过该类预览预算。显示行包含软换行；源文件行号另算。差异行被窄屏软换行时，续行对齐正文，不重复伪造新行号。diff 截到 hunk 中部可用明确省略结尾，不能伪造闭合 hunk 或显示不存在的上下文。

80×24 和 120×40 使用同一单列结构；60×20 压缩摘要、路径和次要信息，保留操作对象可辨、错误与输入。更窄时有界显示，不能截半个宽字素；需要全文时采用正常终端展开/回滚，不新增横向滚动系统。短窗口不改变执行事实或保存内容。

Read/Glob/Grep 的“摘要”是默认紧凑态，用户主动 Ctrl+O 后仍可阅读其实际保存正文；不把模型看过正文当成用户不需要查看的理由。全局展开可能增加输出量，因此其可行性和普通刷新稳定性须通过 Stage 1 验证。

短结果不出现省略标记。紧凑/展开是当前会话的统一模式；帮助里集中写 `Ctrl+O Toggle tool output`，不在每个工具块重复说明，也不新增常驻底栏一行。已采集结果被后端截断时，在该块一次说明 `Output truncated`；没有真实完整日志路径时不显示“查看完整日志”。

## 6. 术语与文案

| 概念       | 界面表达                   | 不使用                           |
| ---------- | -------------------------- | -------------------------------- |
| 工具展开   | Toggle tool output（帮助） | 历史恢复、详情模式               |
| 预览省略   | `… N lines omitted` / `…`  | 把可展开内容称为已经丢失         |
| 源头截断   | Output truncated           | 承诺 Ctrl+O 能找回源头未保存内容 |
| dry-run    | Dry run                    | 已修改、Written                  |
| 后台启动   | Started in background      | Completed（仅因工具返回）        |
| 未知旧回执 | Submission unconfirmed     | Not sent、Failed（没有证据）     |

保持既有英文 UI 语言，本轮不增加国际化系统。成功的正常结果不附解释性教程。空输出只有被确认已完成且确为空时才可称无输出；缺失数据不等于空。

## 7. 视觉验收口径

Ghostty 在 60×20、80×24、120×40 截图，覆盖紧凑/展开、失败、dry-run、后台与恢复状态。正文可读、工具名可扫读、错误不靠颜色、单列 diff 能找到实际变化、展开仍在时间线中。

真实上滚停留、复制、缩放另做操作验收；截图不能证明回滚稳定。深浅背景和低色彩都保留正文层级，不做像素对齐复刻参考项目。

## 8. 实现约束摘要

| 必须遵守                                                                         | 初值可调                                                | 留给实现                                   |
| -------------------------------------------------------------------------------- | ------------------------------------------------------- | ------------------------------------------ |
| 原位单列、Ctrl+O 唯一语义、无阅读页、无 Ctrl+R、真实状态与内容、整帧预算、少提示 | 命令 2 行与正文 5/10 行预览、少量上下文、正文缩进和空行 | 既有 token 内的色值微调、Markdown 细节强调 |

用户已确认要求和本表第一列优先于参考项目、Pi 审查建议与实施模型偏好。调整初值要记录原因并验证宽度和阅读，不能把“初值可调”当成新增交互的授权。
