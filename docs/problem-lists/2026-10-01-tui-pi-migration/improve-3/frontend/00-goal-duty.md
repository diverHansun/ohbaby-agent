# improve-3 前端：目标与职责

2026-10-03。TUI 增量设计，保留前两轮界面骨架；[本轮入口](../README.md)、[实施方案](../02-optimization-plan-and-change-scope.md)。本目录 00–08 都是计划，尚未实施。

## 1. 产品目标

让用户在正常对话中读懂工具做了什么、返回了什么，以及文件实际改变了哪里。长内容可以直接在时间线展开，日常使用不需要学习恢复快捷键。助手 Markdown 更清楚，原生回滚、草稿和审批继续可靠。

## 2. 用户角色

本地 CLI 使用者，既包括只关注结果的日常用户，也包括需要检查命令和 diff 的开发者。没有新增角色、登录或授权体系；工具执行权限仍由后端和 improve-2 审批契约决定。

## 3. 核心任务

- T-01：快速确认工具对象、状态和结果。
- T-02：读懂实际文件改动和命令输出。
- T-03：原位展开长工具结果，再回到紧凑显示。
- T-04：阅读流式 Markdown、回滚和复制内容。
- T-05：临时同步故障后自动继续使用，保留草稿与原请求归属。

## 4. 职责边界

前端负责分类呈现、显示行预算、展开状态、必要错误说明与已有恢复协议的自动调度。工具执行层负责实际修改事实、输出采集和完整性；SDK 负责可靠传递；Ink 负责终端生命周期。

前端不从显示文本猜测是否写入、不事后读取文件复原 diff、不替用户重发结果未知的请求、不把后台启动当成任务完成。

## 5. Non-goals

不增加阅读页、工具浏览器、分页工具列表、鼠标选择系统、外部编辑器、复制按钮、无限日志存储或新的持久化 UI 状态。pi Editor、renderer、通用插件框架与全量输入重构均不属于本轮。
