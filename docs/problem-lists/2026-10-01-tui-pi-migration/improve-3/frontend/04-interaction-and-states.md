# improve-3 前端：交互与状态

本文件为 Ctrl+O、工具块和恢复状态的行为入口；布局见 [03](03-ui-layout-and-style.md)，恢复调度和数据含义见 [06](06-data-api-and-state.md)。

## 1. Ctrl+O 与按键归属

采用 Pi 的双态切换：Ctrl+O 展开工具详情，再按 Ctrl+O 恢复正常紧凑 TUI。任务、输入和事件同步继续运行，不进入独立阅读模式。字母大写只是记法，不要求 Shift。

| 上下文                                         | Ctrl+O 行为                                                            |
| ---------------------------------------------- | ---------------------------------------------------------------------- |
| 普通主聊天输入（空闲或运行中）                 | 切换当前会话工具显示模式，不消费草稿内容、不发送请求                   |
| 审批、命令面板、子代理浏览、队列编辑等独占交互 | 不处理此全局切换，保留交互自身的已有键义；不延后补触发                 |
| 暂无结果或两种投影没有差异                     | 仍切换显示模式，后到结果遵循它；没有可见差异时不提示，也不为此强制清屏 |
| 当前已展开，即使 resize 后内容都变短           | 始终允许切回紧凑，避免未来结果意外继续展开                             |
| 有长结果且部分工具仍在执行                     | 切换已有结果，后到结果遵循当前模式；不改变执行状态                     |

App 的统一输入上下文负责一次按键只执行一次；工具块不能各自监听全局按键。显示模式只需一个布尔值，不按结果是否够长另建切换规则。

切换会话/新建会话重置紧凑；同一会话断线恢复、resize、补载历史维持当前模式。旧历史补载进来后使用当前模式，Ctrl+O 本身绝不调用 loadHistory。

PgUp 历史补载、slash 候选 PgUp/PgDn、↑/↓ 输入历史、原生终端回滚都保留。Ctrl+T 仍归 Tasks。Ctrl+R 不再调用恢复，也不分配新用途；清理帮助、App、Prompt 中所有手动恢复提示。

## 2. 工具状态矩阵

| 状态               | 标题与正文                                           | 展开行为                                        |
| ------------------ | ---------------------------------------------------- | ----------------------------------------------- |
| pending/running    | 可信名称、对象和现有执行状态；没有结果不绘制空正文框 | 仅展示已有事实，不预测结果                      |
| 等审批             | 执行尚未获准；审批由原面板表达                       | 不抢审批焦点、不显示“已修改”                    |
| completed + 短内容 | 直接显示该类默认内容，读/搜索仍摘要                  | 无省略提示；全局已展开时可显示保存的读/搜索正文 |
| completed + 长内容 | 有意义预览、一次省略标记                             | 原位完整可用结果                                |
| failed/aborted     | 可读的错误/中断标记及已有部分输出                    | 长错误也可展开，紧凑不能把唯一失败原因藏掉      |
| dry-run            | 明确 Dry run，可展示真实预演 diff                    | 不改变为正式修改                                |
| 后台已启动         | Started in background 与可信 job 信息、已返回输出    | 不因展开增加轮询或订阅，不声称后台结束          |
| 旧记录无展示字段   | 可信 input/output/error 后备                         | 只展开保存内容；缺 diff 时不给伪造 patch        |
| 结果采集受限       | 一次必要的缺失/截断说明                              | 只展开保留下来的部分，不显示虚假全文入口        |

Error 与工具类别独立。一般成功不重复写“执行成功”。新建 Write 必须由成功结果的 created 事实确认，覆盖 Write 必须有真实 diff 才按 diff 显示；没有可信 diff 时显示路径和实际保存结果。

## 3. 展开时的阅读与焦点

显示变化留在同一调用位置。可用内容增长后，用户通过正常终端回滚阅读；没有新焦点、选中工具、返回按钮或 ESC 退出详情。

主动切换允许 Pi 式一次必要的清屏重印，原生 scrollback 可被替换，阅读位置可回到底部；再按 Ctrl+O 恢复紧凑投影，不承诺还原旧的原生回滚内容或滚动坐标。必须保持消息顺序、调用身份、草稿和光标，不删除会话事实、不重复追加副本。随后普通 token、动画和后台通知不能反复重印已稳定历史。具体输出实现仍须通过本轮 02 Stage 1 验证。

流式/恢复更新沿原身份替换事实，展开模式只影响投影。新结果不能把模式自动改回紧凑；resize 只重排，不重发工具、不重置 UI 模式。

## 4. 自动恢复状态矩阵

| 状态                      | 自动行为                       | 用户看到什么                                                   |
| ------------------------- | ------------------------------ | -------------------------------------------------------------- |
| 健康、无待确认请求        | 无恢复计时器/额外轮询          | 无恢复提示                                                     |
| 短暂失同步                | 沿原 SDK 快速尝试              | 不加瞬时通知；若阻止提交则保留草稿并显示同步状态               |
| 快速尝试耗尽              | 冷却后自动接续，逐步放慢       | 一条 Syncing session…；不显示次数和倒计时                      |
| transport 断开            | 暂停恢复查询，等既有重连       | 必要时 Reconnecting…                                           |
| 原请求确认未知            | 自动查询原 requestId           | Confirming submission…；新草稿可编辑，提交受现有规则保护       |
| 找到匹配回执              | 移除对应 pending，更新其原归属 | 提示自动消失；不覆盖用户后来写的草稿                           |
| 新 runtime 无法确认旧请求 | 不跨 epoch 猜测或重新执行      | Submission unconfirmed；保留既有放弃跟踪能力，不假装一直能恢复 |
| 明确拒收/权限或配置问题   | 不自动重发业务动作             | 显示真实错误，不冒充同步成功                                   |

提示在原单一状态区表达，审批期间服从 improve-2 的提示合并预算，不新增常驻恢复行。结果未知时保留 Ctrl+X 原有“仅放弃跟踪、可能仍在运行”的后果说明；本轮只取消 Ctrl+R，不顺便删除用户已有退出未知跟踪的路径。

## 5. 错误、空态与重复操作

数据为空时没有工具空态页面。无数据时切换模式保持安静，不制造空页面或提示。按一次 Ctrl+O 只能切一次，不能同时触发提交/补载；重复按键按实际事件逐次切换，不增加复杂防抖协议。

“输出为空”“输出未保存”“后台尚未完成”分别表达。正在自动恢复不代表原请求失败。已明确拒收的未发送快照按 improve-2 恢复路径保留；审批响应失败仍等待用户原有的显式选择重试，自动恢复不能代替授权。
