# improve-3 前端：用例与用户流程

任务来自 [00](00-goal-duty.md)。只有现有主会话界面，没有新增路由或详情页。

## 1. 信息架构

```text
主会话
├─ 时间线：用户 / 助手 Markdown / 内联工具块
├─ 当前活动与既有 Tasks
├─ 输入区或独占交互（审批、命令、子代理浏览等）
└─ improve-1 两行底栏
```

| 表面           | 任务      | 前置条件                     | 权限                           |
| -------------- | --------- | ---------------------------- | ------------------------------ |
| 时间线         | T-01–T-04 | 有已加载消息                 | 展示已有事实，不触发执行权限   |
| 输入与恢复状态 | T-05      | 后端状态可判断；草稿独立保留 | 提交仍受原 canSubmit 约束      |
| 审批等既有面板 | 前轮任务  | 对应交互拥有焦点             | 沿 improve-2，不被 Ctrl+O 抢占 |

## 2. 用户流程

```text
发送消息 → 读取助手正文 → 工具开始 → 工具返回
                                ├─ 短结果：直接看完
                                ├─ 长结果：看预览 → Ctrl+O → 原位看完整可用内容
                                ├─ 失败：看错误与已返回输出
                                └─ 后台作业：显示已启动及已知状态

同步/回执暂时未知 → 自动尝试 → 成功后恢复正常
                           └─ 持续失败：保持草稿、低频接续、简短真实状态
```

展开不发历史请求。用户需要更早消息时仍使用现有 PgUp；触控板/终端快捷键回滚只是移动阅读位置；↑/↓ 仍是输入历史。

## 3. 用例

| ID         | 前置与主流程                                      | 异常/边界                                      | 可观察结果                                      |
| ---------- | ------------------------------------------------- | ---------------------------------------------- | ----------------------------------------------- |
| UC-TOOL-01 | 已加载调用，等待结果，阅读摘要（T-01）            | 0 个结果、部分扫描、工具未知、无结果           | 真正的 0 可见；未知不写 0；没有空成功正文块     |
| UC-TOOL-02 | Edit/Write 返回，阅读修改（T-02）                 | dry-run、失败、旧记录无 diff、预算限制         | 真实变化可辨；未写入不称成功修改；缺失不伪造    |
| UC-TOOL-03 | Bash 返回，阅读命令与输出（T-02）                 | stderr/失败、空输出、后台启动、源头截断        | 错误与后台事实可见，完整可用输出有去向          |
| UC-TOOL-04 | 普通聊天中 Ctrl+O，查看长结果，再按回紧凑（T-03） | 已滚出视口、流式追加、补历史、面板独占、切会话 | 同一工具原位切换；草稿不变；无额外执行/历史请求 |
| UC-TOOL-05 | 阅读流式 Markdown，缩放、上滚和复制（T-04）       | 未闭合 fence、宽表格、emoji、长 URL            | 无坏 ANSI/重复换行；普通更新不打断回滚          |
| UC-TOOL-06 | 故障后等待自动恢复（T-05）                        | 暂时断线、确认丢失、旧 epoch、业务拒绝         | 无 Ctrl+R；不重复提交；持续未知如实说明         |

以上用例的状态矩阵见 [04](04-interaction-and-states.md)，数据场景见 [06](06-data-api-and-state.md)，验收见 [08](08-test-and-acceptance.md)。
