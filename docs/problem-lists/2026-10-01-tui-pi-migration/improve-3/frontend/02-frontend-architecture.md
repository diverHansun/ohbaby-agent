# improve-3 前端：架构

## 1. 技术边界

React/Ink 保持现有宿主。只通过官方 pi-tui 的公开导出使用 Markdown、主题接口与文本函数；不调用 pi 的输入处理、终端 start/stop 或 requestRender。不依赖 pi 测试目录中的 VirtualTerminal，也不访问私有成员或深层导入。

小型文本适配集中在既有 `render/`，将 ohbaby token 映射为 MarkdownTheme，返回 ANSI 行。采用的能力通过后删除相应旧解析实现，避免双维护。输入编辑器继续执行 improve-2 的字素、光标和 tab 投影契约，不能顺手换成 Markdown 的 tab 语义。

## 2. 显示数据流

```text
SDK 消息事实 → store → 来源筛选/历史与活动划分（improve-1）
                      → call/result 配对 → 工具投影
                                            ├─ 紧凑/展开
                                            └─ 文本排版 → Ink
```

同一调用以会话/消息/调用身份配对，不靠工具名称或数组相邻关系。迟到结果只更新原调用。工具块不自己查询历史、读文件或持久化副本；Subagent 继续使用前轮安全摘要，不把内部 prompt 当通用参数展开。

## 3. 状态归属

| 状态                     | 所属位置                 | 生命周期                                           |
| ------------------------ | ------------------------ | -------------------------------------------------- |
| 工具输入、结果、执行状态 | Agent/SDK/store          | 原业务生命周期                                     |
| 展示事实                 | 执行结果及 SDK 可选字段  | 同结果持久化；旧记录可缺失                         |
| toolsExpanded            | 当前主会话视图           | 初始 false；切会话清 false；resize/恢复不变        |
| Markdown/工具显示行缓存  | 组件或小型 render helper | 由内容、宽度、主题、展开状态失效；不建全局缓存平台 |
| 自动恢复任务             | 现有 session-recovery    | 按原始 scope/epoch/requestId，取消规则见 06        |

## 4. 输出与布局

所有显示行进入 improve-1 的统一输出路径和 improve-2 的输入模式判断。展开不能绕开整帧预算。输出超过一屏时由已验证的 MainScreen 输出策略和原生 scrollback 承载，不能将几千行留在活动 Box。

已输出的 Static 行不是可任意改高的 DOM。历史展开是否成立由本轮 02 Stage 1 的技术验证门决定；没有通过不得实现一个只影响新工具、却声称展开历史也可用的开关。

## 5. 错误处理与维护

pi 渲染异常时可对当前内容使用有界纯文本后备，保留真实内容和错误状态；不为普通用户展示“parser/adapter”术语。工具失败来自后端，显示失败不改变工具执行状态。恢复的调度失败与原请求执行结果分开。

新依赖精确锁版，记录公开 API 与升级回归用例。回退显示实现不删除保存事实；普通 Web 消费者忽略新增字段仍能正常工作。
