# improve-3 前端：数据、API 与状态

本文件定义本轮所需事实和恢复策略。下述新增字段是拟议契约，当前 SDK 尚不具备；实施要同步类型、校验、导出、RPC 和历史投影。

## 1. API 到界面

| 来源                                                                  | 消费面                                | 要求                                     |
| --------------------------------------------------------------------- | ------------------------------------- | ---------------------------------------- |
| UiToolCall input/status/execution                                     | 工具标题和执行状态                    | 使用原调用身份；不从 result 字符串猜完成 |
| UiToolResult output/error                                             | 原始可用正文和失败                    | 实时/快照/历史保持一致；空和缺失不能混淆 |
| 新增可选 details                                                      | 数量、真实 diff、采集完整性、后台事实 | 白名单类型化，不通传 metadata            |
| 会话快照/增量/历史                                                    | 当前已加载工具块                      | 来源过滤、修正、补载继承 improve-1       |
| getPromptReceipt/getSessionControl/permission snapshot 等已有恢复接口 | 确认原请求、同步身份和控制状态        | 沿既有身份校验，不新建恢复 API           |

## 2. 最小展示事实

建议在 `UiToolResult` 新增可选 `details`，采用有限的可辨识类型；名称可在实现时按仓库规范调整，以下语义必须保留。只有存在真实消费者需求的字段才加入，不能一次性复制工具全部 metadata。

| 类别       | 必需语义                                                      | 缺失时                                        |
| ---------- | ------------------------------------------------------------- | --------------------------------------------- |
| Read       | 实际读取范围、已有的读取限制事实                              | 只显示路径/可信 input；不猜总行数             |
| Glob/Grep  | 结果数的单位（files/matches）、扫描是否完整、输出展示是否受限 | 不声称完整总数；不能用行数统计当匹配数        |
| Edit/Write | 执行层生成的 diff 或不可用原因、created/dryRun                | 展示保存的结果；无 diff 不还原旧文件          |
| Bash       | 若已有：exitCode、后台 job 身份/状态、采集截断事实            | 不猜退出码/运行完成，也不把空文本当完整空输出 |
| 通用       | 实际 output/error 和可靠的源头限制事实                        | 原始结果后备，不依赖自定义 schema 注册        |

源头截断是执行层事实；预览省略行数是前端派生值，不写进持久化。Glob 的 `renderList` token 裁剪若未体现在现有 metadata，应补准确事实。Grep 的扫描不完整和显示受限要分开；数量只能按其实际统计口径命名。

Edit/Write 的 diff 保持当前有界策略：输入预算与输出预算沿 `mutation-budgets.ts`（调研值分别为 256 KiB 与 32 KiB，实施核对）。本轮不以“全文可达”要求保存超预算文件；展开保证可读取全部已保存内容，并说明真实限制。新增 source-truncation 事实不得伪称提供未保存的全文。

## 3. 生产、持久化与兼容

新增一个小型共享投影函数，由 Agent 的实时 adapter 与 persistent-store 消费，校验 metadata 类型/范围后构造 SDK details。工具名与结果对应关系要可信，不能因为第三方 metadata 声称某种 kind 就误投影为内置工具。

Write 覆盖的 before 在原文件锁内、写入前有界读取；after 是这次将写入的内容。成功提交后保存同一次执行的 diff；dry-run 的 diff 必须附 dryRun；失败不把预演当成真实修改。新建内容可取匹配调用的 input.content，但必须有成功 created 事实，旧记录缺 created 不猜。

普通 error 需要在工具状态的类型、状态转换、JSON 校验和历史投影中保留可选的部分 output，复用既有序列化落点。旧 error 没有输出时只显示保存错误，不宣称没有任何输出。新增字段不能使旧快照无法解码；不需要新表则不做数据库迁移。

CLI 不保存第二份完整结果库、不重新读文件、不把工具 output 当 Markdown 自动执行或解释。Web 忽略 details 应维持原行为；共享 diff 文本变化必须回归模型工具结果与 Web 消费者。

## 4. 自动恢复调度

### 4.1 所有权与覆盖

SDK `createSessionSync` 继续负责一次有界快速恢复。CLI 现有 `createTuiSessionRecovery` 负责“是否还需恢复、何时接续”，不新增全局 retry 服务，不改变 Web 的默认行为。

自动工作覆盖：初始化/索引尚未完成、runtime identity 未知、当前会话未同步、需要但未确认的 control、当前可查询的 pending 回执。按缺口执行对应读取；健康后不继续刷新全部端点。`runId=null` 的可信 control 可以是正常 idle，不能当作失败无限查询。

每个作用域最多一个接续计时器，同类请求最多一个在途；SDK 快速轮还在进行时不能由 CLI 再次 retry。共享一个小型协调入口即可，不为五种查询各建状态机。

这里的初始化包含远端 client bootstrap。当前 `ensureInitialized` 会保留 rejected Promise，SSE 初始化又在重连循环外；实施需修复该缓存的失败释放和既有循环重入。复用原 clientId/startup intent，加入重复 initializeClient 的幂等验证，防止意外创建第二个会话或改变授权绑定。这个修复属于已有 transport/client，不让 CLI 自建第二条连接循环。

为 identity/control/index/receipt 与 bootstrap 读取定义有限期限，初值可与 session-view 的 10 秒对齐。已有 signal 参数的请求使用本轮 AbortController；先检查远端 HTTP rpc 已有的 signal 转发，缺失的必要网络读取才增加兼容选项。SDK proxy 只转发实际需要的参数，in-process 只在真实等待边界或挂起测试证明必要时补取消，不以接口形式统一为目的扩大改动。超时须终止实际请求、释放本轮在途标记，之后才能冷却重试；共享 bootstrap 不能被一个无关调用者的取消误杀，需由客户端自己的初始化尝试管理期限。无法取消的依赖要先补可取消边界或明确阻塞证据，不靠 Promise.race 丢弃 Promise 后无限增发。迟到响应即使落在相同 session，也要核对请求代次，不得重装过期数据。

### 4.2 退避与状态

SDK 快速轮耗尽后，以 1、2、5、10、30 秒为接续间隔初值，之后最多每 30 秒一轮；这不是 UI 倒计时或用户配置。无变化的查询结果不触发 stdout 写入。持续失败只能放慢，不能每次 onChange/hello 重置成快速循环；恢复持续稳定后才清失败预算，沿 SDK 现有健康窗口语义验证。

transport 断开时取消定时查询，交给现有 transport 重连。连接恢复后按新 connection/epoch 校验，自动唤起一次恢复；合并重复事件。身份未知时先取得身份，依赖该身份的控制/回执更新再进行，不并发使用尚未确认的旧 epoch。

可识别的明确权限/配置拒绝不做高频轮询，保留简短真实错误，待连接/配置/会话变化后自动重新判断；没有结构化分类时不靠英文错误字符串猜测“永久失败”。暂时读失败继续受冷却约束，不无限立即重试。

### 4.3 原请求与生命周期

普通 pending 沿用既有 requestId/sessionId/runtimeEpoch/binding 身份，不增加正文持久化。只调用 getPromptReceipt，绝不调用 submitPromptAccepted 作为恢复手段；查询结果 `receipt=null` 表示本次未查到，不足以证明没接收或可以重发。

找到身份匹配回执才移除对应 pending；首发新会话按原创建代次完成绑定，不能把迟到回执绑定到用户后来切换的会话。旧 epoch 无法查询的 pending 保留未知，不循环向新 runtime 查询旧请求、不自动丢弃；原 Ctrl+X 仅放弃跟踪的语义保留。

切会话取消当前视图的同步计时器和请求，旧 pending 仍按原归属保留；回来时自动继续可查询的确认。迟到响应可以按原身份完成相应 pending 对账，但不能覆盖当前视图或新草稿。退出/dispose 清除计时器、abort 可取消的请求，并由代次校验忽略其余晚到结果。不能遗留不断唤醒进程的 timer。

明确业务拒收、审批 choice 提交失败、retained 操作的既有重试语义不纳入“自动重新提交”。improve-2 对未发送快照和下一份草稿的隔离要求继续有效。

### 4.4 UI 映射

提示由前端 04 的状态矩阵决定。恢复健康即撤下，不追加“恢复成功”历史消息；持续失败保留真实状态，不在每轮重试时闪烁或追加日志。Ctrl+R handler 与手动恢复文案在自动路径通过后一起删除。

## 5. 开发场景与可测试数据

不搭 Web Mock 平台。沿现有 fake UiBackendClient、真实 store、FakeTTY 和假时钟组合，开发时可切这些场景；真机使用同一组确定性事件 fixture，避免调用真实 LLM。

| Fixture         | 内容与控制                                                                                                     | 用例          |
| --------------- | -------------------------------------------------------------------------------------------------------------- | ------------- |
| F01 mixed-tools | Read/Glob/Grep 的正常、0、部分扫描、token 裁剪                                                                 | UC-TOOL-01    |
| F02 mutation    | 小改一行、多 hunk、新建/覆盖、dry-run、binary/预算限制、旧记录                                                 | UC-TOOL-02    |
| F03 shell       | 短输出、300 行、单条超长行、多行/超长命令配短或空输出、失败前输出、后台启动、源头截断                          | UC-TOOL-03/04 |
| F04 transcript  | 20 条混合调用，晚到结果/旧历史/切会话/审批，按需延迟                                                           | UC-TOOL-04    |
| F05 markdown    | 中英/emoji/表格/代码/长 URL，分片和 resize                                                                     | UC-TOOL-05    |
| F06 recovery    | 断线/重连、首次初始化失败后成功、读取永不返回后恢复、失败超过快速上限、延迟回执/null 回执、epoch 变化、dispose | UC-TOOL-06    |

每组都能构造实时、快照恢复、历史补载的同一事实，避免三套互不相干的假数据掩盖投影不一致。
