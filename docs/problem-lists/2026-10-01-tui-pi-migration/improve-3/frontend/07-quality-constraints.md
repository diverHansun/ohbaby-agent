# improve-3 前端：质量约束

## 1. 可读与可操作

无需鼠标即可读工具结果、切展开并继续编辑。失败、diff、dry-run 和后台状态不能只靠颜色；中文、组合字符、emoji 不截半个字素。命令/代码可通过终端原生选择复制，不增加剪贴板依赖。提示不常驻叠加，不在每条输出后重复快捷键。

## 2. 性能与可靠性

继承 improve-1 的完整动态帧预算；只改变显示投影，不用无限动态 Box 承载全部历史。fixture 至少含 20 条混合工具、300 行 Bash 输出和长单行，记录展开/resize 的控制序列与交互表现。

无可见变化、无活动动画的健康状态不持续写 stdout。自动恢复健康时无额外查询；持续失败使用前端 06 的冷却，单类请求不并发，退出无残留 timer。不能通过停止真实事件订阅换安静。

本轮不凭空设未经测量的毫秒 SLA；Stage 0 记录前轮基线，同 fixture 比较输入响应、终端写入和明显停顿。出现回归需解释并修正，不以功能截图代替性能判断。

## 3. 兼容性

macOS Ghostty 主验收，60×20、80×24、120×40；实际版本与 tmux/SSH 条件记录在实施验收。深浅背景、低色彩、关闭动画都保持含义可辨。既有 Windows 兼容路径不主动删除。

pi 精确锁版、公开 API、真实 Ink 集成检查。Markdown 的 tab、padding、OSC 链接能力须显式验证；不能把输入编辑器约定改成 pi 默认。退出/异常保留原 raw mode、光标恢复。

## 4. 安全与隐私

只展示用户原本有权读取的调用结果。Subagent 内部 prompt 和运行时内部消息继续过滤，展开不能成为绕过来源过滤的入口。新 details 采用有限白名单，不透传凭据、内部路径集合或完整调试 metadata。

工具输出不应执行任意光标移动、清屏、剪贴板等终端控制动作；安全样式与可用链接处理沿现有显示边界核对，必要时补小型归一化，不新建安全平台。原始数据保持不变，控制序列处理仅作用于显示。

## 5. 维护与观测

无新增用户遥测。调试时只记录必要请求计数、状态和原身份，不在终端反复输出恢复日志或秘密 payload。升级 pi 时重跑 Markdown/宽度、真实 Ink、历史展开与复制场景；记录使用的 API，避免私有路径和 fork。
