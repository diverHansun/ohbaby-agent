# 3. 截图参考与取舍

> 三张附件是讨论材料，不是产品指令。前两张展示 ohbaby-web 当前问题；第三张只提供输入框布局参考。权限图标方案来自用户文字确认。

---

## 3.1 截图分别说明什么

| 附件 | 可观察内容 | 用于本轮 |
|------|------------|----------|
| 图 1 | 当前 prompt 框下方有 `auto mode` / `default` 按钮，框与窗口底之间仍有空间 | 定位框外控件与底部留白问题 |
| 图 2 | 当前实白 header、点阵加黑色大写 `OHBABY`、会话列表 | 定位色调与品牌不一致问题 |
| 图 3 | 另一款输入框将控件放在输入区内的底栏，图中有 `+`、`High` 和麦克风 | 仅参考「文字区在上、控件在框内底栏」的布局 |

第三张图**没有展示**权限图标；不能把手或感叹盾的形状与颜色归因于截图。

## 3.2 权限图标的依据

| 状态 | 用户确认 | 建议落地 |
|------|----------|----------|
| `default` | 灰色手形 icon | 轻量 `Hand`，约 16–18px；按钮的可访问名称解释当前权限 |
| `full-access` | 红色盾牌叹号 icon | 轻量 `ShieldAlert`，约 16–18px；按钮的可访问名称解释当前权限 |
| hover / focus | hover 出现浅浅的边缘线 | hover 浅边线；键盘 focus 保留可见焦点环；图形小而点击区域不跟着缩小 |

图标始终放在输入框内底栏左侧；思考状态与发送/停止按钮在右侧。具体灰、红色值为实现建议，需在浏览器里核对与输入卡、连接状态的对比。

## 3.3 不随参考图加入的控件

| 图中元素 | 本轮取舍 | 原因 |
|----------|----------|------|
| `+` | 不加入 | 当前没有对应的附件操作需求 |
| `High` 下拉 | 不照搬 | 当前思考状态控件有自己的语义与状态 |
| 麦克风 | 不加入 | 本轮不增加语音能力 |

## 3.4 对 02 方案的影响

- Stage 1 借鉴图 3 的框内底栏层次，不照搬其具体控件。
- Stage 1 的灰手、红色感叹盾按用户 2026-09-19 的文字确认实施。
- 图 1、图 2 是当前问题证据；实现验收应回到同类页面观察，而非把它们当目标效果图。
