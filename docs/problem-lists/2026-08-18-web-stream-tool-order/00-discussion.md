# 讨论记录与已确认要点

> 2026-08-18 与用户讨论定稿。正式方案见 01–04。

---

## 1. 背景与动机

Web 上即使用具调用先发生，流式过程中也常先看到「最终文字」，工具卡片垫在下面；run 结束后卡片才跳回文字上方。用户要求先消这处「撒谎的时间线」，再处理失败卡片；两件事分成**两份 problem-list**，实施时共用一条临时 git 分支。

## 2. 已确认：目标与范围

| 决策项 | 结论 |
|--------|------|
| 先做什么 | 先消卡片乱跳（本议题）；失败呈现另立 problem-list |
| 文档组织 | **两份独立 problem-list**，避免混在一个 improve 目录里产生歧义 |
| 本议题范围 | 记账规则对齐 TUI，**连同**幽灵消息/缺失消息草稿、下标 key 一起收掉 |
| 做法 | 只改 Web `eventReducer` + `MessagePart` key；不抽 sdk；不改后端事件 |
| TUI | **不动**，只当标准答案 |
| 落点 | `docs/problem-lists/2026-08-18-web-stream-tool-order/` |
| 批次 | 单批；三笔 commit：规则 → 幽灵消息 → key |
| git | 共用临时分支 `codex/web-tool-transcript`；本议题实施全部排在失败呈现之前 |

## 3. 已确认：产品行为

| 场景 | 流式过程与定稿后 |
|------|------------------|
| 先调工具、再出字 | 卡片始终在字上面，结束不跳 |
| 先说一句、再调工具、再出结论 | 三截顺序从头到尾不变 |
| 连续两轮工具 | 每轮都是「该轮的卡 → 该轮的字」，后一轮的字不写进第一句 |
| 缺 `messageId` 的 delta | **丢掉，不造** `streaming:${sessionId}` 第二条消息（对齐 TUI） |
| 有 `messageId` 但目标消息不存在 | **也丢掉，不造草稿**；当前生产者保证先 `message.appended`，缺消息属于事件缺口而非正常首包竞态 |
| Web 缺消息提示 | **本批静默丢弃**且 seq 继续前进；不为与 TUI 表面对齐而新造 transcript notice 通道。若生产轨迹证明频繁发生，再单独设计 resync/可观测性 |

## 4. 已确认：边界（不做的事）

| 项 | 本批不做 |
|----|----------|
| 工具卡配对 / 失败皮肤 / bash `failed` | 下一份 problem-list |
| 抽 sdk 共享 reducer | YAGNI；Web 抄 TUI 规则并补测试 |
| 改后端事件形状或加更频繁的 `message.updated` | 会更闪或加大 SSE；后端已经对 |
| 改 TUI | 本批对齐它，不是改它 |
| 「直播一条气泡 / 刷新多条气泡」 | 已知结构差，本批不碰 |

## 5. 已确认：验收口径（肉眼）

- 先工具后文字：流式过程中卡片在字上方，定稿不跳。
- 前言 + 工具 + 结论：三截顺序稳定。
- 两轮工具：不会把第二轮结论写进第一句前言。
- 纯「工具 → 文字」负对照：没有旧 text 时仍保持工具在前；若真实现场不符，先抓 `seqNum/event/messageId/parts` 轨迹再扩根因。
