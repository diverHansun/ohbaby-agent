# 3. 参考项目借鉴

> 本文记录 2026-11-24 对 `code-cli/` 下三个项目的核查结果，只记事实和借鉴点。

## 3.1 三个项目的做法

| | dsh | kimi-code | ZCode |
|---|---|---|---|
| 样子和位置 | 绿点，标题左边的前导槽；出错的未读显示红点 | 蓝点 `#1783ff`，7px，在行尾，替换掉时间 | 蓝点（sky-500），7px，标题左边 |
| 已读状态存哪 | 后端 Host 内存，各端共享，重启就丢 | 前端 localStorage，按设备 | 后端 SQLite 的 `unread_at`，用比较后写入防止并发覆盖，多设备同步 |
| 什么算新回答 | 每轮结束都算，用 `completedTurn > readTurn` 推出未读 | 只算成功的轮次 | 成功和出错都算，用户自己停止的不算 |
| 当前会话 | 页面可见且获得焦点才算"在看" | 页面隐藏时也算未读 | 打开即已读 |
| 怎么知道别的会话答完了 | 全局状态流 `sessionStatus.follow` | 不知道，只对订阅中的会话有效 | 按工作区推送事件 |
| 和其他状态的优先级 | 审批 > 运行中 > 未读 | 无 | 出错 > 未读 > 运行中 |
| 其他 | 菜单里有"标为已读 / 未读" | 菜单里有"标为未读" | 菜单里有"标为未读"，Dock 角标，侧栏有"未读"筛选 |

三个项目都有一条共同规则：加载或回放历史消息，不会产生未读。

## 3.2 借鉴点

- **位置**：采用 dsh 和 ZCode 的做法，放在标题左边的前导列。ohbaby 的审批点已经在这一列，未读点和它对齐。
- **已读状态存哪**：采用 kimi-code 的做法，存前端 localStorage。ohbaby 的置顶也是这么存的，用户也选了这个。代价是不跨设备同步。
- **什么算新回答**：采用 ZCode 的规则，成功和出错都算，用户自己停止的不算。出错也是"有结果了，该回来看看"；用户自己停的，说明他当时就在场。
- **怎么知道别的会话答完了**：三个项目里有两个靠推送。kimi-code 不推送，结果是别的会话答完了也不亮，等于没做。ohbaby 必须让后端给出信号，具体做法见 02。
- **当前会话**：不采用 dsh 和 kimi-code 的"页面隐藏时也算未读"。ohbaby 没有标签页标题或 Dock 角标，用户切回来时当前会话的点会立刻被清掉，亮了也看不到。不过后台标签页不记已看（02 F4），所以另一个可见的标签页仍会给它亮点，这一点和 dsh 的做法相近。
- **优先级**：采用 dsh 的顺序，未读排在审批和运行中之后。ohbaby 前导列还多一个"移动中"，排最前。
- **不做**：手动"标为未读"、未读筛选、角标。用户确认先不做。
