# 0. 讨论与已确认要点

> 本文记录 2026-11-24 讨论后确认的结论，被否决的方案不再展开。

## 0.1 用户提出的问题

一个会话的回答完成了，但用户当时在看别的会话，没看到。用户希望侧边栏用一个蓝色的点提示"这里有新回答，你还没看"。

## 0.2 现状核实

- 侧边栏只知道当前打开的会话在不在运行、在不在等审批（`AppController.tsx` 只给 `activeId` 打标，见 06 §3.4）。
- 别的会话答完了，前端收不到任何消息。浏览器只连着一个工作区实例的事件流，会话事件也只投影给当前绑定的会话。
- 全局会话列表只在启动、重试、窗口获得焦点、页面重新可见，以及归档、fork、移动这类操作之后才重新读取。

所以"别的会话答完了"这件事，只改前端做不出来，后端要先把信号给出来。

## 0.3 已确认的决定

| 编号 | 决定 |
|---|---|
| C1 | 只做 Web |
| C2 | 未读点用 `#60A5FA`，新增专用 token，不复用 `--progress`。它和黄色审批点的醒目程度接近，不会比"需要你动手"的审批点更抢眼 |
| C3 | "看过没有"存在前端 localStorage，和置顶一样按服务器地址存，不跨设备同步 |
| C4 | 当前打开的会话不亮点，新回答来了也不亮 |
| C5 | 手动"标为未读"先不做 |

## 0.4 按默认处理（讨论中未提异议）

- 点放在左侧前导列，7px，和审批点同样大小、同样位置。
- 前导列同一时间只显示一个状态，优先级是：移动中 > 运行中 > 等待审批 > 未读。
- 一轮结束就算新回答，成功和出错都算；用户自己点停止的不算；加载历史不算。
- 打开会话就清掉未读。
- 第一次使用时，已有的会话都当作已读，否则老会话会全部亮起来。

## 0.5 明确不做

- 不做手动"标为未读"。
- 不让非当前会话显示"运行中"和"等待审批"，归"跨会话等待状态"议题。本议题的后端信号要能被那个议题复用。
- 不跨设备同步已读状态。
- 不做 TUI。
