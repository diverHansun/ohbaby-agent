# Mermaid 图表：架构设计

> 前置：[goals-duty.md](goals-duty.md)。

## 1. Architecture Overview（架构概览）

Markdown 渲染照旧产出一段清洗过的 HTML，Mermaid 代码块先以普通代码块的样子显示。消息完成后，增强层找到这些代码块，把图插到代码旁边，再把代码隐藏。

```
消息文本
   │
   ▼
Markdown 渲染层        解析、清洗，给真实的 Mermaid 代码块打标记
   │  HTML
   ▼
消息视图              决定这段内容是否允许画图（只有已完成的助手消息）
   │  DOM
   ▼
Mermaid 增强层        找到带标记的代码块，绘制、清洗、挂载、切换
   │  按需加载
   ▼
Pele（独立的懒加载包）   把 Mermaid 文本转成 SVG
```

依赖只有一个方向：消息视图依赖 Markdown 组件，Markdown 组件依赖增强层，增强层依赖 Pele。Pele 只在增强层里出现，以后换绘图库只改这一处。

## 2. Design Pattern & Rationale（设计模式与理由）

采用**渐进增强**：先有一份能读的代码块，绘图成功才升级成图。

这个模式直接对应三个目标：

- 绘图失败时什么都不用做，代码块本来就在页面上（R4）。
- 源码一直留在 DOM 里，复制逻辑不用改（R5）。
- 输出过程不需要知道 Mermaid 的存在，流式渲染和绘图互不干扰（R2）。

绘图库外面包一层很薄的适配，统一安全配置和错误处理。

这里不用状态机，也不用绘制队列。Pele 1.13.0 的配置随每次调用传入，实测 64 个配置各异的图并发绘制，结果和逐个绘制逐字节相同。绘制本身也很快，按顺序处理一条消息里的代码块就够了。

## 3. Module Structure & File Layout（模块结构与文件布局）

路径相对 `apps/ohbaby-web/src/ui/`。

```
shared/
├── markdown-renderer.ts        流式议题 Stage 1 新建；本模块在这里给代码块打标记
├── markdown-mermaid.ts         新增：识别、绘制、清洗、挂载、切换
├── markdown-mermaid.unit.test.ts
├── markdown-scroll-region.ts   和公式共用，先实施的一方新建：同步宽内容的键盘属性
├── MarkdownBlock.tsx           增加“允许画图”的开关，默认关闭
└── markdown.css                统一排版议题新建；本模块加图表容器和切换按钮的样式
conversation/
└── MessageRow.tsx              只给已完成的助手文字打开开关
```

| 单元 | 负责 | 不负责 |
|---|---|---|
| Markdown 渲染层 | 判断语言、输出防伪标记 | 绘图 |
| Markdown 组件 | 在内容变化时启动和取消增强 | 判断消息是谁发的 |
| 消息视图 | 决定哪些内容可以画图 | 绘图细节 |
| Mermaid 增强层 | 绘制、清洗、挂载、切换 | Markdown 解析 |
| 样式 | 图表容器、切换按钮、token 映射 | 图的内部布局（由 Pele 决定） |

## 4. Architectural Constraints & Trade-offs（架构约束与取舍）

约束：

- 不能改变现有复制按钮的结构。复制逻辑靠按钮和 `<pre>` 的父子关系防止伪造，切换按钮只能作为新的兄弟元素加入。
- 不能引入新的 Markdown 解析链路。现有渲染方式是“HTML 字符串 + 事件委托”，本模块沿用。
- 绘图库必须和首屏代码分开打包。`markdown-renderer.ts` 会静态导入 `isMermaidLang`，所以 Pele 只能在 `renderDiagram` 里用 `await import("pele/lazy")` 加载。
- `markdown-mermaid.ts` 不导入 `markdown-renderer.ts`，避免循环依赖。防伪标记由 `MarkdownBlock` 调用 `enhanceMermaidBlocks(root, COPY_TOKEN)` 时传入。

| 编号 | 决策 | 理由 | 放弃的选项 | 代价 |
|---|---|---|---|---|
| M1 | 用 Pele | 首张流程图下载量约为官方库的十分之一，渲染更快，真实样本通过率相同，没有 HTML 标签入口 | Mermaid 官方库：语法最权威，但体积大，还需要处理全局状态和配置注入 | 非官方实现，图的布局和官方不同，版本更新快 |
| M2 | 渐进增强 | 失败不用额外处理，源码始终可用 | 把代码块换成 React 组件：要改解析链路 | 有一小段命令式 DOM 操作 |
| M3 | 消息完成后才绘制（ZCode 也是这样） | 不闪动，不用处理半截语法 | 输出中反复绘制并保留上一张成功的图（opencode）：状态更多 | 输出过程中看不到图 |
| M4 | 只开放给助手消息 | 这是用户提出的场景，改动最小 | 所有 Markdown 都画：用户原文和文件内容也会变样 | 文件预览暂时看不到图 |
| M5 | 防伪标记沿用复制按钮的随机值 | 模型猜不到，不需要第二套机制 | 只看 class 或 `data-*`：模型输出的 HTML 可以伪造 | 渲染器要把这个值提供给增强层 |
| M6 | 绘制结果再清洗一次 | Pele 输出也当作不可信内容，多一道防线 | 完全信任绘图库：一旦绘图库出漏洞就直接进页面 | 清洗时根 SVG 的 `role` 被去掉，挂载时补回 |
| M7 | 宽图按原始大小横向滚动 | 文字保持 14px，能看清 | 缩小到容器宽度：大图文字小到读不了 | 大图要横向滚动 |
| M8 | 失败时不显示错误 | 模型写错语法对用户没有行动价值，代码已经能读 | 显示报错条：打断阅读 | 用户不知道为什么没出图 |
| M9 | 切换按钮贴右，Copy 排在它左边 | Copy 的文字变长时只向左伸展，永远压不到切换按钮 | 把两个按钮包进新容器：会破坏复制的防伪校验 | Mermaid 代码块里 Copy 的位置比普通代码块靠左一点 |

### 和参考项目的对照

| 问题 | opencode | ZCode | deepseek-harness | ohbaby |
|---|---|---|---|---|
| 绘图库 | Pele 1.7.0，懒加载 | Mermaid 官方库（经 `@streamdown/mermaid` 封装） | 聊天内置没有，靠插件插槽 | Pele 1.13.0，懒加载 |
| 输出过程中 | 按完整行尝试绘制，首图前显示空图框，之后保留上一张成功的图 | 不绘制，显示未高亮的代码 | 由插件决定，文档示例显示代码 | 显示代码 |
| 失败时 | 输出中保留上一张图，没有就显示代码；完整内容失败时显示代码 | 退回纯文本，不显示错误 | 插件自行处理；插件组件崩溃时退回普通代码块 | 保留代码，不显示错误 |
| 绘制并发 | 不排队，忽略过期结果 | 全局串行队列，每个任务依次写配置并绘制，过期结果丢弃 | 由插件决定 | 按顺序处理，可取消 |
| 限制 | 没有长度或复杂度预算 | 20,000 字符、600 行、复杂度 1,500，页面不可见时也不画 | 由插件决定 | 只限 20,000 字符 |

绘图库和 opencode 相同，绘制时机和 ZCode 相同。消息完成后才画，所以不需要“上一张成功的图”这类状态。ZCode 的队列把写全局配置和绘制放在同一个任务里；Pele 的配置随调用传入，不需要这一层。
