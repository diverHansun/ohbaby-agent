# 01 用例与用户流程

## 1. 信息架构

### 1.1 页面树

本功能不新增路由，只在已有的右侧栏里加一种页面。右侧栏是不写进 URL 的 Tab 容器（redesign-2026-10 D33）。

```
会话页（主区）
├── 对话流
│   └── bash 工具卡
│       └── 入口行 “Background task ›”         ← T-04
└── 右侧栏
    ├── [+] 菜单 / 入口页
    │   └── Background tasks（有任务才出现）    ← T-01 的入口
    └── Background tasks 页（一个 Tab）
        ├── 列表视图                            ← T-01、T-03
        └── 详情视图（同一 Tab 内切换）          ← T-02、T-03
```

### 1.2 页面表

| 页面 / 视图 | 位置 | 主要任务 | 前置条件 | 核心 |
|---|---|---|---|---|
| 入口行 | bash 工具卡下方 | T-04 | 这次 bash 调用启动了后台任务（结果里有 `jobId`，`mode` 为 `background`） | 否 |
| Background tasks 列表 | 右侧栏 Tab | T-01、T-03 | 当前会话有过至少一个任务 | 是 |
| Background tasks 详情 | 同一 Tab | T-02、T-03 | 从列表行或入口行进入 | 是 |

“当前会话有过任务”指后端 `listShellJobs` 的 `statusCounts` 之和大于 0（主代理和子代理分别查，见 06 §3.1），包括已结束的任务。还在登记中的任务（`pendingStartCount`）不算，登记完成后自然会出现。前台命令不算（D12）：每条前台 bash 都会留下记录，后端默认列表还会带上刚结束、尚未收尾的前台命令和清理异常的前台命令，所以探测和列表都带 `mode=background`，只看后台任务（自动转后台的也算）。只跑过前台命令的会话不出现入口。

### 1.3 权限

单角色，没有权限区分。有两种“不能取消”，表现不同：

| 情况 | 判断 | 表现 |
|---|---|---|
| 任务已结束 | `status` 不是 `running` | 没有 Cancel，这是正常情况，不解释 |
| 任务由另一个 ohbaby 后端管理（例如在 TUI 里启动） | `status` 为 `running`，`canStop` 为 false，且 `managedByCurrentBackend` 为 false | 列表行没有 Cancel；详情页一行灰字说明去原来的窗口取消 |

`managedByCurrentBackend` 只在任务运行中有意义：每个后端进程启动时都会换一个身份，服务重启后，所有旧任务（包括已结束的）这个字段都是 false。所以已结束的任务不看它。

### 1.4 术语草稿

| 概念 | 界面用词 | 不用 |
|---|---|---|
| ShellJob / 后台任务 | Background task（复数 Background tasks） | job、shell job、bg task |
| 取消任务 | Cancel / Cancelling… | Stop、Kill、Terminate、Pause |
| 主代理 | Main agent | primary、parent |
| 子代理 | Subagent | child、worker |

定稿见 [03 §5](03-ui-layout-and-style.md#5-内容与文案)。

## 2. 用户流程

### 2.1 从右侧栏查看任务（T-01、T-02）

```
用户在会话里，agent 已经启动过后台任务
↓ 打开右侧栏 → [+] 菜单 → Background tasks
├── 菜单里没有这一项 → 这个会话从来没有任务（正常，不提示）
↓ 列表：Running 组在上，Done 组在下
├── 首次加载慢（>300ms）→ 显示一行 Loading…
├── 加载失败 → 一行错误说明 + Retry；之前有数据就保留旧列表
├── 主代理没有任务、只有子代理有 → 默认直接显示 All
↓ 点一行 → 详情
├── 任务在跑 → 输出区贴底跟随，每 2 秒刷新
├── 任务已结束 → 输出尾部只拉一次
├── 输出拉取失败 → 输出区上方一行错误 + Retry，已有输出不清空
└── 任务已不存在（会话树变化）→ 回到列表并刷新
↓ 点返回 → 回到列表，焦点落回刚才那一行
```

### 2.2 取消一个任务（T-03）

```
列表行或详情页上，运行中的任务有 Cancel
↓ 点击 Cancel
↓ 按钮立刻变成禁用的 Cancelling…（发出请求）
├── 后端接受 → 保持 Cancelling…，直到后端推送的状态不再是 running
│     └── 行移到 Done 组，右侧显示时长（被取消不算失败，不标红）
├── 后端说已经结束（already-terminal）→ 刷新列表，行自然移到 Done
├── 另一个后端管理（SHELL_JOB_OTHER_BACKEND）→ Cancel 消失，刷新后详情页显示说明
├── 网络失败或其他错误 → 恢复 Cancel；列表顶部（在详情里则是标题区下方）一行错误说明
└── 连点 → 第一次点击后按钮已禁用，不会发第二个请求
```

取消后切换会话或关闭右侧栏，请求照常完成，回来时以后端状态为准。

### 2.3 从对话打开任务（T-04）

```
对话里一张 bash 工具卡，它启动了后台任务
↓ 卡片下方有一行 “Background task ›”
↓ 点击
↓ 右侧栏展开（若收起），切到 Background tasks Tab（没有就新开一个），进入这个任务的详情
├── 任务属于子代理 → 照样打开，详情里写明启动者
├── 子代理对话（右侧栏 Subagents 详情）里的 bash 卡片 → 同样有入口行，点击切到 Background tasks Tab
└── 任务已不存在 → 详情区显示 “This task is no longer available.” 和返回
```

### 2.4 跨会话与刷新

- 切换到没有任务的会话：确认没有任务后，Background tasks Tab 隐藏；它正被选中时的选中规则沿用 Side chat Tab 隐藏的现有做法。切回来时 Tab 重新出现，回到列表视图。
- 切换到另一个有任务的会话：Tab 保留，回到列表视图，显示新会话的任务。
- 探测结果还没回来或失败时，Tab 保持原来的显示状态，不先藏再出现。
- 刷新页面：右侧栏只记住展开和宽度（redesign-2026-10 D33），Tab 不恢复。
- 断线重连：重新拉列表；详情页重新拉输出。

## 3. 用例

### UC-BGT-01 查看当前会话的任务列表

前置条件：当前会话有过至少一个后台任务。

主流程：

1. 用户打开右侧栏的 `[+]` 菜单，看到 Background tasks。
2. 点击后新开一个 Tab，显示列表。
3. 列表分 Running 和 Done 两组，组标题后是数量。
4. 每行显示任务说明（没有说明就用命令摘要）、命令、时长或失败标记。

异常流程：

- 首次加载超过 300ms → 一行 `Loading…`；300ms 内完成不闪烁。
- 加载失败 → 一行原因 + `Retry`；已有列表保留。
- 已结束任务多于一页 → 滚动到接近底部时自动加载下一页，没有按钮，也不显示“已到底”之类的说明。
- 主代理没有任务、子代理有 → 打开时筛选为 All。
- agent 又启动了新任务 → 列表自动出现新行，不需要用户刷新。

完成结果：

- 运行中的任务全部在 Running 组，按后端顺序排列，每行有实时走动的时长。
- 已结束的任务在 Done 组；只有失败和超时的行带红字，其他行只显示灰色时长。
- 组标题的数量等于后端统计数，不受已加载页数影响。

### UC-BGT-02 按启动者筛选

前置条件：列表已加载，并且子代理也启动过任务。

主流程：

1. 面板右上角出现筛选图标（只有子代理也有任务时才出现，判断来自探测，见 06 §3.1）。
2. 点开是三项菜单：Main agent、Subagents、All，当前项带对勾。
3. 选择后列表重新加载，组数量跟着变化。

异常流程：

- 切换后的加载失败 → 保留筛选选择，显示错误和 `Retry`，不回退到旧筛选的列表。
- 快速连续切换 → 只显示最后一次选择的结果。

完成结果：

- 选 Subagents 或 All 时，每行在命令下面多一段启动者名字。
- 筛选只在本 Tab 内记住，切换会话后回到默认值。

### UC-BGT-03 查看单个任务的详情和输出

前置条件：从列表行或入口行进入。

主流程：

1. 详情顶部：返回、任务说明、Cancel（运行中且可取消时）。
2. 下面一行小字：状态和时长，完整命令（等宽）。不是主代理启动的，加上启动者。
3. 输出区显示后端给的输出尾部（最多 32KiB），任务在跑时贴底跟随。

异常流程：

- 用户向上滚动 → 暂停跟随，右下角出现“回到底部”按钮。
- 输出超过 32KiB → 输出区顶部一行灰字说明只显示最后一部分；有日志路径时提供复制。
- 日志文件本身因为输出太多被截断（`outputTruncated`）→ 再加一行灰字说明日志不完整。
- 任务没有保存输出尾部（`tailAvailable` 为 false，例如还没写下第一个输出检查点就结束的任务）→ 输出区显示 `No output was saved for this task.`。
- 任务处于 `lost`、清理未确认、由别的后端管理 → 详情顶部各加一行灰字说明（文案见 03 §5）。
- 输出拉取失败 → 输出区上方一行错误 + `Retry`，已有输出保留。

完成结果：

- 运行中的任务，输出每 2 秒更新一次，贴底时自动滚到最新。
- 任务结束后，状态行在下一次刷新时变成结束状态，输出停止轮询。

### UC-BGT-04 取消运行中的任务

前置条件：任务 `status` 为 `running` 且 `canStop` 为 true。

主流程：

1. 用户在列表行或详情页点 `Cancel`。
2. 按钮变成禁用的 `Cancelling…`，宽度不变。
3. 后端停止任务后，行移到 Done 组，显示时长；详情状态行显示 `Cancelled by you`。

异常流程：见 §2.2。

完成结果：

- 一次点击只发一个取消请求。
- 取消后的任务不标红。
- 后端以 `user` 为停止原因通知模型（后端行为，前端不做额外操作）。

### UC-BGT-05 从 bash 工具卡打开任务

前置条件：bash 工具结果里有 `jobId` 且 `mode` 为 `background`。

主流程：

1. bash 工具卡下方有一行 `Background task ›`，带一个小图标，样式和 Subagents 的委派入口行一致。
2. 点击后右侧栏展开，切到 Background tasks Tab（没有就新开），直接进入该任务详情。

异常流程：

- 任务属于子代理 → 照样打开，筛选不影响详情。
- 任务已不存在 → 详情区显示不存在说明和返回。
- 工具结果还没回来（调用进行中）→ 不显示入口行。

完成结果：

- 入口行文字固定，不随任务状态变化。
- 打开的详情就是这次调用启动的那个任务（按 `jobId` 定位）。

### UC-BGT-06 主会话不显示任务结束消息

前置条件：后台任务结束，后端把结果作为 `background-task-result` 交给主代理。

主流程：

1. 主会话对话流里不出现这条消息（不显示成用户气泡，也不显示成系统行）。
2. 这条消息唤醒的那一轮，助手回复照常显示。

完成结果：

- 对话流里找不到任何以任务结果为内容的气泡或行。
- 编辑消息、回退等只作用于用户自己发的消息，不受影响。
