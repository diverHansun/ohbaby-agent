# LaTeX 公式：测试设计

> 前置：[goals-duty.md](goals-duty.md)、[dfd-interface.md](dfd-interface.md)。遵循 [Web 测试规范](../test.md)。

## 1. Test Scope（测试范围）

**覆盖：**

- 五种写法的识别和普通文字的防误判。
- 流式更新、渲染失败、取消和 React 更新。
- 选区复制、公式代码块 Copy。
- 渲染结果的安全边界。
- 真实页面里的按需加载、字体、排版、滚动和消息流程。

**不覆盖：**

- KaTeX 内部排版的像素结果。
- 通用 Markdown 解析和增量算法，它们由相关议题测试。
- 深色模式、公式缩放和导出，本模块不做。

## 2. Critical Scenarios（关键场景）

### U 组：单元测试

放在 `shared/markdown-math-syntax.unit.test.ts` 和 `shared/markdown-math.unit.test.ts`，环境用 jsdom，调用真实的 `marked`、DOMPurify 和 KaTeX。

| U-2 | `\(a_1 + b_1\)`、行内 `$$x$$` | 识别为行内公式 |
| U-3 | `$$...$$`、`\[...\]`，单行和多行，段落中间，列表里 | 识别为独立公式 |

| U-8 | `$a_1*b_2*c_3$`、`\(x*y*z\)` | 没有 `<em>`，`data-tex` 等于原公式 |
| U-9 | 表格单元格里的 `$x_1$`，以及竖线已转义的绝对值公式 | 列数正确，公式内容分别是 `x_1` 和绝对值 |
| U-10 | 未开 `math` 的 `renderMarkdown` | 输出和不带扩展时逐字节相同 |
| U-11 | 模型手写带假 `data-math` 的 HTML | 不渲染 |
| U-12 | 正常公式 | 占位被替换，状态为 `ready` |
| U-13 | `\notacommand{x}`、`\frac{1}{` | 保留原文，状态为 `error`，同消息其他公式正常 |
| U-14 | 5,000 和 5,001 字符的公式 | 前者尝试渲染，后者不调用 KaTeX |
| U-15 | `\href`、`\url`、`\includegraphics`、`\htmlClass`、`\htmlId`、`\htmlStyle`、`\htmlData` | 没有链接、图片、ID、事件属性和注入的样式，没有 `#cc0000` |

| U-17 | `\rule{100000em}{100000em}` | 尺寸被限制 |
| U-18 | 中文写在公式里：`速度=\frac{路程}{时间}` | 能渲染 |
| U-19 | 同一公式重复增强 | 第二次命中缓存，不再调用 KaTeX |
| U-20 | 8 种分块大小逐步输入一篇含五种写法的文档 | 最终结果等于全量渲染，公式数量不回退 |
| U-21 | 逐字符输入 `From $5-$10`、`$HOME/$USER` | 过程中从不出现公式 |
| U-22 | 结尾是代码块，内容以 `$` 结尾 | `$` 不被暂缓 |

| U-24 | 公式代码块渲染后点 Copy | 复制结果等于 LaTeX 源码 |
| U-25 | 选区从段落中间到公式内部 | 剪贴板文字含完整的 `$...$` |
| U-26 | 选区含独立公式和公式代码块 | 输出 `$$...$$`，不含按钮文字 |
| U-27 | 选区没有已渲染公式，或 KaTeX 失败的公式 | 不接管默认复制 |
| U-28 | StrictMode 挂载、内容不变重渲染、内容变化 | 公式不重复，内容为最新值 |
| U-29 | KaTeX 加载完成前卸载或取消 | 不写 DOM |
| U-30 | KaTeX 加载失败 | 公式保留原文，不抛错，后续不重复请求 |
| U-31 | 默认的 `MarkdownBlock` | 不启动增强，现有调用方行为不变 |

## 3. Integration Points（集成点）

| 集成点 | 风险 | 验证 |
|---|---|---|
| `markdown-renderer.ts` | 其他调用方的解析结果改变 | U-10、U-31、B-4 |
| 流式增量 | 公式闪动，或破坏顶层节点计数 | U-20、U-21、B-1、B-2 |
| 现有复制逻辑 | 隐藏 `<pre>` 后读不到源码 | U-24 |
| `ConversationStream` 的滚动 | 公式高度变化导致跳动 | B-3、B-13 |
| Vite 打包 | KaTeX 进首屏，或字体过滤失效 | B-5、B-6、B-7 |
| daemon 静态资源 | 字体类型错误 | B-6 |
| KaTeX 升级 | 语法或输出结构变化 | U 组、B 组 |

## 4. Verification Strategy（验证策略）

规划阶段已经用临时原型在 Chrome 上验证了设计，原型接的是真实的 `marked`、DOMPurify 和 KaTeX：

- 30 个公式样例和 20 个非公式样例全部判断正确。这组样例参与了规则调整，所以另外扫描了约 156 万行真实 Markdown。
- 8 种分块大小的流式结果都等于全量渲染，暂缓结尾 `$` 后公式数量没有回退。
- 14 个恶意样例没有产生链接、图片、脚本或外部请求。
- 选区复制、宽公式滚动和 Vite 懒加载分包都已跑通。

这些结果说明方案可行，**不能代替实施后的验收**。下面几项只有接入项目后才能确认：

1. 真实消息流里的输出、完成切换和滚动。
2. daemon 实际返回的字体类型和缓存行为。
3. Safari、Firefox 和 Edge 的显示。
4. App 窗口里的显示。App 还没有实现，等它落地后抽查 B-6、B-8、B-12。

验收标准：

- U 组全部通过，并写入 Web 单测。
- B 组在 Chrome 全部通过；B-15 在四个浏览器上通过，没法在本机运行的浏览器要明确记录。
- 现有 Web 单测和类型检查通过，`ohbaby-server` 的静态资源测试通过。
- `redesign-2026-10/05-components.md` 的 `MarkdownBlock` 说明同步了 `math` 开关。
