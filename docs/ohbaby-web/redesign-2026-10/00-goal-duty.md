# 00 目标与职责

## 1. 产品目标

让用户打开 ohbaby Web 就能直接对话，不必先选工作区。同时，用户能在一个侧栏里找到、搜索并整理所有工作区和无工作区的会话，在一个安静的界面里看清 agent 正在做什么，并且不用编辑配置文件，就能在设置页查看和修改常用配置。

做到以下几点算成功：

- 新用户第一次打开页面，看到的是可以直接输入的输入框，而不是“先打开项目”。
- 老用户能在侧栏按工作区找到任意一个历史会话，或者用关键词搜到它。
- 界面整体是中性色、少装饰，品牌只通过“ohbaby”字标体现。对话内容是视觉主体。
- 模型和联网搜索的全局配置可以在设置页完成；MCP 的配置、状态以及 Skills 能在设置页查看。MCP 配置修改继续通过对话交给 ohbaby。

## 2. 用户角色

| 使用阶段 | 说明 |
|---|---|
| 初次使用者 | 刚启动 daemon，可能还没有配置模型，也没有工作区 |
| 日常用户 | 已经配置好，在多个工作区和无工作区对话之间切换 |
| 排查者 | 遇到 MCP 加载失败、模型不可用等问题，需要查看状态和诊断信息 |

权限身份：只有一种，本机单用户，所有操作权限相同。工具执行的审批（权限模式、放行规则）属于 agent 运行规则，不是页面访问权限，在 04 中作为交互状态处理。

## 3. 核心任务

- T-01 不选工作区，直接开始一个对话
- T-02 在指定工作区里开始对话
- T-03 在侧栏浏览、打开并继续已有会话
- T-04 按关键词搜索全部历史会话
- T-05 调整会话的工作区归属（移入、换工作区、移出）
- T-06 整理会话（置顶、排序、归档）
- T-07 在对话中控制 agent（查看过程、审批、插话或排队、停止、切换模型、思考强度和权限模式）
- T-08 打开一个新工作区目录
- T-09 查看和修改设置（第二批）

T-01 到 T-08 属于第一批，T-09 属于第二批（见 README 的 D1）。T-07 是现有功能，本轮只改外观和位置，不改行为。

## 4. 职责边界

前端负责：

- 管理发送前的草稿：输入文字、所选工作区都只存在前端，第一次发送时才创建服务端会话。
- 按服务端返回的执行目录连接实例、发送请求和订阅事件。侧栏的工作区归属只用于组织列表。
- 展示会话列表、搜索结果和工作区归属。
- 浏览器本地保存：草稿文字和所选工作区、侧栏收起和分组折叠、置顶、设置页上次停留的分区（06 §3.5、§3.6）。
- 做格式级校验（比如不能为空），展示后端返回的错误，并保留用户的输入。

前端不负责：

- 搜索匹配和排序。前端不能拿已加载的会话自己过滤，必须调用搜索接口。
- 判断会话该在哪个目录运行。以服务端为准，收到“会话已移动”的错误时按返回的目录重发。
- 校验模型凭据和搜索 key 是否有效，也不保存或显示凭据原文。
- 迁移权限状态。换工作区后，审批规则以目标目录为准。
- 把后端错误静默当成成功处理。

## 5. Non-goals

本轮不做：

- 暗色模式和多主题（只把颜色整理成 token，为以后留口子）
- 右侧面板（文件、终端、子代理面板）
- 项目级配置的查看与在线编辑（MCP、Skills 只呈现全局配置，README 的 D13）
- MCP 的前端添加、编辑、删除、启停、重连或手动工具调用入口（D25）；工具仍由运行时直接注入 agent 工具列表
- Agents 设置、MCP OAuth 登录、Skills 的启用停用或编辑
- 按会话保存或切换模型（模型切换只改全局默认，improve-2）
- 在设置页显示或手动填写推理能力（由后端自动探测，README 的 D14）
- 权限默认值持久化、hooks、快捷键自定义、插件设置页（04 §3 只新增一个搜索快捷键）
- 手动重命名会话（目前服务端没有改标题的接口，标题沿用自动生成的）
- 会话拖拽排序与分组、时间线视图（已归档会话的列表、恢复和永久删除由[归档会话议题](../../problem-lists/2026-10-25-archived-sessions/README.md)补上，入口在 Settings › Archived）
- 路由库和 SSR，以及迁移到 Tailwind 或 shadcn
- 移动端原生 App（窄屏只保证能用，见 03）
- 附件上传与附件消息协议（当前没有这条链路，本次暂隐藏入口，见 README 实施约定）
- 常态的连接状态展示
