# 03 界面布局与视觉

> 本文分三层：**必须遵守**（结构、原则、底线），**初值可调**（具体数值），**自由发挥**（细节手感）。第 8 节是给实施会话的交接清单。
>
> 2026-10-22 用户确认：大的结构按本文线框，细节照 pi-web 做（README 的 D10）。2026-10-23 改为对齐 Claude、Codex、Cursor 桌面端：轻玻璃只给浮起元素（D21，取代 D11 的 `sand`），输入框控制按钮放进卡片底部（D22）。2026-10-24 去掉暖色调，改为纯中性白灰（D30）；Lychee 重画并放大到约 52px（D31）；停止按钮改黑、红色只留给错误（D32）。下文写的 pi-web 数值都是初值，出处用文件名和行号标注，根目录是 `code-cli/frontend/pi-web`。

## 1. 设计原则

| 原则 | 截图上看什么 | 反例 |
|---|---|---|
| 内容是主角 | 助手回复是直接排在页面上的文字，没有底色和边框 | 每条消息都放在一张卡片里 |
| 平，不套 | 没有卡片里再放卡片、按钮外再套一圈边框；工具栏按钮都是无边框的文字按钮，hover 才有底色 | 设置页每项一张卡片，卡片里又是一个带边框的按钮组 |
| 常态安静，异常明确 | 正常时看不到连接状态、端口、版本；出问题时有一条写清原因的提示 | 顶栏常驻绿色的“已连接” |
| 少提示（D16） | 只在操作失败或用户没法继续时出现提示；操作成功、状态切换、“下一轮生效”这类信息不额外说明，由界面本身的变化体现 | 保存后弹 `Saved`；换项目后提示“下一轮在新目录运行”；归档后弹 `Chat archived` |
| 品牌只在字标和 Lychee 标识 | 除了“oh/ba/by”字标和空状态的荔枝图标，界面上找不到金、粉、蓝、红这些品牌色 | 发送按钮用品牌蓝 |
| 一个强调色，用得很少 | 强调色（近黑）只出现在发送按钮、当前会话左侧竖条、运行中转圈和焦点上 | 链接、标签、图标都是强调色 |
| 状态不只靠颜色 | 运行中有转圈，等待审批有圆点加提示，错误有文字 | 只用红点、绿点区分状态 |
| 紧凑、可扫描 | 会话行是单行、约 28px 高、12px 字；分组之间只有小标题，没有额外留白块 | 会话行两行高，带摘要 |

## 2. 视觉方向与来源

**一句话方向**：Claude、Codex、Cursor 桌面端的气质（简洁大气、轻微玻璃质感、少卡片、少提示），pi-web 的骨架、尺寸和代码细节。

| 来源 | 借什么 | 标志性特征（验收时逐条核对） |
|---|---|---|
| Claude 桌面端截图 | 配色和侧栏 | 主区接近中性的白，侧栏浅灰略深一档；侧栏是入口加按项目分组的单行会话，分组标题小而淡；输入框下方没有花哨元素 |
| Codex 桌面端截图 | 玻璃质感、输入框 | 侧栏半透明，透出背后的底色；输入框卡片上方是项目和环境选择，卡片里底部一行放模型和发送 |
| Cursor 桌面端截图 | 空状态和行尾信息 | 空状态是一组居中的选择器加输入框；会话行尾是淡色相对时间；发送是深色圆形按钮 |
| pi-web（代码来源） | 侧栏、会话树、菜单、消息、通知的结构和尺寸 | 侧栏顶部和主区顶部是同高（36px）的一条，底线连在一起；会话行 28px、12px 字 |
| Apple（`awesome-design-repository`） | 克制 | 没有彩色渐变；阴影只出现在浮起的元素上 |

**玻璃怎么用**：浏览器里侧栏背后只有页面底色，单独给侧栏加 `backdrop-filter` 看不出效果。所以玻璃只用在叠在内容上方的元素：菜单、通知、输入框卡片、审批浮层。主区顶栏不叠在消息上，用普通一行（D27）。侧栏用比主区深一档的半透明底，页面底层铺一层很淡的中性渐变，让侧栏有一点通透感。模糊和透明度都要克制，文字始终在不透明度足够的底上，保证对比度。不支持 `backdrop-filter` 的浏览器退回同色实底。

**字体**（照 pi-web）：
- 界面：`-apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, "PingFang SC", "Microsoft YaHei", sans-serif`，正文 14px。
- 等宽：`"JetBrains Mono", "Fira Code", Consolas, ui-monospace, "PingFang SC", monospace`。只用于路径、代码、工具名和工具参数。
- 现在的 IBM Plex Sans 和 Plex Mono 不再使用。

**图标**：lucide-react，线性，侧栏和工具栏 14–16px，描边粗细全站统一。

**字标**：保留三色“oh/ba/by”和圆体字形（D5），只改尺寸和位置：
- 侧栏顶部左侧，小号（初值 15–16px，对应 pi-web 品牌字 15px/700，`app/sidebar.css:1021`）
- 其他地方都不出现（启动失败页除外，那里没有侧栏）。思考中的指示不再用三色波点

**Lychee 标识**（D26）：agent 的名字叫 Lychee，用单色线性荔枝图标（圆形果实、几道鳞纹、一片叶子），颜色 `--brand-lychee`，描边风格和 lucide 一致：
- 空状态，项目选择条上方，约 52px（D31）
- favicon 用同一图形，加粗描边、减少鳞纹，保证 16px 下能认出
- 其他地方都不出现，消息旁也不加

**动效**（照 pi-web）：
- hover 和颜色变化 .12s；chevron 旋转 .15s；菜单入场 .12s ease-out（上移 3px 淡入）
- 侧栏开合 .2s ease，手机抽屉 .25s ease
- 转圈 .9s linear；运行中的文字提示做透明度呼吸（1.5s）
- `prefers-reduced-motion` 下关闭转圈以外的动效（转圈表示状态，保留）
- 去掉现在的挤压回弹和跳动动画

## 3. Design Tokens

### 3.1 语义色

角色必须定；色值是初值，按中性白灰取（D30，见 `apps/ohbaby-web/src/ui/styles/tokens.css`）。只有这一套亮色（D7）。

| token | 用途 | 初值 |
|---|---|---|
| `--bg` | 主区底色 | #fbfbfa |
| `--bg-canvas` | 页面最底层（侧栏透出的底色） | 由 #f6f5f3 到 #f1f0ed 的极淡渐变 |
| `--bg-panel` | 侧栏、设置导航 | rgba(243, 242, 239, .82) |
| `--bg-glass` | 菜单、通知、输入框卡片、审批浮层 | rgba(255, 255, 255, .78)，配 `--glass-blur` |
| `--glass-blur` | 玻璃模糊 | `saturate(1.4) blur(18px)` |
| `--bg-hover` | hover | rgba(0, 0, 0, .045) |
| `--bg-selected` | 当前会话行、菜单选中项 | rgba(0, 0, 0, .07) |
| `--bg-subtle` | 行内代码、工具展开区 | rgba(0, 0, 0, .035) |
| `--user-bg` | 用户消息 | #f1f0ec |
| `--border` | 侧栏右边线、输入框和菜单描边 | rgba(0, 0, 0, .08) |
| `--text` | 正文、标题 | #1f1e1c |
| `--text-muted` | 次要文字、图标、工具栏按钮 | #5f5d58 |
| `--text-dim` | 元信息、时间、分组标题 | #75736d（在 `--bg` 上约 4.7:1） |
| `--accent` / `--accent-hover` / `--accent-contrast` | 发送按钮、当前会话竖条、转圈、焦点 | #1f1e1c / #000 / #fff |
| `--danger` | 错误圆点、失败描边、停止按钮的浅底 | #ef4444（浅底用 8% 透明） |
| `--danger-ink` | 错误文字、Stop 文字 | #b42318 |
| `--warning` | 等待审批的圆点、运行中可插话的描边 | #d97706 |
| `--warning-ink` | 警告文字、上下文用量超过 70% 的数字 | #92400e |
| `--success` | 成功圆点 | #10b981 |
| `--brand-oh` / `--brand-ba` / `--brand-by` | 只用于字标 | #c9a23f / #c97e92 / #5f86c4（沿用现值） |
| `--brand-lychee` | 只用于 Lychee 标识（D26） | #c0444f |

`--danger`、`--warning`、`--success` 做文字时对比度不够，所以只用于圆点、图标、描边和浅底；需要做文字时用对应的 `-ink`。斜杠命令面板现有的金、粉、蓝分类色（`slashCommandAccent`、`.ohb-tool-blue` 等）改为中性色，品牌三色只留给字标（D5），荔枝红只留给 Lychee 标识（D26）。

### 3.2 阶梯

规则必须定，数值是初值，取自 pi-web。

| 阶梯 | 规则 | 初值 |
|---|---|---|
| 间距 | 2px 起，常用 4 的倍数 | 2 / 4 / 6 / 8 / 12 / 16 / 20 / 24 |
| 字号 | 界面以 12 为主，正文 14 | 10 / 11 / 12 / 13 / 14 / 15 / 22 |
| 字重 | 3 种 | 400 / 500 / 600（字标可用 700） |
| 圆角 | 由外向内递减 | 5（菜单项、行内代码）/ 7（会话行、代码块、工具行）/ 8（菜单、弹层）/ 12（用户消息）/ 14（输入框、通知） |
| 阴影 | 3 级，只给浮起的元素 | 输入框：`0 1px 2px rgba(15,23,42,.04), 0 8px 24px -12px rgba(15,23,42,.10)`；菜单：`0 6px 20px rgba(0,0,0,.10)`；通知：`0 1px 2px rgba(15,23,42,.05), 0 10px 28px -14px rgba(15,23,42,.24)` |
| 行高 | 控件行固定高度 | 侧栏行 28 / 顶栏 36 / 工具栏按钮 32 / 手机触控行 44 |

组件样式只引用 token 和阶梯。不够用时在 token 文件里加一级，不在组件里随手写数值。

### 3.3 硬底线（和 07 一致）

- 正文对比度 ≥ 4.5:1。`--text-dim` 在 `--bg` 上约 4.7:1；玻璃底上的文字按最不利的背景核对，不够就提高该元素的不透明度。
- 可点击区域 ≥ 22px（侧栏行内小按钮，照 pi-web）；手机 ≥ 44px。
- 所有可交互元素都有可见的键盘焦点样式（2px `--accent` outline）。

### 3.4 层级与断点

- 层级：侧栏抽屉 < 菜单与弹出层 < 审批与询问浮层 < 模态（目录选择、命令结果）< 通知。
- 断点：`640px`（手机）、`1024px`（窄桌面），和 pi-web 一致。

## 4. 布局与关键线框

### 4.1 布局骨架（必须遵守）

- 两栏：左侧栏（初值 260px，可收起，不做拖拽改宽），右侧主区。侧栏右边有 1px 分隔线。不做右侧面板，去掉最左侧的项目图标栏。
- 侧栏顶部和主区顶部同高（`--header-height`，44px），连成一条：侧栏一侧用 `--bg-panel`，主区一侧和主区同底色，没有玻璃和底线；消息区从顶栏下方开始（D27）。
- 对话列居中，最大宽度 820px，左右内边距 16px；输入框和对话列同宽。
- 滚动：消息流和侧栏会话列表各自滚动。两条顶栏、侧栏底部的设置按钮、主区底部的输入框固定。

### 4.3 会话态

```
+-----------------------------+--------------------------------------------------+
| ohbaby          |+ New| Q | | [=] | Refactor runtime  ~/Projects/ohbaby-agent  42% / 200k |
+-----------------------------+--------------------------------------------------+
| v ohbaby-agent              |                                                  |
| |   Refactor runtime     (o)|                    +----------------------------+|  <- 用户消息：右对齐，浅灰底
|     Sidebar redesign     1d |                    | Split the runtime into ... ||
| v No project                |                    +----------------------------+|
|     Quick question       5m |  Sure. I'll start by reading runtime.ts.         |  <- 助手：纯文字
|                             |  > 6 tool calls · 12s                            |  <- 过程折叠组
|                             |  The facade now owns two layers...               |
|                             |                                                  |
|                             |    +--------------------------------------------+|
|                             |    | Reply...                                   ||
|                             |    | [Ask v]            [gpt-5 v] [Med v] (^) ||
|-----------------------------|    +--------------------------------------------+|
| [gear] Settings             |                                                  |
+-----------------------------+--------------------------------------------------+
```

- 主区顶栏（照 pi-web `AppShell.tsx:2208`）：
  - 左边是侧栏开关 `[=]`，然后是会话标题和工作目录（等宽字体、`--text-dim`，过长时从中间省略）。
  - 右边是上下文用量 `42% / 200k`：超过 70% 变 `--warning-ink`，超过 90% 变 `--danger-ink`，点击打开详情。
  - 草稿态顶栏只有侧栏开关。
- 当前会话行左侧有一条 3px 的 `--accent` 竖条（`|`）。行尾按优先级只显示一项：等待审批的琥珀点、运行中的转圈 `(o)`、相对时间。
- 输入框（结构照 Codex / Cursor，细节参考 pi-web `ChatInput.tsx`）：一张玻璃卡片，上半部分是输入区，底部一行是控制按钮（D22）。
  - 底部一行左边是权限模式；右边是模型、思考强度和深色圆形发送按钮。选择控件都是无边框文字按钮。附件暂不显示，范围见 README。
  - 运行中，卡片描边变成浅琥珀色，表示现在可以插话；发送按钮旁出现插话和排队按钮。
  - 运行中且草稿为空时主位是 Stop，有草稿时保留现有插话/排队发送规则。Stop 是唯一带描边的按钮（`--danger` 8% 浅底和描边，`--danger-ink` 文字）。
  - Todo、未消费的插话放在卡片上方，用不带边框的行。
- 消息（照 pi-web `MessageView.tsx`）：
  - 用户消息右对齐，最大宽 85%，`--user-bg`，圆角 12。
  - 助手消息无底色，14px，行高 1.7。
  - 一轮里的中间过程（工具调用、思考）收在一个折叠行里，形如 `> 6 tool calls · 12s`，展开后每个工具一行。工具行用细描边、圆角 7，标题是等宽的工具名加参数预览；失败的工具行用 `--danger` 描边。和 pi-web 的区别是：成功的工具行不用绿色底，保持中性。
- 思考中：一行 13px `--text-muted` 文字（比如 `Thinking…`、`Running Read`），做透明度呼吸，不用三色波点。

### 4.6 审批与询问

pi-web 没有工具审批的界面，这里借它“询问用户”对话框的做法（`ChatWindow.tsx:1701`）：

```
|  ...assistant text...                                    |
|                                                          |
|      +------------------------------------------+        |
|      | Allow Bash?                          [-] |        |  <- 标题 14px；[-] 折叠成顶部一条
|      |------------------------------------------|        |
|      | rm -rf build/                            |        |  <- 等宽显示命令或路径
|      |------------------------------------------|        |
|      | [Deny]          [Allow once] [Always]    |        |  <- 按钮来自后端返回的选项，数量不固定
|      +------------------------------------------+        |
|                                                          |  <- 输入框在审批期间隐藏（D28）
```

- 浮在消息区底部、输入框的位置，居中，宽度约 560px。不加整页遮罩，用户仍然可以滚动看上文。审批期间输入框隐藏，草稿保留，处理完恢复并把焦点还给输入框（D28）。
- 可以折叠成消息区顶部的一条；侧栏对应会话行显示琥珀点。
- 内容和能力沿用现有 `PermissionModal`：按钮是后端返回的选项，数量不固定，主选项用 `--accent`；多个待审批请求时标题栏有 `1 / 3` 和上一条、下一条；同步中、同步失败（带 Retry）、Stop run 都保留。这里只改位置和外观。

### 4.7 设置页（第二批）

整体结构：打开设置时侧栏内容换成设置导航，主区显示分区内容。Models 是“列表 → 编辑子页”；MCP 是列表加原地展开的只读详情（D25）。借鉴 pi-web 的行式布局，不做三栏。

```

模型编辑子页（新增和编辑共用）：

MCP 列表与只读详情：

```
+--------------------------------------------------+

+--------------------------------------------------+
| > github                              8 tools   |  <- 名称 + 状态文字；点一行展开

原地展开的详情按行显示：Transport、Command + Args 或已脱敏 URL、Environment / Headers 名称、
Start in、Timeout (ms)、Trust、Include / Exclude tools，以及实际连接的 Status、失败原因和 Tools。
没有值的可选项不显示。配置使用普通文本，不使用输入框或开关；详情不用额外卡片包裹。

MCP 只有展开/收起、Refresh 和读取失败后的 Retry；Refresh 只重新读取数据，不触发重连。不显示添加、编辑、删除、启停或 Save 按钮，也不常驻配置教程（D16、D25）。

Web search 是一页表单（API key、> More options：Key variable、Base URL、Search depth、Max results、Topic、Timeout、Save）。Skills 是按来源分组的只读列表，点一行原地展开描述和路径。About 是只读的行，每行右侧一个复制图标。

- 选中的导航项和会话行一样：左侧竖条加选中底色。
- 内容区最大宽度初值 680px。列表和表单都是“标签 | 值或控件”的行，行之间用细线分隔，不用卡片包。
- 主按钮（Save、Add model）是唯一的实心按钮，用 `--accent`；其余都是无边框文字按钮。Save 在没有改动时不可点。
- 字段的出错原因写在该输入框下方，`--danger-ink`，13px。
- 不显示推理能力、不显示 key 原文，也不显示 provider 名以外的来源标签。

- 操作结果和错误通知：浮在对话区右上角，向下叠放，圆角 14，左侧一个 7px 的类型色点，最大宽 620px，入场 .18s。

## 6. 内容与文案

### 6.1 界面语言

本期沿用英文界面，不做多语言。文案集中定义，不在组件里拼接。

### 6.3 写法

- 错误写“原因 + 下一步”：`Couldn't load this chat. Its folder no longer exists — move it to another project to continue.`
- 按钮用动词：`Save`、`Open folder`、`Retry`。
- 空态一句话，写为什么空、可以做什么。比如搜索无结果：`No chats match "foo".`
- 不加感叹号，不用 emoji，去掉 “Ask Lychee anything…” 这类轮播占位。
- 输入框占位：草稿 `Ask anything...`，会话 `Reply...`，运行中 `Steer now or queue a follow-up...`（照 pi-web 的三态写法）。

## 7. 视觉验收口径

**硬指标**：

- 对比度、点击区域、焦点样式符合 §3.3。
- 组件样式里没有字面量颜色；字号、圆角、阴影都来自阶梯。
- 1440、900、390 三个宽度下的布局行为符合第 5 节。

**方向性判断**（浏览器截图 + 模型判断，逐条核对，不凭整体感觉）：

- 截图对照第 4 节的线框：区域划分、信息层级、主要操作的位置是否一致。
- 截图和 Claude、Codex、Cursor 的参考截图并排对比：底色层次、侧栏密度、输入框结构、留白是否接近；尺寸和行高再和 pi-web 对照。
- 逐条核对第 1 节原则的“截图上看什么”和第 2 节的标志性特征。
- 对照 `design-taste-frontend` 的反默认清单，检查有没有滑向 AI 默认审美（紫色渐变、居中大标语、三张等宽特性卡等）。
- 文案和术语符合第 6 节。

方向内的合理调整算通过，调整后的值回写本文。偏离原则、线框或标志性特征才算问题。拿不准的交给用户判断。
