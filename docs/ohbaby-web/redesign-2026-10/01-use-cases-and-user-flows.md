# 01 用例与用户流程

> 产品行为以 [improve-1 00](../../problem-lists/2026-10-20-workspaceless-sessions-and-settings/improve-1/00-discussion.md) 和 [improve-1 02](../../problem-lists/2026-10-20-workspaceless-sessions-and-settings/improve-1/02-optimization-plan-and-change-scope.md) 为准，设置以 [improve-2 00](../../problem-lists/2026-10-20-workspaceless-sessions-and-settings/improve-2/00-discussion.md) 为准。本文把那些规则展开成页面和流程；两边有出入时，以 improve 文档为准并回改本文。

## 1. 信息架构

### 1.1 页面树

Web 只有一个页面。左侧是固定的侧栏，右侧主区在“对话”和“设置”两个视图之间切换。

```
ohbaby Web
├── 侧栏（常驻，可收起）
│   ├── 字标、新对话、搜索（搜索框与结果在侧栏内展开）
│   ├── 项目分组 → 会话
│   ├── 无项目对话 → 会话
│   └── 设置入口（左下角齿轮）
├── 主区：对话视图
│   ├── 草稿态（新对话，输入框居中）
│   └── 会话态（消息流，输入框在底部）
├── 主区：设置视图（第二批）
│   └── Models（列表 → 编辑子页）/ MCP（列表 → 编辑子页）/ Skills / Web search / About
└── 浮层
    ├── 打开项目（目录选择）
    ├── 会话菜单（Move to project… 打开项目列表）
    ├── 工具审批
    ├── 子代理只读视图
    └── 斜杠命令面板与命令结果
```

### 1.2 视图表

项目继续不引入路由库。视图状态写在 URL hash 里，沿用 `runtime.ts` 现有的 `replaceNavigationHash` 机制。

| 视图 | hash（建议） | 主要任务 | 前置条件 | 核心 |
|---|---|---|---|---|
| 对话 · 草稿态 | 空 | T-01、T-02 | 无 | 是 |
| 对话 · 会话态 | 带会话 ID 和执行目录 | T-03、T-05、T-07 | 会话存在且执行目录可用 | 是 |
| 侧栏 | 不进 hash | T-03、T-05、T-06、T-08 | 无 | 是 |
| 侧栏搜索 | 不进 hash | T-04 | 无 | 是 |
| 设置 | `settings/<分区>`；编辑子页 `settings/models/new`、`settings/models/<id>`、`settings/mcp/new`、`settings/mcp/<name>`（id 和名称做 URL 编码） | T-09 | 无 | 是 |

设置写进 hash，刷新后停在原来的分区。进入设置时只 `pushState` 一条记录，保存进入前的对话 hash；设置内切分区、进入编辑子页使用 `replaceState`，编辑页的返回按钮回到所属列表。这样无论停在哪个设置子页，Back to app 和浏览器后退都一次回到原对话。直接打开设置链接时，Back to app 用 `replaceState` 回草稿，不能凭 `history.length` 跳到站外。返回标记放在本应用的 `history.state`，刷新后仍可识别；无有效标记时使用草稿兜底。监听 `popstate` / `hashchange`，程序调用 push/replace 后同步更新视图。设置打开期间会话 SSE 继续工作，但不得用会话同步覆盖设置 hash。

会话之间切换仍用 `replaceState`，不让后退在会话间来回跳。会话态 hash 保留现有格式，保证旧链接能恢复原会话（improve-1 T20）；未知设置分区回 Models，非法编辑 ID 回所属列表。

### 1.3 权限

单用户，没有权限区分。工具审批不属于页面权限，见 04。

## 2. 用户流程

### 2.1 不选项目直接开始（T-01）

```
打开页面（或点“新对话”）
↓ 主区显示草稿态：字标 + 居中的项目选择条（显示“无项目”）和输入框卡片
↓ 输入文字，发送
├── 成功 → 创建会话（默认目录），切到会话态，侧栏“无项目对话”顶部出现这条会话
├── 模型未配置 → 不提前提示；点发送时不创建会话、保留文字，直接打开配置入口（第一批是现有 /connect 浮层，第二批是设置 › Models）
├── 创建失败 / 网络断开 → 保留文字和项目选择，提示错误，可再次发送
└── 连点发送 → 第一次请求返回前，发送按钮不可用
```

### 2.2 在项目里开始（T-02）

```
入口 A：草稿态 → 输入框卡片上方的项目选择条 → 选一个已有项目
入口 B：侧栏项目分组标题上的“+” → 打开预选了该项目的草稿
入口 C：项目选择器里的“打开文件夹…” → 目录选择 → 新项目被选中（见 T-08）
↓ 输入文字（选择或更换项目时文字保留）
↓ 发送 → 在该项目目录创建会话，出现在该项目分组顶部
└── 异常同 2.1
```

### 2.3 浏览并继续会话（T-03）

```
侧栏：置顶区（先显示 8 条）→ 各项目分组（每组先显示 6 条）→ 无项目对话
├── 某组还有更多 → 点“显示更多”，每次多显示 20 条
├── 折叠 / 展开项目分组 → 记在浏览器本地
└── 点击一条会话
    ↓ 按服务端返回的执行目录连接实例，加载历史
    ├── 成功 → 会话态，主区顶栏显示工作目录
    ├── 执行目录已被删除或不可读 → 显示错误，提示用 Project 菜单换一个项目
    └── 加载失败 → 主区显示错误和“重试”
```

### 2.4 搜索（T-04）

```
点侧栏顶部的搜索 → 侧栏里展开搜索框，焦点在输入框；结果替换会话树
↓ 输入关键词（防抖后调用搜索接口）
├── 有结果 → 列出标题、所属项目、命中片段；标题命中排在前面
├── 无结果 → “没有找到匹配的对话”
├── 输入为空 → 显示原来的会话树
├── 请求失败 → 面板内提示，可重试；保留关键词
└── 选择一条结果 → 搜索收起，按执行目录打开该会话（同 2.3）
```

### 2.5 调整项目归属（T-05）

```
会话行“…”菜单（或右键）→ Move to project… → 项目列表 →
├── 选另一个已有项目
│   ├── 会话空闲 → 立即归到新项目，下一次发送在新目录运行
│   └── 会话运行中 → 立即归到新项目，当前回复不中断；下一轮在新目录运行，顶栏目录随之更新（不额外提示）
├── 从项目中移出 → 归到“无项目对话”，工作目录不变；取消尚未生效的换目录
└── 请求失败 → 侧栏不变，提示错误
发送时如果服务端返回“会话已移动” → 前端自动换到目标目录重发，并切换事件订阅，不打扰用户
```

### 2.6 整理会话（T-06）

```
会话“…”菜单 → 置顶 / 取消置顶 → 移到置顶区（本地保存，沿用现有实现）
             → 导出 → HTML / JSONL 下载（沿用现有实现）
             → 归档 → 从侧栏消失；如果正在打开这条会话，主区回到草稿态（Web 上不能撤销）
```

### 2.7 对话中控制 agent（T-07）

现有功能，行为不变，只重新安排位置（见 03）：查看消息流、工具过程和子代理，审批工具调用，运行中插话或排队，停止，切换思考强度和权限模式，斜杠命令，上下文用量。

模型按钮在第二批改为直接选择：菜单按 provider 列出配置完整的模型，选中即设为全局默认模型，所有对话从下一轮起使用，当前回复不受影响；菜单最后一项 `Manage models…` 打开设置 › Models。不加说明文字（README 的 D15）。第一批保持现有行为。Web 端的 `/connect`、`/connect-search` 命令在第二批删除（D18）。

### 2.8 打开新项目（T-08）

```
侧栏“项目”标题的“+”，或项目选择器的“打开文件夹…”
↓ 目录选择浮层（沿用现有 DirectoryPicker）
├── 选定 → 项目出现在侧栏；如果是从草稿里打开的，草稿同时选中该项目
├── 选的是默认工作区 → 不作为项目登记（服务端过滤）
└── 取消 → 什么都不变
项目分组“…”菜单 → 隐藏项目（沿用现有规则，搜索仍能找到它的会话）
```

### 2.9 设置（T-09，第二批）

```
点左下角齿轮 → 侧栏换成设置导航，主区显示上次停留的分区（第一次打开 Models）
↓ 左侧导航切换分区：Models / MCP / Skills / Web search / About
├── 某分区加载失败 → 只有该分区显示原因和 Retry
└── 点侧栏顶部的 Back to app，或用浏览器后退 → 回到原来的对话（草稿保留）
```

**Models**

```
模型列表（按 provider 分组，组内按保存顺序）
├── Add model → 编辑子页（空表单）→ Save → 回到列表，新模型排在末尾
│   ├── 已有默认模型 → 默认不变
│   └── 还没有默认模型 → 前端紧接着把它设为默认（D20）；如果是从草稿点发送跳过来的，且中途没有离开 Models，回到草稿，文字还在
├── 点一行 → 编辑子页 → 改字段 → Save → 回到列表；改的是当前默认模型时，下一轮生效
├── 行菜单 › Set as default → 立即成为全局默认，下一轮生效（配置不完整的条目没有这一项）
├── 行菜单 › Delete
│   ├── 普通模型 → 直接删除
│   └── 当前默认模型 → 确认框 → 删除后列表里的下一个模型成为默认；删完没有可用模型时，默认为空
├── provider 组菜单 › Delete provider → 确认框 → 删除这个 provider 的全部模型
└── 标着 Needs setup 的旧条目 → 点开确认或补齐字段（需要 key 就填上）→ Save 后条目变为完整，可以设为默认；还没有默认时同样自动设为默认（D20）
```

保存只检查格式和必填项，不连上游；推理能力等由后端在后台探测，设置页不显示。API key 只显示 Configured 或 Not set，替换、清除用单独的按钮。

**MCP**

```
全局 MCP 服务器列表（状态取自当前工作区的连接）
├── 行尾开关 → 启用 / 停用，直接保存
├── Add server → 编辑子页 → Save → 回到列表
├── 点一行 → 编辑子页：上方是状态、失败原因和工具列表，下方是配置；Save 后下一轮生效
├── 编辑子页 › Delete → 直接删除
└── Reconnect → 按最新配置重连当前工作区的 MCP；有对话正在运行时在按钮旁写原因
```

当前工作区：打开设置前所在会话的执行目录；在草稿里就用所选项目，没选用默认工作区。页面上不显示是哪个目录（README 的 D13）。

**Skills**：只读列表，只列全局 Skills，按来源分组；点一行展开描述和路径。

**Web search**：一页表单：API key（Configured / Not set，替换、清除）；More options 里是 key 变量名、Base URL 和默认搜索参数。Save 后下一次搜索生效。

**About**：版本、ohbaby home、默认工作区，以及有的话显示诊断文件和日志目录，每项可复制。

### 2.10 跨任务情况

| 情况 | 表现 |
|---|---|
| 刷新页面 | 草稿文字和所选项目保留（06 §3.5）；会话态按 hash 恢复 |
| daemon 断开 | 顶部出现一条提示；恢复后自动同步列表，提示消失。常态下不显示连接状态（README 的 D6） |
| 窗口重新激活 | 重新拉取会话列表 |
| 正在看的会话被别处归档或移动 | 列表同步后，按新状态显示；正在看的会话保持打开 |
| 草稿中途打开设置 | 回来后草稿文字和项目选择都在 |

## 3. 用例描述

### UC-DRAFT-01 不选项目发起对话

- **前置条件**：模型已配置。
- **主流程**：1. 打开页面或点“新对话”；2. 在居中的输入框输入文字；3. 发送；4. 进入会话态。
- **异常流程**：模型未配置时，点发送打开配置入口（第一批用 /connect 浮层，第二批跳设置 › Models），保留文字；创建失败或网络断开时保留文字和选择，可再次发送；请求进行中发送按钮不可用。
- **完成结果**：侧栏“无项目对话”顶部出现新会话并处于选中状态；主区顶栏显示默认工作目录；点“新对话”本身不会产生空会话。

### UC-DRAFT-02 在项目中发起对话

- **前置条件**：至少有一个项目，或者用户愿意打开一个。
- **主流程**：1. 在草稿里通过项目选择器或项目分组的“+”选中项目；2. 输入并发送。
- **异常流程**：更换项目时文字保留；其余同 UC-DRAFT-01。
- **完成结果**：会话出现在该项目分组顶部；工作目录是该项目目录。

### UC-SIDEBAR-01 打开已有会话

- **前置条件**：侧栏里有会话。
- **主流程**：1. 点击会话；2. 加载历史；3. 可以继续发送。
- **异常流程**：执行目录不可用时显示错误并引导到 Project 菜单；加载失败时主区显示“重试”。
- **完成结果**：消息流显示完整历史；主区顶栏显示的是执行目录，而不是侧栏的项目目录。

### UC-SIDEBAR-02 浏览更多会话

- **主流程**：项目分组超过 6 条（置顶区超过 8 条）时点“显示更多”，每次多 20 条，或折叠、展开分组。
- **完成结果**：能加载到该组任意早的会话；折叠状态刷新后保持。

### UC-SEARCH-01 搜索历史会话

- **主流程**：1. 打开搜索；2. 输入关键词；3. 选择结果。
- **异常流程**：无结果时显示空态；请求失败时面板内可重试；输入很快时只发最后一次请求。
- **完成结果**：未在侧栏加载的旧会话也能搜到；结果显示标题、所属项目和命中片段；打开后恢复该会话。

### UC-PROJECT-01 换项目或移入项目

- **主流程**：会话菜单 → Move to project… → 选择目标项目。
- **异常流程**：请求失败时侧栏不变并提示；运行中操作不打断回复。
- **完成结果**：会话立即出现在目标分组；运行中时当前回复不中断，下一轮开始后顶栏的工作目录更新。

### UC-PROJECT-02 从项目移出

- **主流程**：会话菜单 → Move to project… → Remove from project。
- **完成结果**：会话出现在“无项目对话”分组；工作目录保持原目录，不会变成默认目录。

### UC-SESSION-01 置顶与归档

- **主流程**：会话菜单 → 置顶 / 取消置顶 / 归档。
- **完成结果**：置顶的会话出现在置顶区；归档的会话从侧栏消失，如果当时正打开它，主区回到草稿态。

### UC-CHAT-01 对话中控制 agent

- **说明**：现有功能，行为以现有测试为准。本轮的验收重点是改版后这些控件仍然可以找到、可以操作（见 08）。第二批起，模型按钮直接选择全局默认模型（§2.7）。

### UC-PROJECT-03 打开新项目

- **主流程**：侧栏“+”或项目选择器的“打开文件夹…” → 选择目录。
- **完成结果**：新项目出现在侧栏；从草稿发起时，草稿选中该项目且文字保留。

### UC-SETTINGS-01 进入与离开设置（第二批）

- **主流程**：点齿轮 → 设置页 → 切换分区 → 点 Back to app 或浏览器后退。
- **完成结果**：主区是设置页，左侧有 5 个分区；返回后回到原来的对话，草稿内容不丢。

### UC-SETTINGS-02 管理模型（第二批）

- **主流程**：Models → Add model 或点一行 → 填写 → Save；行菜单 Set as default；行菜单或 provider 组菜单删除。
- **异常流程**：字段不合法时在对应输入框下写原因，保留输入；条目已被别处删除时回到列表；删除当前默认模型、删除 provider 前确认；配置不完整的条目不能设为默认，点开补齐后才行。
- **完成结果**：列表顺序稳定，新增排在末尾；已有默认时保存不改变默认，没有默认时新增的模型自动成为默认（D20）；设为默认后所有对话下一轮使用它；页面上不出现 key 原文和推理能力。

### UC-SETTINGS-03 管理 MCP 服务器（第二批）

- **主流程**：MCP → 开关启停，或 Add server / 点一行编辑 → Save；需要立即验证时点 Reconnect。
- **异常流程**：字段不合法时在对应输入框下写原因；有对话运行时 Reconnect 不执行，按钮旁写原因；某服务器连接失败时，行上显示 Failed，编辑子页显示原因。
- **完成结果**：改动写入全局配置，下一轮或 Reconnect 后生效；env 和 header 只显示名字。

### UC-SETTINGS-04 配置联网搜索（第二批）

- **主流程**：Web search → 替换或清除 API key，按需改 More options → Save。
- **完成结果**：下一次搜索使用新配置；页面只显示 Configured / Not set 和变量名。

### UC-SETTINGS-05 查看 Skills 与 About（第二批）

- **主流程**：Skills 浏览全局 Skills，展开看描述和路径；About 查看并复制版本与目录。
- **完成结果**：信息只读，不提供编辑。
