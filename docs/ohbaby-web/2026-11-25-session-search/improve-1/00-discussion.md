# 会话搜索讨论记录

## 2026-11-25 已确认

- 沿用现有跨项目会话查询。首版搜会话标题、用户消息和助手写给用户的正文，包括正文里的代码、路径、报错，以及折叠的执行过程说明。
- 终端返回的信息、其他工具的原始输出、思考详情和后端内部消息均排除。助手在回复里引用工具报错时，这段引用属于正文，可以命中。结果摘要也从可搜索的展示文字中截取。
- 输入 `终端 重连` 时，只要同一条消息正文包含两个词，就要命中。两个词可以相隔任意字符，也可以换序。现有查询已支持这条规则。用户消息里只有“终端”、另一条助手消息里只有“重连”时，两条消息不拼成一次命中。标题沿用相同的多词规则。
- 点击左侧 Search 直接打开搜索卡片。移除 Search 下方展开的小输入框，用户在卡片内输入关键词。
- 本轮先讨论后端。

## 11-25 最终确认（部分已在 11-26 细化）

- 输入 `终端重连` 查连续原文。只有输入空白才拆词。
- 首版点击正文摘要即在主会话定位到命中消息，包括尚未加载的旧消息。点击标题命中结果沿用普通打开会话行为。（11-26 细化为：有正文摘要就跳到那条消息，没有才打开到最新。）

## 2026-11-26 实施前确认

- **分工。** 用户实现后端，包括会话查询、SDK 中 `getSessionHistory` 的类型、server 的 HTTP 与 RPC 入口和会话投影层。Claude 实现前端，只改 `apps/ohbaby-web`，包括 daemon 客户端的请求参数、mock 运行时、搜索卡片和主聊天定位。
- **卡片形态。** 搜索卡片是居中弹窗，参考 [OpenCode 的会话搜索](../../../../../opencode/packages/app/src/shell/commands/session-search.tsx)。弹窗带遮罩，打开时聚焦输入框，按 Esc 或点遮罩关闭，关闭后焦点回到 Search 按钮。侧栏会话列表始终显示，不再被搜索结果替换。
- **视觉参考。** 前端效果参考 Claude、Codex 和 Notion 三个桌面应用的搜索弹窗：输入框在顶部，下方是结果列表，底部是快捷键提示。
- **首版范围。** 搜索会话标题和会话正文。搜索结果要能按时间正序或倒序排列。文件搜索不在本轮，等文件系统优化完成后再做。
- **排序。** 按会话更新时间排序，和侧栏一致。取消“标题命中排在前面”的规则，结果不再分标题组和正文组。
- **结果行。** 一个会话只占一条结果。标题和正文同时命中时放在同一条结果里，不拆成两条。显示的信息参考 Claude 应用：标题、项目名、正文摘要和粗略的相对时间（如 “Past week”）。布局按 Codex 应用：第一行是图标和标题，右侧是项目名和相对时间；有正文命中时第二行显示摘要。只显示必要信息，不按日期分段。
- **视觉风格。** 卡片用毛玻璃质感，简约大气，参考 OpenAI、Tesla、Apple、Anthropic 这类品牌的克制风格。沿用现有的 `--bg-glass` 和 `--glass-blur` 设计变量，以及浏览器不支持模糊时的纯色回退。
- **点击规则。** 有正文摘要的结果，点击后跳到那条消息；没有摘要的结果和最近会话，点击后打开到最新。

以下各项按 Claude 的建议一并确认，细节写在[技术方案](02-optimization-plan-and-change-scope.md)。

- **返回值。** 删除 `matchType`。`messageId` 和 `snippet` 只在正文命中时一起返回，标题是否命中由前端按关键词高亮自行判断。目前只有 Web 使用这个接口。
- **排序参数。** 搜索增加可选参数 `order`，取值 `desc` 或 `asc`，默认 `desc`。游标去掉 `group`，记录 `order`，方向与游标不一致时返回参数错误。摘要固定取会话里最近命中的消息，不随排序方向变化。
- **摘要长度。** 摘要独占结果的第二行。每个关键词前保留约 15 个字，总长不超过 120 个字。
- **旧消息片段。** 片段只能向上翻页，读到末尾时提供“回到最新”。阅读片段时仍可发送消息，发送成功后回到最新。片段状态只保存在会话页本地，不进 store。
- **定点窗口。** 前端定点读取固定传 `limit=50`，目标前后平分余量。服务端定点模式把 `limit` 钳到至少 3，删除原先为 `limit=1` 设计的探针逻辑。
- **目标不可用。** 返回同版本的空历史页，不新增错误码。
- **重试判定。** 先用 LIKE 筛出候选消息，再只对候选做 EXISTS 排除；用同一条重试样例对比 SQL 与 SDK 的结果。
- **高亮。** 前端只折叠 ASCII 大小写，与后端 LIKE 一致。
- **分页。** 结果列表滚到底部时自动加载下一页，去掉 “Show more results” 按钮。
- **键盘。** 焦点始终留在输入框，↑↓ 移动选中行，回车打开，读屏软件通过 `aria-activedescendant` 得知当前行。
- **窄屏。** 宽度小于 640px 时弹窗贴顶、占满宽度，结果行高度不低于 44px。
- **开发顺序。** 用户先提交 SDK 类型（`anchorMessageId`、`order` 和新的搜索返回结构），Claude 先用 mock 运行时完成前端。分支名为 `feat/session-search-card`。

## 本轮设计建议

- **最近会话与排序。** 打开卡片时，从现有活跃会话列表取最近更新的几条；输入关键词后，查询覆盖现有搜索范围，包括隐藏项目中的活跃主会话。沿用每个会话一行，按最近更新排序。相同更新时间沿用会话 ID 定序。（“标题命中优先”和游标里的 `group` 已在 11-26 取消，翻页规则见技术方案第 1 节。）
- **结果要能解释命中原因。** 同一会话有多条正文命中时，取最近命中的消息。两个词靠在一起时，给一段原文；距离远时，分别截取上下文，按原文顺序用省略号连接。沿用现有 `snippet` 字段，长度有上限。每个词按字面高亮，大小写匹配跟随后端；重复或重叠的高亮合并。摘要空间只影响展示，不能反过来决定是否命中。
- **本地参考。** [Pi 的会话选择器](../../../../../pi/packages/coding-agent/src/modes/interactive/components/session-selector-search.ts)对正文使用连续片段匹配，部分字段可以跳字，而且多个词可以分布在不同字段。这里保留 ohbaby 已有的“同一标题或同一条消息”规则。[OpenCode 的会话卡片](../../../../../opencode/packages/app/src/shell/commands/session-search.tsx)从最近会话切换到服务端查询，这部分可以沿用 ohbaby 已有的两个接口。

### 正文结果的落点

没有正文摘要的结果沿用普通打开会话的行为。正文结果已经带有消息 ID，首版点击后直达对应消息。用户能在上下文中读到原话。

[会话视图](../../../../apps/ohbaby-web/src/ui/conversation/ConversationStream.tsx)已有滚动到指定消息和展开过程说明的能力。[主会话历史接口](../../../../packages/ohbaby-sdk/src/contract/session-view.ts)目前只有向前翻页的游标，[前端历史状态](../../../../apps/ohbaby-web/src/store/store.ts)也只维护一个较早边界。最近已加载的消息可以复用现有定位；要保证直达任意旧消息，建议按消息 ID 读取附近一段对话，同时区分这段历史与最新消息之间尚未加载的部分。直接把两段拼接起来会让用户误以为它们前后相连。

本轮采用的定位方式及历史阅读边界见[技术方案](02-optimization-plan-and-change-scope.md)。

### 后端实现前要验证的两件事

- **搜索正文与聊天展示一致。** 有字符串类型的 `displayText` 时使用这个值，空字符串也有效；只有缺少展示文字时才读取普通消息原文。搜索和摘要用同一套规则。覆盖含隐藏原文的 Goal 消息、重试后被替换的旧回复，以及同时含有助手说明和工具输出的消息。最后一种情况应保留说明、排除工具输出。过滤须在选代表消息和分页前生效，避免本应命中的会话整行丢失。
- **先测实际耗时。** 复用 SQLite 查询。在规模接近日常长期使用的测试库上，分别测中文短词、多词、无结果和翻页。记录库规模与查询耗时，再决定是否需要搜索索引。本次临时库验证的是匹配行为，不能据此判断大库性能。

## 现有实现

[会话查询](../../../../packages/ohbaby-agent/src/services/session/global-query.ts)按空格拆词，支持在一个标题或同一条消息里匹配多个连续片段。正文命中会返回消息 ID 和摘要。

搜索目前读取原始文本，聊天记录优先使用供用户阅读的 `displayText`。[Goal 的集成用例](../../../../packages/ohbaby-agent/src/adapters/goal-context.integration.test.ts)里，原文含有内部标记，界面只显示目标或自动继续提示。匹配与摘要都应采用[聊天记录的文本规则](../../../../packages/ohbaby-agent/src/core/message/origin.ts)。

[聊天记录](../../../../apps/ohbaby-web/src/ui/conversation/ConversationStream.tsx)还会过滤重试后被替换的旧回复。扩展搜索时需要核对这类消息，避免结果指向用户在聊天记录里找不到的内容。

### 用临时数据库复核的三个例子

以下结果来自当前查询函数，测试数据与日常会话隔离。

| 输入 | 消息内容 | 查询结果 |
|---|---|---|
| `终端 重连` | 同一条消息先写“重连”，隔 500 个字符后写“终端” | 命中，但现有摘要只展示了“重连”。把两词分别放到两条消息中，同一查询不会命中。 |
| `终端重连` | 同一条消息先写“重连”，隔 500 个字符后写“终端” | 当前按连续文本查，未命中，符合确认规则。 |
| `展示短句` | 原文是 `internal-marker`，展示文字是“展示短句” | 搜展示文字无结果，搜内部原文却有结果。修正后预期相反。 |
