# 会话搜索技术方案

## 1. 查询、排序与摘要

空输入展示全局活跃会话列表中最近更新的会话，取前 10 条，固定按最新在前。已有列表数据够用时直接复用。输入非空后，调用现有 `GET /v1/sessions/search?q=…`，新增 `order=desc|asc` 参数，沿用分页和取消请求。主动搜索可以找回隐藏项目中的活跃主会话；归档会话、旁聊和子代理会话沿用现有范围。

- **匹配。** 按空白拆词。搜 `终端重连` 要求四个字连续；搜 `终端 重连` 要求同一标题或同一条消息包含两个词，顺序、距离不限。词可以分布在一条消息的不同正文块中。保留英文 ASCII 大小写折叠，以及 `%`、`_`、反斜线的字面含义。
- **正文。** 读取用户和助手给人看的文字，包括用户补充指令、助手折叠的过程说明和回复里引用的代码或报错。对照[聊天正文提取规则](../../../../apps/ohbaby-web/src/ui/conversation/message-text.ts)验收。SQLite 的匹配与摘要回读共用同一正文表达式和过滤条件。以 SQLite 的 `json_type` 判定 `metadata.displayText`，字符串就取它，即使为空；旧消息缺此字段时取 `text`。工具与终端原始输出、思考、系统提示、压缩摘要、生命周期提示、已撤销以及被后续重试替换的旧回复均排除。旧块也按 `metadata.kind` 识别内部摘要及生命周期提示，仅检查 `synthetic` 会漏掉这类数据。含工具调用的助手消息按块过滤，保留其中写给用户的说明。
- **重试。** 按 [SDK 现有判定](../../../../packages/ohbaby-sdk/src/contract/execution.ts)对齐已被替换的尝试。判定要能看到同一轮、同一步后续已启动的尝试，即使后者没有命中搜索词。数据库存的是原始消息，助手状态按[现有投影](../../../../packages/ohbaby-agent/src/adapters/ui-state/persistent-store.ts)先看 `error`，再看 `time.completed`。SQL 不读取界面派生的 `status`。只有安排了重试、后继尚未启动时，仍按实际可见状态处理。在为会话挑选代表消息和分页前排除不可见命中，用同一条重试样例验证 SQL 与 SDK 结果。
- **结果与顺序。** 每个会话一条结果。结果只按会话更新时间排序，由可选参数 `order`（`desc` 或 `asc`，默认 `desc`）决定方向；时间相同时按会话 ID 同向排序。不再把标题命中排在正文命中之前，游标去掉 `group`，改为记录 `order`；请求的方向与游标不一致时，按无效游标处理，返回现有的 `INVALID_CURSOR`；`order` 取其他值时，按 `limit` 非法的现有方式报参数错误。`listGlobalSessions` 的列表游标格式不变，搜索游标单独记录 `order`。正文取会话里最近命中的可见消息，不随排序方向变化。标题和正文同时命中时，照样返回正文命中。
- **返回结构。** 删除 `matchType`，返回值收窄为下面的形状。标题是否命中由前端按关键词高亮自行判断。目前只有 Web 使用这个接口，TUI 不受影响。

  ```ts
  interface UiSessionSearchResult {
    readonly session: UiGlobalSession;
    readonly messageId?: string; // 只在正文命中时出现
    readonly snippet?: string;   // 与 messageId 同时出现，只含正文摘要
  }
  ```

- **摘要。** 各词在展示文字里取一次命中位置，关键词前保留约 15 个字，其余长度向后取，重叠区间合并。相隔较远时按原文顺序用省略号连接。总长按 Unicode 字符计，含省略号不超过 120 个。关键词多到放不下时，按在原文中首次出现的顺序保留，放不下的段落整段舍去，至少保留第一个命中词。前端按同样的拆词规则高亮返回文字，只折叠 ASCII 大小写，合并重叠标记。结果是否命中只由完整正文决定。
- **重试判定的实现顺序。** 先用 LIKE 筛出命中的候选消息，再对候选消息用 `json_each` 取出安排了重试的失败请求；EXISTS 子查询展开同一运行里后继助手消息的 `modelRequests`，查同一步、尝试次数更大且已启动的请求。后继消息不必命中关键词。这样 JSON 展开只发生在候选消息及其同运行的后继上，不扫全表。

保留 SQLite，排序游标按上述规则调整。验收时记录长历史样本的体量及查询耗时，再依据实测决定后续索引工作。

## 2. 点击正文结果，读取命中消息附近的历史

搜索接口只返回摘要。用户点击后，Web 走现有跨项目选会话流程，把 `session.id` 和 `messageId` 一起带到目标会话。若当前可显示的会话历史已包含目标，直接定位；未加载时只发一次定点历史请求。没有正文摘要的结果和最近会话走普通打开流程。

| 调用约定 | 行为 |
|---|---|
| `getSessionHistory({sessionId, before?, limit?})` | 普通历史读取保留现有语义。 |
| `getSessionHistory({sessionId, anchorMessageId, limit?})` | 同一个 history 接口增加可选参数，对应 Web 的 `GET /v1/sessions/:id/history?anchorMessageId=…`。与 `before` 互斥。返回一段按时间正序排列、含目标的 `UiSessionHistory`；沿用原有的消息、运行、输入及版本字段。 |

服务端在当前会话绑定下读取目标。先用按会话查询 ID 的现有入口，再核对主会话范围与目标可见性。与搜索共用重试替换判定，查同一轮、同一步的后继；即使它不在这页内，旧尝试也不能作为定位目标。用目标的 `(created_at, id)` 构造现有消息游标，同一主会话范围下向前、向后各读一小段，显式把目标放在中间。底层前后游标都不含边界消息。定点模式把 `limit` 钳到 3 到 200 之间，目标占一条，余量分给前后两侧，两侧至少各一条，首尾允许少于一页。两侧直接复用现有分页读取，不另写探针。返回的 `before/hasMore` 仍只描述窗口之前的历史，取自向前那一侧分页结果的游标和 `hasMore`。

定点读取与普通历史共用服务端的消息投影、运行和输入整理，以及已有的版本与会话绑定校验。参数从 SDK 传到 Web 客户端、server 的 HTTP 和 RPC 读取入口，再到会话投影层。目标已被撤销或不属于当前可见主会话时，在有效绑定下返回同版本的空历史页（消息、运行和输入均为空，`hasMore=false`）；只有定点调用把该空页解释为“消息不可用”，不新增错误码。绑定失效和网络错误仍走现有错误处理。Web 发起定点读取时固定传 `limit=50`：目标占一条，向前 24 条，向后 25 条，某一侧不足时不挪给另一侧。

## 3. 主聊天内的定位与返回

1. 点击侧栏 Search 或使用已有快捷键，直接打开居中弹窗形式的卡片并聚焦输入框。弹窗带遮罩，点遮罩也能关闭，关闭后焦点回到 Search 按钮。侧栏会话列表始终显示，现有 `SidebarSearch` 包住列表、有关键词时替换列表的结构随之移除。沿用防抖、取消过期查询及 Esc 关闭；结果列表滚到底部时自动加载下一页，不再显示 “Show more results” 按钮。关键词变化后清空上一次查询的可选结果，避免按回车打开旧命中。卡片负责传递完整选中结果，消息 ID 一直保留到目标会话就绪。
   - **结果行。** 第一行是图标和标题（单行省略，关键词高亮），右侧是项目名和粗略的相对时间（Today、Yesterday、Past week、Past month，更早的显示月份，如 `Mar 2026`），时间取会话更新时间。有正文命中时第二行显示摘要，整体浅色，关键词用正文颜色加粗，不加底色。不按日期分段，不做类型标签、预览栏和数字快捷键。
   - **排序切换。** 有关键词时，输入框右侧显示文字按钮，文字表示当前顺序：`Newest` 是最新在前，`Oldest` 是最早在前。点击切换 `order` 并重新查询。弹窗打开期间改关键词保留当前顺序，重新打开时恢复为 `Newest`。最近会话不显示该按钮。
   - **相对时间。** 按本地日历日计算：当天是 Today，前一天是 Yesterday，7 天内是 Past week，30 天内是 Past month，更早显示月份和年份，如 `Mar 2026`。
   - **自动加载。** 列表底部放一个观察哨，它进入可见区域且有 `nextCursor` 时加载下一页。第一页撑不满列表时会继续补拉；按 ↓ 选到最后几行，选中行滚进可视区后同样触发。加载失败时在底部显示重试，不自动反复请求。
   - **键盘。** 焦点始终留在输入框。↑↓ 移动选中行并让它滚进可视区，回车打开。结果列表是 `role=listbox`，每行是 `role=option`，输入框用 `aria-activedescendant` 指向当前行。底部一行提示 `↑↓ Select`、`↵ Open`、`Esc Close`。
   - **样式。** 毛玻璃卡片，复用 `--bg-glass`、`--glass-blur` 及不支持模糊时的纯色回退。遮罩轻、圆角大、阴影柔和，不用胶囊样式的控件。宽度小于 640px 时贴顶、占满宽度，结果行高度不低于 44px。
2. 已加载的消息复用 [ConversationStream 定位](../../../../apps/ohbaby-web/src/ui/conversation/ConversationStream.tsx)。如果目标是折叠的过程说明，先展开所属过程，等消息行出现后再滚动。选中结果时先保存定位意图，等目标数据装入消息流再交付本次定位标记（`anchorToken`）。提前交付标记可能在 DOM 还没有目标行时错过定位。同一会话重新点同一结果也能再次定位。
3. 命中历史窗口外的消息时，在主聊天区用同一个消息流组件显示服务端返回的历史片段。消息、运行和输入均取自该片段。普通历史的[输入查询](../../../../packages/ohbaby-agent/src/runtime/prompt-scheduler/database-store.ts)会额外带上本会话正在排队或运行的输入；定点阅读只展示关联到片段消息或运行的输入，继续上翻时同样过滤。渲染时用片段的输入生成提示行；实时运行进度和待处理的补充指令只传给实时消息流。片段和它的向前游标只属于本次阅读，状态保存在会话页本地，不进 store；片段不向后翻页。片段请求和后续上翻请求返回时，先比对当前会话视图的 `version.sessionId`、`runtimeEpoch`、`viewGeneration` 和 `bindingGeneration`，与 `installSessionHistory` 的校验一致，不一致就丢弃。用户可以继续向上翻页，点“回到最新”切回正常会话并触发现有 `followToken` 滚动到最新消息。片段的末尾保留这个返回入口，方便读完附近的后文后继续工作。普通的最新消息仍由原同步流程接收。禁止把独立片段直接交给会合并实时消息的 [installSessionHistory](../../../../apps/ohbaby-web/src/store/store.ts)，以免两段历史被显示成连续对话。
4. 阅读旧片段时，新回复不抢滚动位置；点击“回到最新”或成功发送新消息后回到实时消息流。切走会话或再次选中结果时丢弃旧定位请求，沿用现有同步链路收到的历史失效事件、重新绑定和重新建立基线通知，撤销在途定位并退出失效片段。普通历史从未加载时，store 不一定发布 `historyStale`，独立片段需要直接接入同一失效处理。消息已不存在时保留已打开的会话并提示“这条消息已不可用”，网络错误可以重试。

前后端交互需要提供查询、加载、错误、无结果、选择、关闭、排序切换和“回到最新”这些行为。改动集中在会话查询、现有历史读链路、Web 搜索入口和主聊天定位。

## 4. 分工与开发顺序

在 `feat/session-search-card` 上分两笔提交。第一笔收录前端已完成的搜索卡片、侧栏入口、排序交互和设计文档。第二笔由 Codex 接入 SQLite 查询、SDK、服务端 HTTP 与 RPC 接口，以及 Web 主聊天的消息定位。联调使用编译后的 CLI 和独立测试数据库。
