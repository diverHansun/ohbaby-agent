# 会话搜索验收标准

以下是实施完成后要通过的场景。相关单测可以先运行（前端卡片的测试已从 `SidebarSearch` 换成 `SearchDialog`）：


## 查询与摘要

| 准备数据及操作 | 通过条件 |
|---|---|
| 标题或正文写“终端断开后自动重连”，分别搜 `终端重连`、`终端 重连` | 前者不命中，后者命中。原文确有“终端重连”时，两种写法都命中。 |
| 同一消息里“重连”和“终端”顺序颠倒、相隔 500 个字符；再把两词分到两条消息 | 同一消息能找到，摘要显示两处原文并分别高亮；不同消息不拼接。 |
| Goal 消息有内部原文和单独的展示文字；另加展示文字为空、旧消息没有展示字段两例 | 搜展示文字命中，摘要只有展示文字；空展示值不回退；旧消息按正文命中。 |
| 同一条助手消息含过程说明与工具调用，只有终端输出或思考里出现某关键词 | 说明可搜，原始输出和思考不命中。用户或助手在正文里引用相同报错时，正文可以命中。 |
| 失败回复安排重试，随后新尝试启动；另有一条同会话可见旧消息也命中 | 后继启动后，结果与摘要只指向可见消息；只有重试计划但后继尚未启动时，匹配与界面一致。撤销的消息和内部压缩摘要不命中。 |
| 多个会话同一更新时间，同一会话有多条命中。含标点的查询用 `%`、`_` 和反斜线 | 结果只按会话更新时间排序，不因标题命中提前；正文取最近可见命中，同一会话一行，静态数据翻页不重不漏。标点按字面匹配。 |
| 同一组数据分别用 `order=desc` 和 `order=asc` 搜索并翻到底；再拿 `desc` 的游标去请求 `asc`；传 `order=foo` | 两次结果互为倒序、各自不重不漏；方向与游标不一致时返回 `INVALID_CURSOR`；非法 `order` 返回参数错误。普通会话列表的翻页不受影响。 |
| 一个会话标题和正文都命中，另一个只有标题命中 | 前者返回 `messageId` 和正文摘要；后者两者都没有。返回值不含 `matchType`。 |
| 正文很长，关键词在中间；另测三个相隔很远的关键词 | 摘要里关键词前约 15 个字，总长（含省略号，按 Unicode 字符计）不超过 120 个；两词相隔很远时两段都在摘要里；放不下时按首次出现顺序保留，至少有第一个命中词。 |

## 定点历史读取

构造一个超过多页的主会话，把命中消息放在老页，并让相邻两条消息共享创建时间。用真实 daemon 完成选会话和 history 请求，核对以下行为。

1. 默认历史与 `before` 翻页仍可用。指定 `anchorMessageId` 时，一次历史请求返回含目标及邻近消息的有界窗口，目标恰好一次，按时间和 ID 稳定排序。测首条和末条。传 `limit=1` 时按 3 处理，返回目标及前后各一条；选一条有前文的消息，沿返回游标继续加载，紧邻的上一条必须出现。
2. 锚点请求的 `before` 能从返回窗口继续向前取相邻一页。组合传入 `before` 和 `anchorMessageId` 得到参数错误。
3. 传入属于另一会话、子代理范围、已撤销或已被重试替换的目标 ID，不报错，返回同版本的空历史页：消息、运行和输入都为空，`hasMore=false`。重试替换样例将后继放在请求窗口之外（如 `limit=3` 且后继离目标较远）。搜索后消息被撤销的情况也要覆盖。

## 主聊天交互

在真实 Web 界面从侧栏打开卡片，至少走一次跨项目旧消息定位。

| 操作 | 通过条件 |
|---|---|
| 点击 Search，再用现有快捷键打开；输入、清空、按 Esc，点遮罩 | 居中弹窗，侧栏列表不被替换。打开时可直接输入，清空显示最近 10 个会话，Esc 和点遮罩都能关闭，关闭后焦点回到 Search 按钮。快速改词不显示上次请求的结果为本次结果。 |
| 输入关键词后按 ↑↓ 并继续打字；滚到结果底部；点 `Newest`/`Oldest`；改词；关闭再打开 | 焦点一直在输入框，`aria-activedescendant` 指向选中行，选中行始终在可视区内；列表是 listbox，行是 option。滚到底部或第一页撑不满时自动加载下一页，加载失败显示重试。切换后结果按新方向重新排列，选中状态清空；改词保留顺序，重新打开恢复为 `Newest`。 |
| 查看结果行，准备更新于今天、昨天、5 天前、20 天前和两个月前的会话 | 第一行是标题、项目名和相对时间；只有正文命中的结果才有第二行摘要。标题和摘要里的关键词都高亮，英文大小写不同也能高亮。时间依次显示 Today、Yesterday、Past week、Past month 和月份年份。 |
| 分别选择最近会话、只有标题命中的结果、已加载的正文命中 | 前两者打开到最新；后者定位到那行消息，避免多发定点历史请求。标题和正文都命中的结果也跳到那条消息。键盘选择与鼠标点击一致。在同一会话滚走后再次选择同一结果，仍能重新定位。 |
| 窗口宽度小于 640px 时打开弹窗 | 弹窗贴顶占满宽度，结果行高度不低于 44px。 |
| 跨项目点击很早的一条正文摘要，目标是折叠过程里的助手说明 | 打开正确会话，实际能读到原话。展开所需的过程，原话出现在视口内，查看网络请求可确认只发了一次带 `anchorMessageId` 和 `limit=50` 的 history 请求，没有从最新一页逐页倒翻。 |
| 在旧消息位置向上阅读，同时有新回复抵达；然后点“回到最新” | 继续翻到相邻的更早内容，实时回复不会把阅读位置拉走；当前排队的无关输入不出现在旧片段中。返回后能看到最新消息，正常历史游标可继续使用。旧片段与最新片段之间没有伪造的连续内容。 |
| 定位期间改选另一条结果、切换会话，或目标恰被撤销 | 较早的请求不覆盖新选择；失效目标给出消息不可用提示；网络故障与目标消失能区分。还要覆盖已打开旧片段但未加载过普通历史页时发生撤销，以及片段应答返回前会话已重新绑定（应答被丢弃）。 |

在长历史样本上另记会话数、消息数，以及常用词、多词、无结果和翻页的耗时。本轮文档不预设未经实测的耗时门槛。

## 2026-11-26 实测记录

在独立 SQLite 数据库里准备了 44 个会话，每个 240 条消息，共 10,560 条。两个项目各有一条旧消息，展示文字里的“终端”和“重连”相隔约 500 个字。用本地编译的 CLI 启动服务，在 Codex 内置浏览器操作。

- 搜 `终端重连` 显示无结果，搜 `终端 重连` 和 `重连 终端` 都能找到两个会话。切到 Oldest 后两者位置互换。
- 窄屏下从结果打开另一个项目，页面滚到了目标原话。点 Back to latest 后重新看到“最新消息：本轮检查已结束。”桌面宽度下用 ⌘K 打开卡片，选中折叠过程里的助手说明，过程自动展开，目标出现在视口内。
- Pi 审查发现了两处阅读位置问题。修复后，选中已加载的消息再发送新消息，界面会立即跟随发送；在旧片段向上翻页遇到网络错误，关闭提示后仍能继续读同一段。两项均已补回归测试，Pi 复核通过。
- 对同一数据库直接调用搜索服务，每页 10 条，每种输入测 6 次。常用词“运行”首页 20–25 毫秒，两词查询 20–21 毫秒，连续词无结果 13–14 毫秒，仅存在于内部原文的词无结果 11–12 毫秒。末次测量中，“运行”和“检查记录”的下一页分别用时 20 和 24 毫秒。耗时仅包含本机查询和摘要生成。
