# 00 目标与职责

## 1. 产品目标

在终端里用 ohbaby 的人，能看到这个会话的 agent 起了哪些后台任务、各跑了多久、输出到了哪里；看到跑飞或不再需要的任务，可以自己取消，不用退出 TUI 或去求模型。

和 Web 一样，这是“看一眼、必要时叫停”的面板，不是任务管理器。终端里的额外要求：

- 不和已有快捷键打架，不让新用户背新键（入口只有 `/bg`）。
- 单个字母键的危险操作要多一步确认。
- 窄终端、长输出行不能把界面撑乱。

## 2. 用户角色

使用阶段：

| 使用阶段 | 说明 |
|---|---|
| 旁观者 | 让 agent 干活，偶尔想知道它起的服务还在不在、输出了什么 |
| 排查者 | 任务失败或卡住，打开详情看输出尾部和退出码，决定要不要取消 |

权限身份：单一身份。是否能取消由后端 `canStop` 决定，前端只多一条展示规则：只给运行中的任务提供取消（Web D10）。

## 3. 核心任务

- T-01 查看当前会话的后台任务：哪些在跑、哪些已结束、各跑了多久
- T-02 查看单个任务的命令和输出尾部
- T-03 取消一个运行中的任务
- T-04 知道当前有几个后台任务在跑（对话区顶部的提示行）

Web 的 T-04（从工具卡跳到任务）在终端里不做，终端没有可点击的入口，见 Non-goals。

## 4. 职责边界

前端负责：

- 处理 `/bg`，打开、关闭整屏面板
- 有任务在跑时，在对话区顶部的提示行显示运行数
- 把后端的状态、停止原因、清理事实翻译成很少的几种表达（文案和 Web 共用，T10）
- 详情页打开且任务在跑时，定期拉输出尾部
- 取消的二次确认、取消中的表达
- 在对话里隐藏 `background-task-result`；给启动了后台任务的 bash 标签加 `· background`

前端不负责：

- 判断能不能取消、任务是否真的停了（以后端 `canStop`、`status`、`cleanup` 为准）
- 通知模型任务结束（后端投递）
- 任务额度、回收、崩溃恢复（后端 improve-1～3）
- 读取完整日志文件（本轮只用尾部）

## 5. Non-goals

本期不提供：

- 快捷键入口（T4）
- 从对话里的 bash 卡片跳到任务详情
- 暂停、继续、重新运行、一次取消全部

“放弃追踪”原本也在这里。[Windows 兼容 improve-1 · D14](../../shell/2026-11-15-windows-compatibility/improve-1/00-discussion.md) 改为提供：只对原后端已退出、清理未确认的任务，按 `u` 并在 5 秒内按 `y` 确认，见 04 §1.3。
- 按启动时间筛选、按单个子代理筛选、搜索输出
- 未读标记、清空已结束任务（pi-background-tasks 有，后端没有删除接口）
- 页脚第三行或徽标（T5 已用现有提示行承载）
- 手动把前台命令转后台
- 颜色以外的主题定制；NO_COLOR 下靠文字区分状态，不另做一套样式
