# 04 交互与状态

结构以 [03 §4](03-ui-layout-and-style.md#4-线框) 为准，文案以 03 §6 和 Web 03 §5 为准。

## 1. 键位与组件状态

### 1.1 键位表

面板打开时独占键盘，输入框隐藏，主屏的 `Ctrl+O`、`Ctrl+T`、`Shift+Tab`、`Ctrl+G`、`Ctrl+C` 都不生效：`app.tsx` 的全局按键处理在面板打开时提前返回，位置和 Side chat 同级（子代理浏览器现在就是这样，`Ctrl+C` 在它打开时也不生效）。唯一例外是 `/compact` 进行中的 `Esc` 中止，它在所有判断之前，沿用不改。Ink 没有阻止按键传播的机制，面板自己的 `useInput` 和全局处理都会收到按键，所以全局那边必须靠这个提前返回让路。

| 键 | 列表 | 详情 | 确认取消中 |
|---|---|---|---|
| `↑` / `↓` | 移动选择；到底部且有下一页时自动加载 | 滚动一行；往上滚即冻结，用 `↓` 滚到底即恢复跟随 | 退出确认，不移动 |
| `PgUp` / `PgDn`（带不带 `Shift` 都接受） | 翻一屏 | 滚一屏；用 `PgDn` 滚到底即恢复跟随 | 退出确认 |
| `Enter` | 打开详情 | — | 退出确认 |
| `End` / `Shift+End` | 跳到最后一行 | 回到底部并恢复跟随 | 退出确认 |
| `c` | 选中运行中且可取消的任务时进入确认 | 同左 | 退出确认 |
| `y` | — | — | 发出取消请求 |
| `f` | 子代理有任务时切换筛选 | — | 退出确认 |
| `r` | 有错误时重试加载 | 有错误时重试输出 | 退出确认 |
| `Esc` | 关闭面板 | 回到列表 | 退出确认 |

规则：

- 确认状态下，除 `y` 外的任何键都只退出确认，不再触发它本来的功能（避免一次误按做两件事）。
- 取消失败的说明在下一次按键时清除（这次按键照常生效）。加载类错误（列表、下一页、输出）一直保留，直到重试成功，`r retry` 不会因为按了别的键而消失。
- 不带 `Shift` 的 `End`、`PgUp`、`PgDn` 有的终端会留给自己的回滚（例如 macOS Terminal.app 默认设置），收不到时仍可用方向键滚到底恢复跟随；实施时在常用终端里实测并记录。
- 不用 `k`、`q`、`x` 等别名键，键位表就是全部。

### 1.2 列表行

| 状态 | 表现 |
|---|---|
| 普通 | 行首两个空格；说明默认色，命令和时长灰色 |
| 选中 | 行首 `›`，整行强调色 |
| 运行中 | 时长每秒更新 |
| 取消中 | 时长位置显示 `Cancelling…`，灰色 |
| 失败 / 超时 | 时长位置显示 `Failed` / `Timed out`，error 色 |
| lost | 时长位置显示 `Unknown`，灰色 |

### 1.3 键位行（面板底部）

为了和主屏“对话区顶部提示行”区分，面板底部这一行叫“键位行”。

只列当前能用的键：选中的任务不在运行、不能取消或正在 `Cancelling…` 时不列 `c cancel`；选中的任务清理未确认且原后端已退出时才列 `u stop tracking`（Windows D14）；子代理没有任务不列 `f filter`；跟随中不列 `End follow`；有加载错误时才列 `r retry`。确认取消时整行换成确认文案（warning 色），5 秒后自动恢复。

### 1.4 输出区

| 状态 | 表现 |
|---|---|
| 跟随 | 新输出到达时显示最后一屏 |
| 冻结 | 用户往上滚以后，新输出到达也不改变显示位置；键位行出现 `End follow` |
| 运行中无输出 | 空白 |
| 结束无输出 | `No output.` |
| 没有保存尾部（仅结束后） | `No output was saved for this task.` |

### 1.5 动效

终端里不做动效。时长每秒刷新一次；Ink 本身的重绘不额外处理。

## 2. 页面级状态矩阵

### 2.1 `/bg` 命令

| 状态 | 表现 |
|---|---|
| 没有打开的会话 | 对话区出一条 info 级本地通知（`emitLocalNotice`，和 `/rewind` 等本地命令相同），命令返回 completed；不打开面板 |
| 确认会话没有后台任务 | 同上，文案不同 |
| 探测还没回来 | 打开面板，列表显示加载状态（列表为空时由列表自己说明） |
| 有后台任务 | 打开面板 |

面板打开时输入框是隐藏的，不会出现“面板已打开又输入 `/bg`”的情况。

### 2.2 列表

| 状态 | 表现 | 操作 |
|---|---|---|
| 首次加载 ≤300ms | 只有标题行 | 等待 |
| 首次加载 >300ms | `Loading…` | 等待、Esc |
| 有任务 | Running + Done 两组；第一行选中 | 全部键位 |
| 筛选后为空 | 一行空态文案（Web 03 §5.4）；组标题不显示 | `f`、Esc |
| 首次加载失败 | 一行原因 · `r retry` | `r`、Esc |
| 刷新失败（已有数据） | 保留旧列表，顶部一行原因 · `r retry` | 照常 |
| 后台刷新中 | 保留旧列表，不显示加载状态 | 照常 |
| 加载下一页 >300ms | 列表末尾 `Loading…` | 照常 |
| 加载下一页失败 | 列表末尾一行原因 · `r retry`，不再自动重试 | `r` |
| 取消失败 | 顶部一行原因，下次按键清除 | 再按 `c` |
| 选中的任务从列表消失 | 选中下一行；没有下一行选上一行 | — |
| 审批等待中 | 顶部一行 `Approval pending · Close this panel to review` | 照常 |
| 当前会话变化 | 立即关闭面板，丢弃确认和取消中状态（照 `app.tsx` 里会话变化时关闭子代理浏览器的做法） | — |
| 终端太小 | 03 §4.5 | Esc |

排序副作用和 Web 04 §2.2 相同：刚结束、还没收尾的任务会先出现在 Done 组顶部，几秒后移到按时间排的位置。

### 2.3 详情

| 状态 | 表现 | 操作 |
|---|---|---|
| 进入时行数据已有 | 头部立即显示；输出等第一次返回 | 全部键位 |
| 运行中 | 状态行走秒；输出每 2 秒刷新、跟随；头部过高时命令只显示前 3 行，末尾 `…` | `c`、滚动、Esc |
| 已结束 | 状态行显示结束状态；输出只拉一次 | 滚动、Esc |
| 取消中 | 状态行右侧 `Cancelling…`；输出照常刷新 | 滚动、Esc |
| 任务不存在 | `This task is no longer available.` | Esc |
| 输出拉取失败 | 头部下一行原因 · `r retry`；轮询暂停 | `r`、Esc |
| 由别的后端管理（仅运行中） | 没有 `c`；说明行 | 滚动、Esc |
| 清理未确认 / lost / 停止原因 | 对应说明行（Web 03 §5.3）；原后端已退出的清理未确认任务可按 `u`，确认行为 `Stop tracking <标题>? y confirm · any key back` | 滚动、Esc、`u` |
| 输出超过 32KiB / 日志被截断 | 03 §4.3 | 滚动、Esc |

### 2.4 主屏

| 元素 | 状态 | 表现 |
|---|---|---|
| 提示行 | 有任务在跑 | 末尾 `/bg background · N running` |
| 提示行 | 有待审批 | 现有逻辑下整行不渲染，运行数也随之不显示；审批处理完恢复 |
| 提示行 | 没有任务在跑 | 没有这一段 |
| 提示行 | 面板打开 | 整个主屏被面板替换，提示行不显示 |
| bash 标签 | 结果里 `mode` 为 `background` 且有 `jobId` | 末尾灰字 `· background` |
| bash 标签 | 前台或旧记录 | 不变 |
| 对话 | `background-task-result` 消息 | 不显示 |
| 对话 | 被唤醒的那一轮 | 照常显示，结尾 `Background task update` |
| 翻历史 | 往上翻 | 分隔线不变，没有文字（T11） |

## 3. 交互规则

- **打开和关闭**：`/bg` 打开；列表里 `Esc` 关闭，回到对话，草稿和光标位置不变（输入框只是隐藏，不卸载）。当前会话一变就自动关闭。
- **焦点**：面板打开时独占键盘；关闭后焦点回到输入框。
- **取消**：两步（`c` → `y`），5 秒超时；不弹独立对话框，确认放在键位行。
- **防重复**：`Cancelling…` 期间 `c` 无效。
- **成功反馈**：不提示；行移到 Done 就是反馈。
- **错误反馈**：留在面板内，下次按键清除；不用对话区的错误横幅。
- **加载**：300ms 内不显示加载状态。
- **复制**：终端里没有复制按钮。命令完整显示在详情头部，日志路径显示为 `Log: <path>`，用户用终端自己的选择复制。
- **无障碍**：状态都有文字；键位提示始终可见；不依赖鼠标。
