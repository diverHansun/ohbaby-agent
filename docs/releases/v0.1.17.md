# ohbaby v0.1.17 — A New Web UI, Per-Chat Models & Subagent Controls

ohbaby v0.1.17 brings a redesigned web interface, per-chat model selection, persistent subagent controls, and a standalone LLM client package. The terminal and browser interfaces share the same runtime and ship together in `ohbaby-cli`.

## Highlights

- **A redesigned web UI:** a session-centered sidebar, workspace groups, searchable chats, a cleaner composer and slash-command palette, improved mobile controls, and the updated Lychee identity.
- **Chats across workspaces:** start a chat without opening a folder, move chats between workspaces, pin them, and find all visible active chats in Recents. Archive idle chats and manage archived conversations in Settings.
- **Per-chat models:** select a model for the current chat or change the default for new chats. Each run captures its model configuration, keeping an in-flight request stable when settings change. The TUI exposes these choices through `/models`.
- **Global settings:** manage model profiles, reasoning settings and web search credentials; inspect MCP servers, skills and runtime information from the web UI.
- **Subagent controls:** new delegated executions run in the background. Open their conversations in the right panel, inspect instance history and control individual instances. Session-owned supervision improves cleanup, result delivery and recovery.
- **Clearer approvals and streaming:** shell approvals show the raw command, query commands preserve your reading position, and the chat follows actual sends without forcing you away from earlier messages.
- **More reliable model connections:** consistent retries for SDK connection failures, credential isolation from host SDK environment variables, and idle-watchdog handling for silent streams.

## New package: `ohbaby-llm`

`ohbaby-llm` is now available as an independent public package for OpenAI-compatible Chat Completions, OpenAI Responses and Anthropic Messages. It provides provider-neutral streaming clients, configuration types and validation helpers without depending on another ohbaby workspace package.

Use `createLLMClientFromConfig` with resolved, validated configuration and consume responses through `streamResponse`. Configuration file loading, environment handling, proxy setup, tools and session persistence remain the responsibility of the host application. Existing `ohbaby-agent` client exports remain available.

## Upgrade notes

**Node.js 24 or later is required. Before upgrading, exit all ohbaby processes, including the daemon, TUI, `serve` instances and SDK hosts.** Stop the local daemon with `ohbaby serve stop`.

```bash
npm install -g ohbaby-cli@0.1.17
ohbaby --version
```

Run `ohbaby` for the terminal UI or `ohbaby serve` for the browser UI. Keep the daemon, web UI and remote TUI on the same version, and refresh open browser pages after upgrading.

### Workspace API changes

This release includes breaking changes for SDK and runtime consumers within the 0.x series. A session's owning folder is now its **workspace**; its execution directory is its **working directory**. Git repository identity remains a project.

| Previous API | Replacement |
| --- | --- |
| `projectDirectory` | `workspaceDirectory` |
| `projectRoot`, `pendingProjectRoot` | `workingDirectory`, `pendingWorkingDirectory` |
| `listByProjectRoot`, `recordExecutionRoot` | `listByWorkingDirectory`, `recordWorkingDirectory` |
| `SessionProjectMove*`, `SessionProjectBinding` | `SessionWorkspaceMove*`, `SessionWorkspaceBinding` |
| `defaultWorkspace` in scopes/about responses | `defaultDirectory` |
| `POST /v1/sessions/:sessionId/project` with `{ projectDirectory }` | `POST /v1/sessions/:sessionId/workspace` with `{ workspaceDirectory }` |

Old field names and export aliases are not retained. The old move endpoint returns 404; the new endpoint rejects a body containing only the old field with 400. Set `workspaceDirectory` to `null` to move a chat out of a workspace. Request header values remain `x-ohbaby-directory` and `x-ohbaby-directory-encoding`; session export files remain version 1 and retain their `session.projectRoot` field.

See the [complete API rename table](https://github.com/diverHansun/ohbaby-agent/blob/v0.1.17/docs/releases/v0.1.17-migration.md) for related helper and type replacements.

### Data and configuration migration

Migration 026 renames the database columns to `workspace_directory`, `working_directory` and `pending_working_directory`. Before migration, ohbaby saves a backup next to the database as `<database-path>.before-retained-<uuid>.backup`. Another live daemon blocks the upgrade, but idle old TUI processes cannot all be detected; close them explicitly.

**The upgraded database cannot be used directly by an older release.** To roll back, stop all processes and restore the pre-upgrade database backup before starting the old version. Data created after that backup will not be present in the restored database. The default directory stays at `<OHBABY_HOME>/workspace/default`; user files are not moved.

Legacy model configuration is migrated to independent model entries when saved, with the original `model.json` backed up under `~/.ohbaby/backups/`.

## Packages

All five public packages use version **0.1.17**: `ohbaby-sdk`, `ohbaby-llm`, `ohbaby-agent`, `ohbaby-server` and `ohbaby-cli`. Most users only need to install `ohbaby-cli`. Their npm documentation now uses the current Lychee logo and repository links; the CLI package documentation includes the new web UI overview and screenshot.
