## 2. Critical Scenarios

### 第一期

权限场景以 `Level = "default"`、没有预先放行操作的会话规则为基线；这是权限档位，不是 `plan`/`auto` 运行模式。模型发起的改写需要验证实际审批流程，不能只检查可信路径的类型。

| ID | 场景 | 验证点 |
|---|---|---|
| S1 | 路径与校验 | `OHBABY_HOME` 设为临时目录时，路径为 `<home>/sessions/<id>`；含 `/`、`..`、空串、超长的 ID 抛错 |
| S2 | 初始化建目录 | 会话运行初始化时，在首轮模型请求和工具使用前完成 `sessions/<id>/scratch` 创建及可信路径登记，`tool-results/` 还没有；在 POSIX 系统上权限为 0700；从没运行过的会话没有目录 |
| S3 | scratch 可读写 | 在 `default` 权限档位下，本会话对 `scratch/` 的写文件、编辑、读文件和简单 Bash（`echo x > <scratch>/a.txt`）不因该目录弹审批；现有任务、角色及其他权限限制保持不变 |
| S3b | 系统文件默认只读 | 分别预置 `subagents/x/y.output` 和 `tool-results/x.txt`：`read`、`grep` 读取不弹审批；模型用 `write`、`edit` 改写时弹审批，批准前及拒绝、取消后文件不变，批准后执行改写。Bash 对这些系统文件执行 `echo x >` 或 `cat` 仍弹外部路径审批 |
| S3c | 系统文件优先于上级目录自动放行 | 分别以临时 home、`OHBABY_HOME` 作为 cwd，并设置覆盖会话目录的普通可写可信根：系统文件的 `write`、`edit` 和 Bash 目录访问仍需审批；scratch 仍可读写。通过 scratch 内的符号链接指向系统文件时，按真实目标执行同样判断 |
| S3d | 读取授权不扩大为写入 | 走真实 PermissionManager 流程，对外部目录读取选择“始终允许”：后续读取免确认，但 `write`、`edit` 与 Bash 的目录访问仍需各自授权。分别验证可信路径登记与已保存会话规则，覆盖作用域重建后仍保留规则的情形。对当前系统目录的上级目录授予读取许可，也不能绕过 S3c。明确批准写入后仅按该写入规则范围放行；拒绝、取消不修改文件 |
| S4 | 会话隔离 | 根会话 A 读写根会话 B 的存储区时，按外部路径走权限确认 |
| S5 | 子代理共享 | 主代理和两个子代理拿到相同的根会话 scratch 路径，运行时不强制创建各自的 scratch 子目录；可写角色使用不同任务文件名写入后，根会话和另一子代理能免确认读取。`explore` 的只读要求仍保留 |
| S6 | 环境提醒 | 第一轮请求中的 scratch 路径已经完成目录与权限准备；子代理拿到根会话路径；准备失败或归属 ID 不合法时不提供可用路径，明确说明不可用，cwd、平台、日期保留；先成功后重建失败时，提醒更新，不继续沿用旧的可用提示 |
| S6b | 运行目录不变 | 登记会话存储区后，Bash 的默认 cwd、文件工具的相对路径解析仍指向原运行目录；显式使用 scratch 绝对路径时文件写进会话目录。没有选择 workspace 时仍沿用原默认目录规则 |
| S6c | 主子代理提示词覆盖 | 检查主代理及 `generic`、`explore`、`research` 的实际请求：基础提示词含固定规则，环境提醒含对应 scratch 绝对路径，基础提示词不含会话路径。保留项目文件例外、按需保存、路径缺失时的处理及 `explore` 只读约束；旧的无条件写报告句子不再出现 |
| S7 | 上下文重建 | 换运行目录、daemon 重启后，同一会话再次运行仍能免确认读写原来的 scratch、读取系统文件，改写系统文件仍需对应授权；已有文件还在 |
| S8 | 永久删除 | 在三个子目录中预置文件，永久删除带子代理的根会话后，其存储区及文件均被清理；另一个根会话的文件和用户 workspace 文件保持不变；删除目录失败不影响数据库删除 |
| S9 | 保留文件 | 一轮任务结束、子代理结束或关闭、会话归档及恢复、移动 workspace 后，目录和已有文件都保留，路径不变；撤销重发议题已落地时，撤销后文件也还在；fork 议题已落地时，新会话有自己的目录，不复制源会话文件 |
| S10 | 目录准备失败 | 模拟 `sessions/` 创建失败：日志记录错误，不登记会话可信路径，提醒明确说明 scratch 不可用；会话可继续，但不能把未准备好的路径当作可用路径提供，也不默认回退到 workspace 写临时文件 |

side chat 的归属（用主会话的目录、关闭时不删除）在 side chat 议题实施时验证，见该议题 04。

规划复查与实施评审还应确认没有新增按文件年龄、会话闲置时长或任务结束触发的自动清理逻辑；不为此新增定时器或专门的时钟测试。

### 第二期

| ID | 场景 | 验证点 |
|---|---|---|
| S11 | 工具存盘 | `list`、`glob`、`web` 的输出超过阈值：返回给模型的结果末尾有文件路径，文件里是完整输出；模型能用 `read` 免确认读取；两次调用的 `callId` 相同时写成两个文件 |
| S12 | Bash 存盘 | 输出 1 MB 的命令：结果被截断并附路径，`.log` 文件里有完整输出；超过 10 MB 时文件截在上限并注明，返回模型的说明也明确只是部分输出；后台任务未超上限且存盘成功时，结束后文件包含完整日志 |
| S13 | 存盘失败如实返回 | 模拟写入失败：保留现有截断内容，明确说明完整输出未能保存，不返回保存成功路径。Bash 命令执行状态与日志保存状态分开报告；部分写入失败不声称保存了完整日志 |
| S14 | 列文件 | `GET /files` 只列 `scratch/` 下的文件，不列 `tool-results/` |
| S15 | 读文件越界 | `path` 为 `../x`、绝对路径、指向外部的符号链接时返回 `INVALID_PATH`；超过上限返回 `FILE_TOO_LARGE`；既不是文本也不是图片返回 `UNSUPPORTED_FILE_TYPE` |
| S16 | 鉴权 | 未绑定该会话的客户端访问文件路由被拒绝 |
| S17 | Files 页 | 右侧面板能列出文件，点开文本和图片能预览，其他类型只显示名字和大小 |
