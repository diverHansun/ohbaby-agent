## 背景

现在 agent 想写一个临时文件、一份调研报告或者一个中间结果时，只能写进运行目录。有工作区的会话会因此弄脏用户的仓库；没选工作区的会话全部挤在共用的 `~/.ohbaby/workspace/default` 里，不同会话的文件混在一起，看不出是谁写的，也没人清理。超长的工具输出则直接被截断丢掉，模型想回头细看也找不到。

参考项目都给每个会话分了目录：kimi-code 是 `~/.kimi-code/sessions/<ws>/<sid>/`，ZCode 是 `~/.zcode/cli/artifacts/<sid>/`，claude-code 有每个会话的 `tool-results/` 和 scratchpad。没有一家把这类文件写进用户的项目。

## Design Goals

1. **每个会话的文件有一个固定、可预期的家。** 用户和 agent 都能说清楚“这个会话写的东西在哪”，不同会话互不混杂。
2. **不打扰用户的项目。** agent 的临时文件、报告和中间产物默认写进会话 `scratch/`。正常代码修改和用户指定的项目文档仍写在项目要求的位置；不改变 cwd，也不重定向工具的相对路径。
3. **agent 用起来顺手，系统文件默认不允许直接改写。** 在默认 `default` 权限档位下，读写本会话的 `scratch/` 不额外触发目录审批；用 `read`、`grep` 读取系统文件不弹审批，模型改写它们需要弹审批，获准后才能执行。对别的会话的存储区没有额外权限。
4. **跟着会话走。** 会话在，文件在；会话被永久删除，文件一起删掉；会话在工作区之间移动，文件位置不变。
5. **简单。** 一个归属会话一个目录，路径由会话 ID 直接算出，不需要数据库记录，不需要索引。

## Duties

1. **定路径**：先确定一个会话的存储区属于谁（子代理归根会话，side chat 归主会话，其余归自己），再由这个 ID 算出绝对路径，拒绝不合法的 ID（防止路径穿越）。
2. **建目录**：会话第一次运行时创建存储区，在支持的系统上权限只给当前用户（0700）。
3. **授权**：给本会话的工具调用登记两档可信路径：`scratch/` 可读写，整个存储区默认只读。在 `default` 权限档位下，模型对系统文件的写入和 Bash 访问按外部路径弹审批；系统自身导出报告、保存工具输出不走模型写入审批。
   第一期同时修正两处现有行为：系统文件不能因位于 workspace 或上级可信目录内就被自动放行；用户批准读取不能顺带授予写入或 Bash 目录访问权限。继续使用现有审批、会话规则与可信路径，不新增权限框架。
4. **告诉模型**：固定的文件落点规则分别写进主、子代理基础提示词；环境提醒提供本会话 `scratch/` 的绝对路径。覆盖全部子代理角色，不改变其任务与权限限制；只读角色不能因为有 scratch 就开始写文件。需要保存时才建文件，不要求每次汇报都额外写一份报告。
5. **删除**：归属会话被永久删除时，删除它的存储区。side chat 关闭不删除（它用的是主会话的存储区）。
6. **（第二期）存放超长工具输出**：已经在截断输出的工具，把完整输出存进存储区，并在返回给模型的截断结果里附上文件路径。
7. **（第二期）给界面列文件、读文件**：按会话列出存储区里的文件、读取单个文件的内容，供 Web 右侧面板展示。

## Non-Duties

1. **不改变运行目录。** 会话仍在原来的工作区或默认目录里运行，存储区只是一个额外的可写目录。没选工作区的会话的默认目录规则不变。
2. **不管数据库和快照，也不管子代理结果怎么导出。** 数据库和快照留在平台数据目录。子代理结果导出到 `subagents/` 的逻辑归[子代理结果搬迁议题](../../problem-lists/2026-11-05-subagent-results-location/README.md)，本模块只提供目录和只读权限。
3. **fork 不复制。** fork 出来的会话有自己的存储区，不复制源会话的文件，也不授权读取源会话的存储区；历史里提到的源会话文件，读取时按外部路径走权限确认。side chat 用主会话的存储区，它写的文件在关闭 side chat 后仍留在主会话那里。
4. **不做按时间的自动清理。** 文件只随会话的永久删除而删除。归档的会话保留文件。
5. **不做上传与附件。** 用户上传文件、粘贴长文本转文件等功能，以后需要时再设计。
6. **不统一所有工具的输出存盘。** MCP 工具的输出不在本模块范围内。
7. **不做文件版本、回滚和配额。**

## 自检

- 一句话说明：每个归属会话（不是子代理、也不是 side chat 的根会话）在 `~/.ohbaby/sessions/<id>/` 有一个自己的目录，它和它的子代理、side chat 都能直接读写其中的 `scratch/`、直接读其余部分；会话删除时目录一起删除。
- 与 `paths` 模块的边界：`paths` 管 `OHBABY_HOME` 和数据目录在哪，本模块只在 `OHBABY_HOME` 下算出 `sessions/<id>`。
- 与 `sandbox` 模块的边界：`sandbox` 管可信路径怎么判断，本模块只把两个路径（存储区只读、`scratch/` 可写）交给它登记。
