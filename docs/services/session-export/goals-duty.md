# session-export 模块 goals-duty.md

本文档定义 `session-export` 模块的设计目标和职责边界。

接入 TUI、server、web 的改造方案见 [improve-1](./improve-1/02-optimization-plan-and-change-scope.md)。

---

## 一、模块定位

**一句话说明**：session-export 把一个会话里用户和 AI 的完整讨论导出成一个文件。HTML 给人看，JSONL 给程序读。

**如果没有这个模块**：
- 用户想留存一段讨论，只能自己复制粘贴，思考过程和工具调用基本带不出来。
- 会话数据只存在本地 SQLite 里，离开 ohbaby 就打不开，也没法发给别人看。
- 以后要做导入、统计或格式转换，没有一个稳定的结构化格式可以依赖。

**主要用途**：保存用户和 AI 的讨论记录。这一版不做调试包，也不做再导入。

---

## 二、Design Goals（设计目标）

### G1: 记录完整

用户在会话里看到过的内容都要导出来，包括思考过程和工具调用。compact 以后，原始消息在数据库里还留着（只是打了 `time.compacted` 标记），导出时也要带上并标注出来，不能因为 compact 丢内容。

### G2: 只导出对人有意义的内容

模型厂商的原始状态（加密的思考内容、签名、接口地址）和程序注入的隐藏上下文，用户从没见过，也看不懂，所以不导出。完整的意思是对话完整，不是把数据库原样搬出来。

### G3: 两种格式，一份数据

HTML 和 JSONL 从同一份中间数据渲染出来，两者的内容范围保持一致。以后加新格式，只需要再写一个渲染器。

### G4: 不碰文件系统，不关心调用方

模块只负责生成文件内容和建议的文件名，不写磁盘，也不判断调用方是 TUI 还是网页。保存到哪里由调用方决定。这样 TUI 写本地文件和网页让浏览器下载能用同一套逻辑，测试也不用 mock 文件系统。

### G5: 导出的 HTML 打开时是安全的

工具输出里可能夹着网页内容，比如 `<script>`、`<img onerror>`。用户打开导出的 HTML 时，这些内容不能被当成代码执行。

### G6: 格式可以演进

JSONL 第一行带格式名和版本号。以后要做导入或者改格式，能识别出文件是哪个版本导出的。

---

## 三、Duties（职责）

### D1: 收集会话数据

按 sessionId 读取主会话的元数据和主上下文里的全部消息（包括 compact 掉的），整理成统一的导出数据（ExportDocument）。

### D2: 过滤和标注

- 去掉 `model-state` part。
- 去掉程序注入的隐藏上下文，也就是 `synthetic` 的 model-context part。
- 给 compact 掉的 part 打上 `compacted` 标记。
- 给 compact 摘要打上摘要标记。
- 给没跑完的工具调用和回答标上它当前的状态。

### D3: 汇总统计

汇总消息数、用到的模型、token 总数，写进导出文件的头部。

### D4: 渲染 JSONL

第一行是会话头，后面每行一条消息。格式定义见 [data-model.md](./data-model.md)。

### D5: 渲染 HTML

生成一个单独的 HTML 文件，可以离线打开。实现参考 pi：数据嵌在页面里，页面内置渲染脚本，思考过程和工具调用可以折叠。所有来自会话的文本都按纯文本处理，不能被当成 HTML 执行。MCP 工具返回的位图（png、jpeg、gif、webp 格式的 data URI）要在页面里显示出来。

### D6: 生成建议文件名

文件名格式是 `ohbaby-<YYYYMMDD-HHmmss>-<会话 id 的随机段>.<html|jsonl>`，例如 `ohbaby-20261017-153012-k3x9ab1.html`。随机段指 id 里最后一个 `_` 之后的部分，用来区分不同的会话。

### D7: 明确报错

下面三种情况要给出能识别的错误：会话不存在、会话是子代理会话、会话里没有可导出的内容。

## 四、Non-Duties（非职责）

- **不写文件，不决定保存位置。** TUI 写到本机 Downloads，网页交给浏览器下载，都是调用方的事。Downloads 目录怎么解析（包括 Linux 的 `XDG_DOWNLOAD_DIR`）也由 TUI 负责。
- **不做再导入。** 只预留版本号，不提供导入能力。
- **不导出费用或估算价格。** HTML 和 JSONL 只保留 token 用量及其完整性说明，不添加金额、单价或费用汇总。会话正文和工具结果仍按原文保留。
- **不导出子代理的中间过程。** 主会话里的 `subagent_run` 工具调用和它的最终结果会照常导出，子会话里的完整对话不导出。
- **不自动识别或替换正文中的秘密。** 内部字段仍按白名单过滤；这与 OpenCode 的整段清理和 ZCode 的公开分享投影不同。导出操作时的前端提示由调用方负责；导出的 HTML 文件本身在页脚保留静态提醒，告知用户可能包含命令输出、文件内容等敏感信息，分享前应检查。
- **不导出 Markdown，也不打调试 ZIP。**
- **不做权限校验和会话归属判断。** 这些由 server 和 adapter 层负责，见 improve-1。
- **不限制导出大小，也不截断。** 这是本轮有意的取舍，不代表会话一定很小。MCP 输出、图片和长历史都可能让会话变大，所以验收时要实测大会话的耗时和内存，见 improve-1/04 §4.5。
- **不管网页端的置顶状态。** 它只存在浏览器 localStorage 里，后端不知道。

## 五、自检

- **能不能用一句话说清楚为什么需要这个模块？** 能：把一个会话完整地变成可以保存的 HTML 或 JSONL 文件。
- **这个模块不该做什么？** 写磁盘、权限校验、导入、脱敏、导出子代理过程。
- **和别的模块有没有重叠？** 和 `adapters/ui-state` 的 UI 投影有部分重叠，因为两边都要把 Message/Part 转成能展示的结构。但用途不同：UI 投影会隐藏 compact 掉的内容和 todo 工具，导出要保留它们。所以导出不复用 UI 投影，直接读 core 的 Message/Part，见 [architecture.md](./architecture.md)。
