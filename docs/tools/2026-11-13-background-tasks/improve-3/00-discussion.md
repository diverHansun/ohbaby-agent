## 3. 工程方案与确认状态

以下是根据上述决定和现有代码推导的工程默认值，不冒充用户逐字段确认：

- 保留 `job_id / block / wait_ms`，不为名称统一重命名持久 ID。等待默认不阻塞；显式阻塞默认 30 秒、最多 10 分钟，沿用现有工具。它与 Bash 默认 120 秒前台等待是两个参数。
- `list` 沿用 improve-1 的自身 ShellJob 列表契约，默认包含最近结束项，默认 20、最多 100；新增可选 status 筛选，使用同一六状态枚举。不混入子代理执行记录；精确筛选参数规则属于工程方案。
- 按动作验证字段、归属和权限。整个 `task` 不能声明为只读；未知动作不能默认进入读取分支。
- 新模型声明只暴露 `task`；旧 `task_output/task_kill` 历史继续可读，不把历史重放成新的停止操作。兼容策略见 [02](02-optimization-plan-and-change-scope.md)。
- 不新增 `status/monitor/wait/start/send/close` 动作，不新增数据库实体、队列或后台运行时。

这些选择可在实施时根据真实基线做等价调整；涉及产品行为变化则回来讨论，不能借“工程细节”改变归属或等待语义。
