## 已实现行为

- 默认开启自动转换，前台等待 120000ms；`wait_ms` 可调整本次等待，`auto_background=false` 可关闭本次转换，全局关闭不能被单次参数绕过。显式后台与自动转换参数冲突在启动前拒绝。
- 等待和硬截止独立。允许后台的命令未传 timeout 不隐式添加硬超时，显式上限 24 小时；纯前台保留默认 120 秒、上限 10 分钟。读输出等待仍独立限于 10 分钟。
- 启动时前台不占后台额；转换在原记录上申请额度，不重新 spawn，不改 ID、owner、启动时间或硬截止。写锁内复查取消、归属准入、进程退出和硬截止，COMMIT 后同步切换内存模式及调用清理归属，再发布变更。
- 满额只取消当前命令，原因 capacity-limit；转换写入失败取消当前命令，原因 internal-error，保留已有输出、具体错误和真实 cleanup。两种失败都不生成后台完成通知；无输出时不附加重复占位，也不把已启动的命令误报为启动失败。
- 主轮 Stop 在转换提交前取消命令，提交后保留后台进程；子代理本次执行结束仍回收所属任务。后台普通执行槽和调用锁释放，环境引用和未确认清理保护继续由 Registry 持有。
- 只有实际可使用同一个 Registry 的两个可信管理工具，角色才能显式或自动后台；否则工具描述明确纯前台，普通命令仍可运行，显式后台策略在启动前拒绝。
- 转换前维护的有界尾部在提交时首次保存，之后复用既有检查点。保存结果读取根据输出字节和尾部字节恢复截断标记，日志截断字段含义不变。

## 独立审查与代码工艺

核心审查和整分支审查均无剩余实证阻断；核心审查找到的 A11 保存后截断标记丢失已通过红绿回归及原独立探针复核。整分支审查与窄复核确认旧静态清理分支删除、测试契约迁移正确。

指定 `github-copilot/gemini-4-carbon high` 完成首轮审查，认可总体 KISS/SWE 结构并提出四项意见：等待提前唤醒及无输出文案已修复；前序持久化失败与提交后 Stop 的两项建议，经子代理和 Pi 重新核查调用链、原契约后撤回。启动登记与身份写入失败会在 start 内停止并抛错，不会进入正常转换；A08 要求提交后后台进程保留，不要求挽救已取消调用的历史回执，因此不添加吞错重试，也不扩大调度状态机。同一 Pi 会话完成最终复审：Spec PASS / Craft PASS，无剩余实证阻断；认为没有过度防御，旧分支删除和 improve-2 范围适当。完整原始回复已在本次对话呈现。

实现继续使用一个 Registry、一个进程硬计时器、既有有界等待和存储事务；只增加必要的同步提交接点，不建立通用生命周期框架。存储提交后仅做内存赋值和解绑，事件发布在其后。角色筛选复用已有规则，模型声明与执行使用同一能力判断。

安全删除：Bash 原按初始 run_in_background 固定的取消分支与单独 abort listener；无生产消费者的静态 detachedCleanup 字段及调度分支；无引用的旧默认超时常量。后台尾部展示直接使用已有统一 tail，避免另一份后台字符串采集。保留进程树清理、source-cleanup、环境 retain/release、持久写入链、现有 output/kill 和历史回滚读取。
