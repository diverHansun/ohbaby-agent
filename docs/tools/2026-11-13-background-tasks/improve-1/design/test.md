## Critical Scenarios

对应 04 的 T 编号。最关键的四类：

1. 前台超时与显式后台隔离：前台到时停止、不转换；同轮启动的显式后台在当前轮 Stop 后继续运行，单停时只停止目标任务。
2. 归属方回收：Stop 不杀后台任务；子代理结束、归档、回滚都按正确原因停掉，且只停该停的。
3. 通知消费与防抖：忙时注入、空闲唤醒、读取不抑制、失败重投；每个结果最多自动唤醒一次，不声称模型外部副作用 exactly-once。
4. 崩溃恢复不误杀：身份不匹配、核验失败、无能力平台时都不发信号。

## Integration Points

- `CurrentRunInputStore` 与生命周期 `beforeStep` / `beforeFinish`。
- 会话闸门、`prepareSession` 和带 `runtimeInput` 的提交入口。
- `startupReady` 的启动顺序。
- 归档流程 `archiveSessionInternal`、回滚流程 `rewindSessionInternal`。

## Verification Strategy

真实进程的用例只放在集成测试里，并用短命令（`sleep 0.2`、少量 `echo`）控制时长。需要“10 分钟”“24 小时”“1GB”的地方，用可注入的时钟和阈值，不真的等。崩溃恢复用两条记录模拟：一条 `owner_pid` 指向已退出的进程，一条指向当前进程。
