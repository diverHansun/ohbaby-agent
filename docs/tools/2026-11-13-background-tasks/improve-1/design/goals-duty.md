# 模块目标与职责

状态：待实施设计。产品规则以 [00 讨论记录](../00-discussion.md) 为准，现状见 [01](../01-problem-analysis-and-current-state.md)。

已纳入输出尾部持久化、实际请求消费、统一输入协调及保守恢复契约。当前仅完成后端规划，整体尚未实施；前端展示另行交付。

本设计里的“后台任务模块”指 shell 任务的登记、生命周期、回收和结束通知。它由现有的 `ShellJobRegistry` 演进而来，不是新建的独立服务。

## Design Goals

每个 shell 任务从启动到结束都有一份持久记录，任何时候都能回答三个问题：它现在怎样了；如果被停掉，是谁、为什么停的；进程树是否确实已经没了。

后台任务可以长时间运行，不被前台时限误杀；结束时主代理会收到一次通知，不需要轮询。任务的归属清楚：属于启动它的会话或子代理作用域，归属方结束时任务随之结束；服务正常退出时全部结束，服务崩溃后重启时把残留情况标记出来，在能够确认身份时清理残留进程。

可靠性的范围是本机共享 SQLite 与各任务所属的后端进程；多个后端只共享持久事实，不共享句柄、不提供控制转发。不承诺任务跨服务重启存活，不承诺通知被模型正确理解。

## Duties

| 职责 | 内容 |
| --- | --- |
| 登记与持久化 | 每次 `bash` 调用写一条任务记录，前台和后台都写；先提交启动占位，进程启动后补写身份，成功登记前不返回启动回执 |
| 状态与停止原因 | 维护 `status`、`stopReason`、进程事实、`cleanup` 四个维度，规则见 [data-model](data-model.md) |
| 时限 | 前台默认 2 分钟、上限 10 分钟，到时停止；显式后台默认不限，可选 timeout 上限 24 小时；本轮不转换模式 |
| 数量上限 | 主代理默认 10、每个子代理默认 5，按归属独立计数，可分别配置；运行及清理未确认任务占名额，超限拒绝启动 |
| 输出兜底 | 日志写满 10MB 截断不杀；累计输出达到 1GB 时以 `output-limit` 停止 |
| 停止与回收 | 执行 `task(stop)`、用户停止、超时、归属方结束、回滚、会话删除或归档、服务退出时的停止，并记录原因 |
| 崩溃恢复 | 后端启动时把原后端已退出的启动占位/running 记录改为 lost；核实原 owner 已退出、目标出生身份与进程组归属后才清理；未确认任务有按需复查和用户放弃追踪出口（D26/D29） |
| 结束通知 | 为需要通知的结局生成一条独立来源的运行时输入，忙时注入、空闲时唤醒；同一结果最多自动唤醒一次，未消费输入可重投 |
| 查询 | 主、子代理均可用 `task(list/output/stop)` 管理自己的任务；另提供面向 UI 的快照 |

## Non-Duties

- 不运行 LLM，不决定模型收到通知后怎么做。
- 不和子代理合并成同一种 Task，不改子代理的执行与投递规则。
- 不做任务跨服务重启存活，不托管给 tmux、launchd 等外部进程管理器。
- 不设所有会话合计的任务上限。
- 不提供增量输出游标，不提供实时日志流平台。
- 当前只交付查询、输出、单停等后端接口；Web/TUI 的面板和交互均暂缓，不宣称已交付界面。
- 不实现自动或用户手动转后台，转换议题留 improve-2。
- 不在崩溃恢复时重放命令或自动重启任务。
