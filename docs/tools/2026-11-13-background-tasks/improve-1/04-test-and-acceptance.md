# 测试与验收契约

本文是实施和验收契约，尚未执行这些测试。三个轮次联合实施时，本轮纯前台用例显式关闭自动转换，默认开启路径另按 improve-2 验收。迁移 031/032 是规划占位号，实际编号须按实施基线分配。测试层级和组织方式见 [design/test](design/test.md)。测试命名沿用仓库现有约定（`*.unit.test.ts`、`*.integration.test.ts`），按类型运行：`pnpm test:unit`、`pnpm test:integration`。路径相对于 `packages/ohbaby-agent/src`。

2026-11-13 用户最新指定当前代理只负责后端、前端暂缓。T26–T28 中的 API/持久状态/真实服务验证属于当前后端验收；前端交互、浏览器与 T32 保留为后续前端验收，不作为后端完成条件。后端通过时不得宣称完整 Web 体验已经交付。

常规自动化中需要“10 分钟”“24 小时”“1GB”的用例，用可注入的时钟和阈值，不真的等待；专门的真实长时验收见 §3。

## 1. 场景和判定

### Stage 1：持久记录与状态模型

| ID | 场景 | 类型 | 判定 |
| --- | --- | --- | --- |
| T01 | 在已有数据库上执行迁移 031；删除会话 | 集成 | 表和索引存在；清理确认后才删除记录和日志。清理未确认且用户未放弃追踪则保留会话与证据并返回明确错误 |
| T02 | 退出码 0、非 0、被外部信号杀掉、spawn 失败、各种停止 | 单元 | 分别得到 `completed`、`failed`、`failed`、`failed` + `error`、超时为 `timed_out + timeout`，其他受控停止为 `cancelled` + 对应原因；stopReason 只在这两类停止结局中有值（旧 cancelled 原因可未知）；两个停止请求先后到达时记先到的原因 |
| T03 | 前台和后台各调用一次 `bash`；模拟写库失败 | 集成 | 预登记提交失败不 spawn；提交后取消不 spawn 并结束占位；spawn 失败更新同一行 failed；身份补写失败停止进程，原占位仍占额，不保留整轮认领、不重复 spawn。崩溃遗留的无 PID 占位按 lost + unconfirmed 处理 |
| T04 | 复现 01 §1 的情况：输出全部重定向到文件的后台命令超时 | 集成 | `task(output)` 的状态行写明 `timed_out: timeout`、运行时长、`0 bytes captured` 和日志可用性；文件可用才给路径，读取故障不伪造零输出 |
| T05 | 输出超过 10MB；输出累计达到 1GB（阈值注入为小值） | 单元 | 10MB 时只截断，进程继续运行；达到阈值时 `cancelled` + `output-limit` |
| T06 | 旧会话里 `timed_out`、`cancelled` 的 tool part；没有 `shell_job` 记录的旧会话回滚；删除 `dispatch` 名额类别 | 单元 + 集成 | 保留 timed_out、cancelled 原值，后者缺失原因保持未知，Web、TUI 投影都不显示成未知状态；旧会话回滚走推断兜底并保持现有行为；调度器测试通过，代码中不再有 `dispatch` 名额类别 |

### Stage 2：时限与按归属方回收

| ID | 场景 | 类型 | 判定 |

| T10 | `sleep 999` 和其他前台命令到时；分别在后台名额有余量和已满时运行 | 单元 | 所有前台命令都按超时停止；不按命令首词特判，不转换模式，不受后台名额影响 |
| T11 | 主代理第 11 个、子代理第 6 个后台任务；主、子及兄弟额度隔离；同物理会话不同 scope；停止清理中；同/跨进程并行启动竞争；写锁等待期间取消；分别覆盖两项配置 | 集成 | 超额拒绝且不启动进程；主代理和各子代理互不占额；未确认清理不自动释放名额，确认消失或用户按 D29 明确放弃后才释放；并发检查不超发；配置分别生效，前台不占后台名额 |
| T12 | 本轮启动后台任务后按 Stop；上一轮启动的任务在新一轮被 Stop；轮次因模型错误失败 | 集成 | 这三种情况下后台任务都继续运行；本轮正在等待的前台任务被停止 |
| T13 | 子代理正常完成、失败、被用户/主代理停止；停止与新后台启动竞态 | 集成 | 关闭本次执行准入，所属任务按 `owner-ended` 停止（不覆盖先前原因）；主代理和兄弟任务不受影响；清理未确认仍可见并保留责任，不能因子代理逻辑结束而遗忘 |
| T14 | 归档会话；删除会话；回滚一轮 | 集成 | 归档和删除：目标集合通过后端归属检查后停止仍活跃的任务，记 cancelled + session-closed；已终态及用户已放弃项不覆盖原结局；回滚：只停被回滚轮次启动的任务，原因 `rewound` |
| T15 | 服务正常退出 | 集成 | 当前后端管理的任务按 cancelled + shutdown 结束，终态写库；不停止另一活跃后端的任务 |
| T16 | 启动恢复：所属进程已退出的 `running` 记录；所属进程是当前进程的记录；PID 出生身份不匹配；原生查询失败/权限拒绝/结构长度异常；组长已退出但组仍存在；不支持平台 | 集成 | 仅原启动占位/running 标 lost，原 owner 确认退出且目标原生身份与组归属核验通过才清理；同一活跃 owner 的记录不动；身份未知/不匹配/不支持不发信号，报告 unconfirmed。恢复也覆盖旧终态清理未确认及 settled_at 为空项，不改其原结局；macOS/Linux 正常匹配路径须真实回收，不能一律 unknown 冒充通过；两个后端同时恢复仅一方取得 CAS 信号权 |

## 3. 整体验收

1. `pnpm run preflight` 全部通过（格式、lint、类型、测试、构建）。
2. 用真实服务复现 01 §1 的会话：
   - 启动一个输出全部重定向到文件、`timeout` 为 60 秒的后台任务，然后结束这一轮。60 秒后，主代理被自动唤醒，收到的通知包含 `timed_out: timeout`、`0 bytes`、运行时长和日志路径；整个过程中模型没有用 sleep 轮询。
   - 启动一个后台任务，在下一轮中途按 Stop。后台任务继续运行。
   - 启动一个运行 3 分钟的前台命令。默认 2 分钟时按超时停止，不转后台、不产生后台结束通知。
   - 显式启动一个不传 timeout 的后台任务，确认超过原 10 分钟上限后仍在运行；在 Web 找到该任务并单独停止，确认模型收到用户停止原因，其他任务不受影响。常规自动化用注入时钟验证上限，真实长时运行只作为专门验收，不反复执行。
   - 后台任务运行时用 `kill -9` 结束服务进程，再启动服务。原 running 被标成 lost；身份核验通过时回收残留，核验失败则明确 unconfirmed 且不误杀；下次在这个会话里发消息时，主代理会收到 `lost` 通知。
3. 检查数据库：上述每个任务在 `shell_job` 中都有一行，状态和停止原因与实际相符。

## 4. 对抗性审查要点

| 攻击面 | 防御 | 残余风险 |
| --- | --- | --- |
| 当前轮中止误杀显式后台任务，或单停影响其他任务 | 取消路径按模式和归属过滤；T09、T12、T26 | 如果在 Registry 之外另有地方直接 kill，仍可能绕过过滤，审查时要搜索所有调用 `killTree` 的地方 |
| 崩溃恢复误杀别人的进程 | 原生出生身份与组归属核验，核实不了就不发信号；T16 | spawn 至 PID/出生身份补写窗口、脱离托管的进程及查验/信号间 OS 竞态不提供系统托管级保证；禁止秒级 ps 容差授权 |
