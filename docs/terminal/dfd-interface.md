# Terminal 数据流与接口

> 第三份模块设计文档。先说数据怎么流动，再给出接口；接口是数据流的表现形式。各部分名称沿用 [architecture](architecture.md)。

## 1. Context & Scope（上下文与范围）

```
用户 ──按键/点击──▶ 浏览器 Terminal 页 ──REST / WebSocket──▶ 终端路由 ──▶ 终端核心 ──▶ node-pty ──▶ shell
                       ▲                                                   │
                       └──────────────── 快照 / 输出 / 退出 ◀───────────────┘
```

- **输入**：用户的新建、接回、关闭操作；按键；面板尺寸变化。
- **输出**：屏幕快照、实时输出、shell 退出信息、错误。
- **不经过本模块的**：agent 的 shell 工具和审批链（N7、N9）、会话事件流（SSE）。

## 2. Data Flow Description（数据流描述）

### F1 打开终端 tab

1. 用户点右侧面板 `+` 菜单或入口页里的 Terminal，浏览器发起新建（F2）。等待期间保持原画面，不显示“正在创建”、转圈或占位 tab。
2. 新建成功后，面板打开并选中新 tab，状态为 `{ terminalId }`，标题为终端图标加目录名，随即接回（F3）。
3. 新建失败（达到上限、不可用）时不新增 tab，用全局 `NoticeStack` 在右上角提示原因。

### F1b 终端 tab 同步

1. 网页加载时、窗口重新获得焦点时，浏览器请求 `GET /v1/terminals`，拿到所有仍保留的终端，包括正在关闭和清理失败的记录。
2. 服务端有、面板里没有的终端，按创建时间补上 tab；按终端 id 去重；当前已打开的 tab、选中项和输入焦点保持不变，面板原来收起就继续收起。没有选中项时选第一个终端，但不展开面板。
3. 按记录状态决定能否接回：`running` 正常接回；`closing` 和 `close_failed` 保留标签但不建立终端连接。关闭失败时显示原因，可用原来的 `x` 重试；正在关闭的记录也可点 `x`，等待服务端已有的关闭任务。只在本页面关闭请求未返回时禁用重复点击，不因刷新得到 `closing` 就一直禁用按钮。
4. 面板里有、服务端已经没有的终端 tab，显示为“终端已结束”，由用户关闭；已经显示退出码的 tab（F7）保持原样，不改写。列表查询期间已经确认的新建和关闭结果不能被旧响应覆盖，借鉴 dsh 的 inventory 合并方式。

刷新网页后，Subagents 等 tab 按 D50 不再出现，终端 tab 则由这一步自动恢复。

### F2 新建终端

1. 浏览器发 `POST /v1/terminals`，带 token 和当前视图的行列数；打开了 workspace 时带上 `x-ohbaby-directory`，没有 workspace 时不带。
2. 终端路由依次检查：是否 loopback 模式、token 是否正确（沿用现有鉴权）；然后确定初始目录：带了 `x-ohbaby-directory` 时，用 `resolveWorkspaceScope` 校验并规范化，它会把子目录归到项目根目录，初始目录就是这个根目录；目录无效时按现有规则返回 400，不改用主目录。没带时，初始目录是 `os.homedir()`（D3）。
3. 终端管理器先检查是否正在停止，再计算“已登记终端 + 正在创建的任务”的总数，满 16 个返回 `TERMINAL_LIMIT_REACHED`。未满时立即登记创建任务、预留名额，然后才进入异步加载和创建；检查与预留之间不能等待异步操作。
4. PTY 适配第一次被用到时加载 node-pty；加载失败则记住原因，本次及以后的新建都返回 `TERMINAL_UNAVAILABLE`。
5. 启动配置算出 shell、参数、环境变量和初始目录（D3–D5），PTY 适配开出 shell。
6. 终端会话建好服务端屏幕（1000 行滚动历史），将创建任务转为正式登记，返回终端信息；这次转移不重复占名额。创建失败时，完成已分配资源的清理后释放名额；清理失败则保留可重试的清理记录及名额，沿用 F6 的清理机制。如果创建期间 serve 开始停止，刚开出的 shell 立即进入清理，停止流程等待创建和清理任务结束。

### F3 接回终端（打开 WebSocket）

1. 浏览器打开 `/v1/terminals/:id/attach`，子协议列表带上 `ohbaby.terminal.v1` 和 `ohbaby.bearer.<base64url(token)>`。
2. 握手前只做三项检查，不通过就直接拒绝升级：Host 头（F9）、loopback 模式、Origin（没有 Origin 时放行，有 Origin 时主机名必须是本机名）。这些检查失败时直接拒绝握手，不额外增加页面状态。
3. 握手完成后，服务端选中 `ohbaby.terminal.v1` 作为协商结果，不能回传含 token 的那一项。浏览器要求服务端必须选中它提供的某个子协议，否则连接失败；这一步由 `WebSocketServer` 的 `handleProtocols` 完成。
4. 接着检查 token 和终端是否存在：token 错误以 4401 关闭，终端不存在或已进入关闭流程时以 4404 关闭，这些情况都不发送任何终端数据。浏览器收到 4404 后同步一次列表：仍有记录则按 F1b 保留关闭入口，确实不存在才显示已结束；查询失败不能当作记录不存在。放在握手之后检查，是因为浏览器拿不到握手失败的 HTTP 状态码，只能看到 1006，无法区分“该重连”还是“别重连”。
5. 将“接回”操作放进该终端的执行队列，与输出和尺寸变化按入队顺序执行。前面的输出必须等 headless 写入回调完成，才轮到接回操作。
6. 执行接回时，先确认连接仍有效，再序列化屏幕及其当前尺寸，把 `snapshot` 放入这个连接的发送队列，随后登记为查看者。这几步在同一个队列任务内连续完成，不等待网络发送。后续输出排在快照后面，使用同一发送队列及 F5 的积压额度，不再使用空写入标记或额外的接回暂存队列。
7. 浏览器按消息顺序将快照恢复放入本地写入队列：重置 xterm、设为快照尺寸、写入快照，等待写入完成回调。此后才允许应用当前面板尺寸并发出 `resize`；恢复期间容器变化只更新待应用尺寸，不直接打断恢复。实时输出继续排队，不能越过快照；连续输出的合并也不能跨过尺寸变化操作。

关掉面板、切换 tab 时，浏览器直接关闭 WebSocket、销毁 xterm；再回来时重新走 F3。

### F4 输入与尺寸变化

- 按键：xterm 产生的数据作为 `input` 发出，终端会话原样写给 shell。浏览器把大段粘贴拆成多条依次发送，每块都检查完整 `{ type: "input", data }` 经 JSON 编码后的 UTF-8 字节数，必须不超过 65,536 字节；不能只检查原文长度。拆分不切断 Unicode 字符，拼接各块必须得到原始输入。服务端 `maxPayload` 对整条 WebSocket 消息执行同一上限，超过时以 1009 关闭连接；不允许通过分片消息绕过限制（D8）。
- 尺寸：容器大小变化时，浏览器用 fit 插件算出新行列数，变化了才发 `resize`；页面重新获得焦点时也发一次，避免另一个页面调整尺寸后，这个页面的显示一直错位。服务端把合法的尺寸变化放入该终端执行队列，轮到时一起调整 PTY 和服务端屏幕；浏览器的本地尺寸变化也走写入队列，不插入尚未完成的快照或输出写入。超出范围（列 2–500，行 1–200）的请求丢弃。多个页面同时打开时，以最后一次为准（D10）。

### F5 输出推送

1. 每个终端用一条内部执行队列，按入队顺序处理输出、接回快照和尺寸变化。处理输出时写入 headless，等待写入完成回调，再向查看者推送；随后处理下一项。队列不能等待某个查看者的网络发送。屏幕未处理完的输出达到内部高水位时暂停读取 PTY，降到低水位后恢复；完成量由 headless 的写入回调确认。高低水位属于内部实现参数，需用持续输出验证，不能靠断开查看者代替服务端的反压。终端关闭时也必须能结束已暂停的 PTY。
2. 每个查看者独立统计应用层待发消息（包括快照后等待发送的输出）与底层 ws `bufferedAmount` 的合计，消息从应用队列移交 ws 时不重复计数。应用队列按 JSON 编码后的 UTF-8 字节数计量。超过 2 MB（`2 * 1024 * 1024` 字节）时，以 4408 关闭该连接并清空它的队列；其他查看者不受影响，也不因这个页面慢而暂停 PTY。
3. 浏览器用一个小型队列合并连续输出，等待 xterm 的写入完成回调后再处理下一批。实时输出按 UTF-8 字节数统计“尚在排队 + 已交给 xterm 但未处理完”的合计；超过 2 MB 时主动断开，丢弃旧连接的待处理输出并退避重连。初始快照单独恢复，其间到达的实时输出也要计入队列额度。旧连接的回调不能继续修改新连接的队列或画面。
4. 收到 4408 或浏览器本地积压超限时，采用同一套退避重连（1 秒起，逐次加倍，最长 10 秒），重新走 F3 拿快照。持续超限时不能仅因握手或收到快照就重置退避。退避降低重试频率，不承诺持续刷屏时不再重连；用户可以关闭终端。
5. 浏览器的写入完成回调只用于本地排队，不发送跨网络的逐条输出确认。服务端因自身屏幕处理不过来而暂停读取时，持续输出的程序可能暂时阻塞；单个慢页面则通过断开隔离（N12）。

### F6 关闭终端

1. 用户点终端 tab 的 `x`，浏览器发 `DELETE /v1/terminals/:id`（不带强制标记）。服务端先查记录：不存在按第 6 步返回 404；已有关闭任务就等待它；上次清理失败则直接重试清理。只有仍为 `running` 且未带强制标记时，才进入第 2 步检查忙闲；带强制标记直接进入第 4 步。
2. 终端会话从进程表（`ps -A -o pid=,ppid=,comm=`）找出 shell 的全部子孙进程：
   - 有子孙进程（前台、后台都算），说明有程序在运行，返回 409 `TERMINAL_BUSY`，带上第一个子进程的名字（取文件名部分）；
   - 没有，说明空闲，进入第 4 步。Windows 上不查进程表，不会返回忙（D7）。
3. 浏览器收到 `TERMINAL_BUSY` 时弹出确认：“终端里还有程序在运行（node），关闭会把它一起结束。”用户取消就保留 tab；确认后再发 `DELETE /v1/terminals/:id?force=1`。
4. 终端会话标记为“正在关闭”，拒绝新输入、尺寸变化和接回，并创建唯一的关闭任务（`closePromise`）。若任务已存在，重复关闭直接等待它，不重新查询忙闲或启动另一轮清理。终端仍留在登记表内并占用名额；列表仍返回这条记录及 `closing` 状态，但不允许接回，接回返回 4404。
5. 关闭任务负责结束进程并释放资源：
   - macOS / Linux：发信号前记录 shell 及需要清理的子孙进程，再向 shell 发 SIGHUP。给进程最多 2 秒正常退出，全部退出即可提前完成；宽限期后对仍存活的 shell 和记录的子孙进程发 SIGKILL，最多再等 1 秒检查结果，仍有进程存活即算清理失败（走第 7 步）。一次关闭最长约 3 秒。shell 先退出不能取消对子孙进程的清理。`setsid`、`nohup` 主动脱离终端的进程遵循 D7 的排除规则。
   - Windows：调用不带信号参数的 `kill()`，等待退出结果；node-pty 在 Windows 上传入信号会抛错。
   - 关闭不能被输出积压或慢查看者卡住；处理已暂停的 PTY，释放屏幕、监听器和连接。进程退出时向仍连接的查看者发送一次 `exit` 并以 1000 关闭连接，不重复通知。
6. 清理成功后，终端管理器删除记录、释放名额，REST 返回 200；浏览器随后移除 tab。终端已不存在（404）也当作关闭成功。
7. 清理失败或等待超时，返回 500 `TERMINAL_CLOSE_FAILED` 并记录原因，不返回成功、不删除记录。列表返回 `close_failed` 及失败原因，浏览器保留 tab，刷新后也恢复该标签，显示失败并允许重试。服务端保留终端不可交互的状态，清除失败的 `closePromise`，让重试或 serve 停止能够再次清理；重试沿用之前记录的待清理进程，不因 shell 已退出而丢掉剩余子进程，也不重新询问忙闲。第一版不增加后台自动重试。创建失败后仍有资源未清理的记录也按此规则返回列表，保留 id、目录和 shell 等展示信息。

前端请求等待期间保持原画面，仅禁用关闭按钮的重复点击，不额外显示“正在关闭”或转圈。shell 的退出通知与关闭任务分工：退出事件只记录结果并通知查看者；主动关闭时，记录删除由关闭任务在清理成功后完成。

### F7 shell 自己退出

终端仍为 `running` 时，用户输入 `exit` 或 shell 崩溃，终端会话向所有查看者发 `exit`（带退出码），以 1000 关闭连接，终端管理器移除登记。浏览器在终端里显示“进程已退出（代码 0）”，tab 保留到用户关闭，关闭时按 F6 第 6 步处理 404。已经进入关闭流程的记录（包括上次关闭失败、当前没有 `closePromise` 的记录）仍由 F6 清理成功后删除，不能仅凭 shell 退出就释放名额。

### F8 `ohbaby serve` 停止

1. 停止开始时，终端管理器标记为“已关闭”，之后的新建一律拒绝；正在开的 shell 开好后立即结束（F2 第 6 步）。
2. 清理步骤里“结束全部终端”：并行启动或等待每个终端的关闭任务，包括正在关闭和上次清理失败的终端；正在新建的终端也必须等创建及后续清理结束。使用 `Promise.allSettled` 收集结果，单个失败不能跳过其他终端。2 秒是进程正常退出的宽限期，不是整个停止流程的绝对耗时上限；清理检查须有界，并纳入 daemon 现有的停止期限与错误汇总。
3. 传输层先对所有 WebSocket 连接 `terminate()`，再关闭 HTTP server，避免停止流程被已升级的连接挂住。

终端不在重启后恢复（N11）。

### F9 Host 校验（所有请求）

daemon 监听 loopback 地址时，每个请求（包括 WebSocket 升级请求）的 Host 头主机名必须是 `localhost`、`127.0.0.1`、`[::1]` 或 serve 实际绑定的 loopback 地址，端口不限，否则返回 403。端口不限是为了兼容 SSH 端口转发。监听非 loopback 地址时不做 Host 校验，但终端接口整体关闭（D11）。

## 3. Interface Definition（接口定义）

### 3.1 共享契约（`ohbaby-sdk/src/contract/terminal.ts`）

```ts
/** 列出和新建返回的终端信息。 */
interface TerminalInfo {
  readonly id: string;          // 服务端生成的随机 id
  readonly directory: string;   // 初始目录：所属 workspace（规范化后的绝对路径），没有 workspace 时为用户主目录
  readonly title: string;       // tab 标题，服务端计算：目录名，主目录为 "~"
  readonly shell: string;       // shell 名，如 "zsh"，用于 tab 悬停提示
  readonly createdAt: number;   // 毫秒时间戳，补 tab 时按它排序
  readonly state: "running" | "closing" | "close_failed"; // 控制接回与关闭，不逐项显示状态标签
  readonly error?: string;      // 清理失败时供页面提示的原因
}

/** 浏览器 → 服务端 */
type TerminalClientMessage =
  | { readonly type: "input"; readonly data: string }
  | { readonly type: "resize"; readonly cols: number; readonly rows: number };

/** 服务端 → 浏览器 */
type TerminalServerMessage =
  | { readonly type: "snapshot"; readonly data: string; readonly cols: number; readonly rows: number }
  | { readonly type: "output"; readonly data: string }
  | { readonly type: "exit"; readonly exitCode: number; readonly signal?: number };
```

另外导出：子协议名 `ohbaby.terminal.v1`、token 子协议前缀 `ohbaby.bearer.`（后接 base64url 编码的 token）、错误码常量、关闭码常量。以上是字段约定，具体写法以实现为准。

### 3.2 REST

沿用现有响应格式：成功 `{ ok: true, ... }`，失败 `{ ok: false, error: { code, message } }`。三个接口都要求 `Authorization: Bearer <token>`；新建时 `x-ohbaby-directory` 可选，不带时在用户主目录打开（D3）。

| 接口 | 请求 | 成功 | 失败 |
| --- | --- | --- | --- |
| `POST /v1/terminals` | `{ cols, rows }` | 201 `{ ok, terminal: TerminalInfo }` | 409 `TERMINAL_LIMIT_REACHED`；503 `TERMINAL_UNAVAILABLE`（附原因） |
| `GET /v1/terminals` | — | 200 `{ ok, terminals: TerminalInfo[] }`，包含所有 workspace 尚未删除的终端（含正在关闭、清理失败），由浏览器按创建时间补齐标签（F1b） | — |
| `DELETE /v1/terminals/:id` | 可选 `?force=1` | 200 `{ ok }` | 409 `TERMINAL_BUSY`（附 `process`）；404 `TERMINAL_NOT_FOUND`；500 `TERMINAL_CLOSE_FAILED` |

三个接口共同的失败：
- 401 未授权，沿用现有响应 `{ ok: false, error: { message: "Unauthorized" } }`（现有 401 不带 code）。
- 403 `TERMINAL_LOOPBACK_ONLY`：非 loopback 模式。
- 403：Host 头不合法（F9，作用于所有接口）。
- 400：目录无效，沿用现有错误码。只有 `POST` 会返回；`GET` 和 `DELETE` 忽略 `x-ohbaby-directory`。

### 3.3 WebSocket

- 地址：`/v1/terminals/:id/attach`
- 子协议：浏览器提供 `["ohbaby.terminal.v1", "ohbaby.bearer.<base64url(token)>"]`，服务端通过 `handleProtocols` 只选中 `ohbaby.terminal.v1`。
- 消息：JSON 文本帧，格式见 3.1。单条完整消息上限 64 KiB（`maxPayload: 65536`）。
- 握手前拒绝（HTTP 403，浏览器只能看到 1006）：Host 头不合法、非 loopback 模式、Origin 不是本机。

| 关闭码 | 含义 | 浏览器怎么做 |
| --- | --- | --- |
| 1000 | shell 已退出，或终端被关闭 | 显示“进程已退出”，不重连 |
| 1009 | 单条消息超过 64 KiB（正常粘贴已被切块，不会触发） | 重连 |
| 4401 | token 错误或未配置 | 走现有的未授权处理，不重连 |
| 4404 | 终端不存在或已进入关闭流程 | 不重连；同步列表，记录仍在则保留关闭入口，不存在才显示“终端已结束” |
| 4408 | 浏览器跟不上，积压超过 2 MB | 退避重连，拿快照 |
| 其他（含 1006、网络断开） | — | 退避重连 |

## 4. Data Ownership & Responsibility（数据归属与责任）

| 数据 | 归属 | 说明 |
| --- | --- | --- |
| 终端登记表（id → 终端会话） | 终端管理器 | 只存在于 serve 进程内存，serve 停止即清空 |
| 正在创建的任务 | 终端管理器 | 创建前登记，成功后转为正式终端；失败完成清理后释放，serve 停止时也等待这些任务 |
| 终端总数 | 终端管理器 | 已登记终端加正在创建的任务，包括正在关闭或清理失败的记录，全局上限 16；同一份资源只计一次 |
| shell 进程 | 终端会话 | 由会话负责结束，包括 2 秒后强制结束 |
| 屏幕内容（含 1000 行滚动历史） | 终端会话的服务端屏幕 | 唯一可信来源；浏览器里的 xterm 只是一个随时可以丢掉的显示 |
| 查看者集合与各自的待发队列 | 终端会话 | 连接关闭即删除 |
| tab 与终端 id 的对应关系 | 浏览器内存中的右侧面板状态 | 刷新后丢失，由 F1b 按服务端的终端重建（D9） |
| node-pty 加载结果 | PTY 适配 | 进程内只加载一次，失败原因保留到 serve 停止 |
| token、daemon 地址、workspace 目录 | 现有 daemon 连接配置 | 终端客户端只读取，不另存 |
