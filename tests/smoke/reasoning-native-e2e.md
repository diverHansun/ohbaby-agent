**For this ZenMux Luna Chat route, select the explicit profile capability `wire: "openai"`.** The real native-wire OFF run produced zero reasoning tokens and no new native state. The generic `reasoning.enabled=false` run still produced reasoning tokens and native state; it is not evidence of effective disabling. This is a profile-specific observation and does not add guessed ZenMux aliases to production defaults.

DeepSeek V4 Flash documents high/max only. Its ON run is explicitly high and cannot establish the T28 default-medium Chat requirement. The harness does not invent a medium mapping. Sonnet 5 supports disabling adaptive thinking; manual budget mode is unsupported. All profiles omit temperature.

Each model profile has a basic budget of four generation HTTP requests across ON/OFF, SDK retries zero, and a 90-second HTTP timeout. Two additional diagnostic requests are reserved but not automatically executed by this runner. Explicit `--diagnose` restricts a run to one HTTP request and labels it diagnostic; a successful diagnostic test means only that the one-request limit was respected, not that the matrix passed. Any HTTP failure or runtime failure stops the profile. The basic sequence is two independent sessions, each with:

1. A real Lifecycle Run through production SDK/adapter, ContextManager, SQLite MessageManager, tool scheduler and cache tracker. The no-argument probe executes once; `shouldStopAfterTurn` stops the Run after the completed tool result.
2. SQLite close/reopen, fresh manager/context/tracker, a new user Run, and exactly one continuation generation containing the prior native state and completed tool result.

The checks require exactly one tool execution, exact tool/result correlation, one persisted usage carrier per accepted assistant, persisted state identity after SQLite reopen, and fresh tracker accounting that does not replay prior usage. Every ON profile must persist actual reasoning/thinking state and send exact fingerprints in the next HTTP request; phase-only output fails this requirement. OFF responses with positive reasoning usage or new native reasoning fail the semantic check even when `runtimePassed` is true. Cache read zero is valid; unknown is preserved by the production tracker. These short native continuation inputs may fall below a model's cache threshold: zero is this test's observation, not evidence that caching is broken.

Evidence files retain control parameters, HTTP status/error code, safe owned protocol failure reasons, numeric raw usage subtrees, accepted Step usage, tracker totals, state estimate source, and SHA-256 fingerprints of native replay items. Responses snapshot metadata also records event type, item type/index, hashed identity/projection, and encrypted-content presence/length/hash. Chat detail metadata records index type, known field names, and payload types/lengths/hashes, with no private values or unknown field names. Completed frames remain available if the SDK aborts later. Reports omit credentials, headers, prompts, model output, signatures and ciphertext. Temporary SQLite files are removed after verification. Tracker totals before and after SQLite reopen are separate because the production tracker starts fresh. `testKnownCache` independently combines accepted usage across this test's four requests; it is not a restored session total.
